引擎基本概念

创建：2026-06-09

本文是 Naiz 引擎制作者手册的第一篇。从制作者视角介绍引擎的核心概念——不涉及源码路径、工具链命令或内部实现细节。

标有 【预留】 的概念尚未实现，不可实际使用；此处仅说明设计意图，供参考。

1. 画面规格

1.1 分辨率与模式

引擎运行在 PC-98 标准的 640×400 像素、256 色 图形模式下（PEGC packed-pixel）。这是经典的视觉小说显示规格——纵向 400 线提供 16:10 的画面比例，接近现代 16:9 的视觉感受。

1.2 默认画面

引擎启动后会加载首个 .nb 场景脚本，由 bg 命令加载背景 MAG 图像（如无则 VRAM 保持初始状态）。对话框叠加在背景之上：

640×400 屏幕全景
┌────────────────────────────────────────────┐
│                                            │
│              背景 MAG 图像 (256c)            │  ← 约 280px 高
│           （由 bg 命令加载）                  │
│                                            │
├────────────────────────────────────────────┤  ← y=280
│  对话框底色 (palette 248, 480×115)         │
│  │ "这里是 Naiz 演示"  (UTF-8, 白色)       │  ← y=308
│  │                                         │
└────────────────────────────────────────────┘
  • 上半部分：背景图像（MAG 格式，256 色）
  • 下半部分：对话框（固定位置，显示对白）

1.3 256 色调色板

引擎使用 PC-98 的 256 色模拟调色板。以下为引擎保留的固定色（其他索引由 MAG 图像动态设置）：

索引颜色用途
0#000000 黑初始值
7#FFFFFF 白文字、边框
15#000000 黑精灵透明色（blit 跳过）
248#000000 (动态黑/蓝)对话框底色
249–255—备用 UI 色（预留）
调色板在每次 bg 命令时更新。索引 248–255 在构建时已被 pack_images.py evacuation，运行时由 cmd_bg（恢复 248）和菜单模块（save/restore 250/251）保护。索引 7、15 在 SPR 类型中跳过。详见 B11 §5.2。

1.4 PC-98 显示架构

PC-98 PEGC 的显示硬件由三部分组成：

硬件层说明引擎使用
Graphic Plane A图像平面 A（4-bit/像素）✅ 合并为 8-bit 256色 packed-pixel 640×400 VRAM，全部渲染目标
Graphic Plane B图像平面 B（4-bit/像素）
Text Plane独立硬件文字层（字符发生器 + 属性内存）❌ 不使用。DOS/4GW 保护模式下不可见，文字经 draw_text() 位图绘制到图像 VRAM

引擎的所有「软件图层」（背景、精灵、对话框、文字）均在单层图像 VRAM 上通过多趟绘制顺序实现叠加，不存在硬件合成。这就是引擎使用 fill_rect/vram_blit 等像素操作而非 printf 的原因。

详见 mc03-图层渲染与换装机制 §1。

2. 对白（Dialog）

对白是视觉小说引擎最核心的 UI 元素。在 Naiz 中，对白是一个固定位置的文字框——位置、尺寸、风格在整个游戏过程中保持不变。

2.1 什么是对白

在绝大多数 ADV/VN 游戏中，角色对话（"台词"）以及旁白叙述，都是通过屏幕底部的对话框逐句呈现的。玩家阅读一句后按键盘翻到下一句——这就是对白系统的基本模型。

Naiz 的对白模型是原地替换式：每次显示一句话时，旧文字被完全清除，新文字在同一位置出现。

2.2 对话框布局

对话框是屏幕底部的矩形区域，覆盖在背景之上：

属性值说明
水平位置 (X)80 px距屏幕左边缘 80px
垂直位置 (Y)280 px距屏幕顶部 280px
宽度480 px约屏幕宽度的 3/4
高度115 px距屏幕底边 5px
背景色palette 248（动态黑/蓝）覆盖背景图
边框白色（索引 7），2px 宽矩形外框
 
对话框放大：
  ┌──────────────────────────────────────────────────────────┐
  │ 白色外框 (draw_rect, 2px 宽, 颜色7)                      │
  │                                                          │
  │  24px 缩进 → "这里是 Naiz 演示"                           │  ← 文字区, y+28
  │                                                          │
  └──────────────────────────────────────────────────────────┘
  ← 80px →←─────────────── 480px ──────────────────→← 80px →

2.3 文字

对白文字绘制在对话框内部：

属性值说明
水平起始 (X)104 px对话框左边缘 + 24px 缩进
垂直起始 (Y)308 px对话框顶部 + 28px 偏移
ASCII 字体8×16 点阵等宽每个 ASCII 字符占 8×16 像素（32 字节/字）
CJK 字体16×16 点阵等宽每个 CJK 字符占 16×16 像素（32 字节/字）
颜色白色（索引 7）与对话框边框同色
每行最大 ASCII 字数约 57 个对话框文字区宽度 456px / 8
每行最大 CJK 字数约 28 个对话框文字区宽度 456px / 16

当前限制：

  • 支持 ASCII（7-bit） + CJK（UTF-8 3 字节编码）
  • 不支持自动换行——过长的句子会超出对话框被裁切，制作者需手动控制每行字数
  • 文字区背景清除使用 palette 248，不依赖固定颜色索引

2.4 玩家操作

Naiz 的对白系统是键控推进式：

操作按键行为
翻到下一句Space显示 host{} 指定的下一句对白
翻到下一句（替代）Enter同 Space
快进Ctrl（按住不放）以最快速度依次跳过所有对白和场景事件

设计细节：

  • Space / Enter 是消费式触发——每按一次只翻一句。按住不放不会连续翻页，避免误操作跳过文本。
  • Ctrl 是快进模式——按住后引擎自动逐帧推进，适用于测试跳转或玩家想快速浏览见过的剧情。

2.5 对白设计须知

对白系统的设计假设和限制，制作者需要了解：

要点说明
位置固定所有对白在同一位置显示——不能设置"第一句在上、第二句在下"
原地替换每次显示新对白会清除之前的文字（palette 248），画上新文字；不存在"文字滚动"或"历史回溯"
单句单位一次显示一段完整的文字；对话框高度不支持多行文本同时存在
无角色名栏当前对话框不区分说话角色——角色名显示功能预留
无文字特效文字不消失、不渐显、不变色——所有对白以同一颜色和位置出现
256 色限制对话框色彩受 256 色调色板约束，UI 保护色为索引 7（白）、15（透明）、248（对话框底色）

3. 场景（Scene）

3.1 什么是场景

场景（scene）是一段按顺序执行的游戏流程单元。一个视觉小说由若干个场景组成，玩家按顺序经历每个场景——就像电影的"场"。

在一个场景内，引擎执行一系列 NB 命令。命令可以是"显示对白"、"等待玩家输入"、"跳转到另一场景"等。

3.2 场景流程示例

  场景开始
    │
    ├─ host{"这里是 Naiz 演示"}        → 显示对白，等待玩家翻页
    ├─ host{"Naiz 是一个文字冒险引擎"} → 显示对白，等待玩家翻页
    ├─ scene end                      → 场景结束
    ▼
  下一个场景 / 游戏结束

完整语法参考 sc01-NB剧本概述。
