图层渲染与换装机制

创建：2026-06-27
最后更新：2026-09-11

本文从制作者视角说明 Naiz 引擎的图层渲染架构——立绘、对话框、背景之间的堆叠关系，以及换表情、换装时的渲染策略。

1. 图层堆叠（从下到上）

PC-98 PEGC 提供 2 个图像平面（Graphic Plane A + B）组合为单层 8-bit 256色 VRAM（640×400），另有一独立硬件文字平面（Text Plane）。引擎只使用图像 VRAM（绘制目标可在 VRAM 与 RAM 复合缓冲间切换：render_set_target / text_set_target），文字平面不可用——DOS/4GW 保护模式下不可见，见 fd01 §1.4。引擎通过多趟渲染顺序在单层 VRAM 上实现多层堆叠效果：

Layer 0: 背景（bg MAG）
Layer 1: 对话框背景区还原
Layer 2: 精灵（立绘/角色，最多 16 个）
Layer 3: 对话框（透明/半透明/实心底色）
Layer 4: 文字（对白文本，覆盖在对话框之上）
Layer 5: 菜单覆盖层（menu_layer，RAM 复合缓冲 → 整屏 blit）

每趟渲染只写入该层对应的区域，不会覆盖下方已绘内容。菜单（主菜单/加载/设置/画廊）是「瞬态覆盖」：激活时内容先绘制进独立的 RAM 复合缓冲，再由 menu_layer_blit 整屏发布到 VRAM，退出时按下层画面还原，见 §6 菜单图层。

2. 精灵（立绘）机制

引擎通过 char 命令控制立绘。详见 mc02-立绘与角色。

2.1 显示与定位

char charlie l            # 左侧显示 charlie（默认 body，左位自动水平翻转）
char charlie r expr_happy # 右侧显示 charlie，表情 happy（face）
char charlie c body       # 中央显示 charlie（body 全身）

2.2 换表情 / 换装

char charlie l expr_angry # 只刷新面部区域（face 模式，不重绘对话框）
char charlie c body       # 从 body 切换，不受 clip_h 限制

face 约束：换表情（face）只在 y < 280 的上半身区域绘制，不触及对话框范围。

全高绘制（R20 起）：立绘（body / 全身）全高绘制，不再因对话框而裁剪——对话框合成盖于其上（z 序在上），PAT75 伪透明孔透出立绘腿；calc_sprite_clip_h() 仅服务于 face 表情的上半身裁剪。

3. 对话框渲染

对话框的外观样式见 cf03-对话框样式方案。本节说明对话框在渲染管线中的出现、更新与清理机制。

3.1 出现时机

对话框由文本指令触发：剧本中第一条台词（host{...}、对白命令等）出现时，引擎自动弹出对话框。具体流程：

  1. 文本指令调用 dialog_show()（nb_dialog.c）
  2. 若对话框尚未显示 → layer_dialog_show()：构建复合缓冲、把「框 + 当前页文字」发布到 VRAM
  3. 若对话框已显示（翻页/后续台词）→ 在复合缓冲内重画框页并更新文字

也就是说：同一个场景内对话框只弹出一次，后续台词复用同一框，只替换文字内容。

3.2 首次弹出（layer_dialog_show）

首次出现时按以下顺序构建：

  1. 分配 复合缓冲 dialog_layer（480×115：框 + 当前页文字）与活动底 dialog_occluder（对话框区域纯背景 + 已有立绘在框内的像素）
  2. 把对话框底色（半透明图案或实心，按样式设定）+ 2px 白色边框绘制进复合缓冲
  3. 标记「对话框已显示」

之后每次文字刷新，只在复合缓冲内重画框页（清掉上一页文字）+ 写入新文字，再整框发布到 VRAM，无需重绘底色边框之外的区域。

3.3 复合缓冲与活动底的分工

对话框区域由两块独立的 RAM 内存承载，用途相反：

内存内容用途
dialog_layer复合缓冲（框 + 当前页文字）勾兑后整框 blit 到 VRAM；换背景后按下层新画面重建底、按「渲染投影」用同一框与当前页文字重新生成
dialog_occluder活动底（对话框区域纯背景 + 立绘框内像素）作为复合缓冲的底（PAT75 伪透明孔透出背景/立绘）；对话框隐藏时用它把该区域还原成纯背景

要点：对话框背后的纯底由背景图层提供（under_dialog）。每次换背景、角色增减之后都要重建活动底，否则伪透明与隐藏还原会用错画面。

3.4 对话框的消失 / 清理

按触发原因分为三种，清理程度不同：

场景触发做了什么
正常隐藏bg(hidedialog) 或 char(hideall)把对话框区还原成纯背景 → 对话框消失；复合缓冲与活动底保留，方便再次弹出
更换背景bg(...){key}框 + 当前页文字跨图存活（按下层新画面重建并重新发布）；cg(){key} 则自动收起对话框并清空台词
切换场景scene(...)清空全部状态，释放缓冲内存；下个场景首次台词再重新弹框

3.5 与角色的联动清理

角色身体与对话框区域重叠时，清理需要按顺序处理：

  • 隐藏单个角色：若该角色身体压住对话框 → 隐藏后重建活动底并重新发布复合缓冲（伪透明孔透出新画面）
  • 最后一个角色消失：先把角色区域（对话框上方）的背景还原，再重建活动底（因为对话框上方的画面已变化）
  • char(hideall)（隐藏所有角色）—— 完整链路：
    1. 逐个隐藏所有角色（依次重建活动底）
    2. 隐藏对话框：把纯背景还原到对话框区
    3. 清空台词状态（角色名、台词缓冲归零）

4. 背景 / CG 与场景切换

  • bg(){key}：加载新背景 MAG 并捕获底下画面；对话框跨图存活——自动按下层新画面重建活动底、按「渲染投影」重新生成「框 + 当前页文字」并发布（背景 key 写在花括号负载）
  • cg(){key}：全屏展示 CG 并自动收起对话框、清空当前台词（全屏事件，下一句台词重新开框）
  • bg(hidedialog) / cg(hidedialog)：只收起对话框并还原对话框区域背景，不加载新图
  • 每次 scene(...) 切换：自动清屏为黑屏，然后执行新场景的 bg(...) 指令

5. 精灵操作速查

NB 命令效果渲染策略
char(pos, body){name}显示立绘（默认 body）全高覆盖式 blit + 重建对话框活动底
char(pos, expr){name}换表情clip_h 限定上半身（y<280），不重建
char(pos, body){name}换全身全高完整重绘 + 重建对话框活动底
char(hideall)隐藏所有立绘 + 对话框 + 清空台词逐精灵隐藏（重建底）→ 还原对话框背景 → 清空台词状态（见 §3.5）

6. 菜单图层（menu_layer）

主菜单（mainmenu()）、加载/存档（save/load）、设置（settingmenu()）、CG 画廊（cgvmenu()）四个菜单共用同一套可复用封装 menu_layer：菜单激活时先把内容绘制进专门的 RAM 复合缓冲，最后整屏发布到 VRAM。这与对话框的复合缓冲（§3.3）是两套独立机制——对话框在演出中持续存在，菜单是瞬态覆盖层。

菜单分为两种模式：

模式做法当前使用
opaque（不透明全遮罩）打开时把下层 VRAM 画面快照为底（menu_layer_open）；内容绘制进复合缓冲，menu_layer_blit 整屏 / blit_rect 局部发布；关闭时把底整块还原（menu_layer_close(1)），下层画面原样回来四个菜单均用
transparent（透明镂空）复合缓冲以透明索引填充，blit 时逐像素跳过透明（不遮下层、不占底内存），关闭时不还原预留（供未来菜单复用）

焦点移动等局部变化走增量会话：menu_layer_begin_draw()（重接缓冲目标）→ 只重画变化的文字/指示符 → menu_layer_commit() → menu_layer_blit_rect()（只发布变化的矩形）。设置菜单还以 menu_layer_erase_to_base() 把旧语言名/光标区域擦回底层画面再画新的，取代了旧的 VRAM 快照数组。API 契约与接入示例见 menu_layer.h 头部注释。
