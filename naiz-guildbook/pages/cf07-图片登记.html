图片登记（images.map）

创建：2026-09-27
最后更新：2026-09-27

本文从制作者视角说明新图片如何进入游戏：images.map 声明 PNG→MAG 转换、ASSETS.DB 登记资源行、build 打包进 IMAGE.DAT。MAG 格式与调色板机制见 mc04 MAG 图片机制，构建命令见 makegame.sh。

1. 文件位置与格式

每个项目有一份映射表 assets/<game>/images.map，另有 assets/common/images.map 存放全项目通用素材（构建时先处理 common，再处理本项目）。一行登记一张图：

<png相对路径>  <MAG相对路径>  [选项...]
  • png相对路径：相对于 assets/<game>/ 的源文件，PIL 可读即可（PNG/JPG 均可）。
  • MAG相对路径：相对于 projects/<game>/ 的输出，一般放在 images/ 下；MAG 基名 ≤8 字符（DOS 8.3 约束，超长会在 HDI 短名阶段截断碰撞）。
  • # 开头为注释行；文件头注释即完整选项说明。

实例（demo-a2 新增 4 图）：

png/bg/bg-beach1.jpg       images/beach1.MAG   --256color --cover
png/bg/bg-home-day.jpg     images/homeday.MAG  --256color --cover
png/cg/cg01.png            images/cg01.MAG     --256color --cover

2. 行内选项

选项含义
--256color量化到 256 色共享调色板（默认标记，背景/立绘/CG 通用）
--sprite角色立绘：调色板索引 15 留作透明标记，不参与量化；alpha<128 区域映射为索引 15
--cover按长边缩放占满 640×400、居中裁掉溢出（保持比例，无黑边）。不加则为 contain：按短边缩放、居中贴、留边。需占满全屏的背景/CG 必须加
--dither量化时 Floyd-Steinberg 抖动
--no-resize跳过自动缩放到 640×400，保持源图像素（仅背景）
--filter-white量化前把近白像素映射到调色板白色

构建是增量的：源文件变新或选项变化（签名记在 projects/<game>/.mag_conv_state.json）才重转，其余跳过。

3. 登记三步

只写 images.map 不够，MAG 还要在资源库里挂名，引擎才找得到：

  1. images.map 加一行（选好选项，背景加 --cover，立绘加 --sprite）。
  2. projects/<game>/ASSETS.DB 的 img_map 表手工插入一行（与 ANI 同待遇，暂无自动化登记入口）： 
    INSERT INTO img_map (name, filename, type) VALUES ('beach1','images/beach1.MAG','IMG');
    name 为剧本引用 key（小写）；type 取 'IMG'（背景）/ 'SPR'（立绘）/ 'CG'（事件图，进画廊）。
  3. 运行 ./makegame.sh build <game>：PNG→MAG → IMAGE.DAT 重打 → nb_asset_table.h 再生（含 cg_map）。

4. 剧本引用

  • 背景：bg(){beach1}；事件 CG：cg(){cg01}——对象一律写花括号负载，bg(beach1) 这类括号形态会被拒绝。
  • cg(){key} 展示后自动收起对话框并永久解锁进画廊，下一句台词自动重开框。

5. 删除旧图（4 层清理）

退役图片要清干净，否则残留进包：images.map 去行 → 源 PNG 与 projects/.../images 下 MAG 删除 → ASSETS.DB 按 filename DELETE → .mag_conv_state.json 去对应签名。动手前先确认 scene/*.nb 与 expressions.json 零引用。IMAGE.DAT 删位留空槽，存量 asset id 不漂移。
