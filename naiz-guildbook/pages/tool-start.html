start.sh 使用说明

创建：2026-08-29
最后更新：2026-08-29

start.sh 是仓库的统一入口脚本，负责环境安装检查、各类依赖/模拟器安装、以及代码审计。日常最推荐直接运行、用数字菜单操作；命令行子命令适合写进脚本或熟练后使用。

1. 交互式菜单（主要用法）

不带任何参数运行：

./start.sh

会显示一个菜单，输入数字并按回车即可执行对应功能：

菜单数字功能
1运行环境检查（check）
2进入「环境安装」子菜单（可逐项安装依赖、模拟器、编译器等，详见下）
3运行代码审计（audit）
4运行完整审计（fullaudit，含编译）
0退出

选 2 进入安装子菜单后，会再列出可安装项，同样按数字选择，例如安装 Open Watcom 编译器、NP2kai 模拟器、系统级工具等。菜单操作失败不会退出，会回到菜单让你重试。

新手提示：第一次搭环境就先跑 1 看缺什么，再用 2 逐项补齐。

哪些是「备用的东西」，不一定要装？

安装子菜单里有几项属于可选 / 备用，正常开发用不到，不必安装：

  • djgpp：另一套编译器工具链，仅当 Open Watcom（主力）不可用时的备选，一般不用装。
  • retroarch：备份模拟器配置（backup-emu），仅在想换用 RetroArch 等其他前端时才需要，NP2kai 才是默认测试用的模拟器。
  • mirror：Git 仓库来源（镜像）设置，只在下载慢、要切换镜像源时才用。
  • commercial：商用相关菜单，仅涉及商用分发时才需要。

真正必装的只有：pip（Python 依赖）、deps（系统工具）、watcom（引擎编译器）、np2kai（测试模拟器）——其余按需再装即可。

2. 命令行用法（进阶 / 脚本化）

熟练或要写进自动化脚本时，可直接跟子命令，跳过菜单：

./start.sh <子命令> [参数]
子命令作用
check检查当前环境（Python venv、依赖、工具链）是否就绪
pip安装 Python 依赖（pip-install）
deps安装系统级工具（system-tools）
np2kai安装/准备 NP2kai 模拟器
retroarch备份模拟器配置（backup-emu）
watcom安装 Open Watcom 编译器（引擎编译用）
djgpp安装 DJGPP 工具链
mirror进入 Git 仓库来源（镜像）设置
commercial商用相关菜单（commercial_menu）
audit运行代码审计（符号审计日志输出到终端与 logs/）
fullaudit [--no-make]六步流水线审计；--no-make 跳过 make 节

3. 常见用法示例

# 交互菜单里按 1 看环境缺什么（推荐）
./start.sh
# 等效的命令行写法：
./start.sh check

# 安装引擎编译所需的 Watcom 编译器
./start.sh watcom

# 提交前跑完整审计（含编译）
./start.sh fullaudit
# 只跑审计不重新编译
./start.sh fullaudit --no-make
