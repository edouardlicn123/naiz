bgm / sound / voice 音频指令

创建：2026-08-13　修订：0.3.019（原文称「平台占位 stub，暂不产生实际声音」，与 0.2.115 起的真实实现矛盾，已订正）

bgm()、sound()、voice() 三个命令分别控制背景音乐、音效和语音。三者均已实装：BGM 走 OPN/OPM 音源的 MIDI 实时解析播放，音效与语音走 YM3433B 的 PCM FIFO 流式播放，无任何占位。

1. 语法

bgm(){key}
bgm(stop)
sound(){key}
voice(){key}

对象（音频 key）写在花括号负载中；bgm(stop) 为 keyword 指令。这是与 bg(effect){key} 等一致的"对象在花括号、括号=参数±keyword"约定。

命令参数说明
bgm{key} 或 stop播放 / 停止 BGM（可循环）
sound{key}播放音效（SE，一次性）
voice{key}播放语音（一次性）

2. 参数说明

  • key 为音频资源键名，写在花括号负载，取自 ASSETS.DB 的 name 列
  • bgm(stop) 停止当前 BGM（对全部 16 个通道发 All-Notes-Off）
  • sound / voice 当前只支持播放，无停止形式；二者永不循环
  • bgm(key) / sound(key) / voice(key)（key 写在括号里）的形态已废止，会被引擎与脚本校验器拒绝

3. 示例

bgm(){morning}      # 播放清晨 BGM（循环）
bgm(stop)           # 停止 BGM
sound(){door_knock} # 敲门音效
voice(){fei_hello}  # 角色语音

4. 资源登记（key 从哪来）

音频源文件放 assets/<项目>/ 下，登记进 ASSETS.DB 的 img_map 表；构建期打包成部署树根部的单个 AUDIO.DAT。源文件不注入 HDI，运行时只读 AUDIO.DAT。

类型源位置格式登记
BGMassets/<项目>/bgm/.mid（SMF，运行时解析，原字节直通）type='BGM'
音效assets/<项目>/se/.pcm（8bit mono 容器）type='SND'
语音assets/<项目>/voice/.pcm（同上）type='VC'
  • filename 列相对 assets/<项目>/ 写（如 bgm/morning.mid），name 列即脚本里的 key
  • wav_convert.py 把 WAV 转 .pcm 并自动登记（--type SND|VC --name <key>）；BGM 无对应转换器，gen_test_midi.py 产测试曲后手动登记
  • name 同时是 AUDIO.DAT 的 TOC 条目名，必须满足 DOS 8.3 且截断后互异——同名会以硬失败拒绝打包

5. 音量与开关

  • BGM 音量 = MIDI CC7（通道音量）0–127，向全部 16 个通道下发；改音量即时生效，无需重播
  • 音效 / 语音音量 = A466 电子音量衰减 0–15，方向相反（0 最响）；二者共用同一条 PCM 通路，故只有一档音量、无法分开调节
  • 玩家设置里 BGM / 音效 / 语音各有独立开关。关闭某一通道时，只有该通道正持有共用 PCM 通路才会真正释放它——关音效不会误伤正在播的语音

key 不要翻译：bgm() / sound() / voice() 的 key 是资产名，不经 tr() 查找，翻译会导致引擎去找不存在的音频文件。请保持译文为空值（＝按原名播放）。

已知小瑕疵：i18n_gen 会把这些 key 当作可翻译文本提取（与 char / bg / cg 的排除清单不同），故它们会以空值形式常驻 game_<lang>.txt。留空即正确，不要填译文。

健壮性：key 未登记、AUDIO.DAT 缺失、.pcm 头非法时，引擎输出对应的 BGM WARN: / PCM WARN: 串口诊断并跳过播放，不崩溃。
