# B17 — 变量系统设计规范

## 一、概述

变量系统为 NB 脚本引擎提供 **通用键值对变量存储**，用于追踪剧情状态、角色好感度、游戏内计数等运行时数据。

设计目标：
1. **通用性** — 不限定用途（好感度/flag/统计计数皆可）
2. **编译期定型，运行时可变** — 变量定义由 JSON 在构建时生成 C 表，运行状态存于可变数组
3. **可扩展** — 为 NB 脚本命令和存档系统预留接入接口

当前阶段仅实现数据层（定义 + C API），脚本命令（`setvar`/`addvar`/`if`）留待后续与问题系统一并设计。

---

## 二、variables.json schema

变量定义文件 `projects/<game>/variables.json`：

```json
{
  "variables": [
    {
      "id":       "bond_fei",
      "name":     "Fei好感度",
      "desc":     "Fei对玩家的好感度",
      "initial":  0,
      "min":      0,
      "max":      100
    }
  ]
}
```

### 字段表

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `id` | string | 是 | 变量标识符，供 NB 脚本命令和 C lookup 使用。小写字母 + 下划线 |
| `name` | string | 否 | 显示名（存档界面、调试输出） |
| `desc` | string | 否 | 说明文字 |
| `initial` | int | 是 | 初始值 |
| `min` | int | 否 | 最小值（默认 0），`nb_var_set`/`nb_var_add` 自动 clamp |
| `max` | int | 否 | 最大值（默认 9999），同上 |

项目 `demo-a2` 当前定义 3 条好感度变量（`bond_fei`/`bond_ira`/`bond_neon`）。

### 类型规则

- 所有值均为 `int`（32-bit 有符号），C 层不做浮点或字符串支持
- 布尔值用 0/1 表示（设 `min=0, max=1`）

### 构建时校验

`export_vars.py` 不做深度校验，仅读 JSON 生成 C。无效 `id`（如空字符串）会在引擎 `nb_var_lookup()` 返回 -1，由调用方处理。

## 三、构建管线

```
projects/<game>/variables.json
    │
    ▼
tools/naiz_build/export_vars.py     ← build_game.py 第 2b 步调用
    │
    ▼
core/engine/nb_var_table.h          ← 自动生成的 C header（DO NOT EDIT）
```

### build_game.py 调用点（位于 export_asset_table 之后、compile_engine 之前）

```python
# 2b. Export variables.json → C header
export_vars_py = ROOT / "tools" / "naiz_build" / "export_vars.py"
var_header_dst = ROOT / "core" / "engine" / "nb_var_table.h"
subprocess.run(
    [str(VENV_PYTHON), str(export_vars_py), str(proj_dir), str(var_header_dst)],
    check=True,
)
```

### 生成的 nb_var_table.h 结构

```c
#define NB_VAR_COUNT 3

typedef struct {
    const char *id;
    const char *name;
    const char *desc;
    int initial;
    int min;
    int max;
} NbVarDef;

static const NbVarDef var_defs[NB_VAR_COUNT] = {
    {"bond_fei", "Fei好感度", "Fei对玩家的好感度", 0, 0, 100},
    {"bond_ira", "Ira好感度", "Ira对玩家的好感度", 0, 0, 100},
    {"bond_neon", "Neon好感度", "Neon对玩家的好感度", 0, 0, 100},
};
```

- 使用 `static const` 直接编译进引擎，不产生运行时文件 IO
- 变量数量和定义在编译期固定，不能在运行时动态增删

## 四、运行时数据结构与 API

### 源文件

| 文件 | 位置 | 说明 |
|------|------|------|
| `nb_vars.h` | `core/engine/nb_vars.h` | 公共接口声明 |
| `nb_vars.c` | `core/engine/nb_vars.c` | 实现 |
| `nb_var_table.h` | `core/engine/nb_var_table.h` | 自动生成（编译时） |

### 数据类型

```c
#include "nb_var_table.h"

/* 编译期变量定义（来自 JSON → C 表） */
static const NbVarDef var_defs[NB_VAR_COUNT];
// 字段：id, name, desc, initial, min, max

/* 运行时可变值 */
static int var_values[NB_VAR_COUNT];
```

### API 函数

```c
/* 将所有变量重置为 initial 值 */
void nb_var_init(void);

/* 按索引读取 */
int  nb_var_get(int idx);

/* 按索引写入（自动 clamp 到 [min, max]） */
void nb_var_set(int idx, int val);

/* 增量写入（自动 clamp） */
void nb_var_add(int idx, int delta);

/* 按 id 字符串查找索引（线性扫描，失败返回 -1） */
int  nb_var_lookup(const char *id);

/* 获取变量数量 */
int  nb_var_count(void);

/* 用于存档系统：返回 var_values[] 只读指针 */
const int *nb_var_get_state(void);

/* 用于存档系统：恢复整个 var_values[] */
void       nb_var_set_state(const int *state);
```

### Clamp 规则

`nb_var_set` 和 `nb_var_add` 内部执行 clamp：

```c
if (val < var_defs[idx].min) val = var_defs[idx].min;
if (val > var_defs[idx].max) val = var_defs[idx].max;
```

越界取值不会报错，静默截断。

### Makefile 集成

`core/Makefile` 中：

```makefile
SRCS += ... engine/nb_vars.c
OBJS += ... build/nb_vars.o
build/nb_vars.o: engine/nb_var_table.h
```

`AUTOEXIT` 变体同理（`a_nb_vars.o`）。

## 五、初始化与生命周期

### 初始化时机

变量系统在两条路径上初始化：

```
路径 A：引擎冷启动
────────────────
main()
  └─ nb_init()
       ├─ ...（settings、翻译表）
       ├─ nb_var_init()    ← 重置所有变量
       └─ nb_load("logo.nb")

路径 B：主菜单开始新游戏
────────────────
cmd_mainmenu()
  └─ "start" 被选中
       ├─ nb_var_init()    ← 重置所有变量（新游戏保证干净）
       └─ nb_load("nbook001.nb")
```

### 脏数据防护

| 场景 | 是否重置 | 理由 |
|------|----------|------|
| 引擎冷启动 | ✅ `nb_var_init()` | 干净状态 |
| 主菜单选 Start | ✅ `nb_var_init()` | 新游戏需重置 |
| 场景跳转 `scene("002")` | ❌ | 剧情推进需保留 |
| `scene("end")` → 主菜单 | ❌ | 回到菜单但不等于新游戏 |
| 主菜单再选 Start | ✅ | 走路径 B |
| 进程退出 | ✅ 自动 | 用户态内存释放，下次冷启动走路径 A |
| 未来 Continue（加载存档） | ❌ | 应恢复存档中的变量值 |

策略：变量在 engine boot 和 mainmenu start 两个入口重置，覆盖所有可能残留脏数据的路径。`scene("end")` 回到主菜单不重置——因为 continue（未来）需保留；再次点 Start 会重置。

## 六、存档系统接口预留

```c
const int *nb_var_get_state(void);
void       nb_var_set_state(const int *state);
```

- `get_state` 返回 `var_values[]` 内部指针（生命周期永久），用于存档序列化
- `set_state` 直接覆盖整个 `var_values[]`（不检查长度，调用方保证 `NB_VAR_COUNT` 一致）
- 存档格式建议：`int[NB_VAR_COUNT]` 紧接在 magic + 版本号之后

未来存档系统的工作流：
```
存档：magic + version + nb_var_get_state() 数据块 + 其他状态
读档：校验 → nb_var_set_state() 恢复变量 → NB 场景跳转
```

变量定义（`var_defs[]`）在编译期固定，不进入存档文件。存档只需存储 `var_values[]` 的值数组。

```

```
