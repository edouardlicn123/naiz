# B97 — 场景过渡状态机规范

**代码**：`core/engine/transition.c`、`transition_blinds.c`、`transition_checker.c`、`transition_pfade.c`
**声明**：`core/engine/transition.h`
**调用方**：`scene_end()`（layer.c）启动，`engine_frame_pump()` 推进

## 一、模型

过渡是**帧驱动状态机**，分两段：

```
transition_start()  →  sweep（step = 0..frames-1，每 pass 一步）
                    →  hold （sweep 完成，画面已全黑，等待装载/解码）
                    →  transition_active() 归零，脚本恢复
```

| 接口 | 语义 |
|---|---|
| `transition_start(x,y,w,h,type,frames,color)` | 在矩形上启动过渡；`TRANSITION_CUT` 直接填色、不武装 |
| `transition_tick()` | 推进一帧；最后一步覆盖矩形、强制调色板黑、`vm_request_process()` |
| `transition_active()` | 非零期间 `nb_process()` 挂起脚本 |
| `transition_sweeping()` | 仅在 sweep 阶段（`step < frames`）为真，供 `frame.c` 判断解码时机 |

## 二、过渡类型

| 值 | 名称 | 行为 |
|---|---|---|
| 0 | `TRANSITION_CUT` | 硬切，立即填 `color` |
| 1 | `TRANSITION_VBLINDS` | 竖条由细变粗，直到全黑（默认） |
| 2 | `TRANSITION_HBLINDS` | 横条 |
| 3 | `TRANSITION_DBLINDS` | 正向对角条 |
| 4 | `TRANSITION_RDBLINDS` | 反向对角条 |
| 5 | `TRANSITION_PFADE` | 只改调色板，不写 VRAM 像素 |
| 6 | `TRANSITION_CHECKER` | 棋盘交错擦除 |

默认 `NAIZ_TRANSITION_FRAMES = 16`；每条带只写「本帧新覆盖的单元」，场景在前景覆盖前保持可见。

## 三、与解码的时序约束（重要）

- **sweep 阶段禁止 preload decode**：`frame.c` 在 `transition_sweeping()` 为真时跳过解码，避免单次 decode 把 50 ms 的帧拖到 ~1050 ms（历史上表现为「棋盘卡顿」，见 devdoc 200 §九）。
- 解码推迟到 **hold 阶段**（屏幕已全黑），此时卡顿不可见。
- 因此不要把过渡改成「时间基准」：decode 阻塞期间若按时间一次性走完 30 步，过渡会直接消失。**过渡必须按帧推进**（每 pass 一步）。

## 四、禁止事项

1. 不要在 `transition_tick()` 里做解码、文件 I/O 或大块内存分配。
2. 不要在 sweep 期间推进动画/打字机（它们在解码恢复后会补帧，造成跳变）；需要时用 `transition_active()` 门控。
3. 过渡期间 `nb_process()` 必须挂起脚本；新增调用路径要同时检查 `transition_active()`。
4. `TRANSITION_CUT` 不武装状态机，调用方不得假设 `transition_active()` 会短暂为真。

## 五、验收

- 任意类型过渡的 sweep 帧耗时 ≤ 一帧绘制预算；不得出现「sweep 阶段每帧数百毫秒」。
- 过渡结束后首帧应显示新场景的完整背景（解码已在 hold 阶段完成）。
