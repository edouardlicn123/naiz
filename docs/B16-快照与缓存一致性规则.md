# B16 — 快照与缓存一致性规则

> **最后更新**：2026-09-11（R19 复合缓冲模型落地：规则 4 例改新范式；`bg_dialog_snapshot`→`under_dialog`/`dialog_occluder`；缓存表同步）

## 一、问题案例与最终方案

### 原始问题（2026-06-21）

`dialog_show()` 在 `commit 85f9951` 中用 `fill_rect(DIALOG_X, DIALOG_Y, DIALOG_W, DIALOG_H, 248)` 全覆盖清除后重绘 PAT75，破坏了 PAT75 的 25% 跳过像素中应显示的背景/立绘内容，导致对话框伪透明效果丢失。

过程：`fill_rect(248)` 用纯色 248 填满整个对话框区域（包括 PAT75 本应跳过的 25% 像素），后续 `fill_rect_pattern(PAT75, 248)` 只覆盖 75%，但跳过的 25% 已被 fill_rect 覆盖为纯色 248，无法恢复背景/立绘。

### 最终方案——惰性截图（devdocs/0.1版开发文档总结.html#doc-32）

引入 `dialog_dirty` 标志，将截图操作从对话时延迟到变更时：

```
变更 → 设 dialog_dirty=1 → 下一句 dialog_show
                             ├─ dirty? → 重建 PAT75 + 更新 snapshot
                             └─ !dirty → layer_dialog_restore()
```

核心变化：
- `dialog_snapshot` 仅在 PAT75 写定且未画文字时拍摄（`layer_dialog_open()` 或 `layer_dialog_snap()`）
- 新台词统一走 `layer_dialog_restore()`，不需重建
- body/hide 变更时设 `dialog_dirty=1`，`dialog_snap()` 消费

> ⚠️ **禁止**：在 `dialog_show()` 的文本刷新路径中使用 `fill_rect(248)`。伪透明区域通过 `dialog_dirty + layer_dialog_snap()` 维护。

> **R19 取代**：`dialog_dirty`/`dialog_snapshot`/`layer_dialog_snap()` 机制已被 **RAM 复合缓冲**（`dialog_layer` + `dialog_occluder` 活动底）整体取代——PAT75 孔洞不再"从 VRAM 回读伪透明"，而是**在 RAM 内先种底再合成**（见 `B93-图层渲染与菜单图层规范.md` §4、`B15-图层渲染与换装机制.md`）。本节的历史方案保留用于解释伪透明正确性原则的起源。

## 二、核心规则

### 规则 1：条件跳过写入不可回读

| 写入类型 | 行为 | 可 vram_read 回读 |
|---|---|---|
| 全覆盖写入（`fill_rect`, `vram_write`, `memset`） | 100% 像素被写入 | ✅ 安全 |
| 条件跳过写入（`fill_rect_pattern`, `vram_blit_sprite`, `draw_glyph` 等） | 部分像素跳过 | ❌ 不安全 |

条件跳过写入后的 VRAM ≠ 干净状态。从它回读作为快照 = 缓存污染。

### 规则 2：快照必须在"干净状态"下拍

"干净状态"指：
- **写入前**（初始状态，如 R19 前 `layer_dialog_open()` 在画文字前拍快照；R19 后由 `layer_dialog_render_page()` 重画框体达成）
- **全覆盖写入后**（如 `fill_rect` 或 `vram_write` 之后）
- **程序化生成**（用 `memset` + 按 pattern 写入 buffer，不从 VRAM 回读 — R19 复合缓冲即此形态）

### 规则 3：缓存刷新必须同步更新内容

任何缓存只要有对应的刷新操作（refresh），刷新后必须同步更新缓存，否则后续 restore 会回退到旧状态。

对应本项目的缓存（R19/R22/R23 形态）：

| 缓存 | 创建 | 刷新操作 | 更新缓存 |
|---|---|---|---|
| `bg_snapshot`（全屏纯背景） | `layer_bg_change` 源图直拷 | `layer_redraw_sprites()` | ✅ 不依赖 snapshot，直接读源图/VRAM |
| `under_dialog`（对话框区纯背景） | `layer_bg_change` 源图直拷（原 `bg_dialog_snapshot`） | 换图重种 | ✅ 源图直拷，零 VRAM 回读 |
| `dialog_occluder`（纯底+立绘框内像素活动底） | `layer_sprite_sync_dialog_base()` | 每次精灵变更/开框重建 | ✅ 程序化生成（RAM 落底），非回读 |
| `dialog_layer`（框+当前页文字复合缓冲） | `layer_dialog_show()` | `layer_dialog_render_page()` 重画 | ✅ RAM 合成（`text_set_target` 分流），非回读 |
| `menu_layer`（全屏菜单复合缓冲，R23） | `menu_layer_open()` | `begin_draw/commit` 会话增量 | ✅ RAM 合成 |
| 槽位头部缓存（R22：`slot_label_cache`/`slot_exists_cache`，键 `slot_cache_page`） | `save_load_cache_build(page)` | `save_game_slot` 后失效重建 | ✅ 按键翻页失效 |

> R19 的正面范例（比"回读快照"更强的形式）：**程序化 RAM 合成**——覆盖层缓冲（`dialog_layer`/`menu_layer`）不是 VRAM 快照，而是可随时按当前状态重算生成的缓冲；无脏标记、无回读、无"干净状态"窗口。

### 规则 4：条件写入场景下的快照策略

当某区域被条件跳过写入（如 PAT75）覆盖后，正确更新快照的方式：

1. **全覆盖清除该区域**（`fill_rect` 或 `bg_restore`）→ 清除旧数据
2. **条件写入**（如 `fill_rect_pattern`）→ 写入新数据
3. **不要从 VRAM 回读** → 因为 VRAM 仍有条件跳过的旧像素
4. **或者**：在全覆盖清除后拍快照，再执行条件写入（快照不含旧数据）

本项目 `dialog_show()`（R19 前）采用的方案（规则 4 之例，历史版本）：

```c
if (!layer_dialog_drawn()) {
    layer_dialog_open();         // PAT75 + vram_read → snapshot
} else {
    layer_dialog_snap();         // 如有 dirty → 重建 + 更新 snapshot
}
layer_dialog_restore();          // 写回 snapshot（无文字，仅 PAT75 + 背景/立绘）
```

`layer_dialog_snap()` 仅在 `dialog_dirty` 时执行重建+截图：
```c
void layer_dialog_snap(void)
{
    if (!dialog_dirty) return;                        // 无变更，跳过
    bg_restore_rect(DIALOG_X, DIALOG_Y, DIALOG_W, DIALOG_H, 0);
    layer_redraw_sprites();
    layer_dialog_refresh();                           // PAT75 写定后
    vram_read(..., dialog_snapshot);                  // 更新 snapshot
    dialog_dirty = 0;
}
```

`dialog_dirty` 由 `layer_sprite_replace()` 和 `layer_sprite_hide()` 在 body 变更时标记（同时仍执行 `layer_dialog_refresh()` 保证中间态正确），在下次 `dialog_show()` 中由 `layer_dialog_snap()` 消费——仅重建一次后所有台词直接 restore。

> **R19 当前实现（规则 4 之正面范例升级）**：改为 RAM 复合缓冲——`layer_dialog_render_page()` 每页在 `dialog_layer` 内**先种底（`dialog_seed_base`）再逐孔洞合成**（pattern 跳过位直接保留已种底像素），全程无 VRAM 回读，天然规避"条件写入后回读摄入旧数据"。新台词/换图 recompose/hide 都走同一合成路径。

### "背景对话框截图"缓存（R19 后：`under_dialog` + `dialog_occluder`）

原 `bg_dialog_snapshot`：对话框区域 [80,280,480,115] 的纯背景截图（不含对话框、不含精灵）。

| 缓存 | 创建 | 使用 | 回收 |
|------|------|------|------|
| `under_dialog`（旧 `bg_dialog_snapshot` 直拷改名） | `layer_bg_change` 从源图像素缓冲直拷 | `layer_dialog_hide()` 恢复纯背景、`dialog_seed_base` 底源 | `layer_init()`、下次换图重种 |
| `dialog_occluder`（活动底：under_dialog 纯底 + 立绘框内像素） | `layer_sprite_sync_dialog_base()`（每次精灵变更 + 开框） | 复合缓冲种底、伪透明孔洞像素源 | `layer_dialog_hide()` 清活 |

R19 相对旧版的两点强化：

1. **0→1 精灵过渡 / 换装 / 隐藏**：不再需要"场景顺序编排"——`layer_sprite_sync_dialog_base()` 每次都把**当前所有 active 精灵的框内像素**落到底（RAM 直拷，非 VRAM 回读），对话框合成自动含立绘下半身。
2. **`bg(hidedialog)`/`cg(hidedialog)`**：`layer_dialog_hide()` 用 `under_dialog` 直写还原对话框区为纯背景。

**与 dialog_layer 的区分**：

| 缓存 | 内容 | 用途 |
|------|------|------|
| `dialog_layer` | PAT75 框 + 白边 + 当前页文字（合成结果） | `layer_dialog_render_page` 目标、`blit` 发布源 |
| `dialog_occluder` | 活动底（纯背景 + 立绘框内像素，无框无文字） | 合成时的种底/孔洞像素源 |
| `under_dialog` | 对话框区纯背景（无对话框、无精灵） | hide 还原、occluder 基底 |

## 三、本项目绘制函数分类

| 函数 | 类型 | 可回读 |
|---|---|---|
| `fill_rect` | 全覆盖 | ✅ |
| `vram_write` | 全覆盖 | ✅ |
| `vram_blit` | 全覆盖（无 transparent_idx） | ✅ |
| `fill_rect_pattern` | 条件跳过（pattern bit=0 跳过） | ❌ |
| `vram_blit_sprite` | 条件跳过（`transparent_idx` 匹配跳过） | ❌ |
| `draw_glyph` | 条件跳过（glyph bitmap bit=0 跳过） | ❌ |
| `draw_glyph_cjk` | 条件跳过（同上） | ❌ |
| `draw_text` | 条件跳过（内层调用 glyph） | ❌ |
| `draw_rect` | 条件跳过（只画边框线） | ❌ |

### 例外处理

`bg_snapshot` / `under_dialog` R19 起**不进行任何 VRAM 回读**——`layer_bg_change` 从解压后的 MagImage 像素缓冲直接行拷贝（等效于程序化生成），故天然安全。复合缓冲（`dialog_layer`/`menu_layer`）同理全为 RAM 合成。

## 四、代码审查清单

增删改涉及 VRAM → buffer → VRAM 缓存路径时，请过此清单：

- [ ] 写操作是全覆盖还是条件跳过？
- [ ] 回读 vram_read 前，目标区域的每个像素是否都来自**最近一次**的全覆盖写入？
- [ ] 如果有条件跳过写入（pattern / transparent / glyph），回读是否会摄入旧数据？
- [ ] 刷新操作（refresh）是否同步更新了缓存？
- [ ] 程序化生成 buffer（不依赖回读）是否可行？

> 新范式优先选择"程序化 RAM 合成"（B93）：覆盖层不建模为 VRAM 快照，而是重算生成的缓冲——最后一项从"是否可行"升级为"首选"。
