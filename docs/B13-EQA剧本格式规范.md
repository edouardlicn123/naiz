## 1. 概述

EQA 是 love es×××× 引擎（`EQAP32.EXE`）使用的**二进制场景脚本格式**，与 Naiz 当前采用的 MHVN98 `.sca`/`SCENE.DAT` 格式完全不同。

每个 `.eqa` 文件是一个自包含的游戏脚本，包含：
- 文件头（元数据 + 场景标识）
- 顺序指令流（资源加载、控制流、文本显示）
- 文本条目（ROM 编码的对话/叙述文字）
- 场景页脚（返回主循环 / 结束标记）

### 1.1 与 MHVN98 格式对比

| 方面 | MHVN98 (SCENE.DAT) | EQA (.eqa) |
|------|--------------------|------------|
| 容器 | 多场景 LZ4 压缩块 | 单文件顺序字节流 |
| 文本存储 | 外置 TXA 文本包 | 内嵌在指令流中（ROM 编码） |
| 指令集 | 46 条 opcode（0x00–0x3F） | 待反编译（估计 20–40 条） |
| 字符编码 | Unicode/ASCII | JIS ROM 编码（双字节 +0x20） |
| 压缩 | LZ4 逐场景 | 无压缩 |
| 场景切换 | `gotoscene` 操作码 | `67 66` 跳转指令 + RESIO 页脚 |
| 资源引用 | MAG id (IMAGE.DAT) | EAR 索引（offset + size） |

### 1.2 数据来源

- 63 个 `.eqa` 文件从 `LOVE.EAR` 解包（`parse_ear_correct.py`）
- 引擎代码段从 `EQAP32.EXE` 提取（DOS/4GW unpack → `EQAP32_CODE.BIN`）

## 2. 文件头（32 字节）

每个 `.eqa` 文件以固定 32 字节文件头开始：

| 偏移 | 大小 | 字段 | 示例 (BOOTMENU.EQA) |
|------|------|------|---------------------|
| 0x00 | 4 | version/checksum | `0x1E0F0334` |
| 0x04 | 4 | magic "LOVE2" | `"LOVE2"` |
| 0x08 | 4 | BGM 引用 | `"3.BGM"` |
| 0x0C | 4 | 参数字段 _01 | `"_01"` |
| 0x10 | 4 | 参数/指令计数 | `0x001E0E00` |
| 0x14 | 4 | 场景编号 | `" dv6"` |
| 0x18 | 4 | 场景标识 | `"6.BOOT"` |
| 0x1C | 4 | 场景名称 | `"MENU"` |

各字段以 `\x00`（或空格 `\x20`）填充固定 4 字节。

文件头之后立即开始指令流。

## 3. 文本条目格式

文本条目是 EQA 中最了解的部分（`loveEs××××TL` 翻译管线已验证）。

### 3.1 二进制结构

```
00 [ROM 编码序列] 01 23 00 15 XX XX
```

| 字节 | 含义 |
|------|------|
| `00` | 条目前缀（文本开始标记） |
| ... | ROM 编码文本（见 §3.2） |
| `01 23` | 说话人结束标记（对应文字 `」`） |
| `00 15` | 条目尾部前缀 |
| `XX XX` | 长度或校验和（小端 uint16） |

**条目总长度**：ROM 文本长度 + 6 字节（`00` + `01 23 00 15 XX XX`）。

### 3.2 ROM 编码规则

文本使用 JIS 派生编码，所有字节偏移 +0x20：

| 字节范围 | 含义 |
|----------|------|
| `0x20–0x7E` | ASCII 字符（直接映射，实际存储时 +0x20） |
| `0x80–0xFF` (双字节) | JIS 区位码第一字节（存储值 = JIS 高字节 + 0x20） |
| `0x80–0xFF` (单字节) | 控制操作码（见 §3.3） |

**解码算法**：

```
for each byte b:
  if b == 0x81 → 换行
  elif b == 0x22 → 「(说话人开始)
  elif b == 0x23 → 」(说话人结束)
  elif b == 0x01 → 后接 1 字节资源名
  elif b == 0x90/0x92 → 主角名字替换
  elif b >= 0x80 and 后字节 >= 0x80:
    hi = b - 0x20     # JIS 区
    lo = next_byte - 0x20  # JIS 位
    → JIS 区位码 (hi, lo) 查表得字符
  else:
    → 直接作为 ASCII 输出 (实际为 b - 0x20 后的值)
```

### 3.3 控制操作码（文本内联）

| 字节 | 含义 | 说明 |
|------|------|------|
| `0x81` | 换行 | 文本内换行 |
| `0x22` | 说话人开始（`「`） | 标记角色名起始 |
| `0x23` | 说话人结束（`」`） | 标记角色名结束 |
| `0x90` | 主角名替换 | 被玩家自定义名称替代 |
| `0x92` | 主角名替换（变体） | 同上 |

### 3.4 文本条目定位

引擎**顺序扫描**文件头之后的字节流：

1. 遇到 `00` 字节时，检查其后是否跟有效 ROM 编码序列
2. 读取直到遇到 `01 23 00 15` 终止序列
3. `XX XX` 为尾部校验（可能是条目长度或校验和）
4. 继续从终止序列后扫描下一条文本

**注意**：`00` 字节也可能出现在指令操作数中导致误匹配。实际引擎的解释器通过上下文区分。

## 4. 指令集（逆向中）

以下指令模式通过字节扫描识别，**尚未经过 Ghidra 反编译验证**。

### 4.1 已知指令模式

| 字节模式 | 长度 | 疑似功能 | 出现次数 |
|----------|------|----------|----------|
| `1E 0B oo oo ss ss` | 6 | 资源加载（offset/size） | 46 |
| `67 66 tt tt ss ss` | 6 | 场景跳转（target/size） | 46 |
| `50 xx` | 2 | PUSH 立即数 | ~111 |
| `58 xx` | 2 | POP 立即数 | ~111 |
| `B8 21 vv vv vv vv` | 6 | MOV EAX, imm32 | ~55 |
| `E0 xx` | 2 | 循环指令 | ~55 |
| `B0 xx` | 2 | 条件跳转 | ~46 |
| `3D 85` | 2 | 未知（常出现于页脚） | — |
| `18 3D 82 31` | 4 | RESIO — 场景结束返回主循环 | — |

### 4.2 资源加载指令 (`1E 0B`)

```
1E 0B <offset_L> <offset_H> <size_L> <size_H>
```

- 从 `LOVE.EAR` 加载资源
- `offset` = 资源在 EAR 文件中的偏移量
- `size` = 资源大小

### 4.3 跳转指令 (`67 66`)

```
67 66 <target_L> <target_H> <size_L> <size_H>
```

- 跳转/切换到指定场景
- `target` = 场景标识或文件内偏移
- `size` = 场景大小或参数

### 4.4 场景页脚（文件尾部）

所有 `.eqa` 文件末尾的结构高度一致：

```
67 68 18 3D 82 31 01 4C 4F 56 45 00
1E 0C 00 4E 0A 01
3C 12 20 E1 57 2A
32 01 42 4F 4F 54 4D 45 4E 55 00
2C 00 16
```

解码：
- `31 01 4C 4F 56 45 00` = 返回场景 `LOVE`（主循环）
- `32 01 42 4F 4F 54 4D 45 4E 55 00` = 返回场景 `BOOTMENU`
- `2C 00 16` = 文件结束符

### 4.5 解释器函数（待 Ghidra 反编译）

从 `EQAP32_CODE.BIN` 中定位的候选函数：

| 地址 | 疑似功能 | 关联指令 |
|------|----------|----------|
| `0x167E2` | 资源加载器 | `1E 0B` |
| `0x16786` | 场景跳转 | `67 66` |
| `0x169E6` | 文本显示 | 文本条目处理 |
| `0x107C6` | 视频初始化 | — |
| `0x01A7D` | 视频显示 | — |
| `0x014C0` | 视频清理 | — |
