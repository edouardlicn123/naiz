# B93 — 图层渲染与菜单图层规范

> **状态**：活跃维护
> **创建**：2026-09-11（R23 菜单 UI 图层化后落库，作为 R19-R23 图层化范式的正式规范）
> **依赖**：`B02-显示管线规范.md`（VRAM 布局、图元函数）、`B12-VRAM渲染策略：两趟叠加与局部刷新.md`（渲染顺序）、`B11-MAG图片加载与显示规范.md`（图像加载）
>
> 本文定义引擎当前（R19–R23）的图层渲染范式：**RAM 复合缓冲 + 整框/整屏 blit 发布**。对话框（`dialog_layer`）与菜单（`menu_layer`）均先在 RAM 中离屏合成，再原子发布到 VRAM；渲染原语经 `render_set_target`/`text_set_target` 在"VRAM 目标"与"RAM 复合缓冲目标"之间路由。取代旧"对话框快照 + 两趟叠加"模型（相关历史见 `B15` §12、`B16` §一，以及 `devdocs/96`）。

---

## 1. 范式总览

### 1.1 解决的问题

PC-98 只有单层 VRAM，且 PEGC bank 窗口写入昂贵。R19 起把"需要反复重绘的 2D 覆盖层"（对话框、菜单）从"直接写 VRAM + 快照恢复"改为 **RAM 中一次性离屏合成**：

```
┌─────────────────────────────────────────────────────────────┐
│  RAM 复合缓冲（离屏）       │         发布（原子 blit）       │
│  dialog_layer  480×115      │ → dialog_layer_blit()          │
│  menu_layer    w×h          │ → menu_layer_blit()/blit_rect() │
└─────────────────────────────────────────────────────────────┘
          ▲ 绘制经 render_set_target / text_set_target 重路由
```

**关键收益**：
- 复杂绘制（PAT75 盒、圆角浮雕、文字字形）全部发生在 RAM，**不产生中间态可见帧**——彻底消除"两趟叠加"模型的闪烁来源
- 绘制代价从"逐像素 PEGC bank 端口写"降为"RAM 字节写"，菜单/对话框合成快一个数量级
- 伪透明（dither/transparent 镂空）由复合缓冲的"底 + 覆盖层"合成实现，不再依赖 VRAM 回读（规避 B16 规则 1 的缓存污染）

### 1.2 三层构成

| 缓冲 | 尺寸 | 内容 | 提供者 | 生命周期 |
|------|------|------|--------|----------|
| `under_dialog` | 480×115 | 对话框矩形背后**纯背景**（源图像素，零 VRAM 回读） | `layer_bg.c` | bg 捕捉 ~ 下次 bg change |
| `dialog_occluder` | 480×115 | 纯背景 + 立绘框内像素（**活动底**，伪透明孔洞透出立绘） | `layer_dialog.c`（数据）+ `layer_sprite.c`（维护） | 与 dialog_layer 同生灭 |
| `dialog_layer` | 480×115 | 框 + 当前页文字（不透明复合缓冲） | `layer_dialog.c` | 首个 dialog_show ~ reset/hide |

菜单层（`menu_layer`）独立于上述三件套，见 §3。

## 2. 渲染目标切换

### 2.1 `render_set_target()` / `render_set_target_vram()`

**文件**：`core/engine/render.c` / `render.h`

```c
void render_set_target(uint8_t *buf, int w, int h, int stride, int offx, int offy);
void render_set_target_vram(void);
```

- `render_set_target(buf, w, h, stride, offx, offy)`：把"屏幕空间坐标"映射到 RAM 缓冲。调用后 `fill_rect` / `fill_rect_pattern` / `vram_pset_addr` 三个原语的写入改落到缓冲中坐标 `(y-offs_y)*stride + (x-offs_x)`；屏幕 clip（x/y 越界钳制）与缓冲边界双重钳制同时生效
- `render_set_target_vram()`：恢复默认 VRAM 目标（写入改回 PEGC bank 窗口）
- **未设目标时**：三原语操作 VRAM（历史行为不变）

> R23 起 `fill_rect/fill_rect_pattern/vram_pset_addr` 具备 RAM 分支，`render.c` 内按"是否设了 RAM 目标"分流。`ui.c` 的 emboss 等高级原语内部调 `fill_rect`，**零改动自动跟随**复合缓冲目标。

### 2.2 `text_set_target()` / `text_set_target_vram()`

**文件**：`core/engine/render_text.c` / `render_text.h`

```c
void text_set_target(uint8_t *buf, int w, int h, int stride, int offx, int offy);
void text_set_target_vram(void);
```

R19 阶段 A 引入。`draw_glyph_internal` 末级写分流：设目标后字形像素写入 RAM 缓冲（坐标映射同 §2.1），否则落 VRAM。对话框页渲染（`layer_dialog_render_page`）用其把角色名/正文写进复合缓冲。

### 2.3 `render_blit_transparent()` — 透明 blit 原语

**文件**：`core/engine/render_vram.c` / `render.h`

```c
void render_blit_transparent(const uint8_t *buf, int stride, int sx, int sy,
                             int w, int h, int dx, int dy, uint8_t transparent_idx);
```

逐像素从 RAM 缓冲拷贝到 VRAM，跳过等于 `transparent_idx` 的像素（`VRAM_SET_BANK` 宏分段切 bank）。供 `menu_layer` 透明宏镂空模式发布；语义与 `vram_blit_sprite` 的透明跳过一致。

## 3. 菜单图层 `menu_layer`

### 3.1 定位

`menu_layer.c/.h` 是**自包含可复用封装**，把"菜单按键 UI 绘制进复合缓冲 → 原子发布"做成通用原语。`menu_layer.h` 头部契约注释含最小接入示例。要点：

- 层模型仿 `dialog_layer`：菜单控件绘制进 RAM 复合缓冲，整区/局部 blit 发布
- 不注册 `LAYER_Z_*`、不触碰 `g_layer_active`（活动标志块留给持久场景层）；生命周期由调用菜单拥有
- 两种模式（open 时选择），见 §3.2

### 3.2 两种模式

| 模式 | `transparent` | base 快照 | blit | close(1) | 用途 |
|------|---------------|-----------|------|----------|------|
| **opaque** | `0` | open 时 vram_read 快照区 → 拷贝进复合缓冲 | 复合缓冲已含底，`vram_write` 直发 | 整底还原（像素级干净退出） | 主菜单/加载/设置/画廊（均全屏） |
| **transparent** | `1` | 无（省一半内存） | `render_blit_transparent` 跳 `PAL_TRANSPARENT` 镂空，底层透过孔洞可见 | **恒不还原**（调用方自行重建/清屏） | 悬浮覆盖层 |

**约束**：transparent 模式的绘制内容**不得使用调色板索引 15**（`PAL_TRANSPARENT`），同 `vram_blit_sprite`（B02 §7.11：索引 15 为精灵透明色）。

### 3.3 OOM 降级契约

```c
if (menu_layer_open(0, 0, 640, 400, 0) != 0) {
    /* OOM：绘制直落 VRAM，菜单仍可用 */
}
```

- `menu_layer_open` 分配失败返回 `-1` 且**不切换渲染目标**（VRAM 回退完好）
- 所有 `malloc` 失败路径打 `hal_log("OOM: ...")`（C14）
- `menu_layer_blit_sprite` 在层未开时**降级为普通 VRAM 精灵 blit**，菜单绘制代码可无条件调用
- 重复 `open` = 重建（自动 close 前一个）

### 3.4 API 全表

**文件**：`core/engine/menu_layer.c` / `menu_layer.h`

| 函数 | 行为 |
|------|------|
| `menu_layer_open(x,y,w,h,transparent)` | 开层。区域 clamp 到屏幕；重复 open=重建；OOM 返 -1（目标未切换，调用方降级直绘 VRAM + C14 日志） |
| `menu_layer_begin_draw()` | 增量重绘会话开始：重接 render/text 双 target 到复合缓冲 |
| `menu_layer_commit()` | 会话结束：双 target 复位回 VRAM |
| `menu_layer_blit()` | 整区发布（opaque=vram_write；transparent=render_blit_transparent）。未开 no-op |
| `menu_layer_blit_rect(x,y,w,h)` | 屏幕空间子矩形发布（自动与开区求交，幂等可重复调） |
| `menu_layer_close(restore)` | 关层。opaque+restore=1 整底还原；transparent 恒不还原。释放双缓冲、复位 target、幂等（置 NULL） |
| `menu_layer_is_open()` | 层是否打开（非 0=开） |
| `menu_layer_pixels()` | 当前复合缓冲像素（诊断/测试用）；未开 NULL |
| `menu_layer_erase_to_base(x,y,w,h)` | opaque 模式把复合缓冲矩形区域回写为 base 快照（擦掉已绘控件，无需菜单自留干净背景快照） |
| `menu_layer_blit_sprite(img,x,y,transparent_idx)` | 精灵 RAM 直拷进复合缓冲（层不开降级 vram_blit_sprite） |

### 3.5 典型接入模式（opaque 全屏）

```
入口（一次）：
  open(0,0,640,400,0)         → 快照底 + 全量绘制（emboss/text/blit_sprite…全部进缓冲）
  commit() + blit()           → 整屏发布

交互循环（增量）：
  begin_draw()                → 重接双 target
  ...重绘受影响控件（erase_to_base 清理后重画）...
  commit()                    → target 复位
  blit_rect(x,y,w,h)          → 只发变化区域

退出：
  close(1)                    → 整底还原（像素级干净）
```

四菜单接入均为此模式：
- **主菜单 `menu_show`**（nb_mainmenu.c）：open→全量→blit；焦点移动走增量会话 begin_draw→commit→blit_rect
- **加载 `nb_saveload`**：绘制包裹层化；标题 sprite 走 `menu_layer_blit_sprite`
- **设置 `settings_menu`**：删原 bg_lang_name/ind/start_ind 三快照数组，改 `erase_to_base` 语义
- **画廊 `nb_cggallery`**：preview 进出 = `close(0)` → `layer_bg_change` 全屏 → 重新 `open` + `draw_grid`

## 4. 对话框复合缓冲（R19/R20 模型）

> 本节为对话框图层的当前实现范式（相关历史机制在 B15 §12、B16 §一 有废弃说明）。决定级细节见 `layer_dialog.c` 注释与 `devdocs/96`。

### 4.1 对话框显示（ui 层）

```
首次 dialog_show：
  layer_dialog_show()
    ├─ 未分配 → malloc dialog_layer + dialog_occluder（C14 OOM 日志）
    └─ 首次（dialog_drawn==0）→ layer_set_active(DIALOG,TEXT) + sync_dialog_base()
    dialog_paint_box(dialog_layer)→ 框（PAT75 孔洞保留已种底）
  layer_dialog_render_page(name,text,off)
    ├─ dialog_seed_base()        ← occluder → 退化为 under_dialog → 退化为黑
    ├─ dialog_paint_box()        ← 重画框（擦除上一页文字）
    ├─ text_set_target(缓冲) + draw_text(角色名/正文) + text_set_target_vram()
    └─ 返回 draw_text 续行偏移（翻页契约）
  dialog_layer_store_render(name,text,off)  ← 记录渲染投影（供换图后重绘）
  dialog_layer_blit()            ← 整框原子发布
```

翻页：再次 `layer_dialog_render_page`（框重画 + 新文字进缓冲）→ `dialog_layer_blit`。

### 4.2 换图跨图存活（背景换图重合成）

`layer_bg_change(img)`（layer_bg.c:166，统一 7 步）：
```
vram_blit(img,0,0)
  → layer_capture_bg_from_image(img→bg_snapshot，RAM 直拷，零回读)
  → layer_capture_bg_dialog_from_image(img→under_dialog，RAM 直拷)
  → layer_redraw_sprites()（全身重绘，尾部 layer_sprite_sync_dialog_base()）
  → dlg_update_palette() + btn_update_palette()
```

- `layer_redraw_sprites` 尾部 `layer_sprite_sync_dialog_base()` 重建活动底（纯背景 + 逐 active 精灵 RAM 落底），随后 `layer_dialog_recompose` 从渲染投影重绘框 + 当前页文字，再 `dialog_layer_blit`——**框+当前页文字跨图完整存活**（devdoc 96 裁决 A）
- `layer_dialog_recompose` 仅在 `dialog_drawn && dialog_layer` 时执行；无渲染投影则只重画框底
- 文本投影 `dialog_render_name[64] / dialog_render_text[1024] / dialog_render_off` 为 ~1KB static（无堆无 OOM）

### 4.3 `bg(hidedialog)` / `cg(hidedialog)` 收起

`layer_dialog_hide()`（layer_dialog.c:310）：
```
hal_mouse_invalidate_cursor()
  → dialog_drawn==0 → 早退（跳过冗余 55KB 写，R17）
  → vram_write(under_dialog, 对话框区)   ← 纯背景还原
  → dialog_drawn=0 + layer_set_active 清标志
  → layer_redraw_sprites()               ← 全身重绘（对话框不再遮挡 y≥280）
```

- `bg(){key}` 换图后对话框**跨图存活**；`cg(){key}` 为**全屏事件**，资产分支自动 `layer_dialog_hide()` + `nb_dialog_reset()`（收起对话框、清空当前对白），下一句台词重新开框（R20）
- 语义差异：`bg(hidedialog)`/`cg(hidedialog)` 保留为显式指令，`cg(){x}` 后尾随降为无害空转

### 4.4 立绘 z 序（R20 撤销 Option X）

- 对话框开启时立绘**整层全高绘制**（200×400），不再裁剪到 y<280；对话框矩形在其上合成（z 序：bg → sprite 全身 → dialog → text）
- `layer_sprite_face` 保留上半身 clip（不碰对话框区）；show/replace/redraw/hide 的**背景还原**仍 `clip_dialog=1` 跳过对话框矩形，不盖框
- 伪透明经活动底 `dialog_occluder` 恢复：PAT75 孔洞透出立绘腿部
- `layer_sprite_sync_dialog_base()` 在每次精灵变更（show/replace/redraw/hide/hide_all）与开框时重建 occluder：reset 纯底 → 逐 active 精灵 RAM 落底 → recompose 框 + 当前页盖回；动画帧不触对话框区无需复位

### 4.5 读档恢复对白

`nb_save_dialog.c` 读档恢复文字收口到 `layer_dialog_render_page` + 投影 + blit（菜单为暂态 VRAM 覆盖，缓冲为持久态）。`dialog_show` 与存档还原时写入投影供 recompose 使用。

## 5. 与硬件约束的关系

- **最终可见输出仍全部经 VRAM 像素操作发布**（`vram_write` / `render_blit_transparent` / `vram_pset_addr`）——满足 B02 §1.2"只能用 render.h 提供 VRAM 像素函数"的硬性约束：RAM 复合缓冲只是中间目标，不绕过最终发布
- **禁止 printf / DOS 文本层**：菜单文字仍走 `draw_text`（字形写进复合缓冲）
- **B16 规则 2 的正面范例**：dialog_layer/menu_layer 均为"程序化生成 buffer，不从 VRAM 回读"（opaque 模式的 base 快照用 vram_read **一次**，属全覆盖读安全路径）；RAM 目标下原语回读安全（缓冲是程序化生成的干净态）
