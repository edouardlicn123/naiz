### 1.2 运行时链

```

  DEVICE=A:\VEM486.EXE /U           ← VCPI 保护模式服务
  DOS=HIGH,UMB

AUTOEXEC.BAT:

       │    ├─ 定位 DOS4GW.EXE
       │    ├─ DOS/4GW v4.45 加载 (ring 1)

       │

                 ├─ hal_init()            → COM1 串口调试 (含 serial_init)

                 ├─ hal_set_palette()     → 启动调色板 (0=黑, 1=蓝, 2=绿, 3=红, 7=白, 15=白, 248=黑)
```

### 2.2 补丁清单

补丁文件位于项目 `tools/np2kaipatch/`，由 `start.sh np2kai` 自动应用（按文件名 sorted 顺序）。每次 `git pull` 或重编译后必须重新应用。

补丁分两类：

#### 显示必需（P1-P3）

| # | 文件 | 修改内容 | 若不应用 |
|---|------|---------|----------|
| P1 | `mem/memvga.c` | VGAWR8 宏：`gdcs.grphdisp \|= bit` → `gdcs.grphdisp \|= 5` | VRAM 写入后图形合成不触发，全黑 |

| P4 | `wx/kbtrans.cpp` | `WXK_SPACE` 与 ASCII 0x20 映射 `0x35 → 0x34`（2 处） | wx 前端空格发 0x35(XFER) 而非 0x34(SPC)；SDL 前端不受影响（映射本就正确） |

## 3. 显示管线

> **规范文档**：引擎侧 VRAM/调色板/像素图元/初始化顺序的完整规范见 `docs/B02-显示管线规范.md`。
> 本章聚焦于显示管线的**全链路流程**（引擎 → NP2kai 内存 → 合成 → 渲染 → 屏幕）及 **NP2kai 兼容性细节**。

### 3.1 整体流程图（256c 管线）

自 2026-06-12 起，引擎切换到 **PEGC 640×400 256 色 packed-pixel 模式**。旧 16color 4-plane 管线不再使用。

```
引擎 C 代码 (core/plat/gdc.c / render.c)
  │ outb(0xE0004, bank) → PEGC bank 选择
  │ outb(0xA8000+off, pixel) → packed-pixel 写（每个字节 = 一个像素）
  ▼
NP2kai ── VGA 内存模拟 (mem/memvga.c:40 VGAWR8 宏)  [必需补丁 P1]
  │ gdcs.grphdisp |= 5                            ← 触发图形合成 + 显示使能
  │ vramex[(bank<<15) + offset] = pixel           ← 存到 vramex[]
  ▼
NP2kai ── GDC 模拟端口 (io/gdc.c:552,558)  [必需补丁 P2]
  │ outb(0x6A, 0x20) → gdc_analogext(FALSE)       ← 无门控，直接执行
  │ outb(0x6A, 0x21) → gdc_analogext(TRUE)        ← GDCANALOG_256 置位
  ▼
NP2kai ── BIOS CRT 模式设置 (bios/bios18.c:389-401)  [必需补丁 P3]
  │ INT 18h AH=30h AL=0x08 (640×400 256c)
  │   → gdc_analogext(TRUE)                       ← 256c 标志
  │   → mem[MEMB_PRXDUPD] |= 0x80                 ← VGA VRAM 映射
  ▼
NP2kai ── 图形合成 (vram/makegrex.c:279-318)
  │ makegrphex(page, alldraw)
  │   读取 vramex[]（packed-pixel 8bpp）@ GDC 滚动寄存器地址
  │   不调色板直接拷贝到 np2_vram[]（32-bit 值包装）
  ▼
NP2kai ── 调色板更新 (vram/palettes.c:494-498)
  │ pal_change() → pal_make9821(gdc.anareg + 48)
  │   从 gdc.anareg[48..] 读取 256×4 字节 (G/R/B/填充)
  │   写入 np2_pal32[NP2PAL_GRPHEX..] + np2_pal16[]
  ▼
NP2kai ── 渲染器 (vram/sdraw.mcr)
  │ sdraw16p_2(&sdraw, height)
  │   SDSETPIXEL(ptr, pal) → np2_pal16[pixel_index]
  │   每行检查 dirty[y]，脏则写 16bpp RGB565 → 显示面 pixbuf
  ▼
wxNP21kai 前端 (wx/np2panel.cpp)
  │ Np2Panel::UpdateScreen()
  │   scrnmng_getpixbuf() → wxImage → wxPaintDC
  ▼
屏幕显示
```

### 3.2 引擎侧：GDC 初始化与 VRAM 写入

`core/plat/video.c` — CRT BIOS 256c 模式设置序列：

```c
void video_init(void)
{
    union REGS regs;

    /* PEGC MMIO */
    *PEGC_MODE_PORT   = 0x00;
    *PEGC_VRAM_ENABLE = 0x01;

    /* INT 18h AH=30h: 640×400 256c (DPMI 方式) */
    regs.h.ah = 0x30;
    regs.h.al = 0x08;
    regs.h.bh = 0x00;
    int386(0x18, &regs, &regs);

    /* INT 18h AH=40h: 显示使能 */
    regs.h.ah = 0x40;
    regs.h.al = 0x01;
    regs.h.bh = 0x00;
    int386(0x18, &regs, &regs);

    outb(0x6A, 0x21);   // 后备：强制 GDCANALOG_256 + VGA VRAM 映射
}
```

> **修复记录**（2026-06-19）：`int386` 调用前 `regs.h.al` 和 `regs.h.bh` 被显式初始化。脏值会导致 NP2kai 的 `bios18.c` 忽略模式设置请求。

**VRAM 写路由**（256c packed-pixel）：引擎通过 PEGC bank + 窗口写入，每个字节 = 1 个像素。

```c
#define PEGC_BANK  ((volatile uint16_t *)0xE0004L)
#define VRAM_WIN   ((volatile uint8_t  *)0xA8000L)

// 单像素写
*PEGC_BANK = bank;              // 选择 32KB bank
VRAM_WIN[offset] = pixel;       // 写像素值（0-255）

// 批量写（优化：按行切 bank，每 bank 只选一次）
for each row y:
    addr_base = y * 640;
    while addr < addr_base + 640:
        bank = addr >> 15;
        bank_end = (bank + 1) << 15;
        *PEGC_BANK = bank;
        for i = 0 to min(addr_base+640, bank_end) - addr:
            VRAM_WIN[addr & 0x7FFF] = pixel;
```

NP2kai 侧路由：

```
outb(0xE0004, bank) → memvgaio_wr8() → vramop.mio1[0] = bank  (bank 寄存器)
outb(0xA8000+off, pixel) → VGAWR8 宏
  ↓ vramex[(vramop.mio1[0]&15)<<15 + offset] = pixel  (写入 packed-pixel 缓冲)
  ↓ gdcs.grphdisp |= 5                                 (触发合成)
```

### 3.3 关键数据结构

| 符号 | 定义位置 | 类型/大小 | 说明 |
|------|---------|----------|------|
| `vramex[]` | `mem/memvram.c` | `UINT8[0x80000]` | 512KB VGA VRAM 扩展区；packed-pixel 模式下存储 256c 像素数据 |
| `vramop.mio1[4]` | `io/gdc.h` | `UINT8[4]` | PEGC 寄存器 `0xE0004-0xE0007`；`mio1[0]` 低 4 位 = bank 号 |
| `vramupdate[]` | `mem/memvram.c` | `UINT16[32768]` | 逐字 VRAM 更新标志（每 8 字节一个字） |
| `gdc.anareg[16*3+256*4]` | `io/gdc.h` | `UINT8[1072]` | 调色板数据：前 48B = 16 色 analog，后 1024B = 256 色 (G/R/B/填充) |
| `gdc.analog` | `io/gdc.h` | `UINT8` | Analog 模式标志：bit1=`GDCANALOG_256`，bit2=`GDCANALOG_256E` |
| `gdcs.grphdisp` | `io/gdc.h` | `UINT8` | 图形层标志：bit0=`GDCSCRN_MAKE`，bit2=`GDCSCRN_ENABLE` |
| `gdcs.textdisp` | `io/gdc.h` | `UINT8` | 文本层显示标志 |
| `gdc.s.para[GDC_SCROLL+0..5]` | `io/gdc.h` | `UINT8[6]` | GDC 从属滚动/剩余参数；决定 `makegrphex` 从 vramex 何地址读取 |
| `gdc.s.para[GDC_PITCH]` | `io/gdc.h` | `UINT8` | GDC 从属间距（字节，256c 下=40，经 `gdc.clock` 调整后为 80） |
| `np2_vram[2][SURFACE_SIZE]` | `vram/scrndraw.h` | `UINT8[2][640×480]` | 合成像素缓冲（8bpp 索引值） |
| `np2_tram[SURFACE_SIZE]` | `vram/scrndraw.h` | `UINT8[307200]` | 文本层缓冲（字符代码） |
| `np2_pal32[NP2PAL_EXTEND]` | `vram/palettes.h` | `RGB32[456]` | 32-bit BGRA 调色板；`NP2PAL_GRPHEX=200` 起为 256 色 8bpc 值 |
| `np2_pal16[NP2PAL_EXTEND]` | `vram/palettes.h` | `UINT16[456]` | 16-bit RGB565 调色板（由 `np2_pal32` 转换） |
| `sdraw.dirty[480]` | `vram/scrndraw.c` | `UINT8[480]` | 逐行脏标志；0=跳过，非0=渲染 |

### 3.4 合成→渲染路径（256c）

自 2026-06-12 引擎切换到 PEGC 256c 模式后，VRAM 写入走 VGAWR8 → `vramex[]`，合成由原生 `makegrphex()` 完成，不再需要 `naiz_composite_planar()` bypass。

**图形合成**：`vram/makegrex.c:279-318` `makegrphex()`

- 读取 `vramex[]` 中 packed-pixel 8bpp 数据（PEGC bank-select 写入）
- 读取 GDC 滚动寄存器 `gdc.s.para[GDC_SCROLL+0..5]` 决定起始地址
- 直接拷贝 32-bit 值到 `np2_vram[]`（不经过调色板——调色板在 sdraw 阶段应用）

**渲染器**：`vram/sdraw.mcr` `sdraw16p_2`

- `SDSETPIXEL(ptr, pal)` = `*(UINT16*)ptr = np2_pal16[pal]`
- `pal` = `np2_vram[0][y*640+x]`（8bpp 索引）+ `np2_tram[]` 文本层值 + `NP2PAL_GRPHEX`
- 文本层 `np2_tram[]` 在 256c 模式下应全零（对应索引 200+0，该处 palette = entry 0 color）

**调色板应用时序**：

1. 引擎调用 `hal_set_palette(idx, r, g, b)` → `outb(0xA8/0xAA/0xAC/0xAE)` → `gdc.anareg[48+idx*4+0..2]` 存储 8-bit 分量
2. 每帧 `pccore.c:`1529-1548 检测 `gdc.analog & 2` → 调用 `makegrphex()` 合成
3. 合成前 `pal_change()` → `pal_make9821()` → `np2_pal32[NP2PAL_GRPHEX+i]` 从 `gdc.anareg[48+]` 更新
4. `sdraw16p_2` 用 `np2_pal16[]`（由 `np2_pal32[]` 经 `scrnmng_makepal16` 转换，RGB565）写 pixbuf

**初始化顺序联动**（必须严格遵守）：

```
video_init(): INT 18h AH=30h AL=0x08  → NP2kai BIOS 置 GDCANALOG_256 + VGA 映射
outb(0x6A, 0x21): 后备，确保 GDACANALOG_256 已置位
INT 18h AH=40h: 显示使能
hal_set_palette(idx, r, g, b): 写入 anareg[48+]
fill_rect(...): PEGC bank 写入 vramex[]
→ next frame: makegrphex + pal_make9821 + sdraw → 屏幕
```

## 4. NP2kai 兼容性

### 4.1 设计原则

Naiz 引擎遵循"双平台兼容"策略：

1. **代码无条件编译**：不使用 `#ifdef NP2KAI` 平台宏，同一份 Open Watcom 生成的二进制在真机 PC-98 和 NP2kai 上运行相同
2. **Workaround 不破坏真机行为**：所有 NP2kai-specific workaround 在真机上无害（功能等价或性能略有下降，语义相同）
3. **Workaround 在 HAL 层隔离**：平台差异处理局限在 `core/plat/` 内，`core/engine/` 不感知

### 4.2 Quirks 数据库

**Q001: `rep stosw` 写入 VRAM 导致模拟器崩溃**

| 属性 | 值 |
|------|-----|
| 影响范围 | 任意 VRAM 段使用 `rep stosw` |
| 根因 | NP2kai IA-32 核心 CPU 模拟层在处理 `rep stosw` 写到内存映射 I/O 区域时的 bug |
| 状态 | **已修复**（改用 `stosw` + `loop`） |
| 修复文件 | `core/plat/x86strops.h`, `core/plat/hal_pc98.c` |
| 备注 | `rep movsw`（系统内存→VRAM）正常工作 |

**Q002: EGC 操作不生效**

| 属性 | 值 |
|------|-----|
| 影响范围 | 所有 EGC 寄存器写入（端口 0x4A0-0x4AF） |
| 根因 | EGC 换启需要 `gdc.mode2 & 0x08` + `grcg.chip == 3`。引擎写入 0x04→0x00 序列不满足 NP2kai 换启条件 |
| 状态 | **已修复**（非 EGC 回退路径：直接向 4 个图形平面写） |
| 修复文件 | `core/plat/pc98/hal_pc98.c` |

**Q003: Text plane 强制显示**

| 属性 | 值 |
|------|-----|
| 影响范围 | 所有显示状态 |
| 根因 | `scrndraw.c` 中 debug workaround 使 text plane 始终合成 |
| 状态 | **Workaround 保留**（将 text VRAM 清空为 0x0000 黑色） |
| 真机对比 | 真机上 `gdc_stop_text()` 即可隐藏文本层 |

**Q004: GDC mode1 位操作**

| 宏/值 | 真机效果 | NP2kai 效果 |
|--------|---------|------------|
| `0x03` (彩色) | 设置 | 设置 |
| `0x02` (单色) | 设置 | 设置 |
| `0x09` (行倍开) | 开 | 开 |
| `0x08` (行倍关) | 关 | 关 |
| `0x0F` (显示开) | 开 | 开 |
| `0x0E` (显示关) | 关 | 关 |
| `>0x80` | 直接写模式 | 被忽略 |

**Q005: GDC mode2 (port 0x6A) 位操作**

| 值 | 真机 | NP2kai |
|-----|------|--------|
| `0x00` | 8-color digital | 清除 analog bit |
| `0x01` | 16-color analog | 设置 analog bit + 更新 palette |
| `0x04` | 设置 EGC 模式 | 设置 EGC bit（需 bit3 + PC-9821） |
| `0x05` | EGC + 16-color | 只处理一位！需分写 `0x01` 再 `0x04` |

**Q006: SCSI HDI 写不回**

| 属性 | 值 |
|------|-----|
| 表现 | NP2kai 关闭后 HDI 文件 SHA256 不变 |
| 影响 | `ENGINE.LOG` 等运行时创建的文件无法保存到主机文件系统 |
| Workaround | 使用 serial 输出代替文件输出 |

**Q007: VGAWR8 宏不触发图形合成（P1）**

| 属性 | 值 |
|------|-----|
| 文件 | `mem/memvga.c:40` |
| 原代码 | `gdcs.grphdisp \|= bit` (bit = 平面号 0-3) |
| 修复后 | `gdcs.grphdisp \|= 5` (固定 bit0 + bit2) |
| 根因 | 256c packed-pixel 模式不经过 4-plane 路径，`bit` 始终为 0，`grphdisp` 不置位 → `makegrphex` 不运行 |
| 修复方式 | 硬编码 `|= 5`：bit0=`GDCSCRN_MAKE`（触发合成），bit2=`GDCSCRN_ENABLE`（显示使能） |
| 若不应用 | VRAM 写入后图形合成不触发 → 全黑屏 |

**Q008: port 0x6A 0x20/0x21 门控导致 VGA 映射不生效（P2）**

| 属性 | 值 |
|------|-----|
| 文件 | `io/gdc.c:552,558` |
| 原代码 | `if (gdc.mode2 & 0x08) { ... gdc_analogext(...); }` |
| 修复后 | 移除 `if` 门控，直接执行 `gdc_analogext(dat & 1)` |
| 根因 | PC-9821 模式下 `gdc.mode2 & 0x08` 可能为 0，导致 `gdc_analogext()` 永远不执行 → `GDCANALOG_256` 不置位，VGA VRAM 映射不建立 |
| 修复方式 | 无条件执行 `gdc_analogext()`；`gdc_analogext(TRUE)` 设置 bit1=256c、bit2=256E 并更新 `gdc.anapal[]` |
| 若不应用 | `outb(0x6A, 0x21)` 无效 → VGA VRAM 写不命中 `vramex[]` → 全黑屏 |

**Q009: BIOS INT 18h AH=30h 不初始化 256c 模式（P3）**

| 属性 | 值 |
|------|-----|
| 文件 | `bios/bios18.c:389-401` |
| 原代码 | 非 640×480 分支：只有 `gdc_analogext(FALSE)` 被守卫调用，从未调用 `gdc_analogext(TRUE)` |
| 修复后 | `if (rate & 0x0c) { gdc_analogext(TRUE); mem[MEMB_PRXDUPD] \|= 0x80; }`；`gdc_analogext(FALSE)` 和 `MEMB_PRXDUPD &= ~0x80` 移到 `!(rate & 0x0c)` 守卫内 |
| 根因 | `bios0x18_30()` 的 `rate & 0x0c`（640×400 和 640×480 的 256c 模式）缺少 EGCC 寄存器与 VGA 映射初始化 → `GDCANALOG_256` 未置位 |
| 修复方式 | `rate & 0x0c` 时调用 `gdc_analogext(TRUE)` 设置 256c 标志 + `MEMB_PRXDUPD |= 0x80` 启用 VGA VRAM 映射 |
| 若不应用 | INT 18h AH=30h 后 256c 调色板路径不激活，palette 读默认 digital 表 → 花屏 |

### 4.3 GDC 仿真已知缺陷

**GDC 命令表全为空操作**。`io/gdc.c` 中 `gdc_cmd.tbl[]` 所有条目为 `{0,0,0,0}`：

```
gdc_cmd.tbl 命令表 (88 条):
  0x00-0x33: GDC RESET, START, STOP 等 → {0,0,0,0} (无效果)
  0x34-0x4F: 寄存器设置 R00-R11, CSRW → {0,0,0,0}
  0x50-0x7F: SYNC, PITCH, ZOOM 等 → {0,0,0,0}
```

后果：
- GDC RESET/START/STOP 命令无效果
- 所有 GDC 参数寄存器读写被丢弃
- `makegrph`/`maketextgrph` 图形合成路径无输入
- 引擎通过 `outb(GDC_GFX_CMD, ...)` 发送的命令全部落空

这是 Naiz 引擎早期（16-color 4-plane 阶段）使用 `naiz_composite_planar()` bypass 的根本原因。自 2026-06-12 切换到 PEGC 256c 模式后，合成路径改为 `makegrphex()` 原生函数，不再需要手工 bypass。

**love es×××× 为何没踩中此缺陷**：该引擎不向图形 GDC 发送命令，仅用 4 个端口写入（0xA0 参数、0xA2 命令、0x6A CRTC、0xA4 页选择），从未依赖 GDC 命令表。页选择 `outb(0xA4, 1)` 是唯一有效的 GDC 端口。

**实机行为对比**：真机 PC-98 上 μPD7220 GDC 芯片处理所有 88 条命令，全部寄存器生效，GDC 图形合成正常。本文所有 bypass 在实机上**不需要**。

### 4.4 行为差异速查表

| 功能 | 真机 PC-98 | NP2kai | Workaround |
|------|-----------|--------|------------|
| `rep stosw` to VRAM | ✅ | ❌ 崩溃 | `stosw` + `loop` |
| EGC VRAM 加速 | ✅ | ❌ 不生效 | 非 EGC 回退路径 |
| Text plane 隐藏 | ✅ `gdc_stop_text()` | ❌ 仍显示 | 清 text VRAM 为 0 |
| `outb 0x6A, 0x05` | ✅ 一次写两 bit | ❌ 需两次写 | 拆为 `0x01` + `0x04` |
| HDI 写回 | ✅ | ❌ | 用 serial 输出 |
| VGAWR8 `grphdisp |= bit` | ✅ 正常 | ❌ bit=0 不触发 | `gdcs.grphdisp |= 5` (P1) |
| `outb 0x6A, 0x21` gate | ✅ 无条件 | ❌ `mode2&0x08` 门控 | 移除 `if` 守卫 (P2) |
| BIOS INT 18h AH=30h 256c | ✅ FC9846 | ❌ 缺 `gdc_analogext(TRUE)` | `rate&0x0c` 分支追加 (P3) |
| GDC 图形合成 | ✅ μPD7220 | ❌ 命令表空 | 256c 下走 `makegrphex` 原生路径 |
| 脏标志自动更新 | ✅ | ❌ 依赖无效 GDC 命令 | VGAWR8 每写设 `|=5` 触发合成 |

### 5.3 常见问题排查

| 症状 | 可能原因 | 检查方法 |
|------|---------|---------|

| 窗口僵死 (Wayland) | SDL Wayland 键盘独占 | 不设置 `SDL_VIDEODRIVER=wayland` |

## 6. 历史修复记录

### 6.1 全屏填充修复

**问题**：`hal_video_fill_rect` 每平面填 `8000 words`（640×200），对应上半屏。640×400 需要 `16000 words/plane`。

**修复**：`core/plat/pc98/hal_pc98.c:93-96` — `8000` → `16000`。

### 6.2 显示管线修复（16-color 4-plane 阶段 — 已归档）

**问题**：GDC 命令表空操作 + dirty 标志状态机失效 → NP2kai 完全无图形输出。

**修复** (2026-06-09)：
- `gdc.mode1 = 0x9a`（激活合成路径入口）
- 新增 `naiz_composite_planar()`（手工 4-plane → 8bpp 合成）
- Bypass `rasterdraw` 函数表 → 直接 `sdraw16p_2`
- 引擎 `outb(0xA4, 0)` 设显示页 0
- 每帧 `memset(sdraw.dirty, 1)` 强制渲染

**归档原因**：2026-06-12 切换到 PEGC 256c 模式后，VRAM 写路径改为 VGAWR8 → `vramex[]`，合成改为原生 `makegrphex()`。此修复不再需要。

### 6.3 256 色模式修复（当前）

**问题**：切换到 PEGC 256c 后，3 个 NP2kai 缺陷导致黑屏/花屏：
1. VGAWR8 宏 `|= bit` 不触发 256c 合成
2. `port 0x6A 0x20/0x21` 门控阻挡 `gdc_analogext()`
3. BIOS `bios0x18_30()` 缺 `gdc_analogext(TRUE)` 调用

**修复**：
- P1: `mem/memvga.c:40` — `gdcs.grphdisp |= 5`
- P2: `io/gdc.c:552,558` — 移除 `if (gdc.mode2 & 0x08)` 门控
- P3: `bios/bios18.c:389-401` — `rate & 0x0c` 时 `gdc_analogext(TRUE)` + `MEMB_PRXDUPD |= 0x80`

详见 §2.2 必需补丁清单、§4.2 Q007-Q009。

详见 §3.6 修补清单。

### 6.3 EGC 回退修复

**问题**：EGC 在 NP2kai 上不生效，循环中 `egc_enable()` → `egc_disable()` 序列无实际效果。

**修复**：`core/plat/pc98/hal_pc98.c` — 非 EGC 回退路径直接写 4 个图形平面。

### 6.4 引擎 video_init 重写（256c）

**问题**：旧 `video_init()` 使用 `INT 18h AH=42h CX=0xC0`（640×400 16色 4-plane 模式），与 PEGC 256c packed-pixel 模式不匹配。

**修复**：`core/plat/video.c` — 三段式初始化：
1. `INT 18h AH=30h AL=0x08`（640×400 256c PEGC）
2. `outb(0x6A, 0x21)`（后备强制 `GDCANALOG_256` + VGA 映射）
3. `INT 18h AH=40h`（显示使能）

### 6.5 `rep stosw` 崩溃修复

**问题**：NP2kai IA-32 核心中 `rep stosw` 到 VRAM 地址时 CPU 模拟层崩溃。

**修复**：`core/plat/pc98/x86strops.h` — 用 `stosw` + `loop` 代替 `rep stosw`。
