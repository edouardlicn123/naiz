# B19 — 时钟计算经验参考

> **状态**：活跃维护（长期参考）
> **最后更新**：2026-09-21（0.2.134 虚拟时钟下沉为 HAL 层 `hal_wallclock_smooth_ms()` 单一事实源，动画/BGM/打字机三消费方统一；时间基结论经历 PIT → 帧节拍 → DOS 系统时钟 → 虚拟时钟 → smooth 时钟共五次迭代）

本文沉淀 Naiz 引擎在 **PC-98 / NP2kai（DOS/4GW 32-bit 保护模式）** 下「真实墙钟」与「时间基计速」的选择陷阱、验证方法与实现约定。凡新增/修改任何依赖真实秒的机制（打字机揭示、动画时长、脚本延迟、MIDI 时序）前，应通读本文避免重复踩坑。

---

## 1. 一句话结论

**NP2kai 下宏观可靠墙钟 = DOS 系统时钟 `INT 21h AH=2Ch`**：整秒值平均 ~1:1 于真实时间（宏观聚合可用，0.2.131 58s 对拍 ±2.5%），但**百分秒字段 `dl` 恒为 0、秒值成块交付**（冻结 3-6s 后跳 +1000..+6000ms，0.2.133 一次性 `[CK]` 探针钉死）——**微观节拍不可直接用作逐字计时**。对策见 §2.4/§3：引擎在 `hal_wallclock_ms()` 之上叠加**虚拟时钟钳制**（地板/天花板），微观平滑由主循环 pass 节奏保证、宏观速率由墙钟平均保证；0.2.134 起该钳制下沉为 HAL 层 `hal_wallclock_smooth_ms()` 单一事实源，anim/audio/reveal 三处统一改走它。真实 PC-98 上 DOS 时钟为硬件同步（10ms 粒度），两界不触发。

`core/plat/hal_pc98.c` 的 `hal_wallclock_ms()` 是**全引擎唯一墙钟事实源**，`anim_tick` / `nb_dialog_reveal_tick` / MIDI 调度共用；改动它即改动一切时间基机制。

## 2. 时钟源决策全谱

曾考察三族时钟源，逐一实测淘汰/胜出（决策表先列结论，证据见 §2.1–2.3）：

| 候选源 | 端口/调用 | 结果 | 实测证据 |
|---|---|---|---|
| PIT 8253（正确端口） | 0x71/0x75/0x77（refdocs B02 §定时器） | **不可用** ─ NP2kai IA32 核读回 = `nevent_getremain(NEVENT_ITIMER)/pccore.multiple`，由**模拟 CPU 时钟**驱动（clk_mult 倍频缩放）、读数非单调 | 0.2.130 探针：`dVB(60x2+60)=24123/25185`、`dLOOP(4M)` 反向跳动 −7326/−38029 |
| PIT 8253（IBM 错误端口） | 0x40/0x43（实为打印/键盘区） | 历史事故 ─ latch 写错端口读到跳动值 + 换算频率用 IBM 1.193182MHz（正确 = /4 ≈ 298295Hz） | 0.2.128-129 根因，G04 §2 本地证据 |
| VSYNC 帧节拍 | GDC 0xA0 bit5（`hal_vblank_wait()` 计数） | **不可用** ─ NP2kai pass 率仅 **~20.5Hz**（每 pass ~49ms），帧计数每真实秒只 +20.5 → 墙钟每秒只推 ~342ms，**慢 3 倍** | devdoc 82 §5.2 pass 率；0.2.131 串口复验 |
| **DOS `INT 21h AH=2Ch`** | DOS 系统时钟，`int386()` DPMI 转发 | **宏观胜出** ─ DOS 维护、模拟器与真机一致；**微观不可用** ─ NP2kai `dl` 恒 0、整秒成块冻结（0.2.133 探针）；宏观平均 + 虚拟时钟钳制兜微观节拍 | devdoc 82 §5.3 实测 guest 精确 5000ms 整；0.2.133 `[CK]`/`[RV]` 探针 |

### 2.1 PIT 8253：模拟器里不是墙钟

- **正确端口**是 0x71/0x75/0x77（Power 系列兼 0x43/0x47/0x4F），**0x40/0x43 是 IBM/AT 布局**，在 PC-98 上是打印/键盘区（refdocs B02 §定时器）。移植 C 代码时照搬 IBM 端口会直接锁死整条时间链（0.2.128-129 教训）。
- 即使端口正确，**NP2kai IA32 核心的 PIT 计数 = `nevent_getremain(NEVENT_ITIMER) / pccore.multiple`**，由模拟 CPU 时钟驱动——`clk_mult` 倍频缩放它、样本非单调（忙循环段读数反向跳动）。这是模拟器实现属性，**真机上 PIT 是可靠墙钟**，但模拟器里不可用。
- 结论：**任何端口/频率组合下，PIT 都不是 NP2kai 里的真墙钟**，不必再在端口/频率/换算上花时间。

### 2.2 VSYNC 帧节拍：隐含 pass 率假设

帧节拍的错误假设是**「每次 `hal_vblank_wait()` 恰好跨 1/60 秒」**。真机上成立（垂直回扫 60Hz）；但 NP2kai 的引擎主循环 pass 率仅 ~20.5Hz——每 pass = VSYNC 等待 + 引擎工作 + NP2kai 解释核上的 VRAM/解释开销 ≈ 49ms，两次 `vblank_wait()` 之间实际跨过近 3 个 VSYNC 周期，中间的翻转在 busy-wait 轮询下**全部漏计**。

于是 `wallclock_frames++` 每真实秒只 +20.5，`hal_wallclock_ms()` = `delta×1000/60` 每秒只推进 ~342ms——**慢 3 倍**。这与 0.2.127「每 pass=1/60s」的错误同源换皮：凡是把「主循环 pass」当节拍的计速，都必须在目标平台的**实测 pass 率**上验证，不能假设 60Hz。

> 配套事实：位掩码本身曾有历史事故（0.1.008 用 bit2 FIFO EMPTY 当 VSYNC，导致从不等待），VSYNC 位是 0xA0 bit5（refdocs C01 §状态寄存器）。`hal_vblank_wait()` 现在回归纯 VSYNC 等待、不再承担墙钟职责。

### 2.3 DOS 系统时钟：宏观正确、微观成块

`INT 21h AH=2Ch` 返回 CH=时、CL=分、DH=秒、DL=百分秒（0–99，10ms 粒度）。在 DOS/4GW DPMI 保护模式下经 `int386()` 转发调用（video.c 的 CRT BIOS INT 18h 用同一通道，是既有先例）。**devdoc 82 §5.3 早已实测**：guest 时钟上引擎时长精确 5000ms 整（host 观感 5.8–6.4s 为 NP2kai guest 时钟漂移，模拟器属性，真机不存在）。

**0.2.133 修正（NP2kai 微观无效）**：一次性 `[CK]` 探针（settings 菜单 6 次采样）证明 NP2kai 的 `dl` 恒为 0，且秒值**成块交付**——时钟冻结 3-6 真实秒后一次跳 +1000..+6000ms。0.2.131 的 58s 对拍（53 样本逐秒 +1000ms）只证明**宏观平均**正确，显微镜下早就是"冻结-爆发"。凡依赖逐字/逐帧微观节奏的模块（打字机 reveal），不能直接用相邻两次 `hal_wallclock_ms()` 差值驱动。

### 2.4 虚拟时钟钳制 → HAL smooth 时钟（0.2.133 → 0.2.134）

0.2.133 起对「绝对期望位置」式计速（目标 = 速度 × 流逝 / 1000），把喂给目标的每 pass 增量钳制到 `[FLOOR, CEIL]` 即得平滑节拍：

- **地板 MIN=40**：`delta_raw==0` 时按 40ms 推进——时钟冻结期内仍按主循环 pass 节奏推进，不会"停一拍"；
- **天花板 MAX=100**：时钟补齐猛跳时丢弃盈余——单 pass 至多追 100ms，杜绝"瞬间满页/爆帧/音乐连发"；
- 主循环 pass 节奏是模拟器下唯一平滑节拍（~20-28Hz，见 devdoc 82 §5.2），虚拟时钟把它与墙钟宏观正确性解耦；0.2.133 打字机实测长句 max/avg = 2.09（devdoc 106 §6），真实硬件（DL≈55ms）两界均不触发。

**0.2.134 下沉（单一事实源）**：旧钳制逻辑只存在于 `nb_dialog.c` 的本地常量（`REVEAL_PASS_MIN_MS/MAX_MS`），仅护打字机一处；而动画 `anim_tick`、BGM/MIDI 调度 `audio_bgm_poll` 仍直接吃 raw 单次 delta，在时钟洞里同样"冻结-爆发"（H1/H2，devdoc 107）。0.2.134 把钳制逻辑上移到 HAL 层 `hal_wallclock_smooth_ms()`，常量改名 `SMOOTH_CLOCK_MIN_MS/MAX_MS` 驻 `hal.h`，**reveal/anim/audio 三消费方统一改走它**，删除 nb_dialog 本地副本。详见 §3 契约与 devdoc 107。

## 3. 实现要点（hal_wallclock_ms）

```c
unsigned long hal_wallclock_ms(void)
{
    union REGS regs;
    unsigned long now;   /* ms since midnight (folded) */

    regs.h.ah = 0x2C;                       /* INT 21h AH=2Ch */
    int386(0x21, &regs, &regs);             /* DPMI-reflected DOS call */

    now = ((unsigned long)regs.h.ch * 3600UL
         + (unsigned long)regs.h.cl * 60UL
         + (unsigned long)regs.h.dh) * 1000UL
        + (unsigned long)regs.h.dl * 10UL;  /* hundredths -> ms */

    if (!wallclock_inited) {
        wallclock_now_prev = now;
        wallclock_inited = 1;
        return wallclock_ms_total;          /* first pass = baseline */
    }
    if (now >= wallclock_now_prev) {
        wallclock_ms_total += now - wallclock_now_prev;
    }                                       /* else: midnight wrap -> recalibrate */
    wallclock_now_prev = now;
    return wallclock_ms_total;
}
```

实现铁律：

1. **折叠为当日毫秒再取差值**——绝不能「秒差 ×1000 + 百分秒」叠加（会重复计算，秒边界多算 100ms）。先合成 `now`，再一步 `delta`。
2. **午夜回绕**：`now < prev`（跨 24:00:00 折叠回零）时丢弃该差值、重校准基线、累计总量不变。调用方原有的「now 减小 → 重校准」语义原样保留。
3. **首 pass / now==0**：`wallclock_inited` 首调用记基线不推进；`now==0`（时钟未开始）由调用方回退固定 16.7ms/帧防冻结（`anim_tick` / `nb_dialog_reveal_tick` 既有兜底逻辑，语义注释为「clock not yet ticking」）。
4. **`hal_vblank_wait()` 与墙钟解耦**：只做 VSYNC 等待（免撕裂窗口），不再递增帧计数。

### 3.1 smooth 时钟契约（0.2.134 新增，`hal_wallclock_smooth_ms`）

对 `hal_wallclock_ms()` 的每一 pass 增量钳制到 `[SMOOTH_CLOCK_MIN_MS=40, SMOOTH_CLOCK_MAX_MS=100]`（`hal.h` 常量）后累计，返回**单调、微观有界**的虚拟毫秒钟：

```c
unsigned long hal_wallclock_smooth_ms(void)
{
    unsigned long raw = hal_wallclock_ms();
    unsigned long delta;
    if (!smooth_inited) {            /* 首 pass 记基线，返回 0 */
        smooth_raw_prev = raw;
        smooth_inited = 1;
        return 0UL;
    }
    delta = raw - smooth_raw_prev;   /* raw 单调（调方保证），无负数 */
    smooth_raw_prev = raw;
    if (delta == 0) delta = SMOOTH_CLOCK_MIN_MS;
    else if (delta > SMOOTH_CLOCK_MAX_MS) delta = SMOOTH_CLOCK_MAX_MS;
    smooth_clock_total += delta;
    return smooth_clock_total;
}
```

**契约铁律**：

1. **只要节奏类消费方**（逐字 / 逐帧 / MIDI 时间轴）用**相邻两次调用的差值**作节拍，一律走此接口——raw `hal_wallclock_ms()` 的 delta 在 NP2kai 上是 chunked（洞内 δ=0），只允许页面级/秒级语义直接用。
2. **单调性**：`smooth_clock_total` 只增不减，`delta ∈ [MIN, MAX]` 恒成立 → 消费方无需再写 `now < last_ms` 回绕分支或 `now==0` 兜底（smooth 首 call 后必有界递增，永不重置 0）。
3. **宏观 ≈ raw**：抄洞最多 ±MAX_MS/pass 的相位误差（≤0.1s/洞），秒级正确性保持；真实 PC-98 DL≈55ms，MIN/MAX 均不触发，smooth ≡ raw。
4. **pass-rate 耦合旋钮**：MIN_MS=40 与主循环 pass 率耦合（NP2kai ~25Hz 恰 1s/s；真机 60Hz 偏快 ~2.4x），MIN/MAX 是标定旋钮，本版按 NP2kai 标定；真机实测需另标定（devdoc 107 §3.4）。
5. **防复发**：`test_smooth_wallclock_bounds_in_hal` 解析 `hal_pc98.c`/`hal.h` 断言钳制分支与常量驻留；`test_reveal_virtual_clock_bounded_delta` 断言 reveal 不再自带 `REVEAL_PASS_*`。

> **已知取舍**：smooth 钟在洞内按 MIN_MS/pass sink——NP2kai ~20-28Hz 下 ≈1s/s（恰好），真机 60Hz 若再遇 `delta==0` 会偏快 ~2.4x。此为固有 pass-rate 耦合而非 bug；可选的 pass 自适应（EWMA）留作未来旋钮，本轮不做（devdoc 107 §3.4）。

## 4. 验证方法论（两条铁律）

### 4.1 双时钟对比法

引擎内部时钟 × **独立参考时钟**（与引擎所有时间链无关的第三方源）对拍，只用定量窗口判定，拒绝「看起来正常」——解码/渲染耗时掩盖效应已在 devdoc 81、82 两次造成误判。

- 参考时钟选择：真机/模拟器可用 **DOS 系统时钟**（独立于引擎实现）；宿主侧用 `time.monotonic()`。
- 判定标准样例：300 tick 动画墙钟 ∈ [4.5, 5.5]s 且换算心跳 ≈ 60Hz ± 10%。

### 4.2 PTY 串口 + 宿主秒对拍（0.2.131 新做法）

面向 NP2kai 的量化复验流程：

1. 引擎加**临时 `[CLK]` 探针**：每累计 1000 墙钟 ms 打一行 `hal_logf("[CLK] %lu\r\n", hal_wallclock_ms())`（建议挂在首个阻塞循环内，如 settings 菜单等待循环）。
2. 用 `tools/naiz_lib/np2kai_capture.py` 的 `write_emulator_toml()` + `pty.openpty()` 启动 `wxnp21kai --start`，把 PTY slave 配到 COM1（`com1_m_o/com1_m_i`）。
3. 宿主侧为每个串口 chunk 记 `time.monotonic()`，按字节偏移回插到每个 `[CLK]` 打点，算 `Δguest_ms / Δhost_s`。
4. 判定：比率 ≈ 1000（guest 毫秒 ≈ 宿主毫秒）± ~3% 抖动为过。0.2.131 实测 53 样本 = ≈1000ms/host-s（PIT 前身 ~1-2ms、帧节拍 ~342ms、DOS 时钟 ≈1000）。

> 注意：NP2kai 有 guest 时钟漂移（~15–28%，见 devdoc 82 §5.3），真机无此问题；判定窗口按摸拟器性质放宽。

**串口链前置三条件（0.2.132 起工具链自动保障，否则"多次才连上"）**：
1. **无残留实例**：旧 `wxnp21kai` 必须已退出（`pkill -9 -x wxnp21kai` 精确匹配；工具链 `kill_stale_emulators()` 自动处理）。
2. **PTY slave 全程保持开启**：`os.close(slave_fd)` 若在模拟器 fork 前执行，NP2kai 路径打不开该端点 → 串口静默（0.2.132 实测 close 后 0 字节 vs 保持开 5.4KB）。
3. **`--start` 直启**：缺该参数时模拟器停配置界面等手动点击，DOS 不启动。

## 5. 时间基计速承接

墙钟被时间基机制复用，改写时须一并回归（0.2.134 起**节奏类统统改吃 `hal_wallclock_smooth_ms()`**，只页面级/秒级语义用 raw）：

- **`anim_tick`（nb_anim.c）**：fixed-point 10-bit 分数，`ms_frac += delta_smooth × 61`（61 ≈ 1024×60/1000，60 tick/s 名义率），满 1024 步进 1 tick；`steps` clamp 180 只作纯防御上限（smooth 后不可达）。[0.2.134 迁 smooth；旧 `now==0` 兜底与 `now < last_ms` 回绕分支已删]
- **`nb_dialog_reveal_tick`（nb_dialog.c）**：绝对期望位置——`target = speed × (smooth − page_ms) / 1000` 每 pass 重算，target 只进不退；smooth 使洞内地板续字、补齐天花板防爆发。翻页 `reveal_page_ms` 重锚（`now − char_count×1000/speed`）。[本地 `REVEAL_PASS_*_MS` 常量与回绕分支 0.2.134 删，钳制统一由 HAL smooth 承载]
- **MIDI 调度（audio.c）**：SMF 事件按 `cur = smooth − wall0` 推进，`wall0`（play 起点）与 loop 复位均记 smooth。[0.2.134 迁 smooth，洞内不静默、补齐不连发]
- **虚拟机延迟 `vm_delay_tick`**：脚本级 `delay` 语义——按 **pass 计数**（`sec×60` 帧），非墙钟；NP2kai ~20-28Hz 下 `delay 1.0`≈3s 实、选项 600 帧≈30s 实为**已接受语义**（H3，devdoc 107 §2.3，真机 60Hz 即名义值），不做修正。

**回归守卫**：`tools/tests/test_reveal_final_page.py` 的 `test_wallclock_backed_by_dos_system_time` 解析 `hal_pc98.c`，断言墙钟用 `int386`+`0x2C`、不得复现 `wallclock_frames` 帧计数或 PIT 端口宏；`test_no_per_frame_floor` 防「每帧保底 +1 字」静默架空速度档；`test_smooth_wallclock_bounds_in_hal` 防再有人绕过 smooth 直接吃 raw delta（0.2.134 新增）。

## 6. 经验教训清单

1. **端口对照 refdocs 本机布局，勿照搬 IBM 惯例**：PC-98 定时器在 0x71/0x75/0x77，0x40/0x43 是打印/键盘区；接口层注释必须标注出处（devdoc 82 §六）。
2. **修调用层之前先核共享时间源**：0.2.128 修对了 reveal 计速调用、却沿用坏端口墙钟，实测仍 1-2 字/秒——共享 `hal_wallclock_ms()` 本身必须先诊断（0.2.129 才根修端口）。
3. **PIT 在模拟器由模拟 CPU 时钟驱动**：任何端口/频率组合都不是 NP2kai 里的真墙钟，无需再试。
4. **帧计数隐含 pass 率假设**：凡「每 pass = 1/60s」的推导，必须用目标平台实测 pass 率验证（NP2kai 实际 ~20.5Hz，慢 3 倍）。
5. **模拟器 guest/host 存在固有时钟漂移**（~15–28%），真机没有；判定窗口按模拟器属性放宽，别误判为 bug。
6. **双时钟对比法是时序类改动的验收标配**，不接受目测「正常」。
7. **墙钟源变更必须同步回归动画/打字机/延迟/MIDI 四类消费者 + 防回归测试断言形态**，并重注入磁盘（`makegame.sh build + make`）。
8. **串口静默先查三元组而不是环境**：残留实例 / slave_fd 提前关闭 / 缺 `--start` 三个可复现根因（0.2.129 把 `sertest.com` 的 0 字节误归因会话环境，实为 INT 14h 在 PC-9821 无 BIOS 处理函数）；DOS 侧串口测试须仿引擎用直接 uPD8251 端口 I/O（0x30/0x32）。
9. **宏观聚合正确 ≠ 微观节拍正确**：0.2.131 的 58s 每秒对拍验证了"平均每秒 +1000ms"，却掩盖了 NP2kai 整秒**成块交付**（冻结 3-6s + 猛跳）；逐字/逐帧节奏类功能必须用**单次事件间隔**（探针相邻 `end`/`target` 增量 + 宿主 monotonic）验证 max/avg 比值，不能只看聚合速率。
10. **凡微秒节奏一律走 `hal_wallclock_smooth_ms()`，禁止逐模块再造本地虚拟时钟**：0.2.133 的钳制只在 `nb_dialog.c` 本地，动画/BGM 仍吃 raw delta 被同一时钟洞波及（H1/H2）；0.2.134 下沉 HAL 后，任何新写"差值作节拍"的代码都必须查 `test_smooth_wallclock_bounds_in_hal` 会不会挂。
11. **`make` 不因 CFLAGS 变量变化重编译**：探针构建（`-DNAIZ_CLOCK_PROBE`）必须先 `rm build/a_*.o`（或 clean）再 make，否则旧对象带不出新宏（0.2.134 实证过程踩到）。
