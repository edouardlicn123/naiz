# Keyboard Scancode Troubleshooting / 键盘映射故障排查

在 NP2kai 保护模式下，引擎通过直接读取 BIOS 键盘缓冲区（`mem[0x0502]`）获取按键。某个键不响应时，按以下流程排查。

## Quick Reference

| Step | Action | Key Target |
|------|--------|------------|
| 1 | 确认引擎定义 | `core/plat/keyboard.h` `KC_*` 宏 |
| 2 | 确认引擎使用点 | `grep -rn 'KC_<TARGET>' core/engine/` |
| 3a | wx `wxkcnv[]` 表 | `wx/kbtrans.cpp` 特殊键映射 |
| 3b | wx `ascii_to_pc98_106[]` 表 | `wx/kbtrans.cpp` ASCII 映射 |
| 3c | wx autokey `s_vkeylist[]` | `wx/np2.cpp`（对照用） |
| 3d | SDL 对照 | `sdl/kbtrans.c` |
| 4 | 标准表 | `/tmp/NP2kai/keystat.tbl` / `docs/refdocs/D01_keyboard.md` |
| 5 | 追踪事件流 | 从 wx 到引擎的完整链路 |

---

## 1. 排查流程

### 1.1 确认引擎定义

检查 `core/plat/keyboard.h` 中目标键的 `KC_*` 宏定义值：

```c
#define KC_SPACE    0x34
#define KC_XFER     0x35
```

比对 `docs/refdocs/D01_keyboard.md` 中的 PC-98 标准扫描码。

### 1.2 确认引擎使用点

```bash
grep -rn 'KC_<TARGET>' core/engine/
```

确认 `kbd_is_down()` / `kbd_wait_release()` 调用是否覆盖了目标键。

### 1.3 检查模拟器映射

NP2kai 有三个映射层，按优先级排查：

#### 1.3.1 wx 前端 `wx/kbtrans.cpp` — `wxkcnv[]` 表

```c
// 特殊键表（WXK_* → PC-98）
{ WXK_SPACE,      0x34, 0x34 },   // L43：修正后
{ WXK_RETURN,     0x1c, 0x1c },   // 回车
```

查找目标 WXK 键码在 `wxkcnv[]` 中的映射值。

#### 1.3.2 wx 前端 `wx/kbtrans.cpp` — `ascii_to_pc98_106[]` 表

```c
static const UINT8 ascii_to_pc98_106[0x60] = {
/* 20 */ 0x34, ...    // ASCII 0x20（空格）
```

ASCII 字符走此表（`wxkey_to_pc98()` 中 `key >= 0x20 && key <= 0x7e` 分支）。

#### 1.3.3 wx 前端 autokey 表 `wx/np2.cpp` — `s_vkeylist[]`

```c
s_vkeylist[(UINT8)' '] = 0x34;   // autokey 路径，常与 kbtrans 不一致
```

autokey 用于按键连发（游戏场景），不影响常规按键事件。

#### 1.3.4 SDL 前端 `sdl/kbtrans.c`

```
{ RETROK_SPACE, 0x34 },
{ SDLK_SPACE,   0x34 },
```

作为对照基准（SDL 映射通常是正确的）。

### 1.4 对照标准表

`/tmp/NP2kai/keystat.tbl:66-67` 或 `docs/refdocs/D01_keyboard.md` 是标准定义源。

```c
0x34 = SPC
0x35 = XFER
```

### 1.5 追踪事件流

对于 wx 前端，按键事件链路：

```
wxWidgets 按键事件
  → np2panel.cpp:OnKeyDown()
    → wxkbd_keydown() [wx/kbtrans.cpp:132]
      → wxkey_to_pc98() 查 wxkcnv[] / ascii_to_pc98_106[]
        → keystat_keydown(sc)
          → keyboard_send(sc) [io/serial.c:137]
            → IRQ1 → INT 09h → BIOS 缓冲区写入
              → 引擎 kbd_update() 读出
                → kbd_is_down(KC_XXX) 匹配
```

若 `wxkey_to_pc98()` 映射错误，后续全错。

## 2. 快速验证脚本

```bash
# 在 /tmp/NP2kai 中运行
echo "=== 检查映射 ==="
grep -n 'WXK_SPACE\|WXK_RETURN\|WXK_UP\|WXK_DOWN\|WXK_LEFT\|WXK_RIGHT' wx/kbtrans.cpp | head -10
echo "=== ASCII 表 0x20 段 ==="
sed -n '/ascii_to_pc98_106/,/^}/p' wx/kbtrans.cpp | head -12
echo "=== 对照 keystat.tbl ==="
grep -n 'SPC\|XFER' keystat.tbl | head -10
echo "=== 引擎定义 ==="
grep -n 'KC_' /path/to/naiz/core/plat/keyboard.h
```

## 3. 常见陷阱

| 现象 | 可能原因 |
|------|---------|
| 回车可用但空格不可用 | wx kbtrans `WXK_SPACE` 映射错（`0x35` 而非 `0x34`） |
| Debug 构建正常，Release 不正常 | 串口 I/O 触发模拟器同步的错觉，实际是映射问题 |
| 小键盘数字键异常 | `WXK_NUMPAD4/5` 映射为 `0x34/0x35`（与 SPC/XFER 冲突） |
| 特定 ASCII 键无响应 | `ascii_to_pc98_106[]` 表对应条目错误 |
| SDL 正常但 wx 异常 | wx `kbtrans.cpp` 和 `np2.cpp`（autokey 表）不一致 |
