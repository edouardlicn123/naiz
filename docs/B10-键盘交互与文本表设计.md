## 1. 功能概述

在现有场景 VM 基础上添加**键盘驱动的文本推进**，替换 auto-advance 帧计数方案。

| 按键 | 行为 | 说明 |
|------|------|------|
| **Space** (0x34) | 推进到下一个文本 | 消费式触发，一按一句 |
| **Enter** (0x1C) | 同上 | 同上 |
| **XFER** (0x35) | 同上 | PC-98 VN 惯例推进键；兼容 wx NP2kai 空格映射（见 `devdocs/0.1版开发文档总结.html#doc-29`） |
| **Ctrl** (0x74) | 快进：跳过等待，逐帧跳过全部文本 | 按住即可持续跳过 |

（提示文字已移除——对话框右下角不再显示任何按键提示。）

## 2. 架构设计

### 2.1 整体流程图

```
main() 初始化
  │ hal_init()                          ← 平台初始化（串口调试通道）
  │ font_init("FONT.DAT")              ← 8×16 字形加载
  │ cjk_init("CJK.DAT")                ← CJK 字形加载
  │ kbd_init()                          ← 初始化本地键盘缓冲
  │ video_init()                        ← PEGC 640×400 256c 模式
  │ hal_set_palette()                   ← 启动调色板
  │ image_init("IMAGE.DAT")             ← MAG 图片归档加载
   │ nb_init()                           ← NB 脚本引擎初始化（加载 logo.nb，准备 NB 解释器）
  ▼
nb_process() 循环
  │ kbd_update()                        ← 每帧排干 BIOS 键码 → 本地缓冲
   │ nb_process()                        ← 运行 NB 脚本 VM 到下一个断点
    │   └→ dialog_show()                  ← 绘制对话框 + 文字；首次自动调用 layer_dialog_open()
    │
    ├─ 如果有 FINALEND/ERROR → break
   │
   └─ 如果 VM 暂停（!VMFLAG_PROCESS）：
        ┌─────────────────────────────────┐
        │  while (!kbd_is_down(SPACE) &&  │
        │         !kbd_is_down(ENTER)) {  │
        │    kbd_update();                │
        │    if (kbd_is_down(CTRL))       │
        │      break;                     │  ← Ctrl 快进
        │  }                              │
        │  VMFLAG_PROCESS = 1             │  ← 恢复 VM 执行
        │  ASYNC_USER = 0                 │
        └─────────────────────────────────┘
```

### 2.2 键盘驱动（复用 `keyboard.c`）

现有的 `core/plat/keyboard.c` 通过 INT 18h DPMI 接口读取 PC-98 BIOS 键盘缓冲：

| 函数 | 用途 | 消费？ |
|------|------|--------|
| `kbd_init()` | 初始化本地缓冲（每次启动时调用一次） | — |
| `kbd_update()` | 从 BIOS 缓冲排干键码到本地缓冲，每帧调用一次 | 是（从 BIOS 移除） |
| `kbd_is_down(sc)` | 查询扫描码是否已被按下；若找到则消费一个实例 | **是（消费 1 个）** |
| `kbd_wait_any()` | 阻塞直到任意键被按下（"任意键" 屏幕） | 是 |

**每帧调用约定**：
1. 先调用 `kbd_update()` 一次（在主循环开始处）
2. 然后使用 `kbd_is_down()` 查询

**Ctrl 快进机制**：
- `kbd_is_down(KC_CTRL)` 每次消费一个 Ctrl 码，退出等待循环
- 用户按住 Ctrl 时：BIOS 持续产生重复码 → 下一帧 `kbd_update()` 再次填入 → 再次 `kbd_is_down` 消费 → 再次 break → 逐帧快速推进

### 2.3 键盘扫描码速查

来源：`core/plat/keyboard.h`（PC-98 标准 BIOS 扫描码，与 NP2kai `keystat.tbl` 对应）

| 键 | 扫描码 | 十六进 |
|----|--------|--------|
| Space | `KC_SPACE` | `0x34` |
| Enter | `KC_ENTER` | `0x1C` |
| Ctrl | `KC_CTRL` | `0x74` |
| Esc | `KC_ESC` | `0x00` |

完整扫描码表（128+ 键）见 `core/plat/keyboard.h:8-113`，涵盖：
- ASCII 字符（`KC_A`=`0x1D`～`KC_Z`=`0x29`，`KC_0`=`0x0A`～`KC_9`=`0x09`）
- 功能键（`KC_F1`=`0x62`～`KC_F10`=`0x6B`）
- PC-98 特有键（`KC_XFER`、`KC_NFER`、`KC_VF1-5`、`KC_STOP`、`KC_COPY`）
- 修饰键（`KC_SHIFT`=`0x70`、`KC_CAPS`=`0x71`、`KC_KANA`=`0x72`、`KC_GRPH`=`0x73`）

## 4. 快进时的视觉效果

用户按住 Ctrl 时：
1. 等待循环内 `kbd_is_down(KC_CTRL)` 消费一个 Ctrl 码 → break
2. VM 恢复，执行下一个 opcode
3. `dialog_show()` 绘制新的对话框正文
4. 再次进入等待循环，Ctrl 仍被按住 → break 继续快进
5. 用户看到的是**快速轮替的对话框内容**（Ctrl 快进）

## 5. 关键设计决策

### 5.1 为什么文本来源是 .nb 脚本而非硬编码表

- 对白文本直接来自 `.nb` 脚本文件（`host{}` / `角色名{}` 命令），无需额外文本表
- 场景切换由 `nb_load()` 处理，NB 解释器自动加载对应 `.nb` 文件
- main.c 只负责编排序列，不涉及文本数据

### 5.2 为什么对白位置是全局常量而非文本条目属性

- **对白**是 VN 引擎的固定 UI 元素，其位置在视觉上不随句子变化
- 每次 `dialog_show()` 已通过 `layer_dialog_snap()`/`layer_dialog_restore()` 恢复干净对话框区域，新文本画在同一位置是自然的
- 如果将 Y 坐标放在文本条目中，会导致"每个句子定义自己的位置"这种不合理的概念
- 全局常量 `LAYER_DIALOG_TEXT_Y` 统一管理对白文字 Y 偏移，未来若需支持 CJK 多行或字号变更，只需调一个值

### 5.3 为什么用 `kbd_is_down` 而非非消费查询处理 Space/Enter

- `kbd_is_down` 是消费式的：一次按键 = 一次推进
- 非消费性查询（原 `kbd_is_pressed`，已删除）会在一帧内推进多次（不想要）
- 快进用 `kbd_is_down(KC_CTRL)` 消费一个码退出等待循环

### 5.5 为什么移除帧计数

- auto-advance 200 帧不是游戏逻辑的组成部分
- 如果未来需要没有键盘的场景（自动播放），通过 VM 标志（如 `nowait` 标志）控制更合理
