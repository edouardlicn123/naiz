# Diagnostic Tools

Tools in `tools/diag/` for diagnosing boot, file I/O, video output, and emulator
write-back issues without requiring engine modifications.

## Quick Reference

| Tool | Location | Purpose |
|------|----------|---------|
| `naiz_screendig` | `tools/naiz_screendig/` | Continuous screenshot capture + analysis (P0) |
| `np2kai_serial` | `tools/diag/np2kai_serial.py` | Automated serial debug (inject + launch + capture) |
| `read_fat16` | `tools/diag/read_fat16.py` | Browse FAT partition of the base HDI |
| `gen_com` | `tools/diag/gen_com.py` | Generate DOS COM test programs |
| `hdi_patch_autoexec` | `tools/diag/hdi_patch_autoexec.py` | Replace AUTOEXEC.BAT directly in an HDI |
| `symbol_audit` | `tools/diag/symbol_audit.py` | Static scan of core/ for encapsulation/split candidates (static candidates / dead exports / coupling view / symbol inventory) |

These tools complement the main `tools/naiz_img/` toolchain (`inject.py`, `listhdi.py`).
All accept an HDI path and run in read-only mode unless explicitly writing.

## 1. gen_com — COM Test File Generator

Generate COM-format executables for targeted DOS subsystem testing.

### Built-in Presets

| Preset | Produces | What It Tests |
|--------|----------|---------------|
| `rwcheck` | `RWCHECK.LOG` → `RWCHECK OK` | DOS file create + write (INT 21h AH=3Ch / AH=40h) |
| `vramwrite` | Writes `ABCD` to text VRAM @ 0xA000:0, then HLTs | Text VRAM layer visible via emulator screenshot |
| `serialwrite` | Inits COM1 (9600 8N1), sends `Hello from DOS!\r\n`, exits | Serial port output (INT 14h) captured via PTY |

### Custom COM

Any 8.3 filename + ASCII data via `--create` / `--data`.

### Usage

```bash
# List presets
python -m tools.diag.gen_com --list-presets

# Generate preset
python -m tools.diag.gen_com --preset rwcheck -o /tmp/rwcheck.com
python -m tools.diag.gen_com --preset vramwrite -o /tmp/vram.com
python -m tools.diag.gen_com --preset serialwrite -o /tmp/serial.com

# Generate custom file-writer
python -m tools.diag.gen_com -o /tmp/test.com --create TEST.LOG --data "PASSED"
```

### Typical Workflow

```bash
# 1. Generate
python -m tools.diag.gen_com --preset rwcheck -o /tmp/rwcheck.com

# 2. Inject into game's HDI directory
cp /tmp/rwcheck.com games/demo-a2/
python -m tools.naiz_img.inject --game demo-a2 --yes

# 3. Patch autoexec to run it instead of ENGINE.EXE
python -m tools.diag.hdi_patch_autoexec disks/demo-a2.hdi "Rwcheck.com"

# 4. Run emulator
makegame.sh test demo-a2

# 5. Check output file in HDI (via serial log or FAT browse)
python -m tools.diag.read_fat16

# 6. Restore autoexec
python -m tools.diag.hdi_patch_autoexec disks/demo-a2.hdi "ENGINE.EXE"
```

## 2. hdi_patch_autoexec — Direct AUTOEXEC.BAT Patcher

Modify AUTOEXEC.BAT in a compiled HDI without rebuilding the entire image.
Works by patching the first cluster's data and updating the directory entry size.

### Limitations

- New content must not exceed the original file's cluster allocation (typically
  2048 bytes for one-cluster files). For larger replacements, use `inject.py`
  with `--no-autoexec` + a custom AUTOEXEC.BAT in the game directory.
- Only patches the root-directory `AUTOEXECBAT` entry.

### Usage

```bash
# Simple replacement
python -m tools.diag.hdi_patch_autoexec disks/demo-a2.hdi "TEST.COM"

# From file
python -m tools.diag.hdi_patch_autoexec disks/demo-a2.hdi --file custom.bat

# Preview without writing
python -m tools.diag.hdi_patch_autoexec disks/demo-a2.hdi "TEST.COM" --dry-run

# List root directory (all entries, not just autoexec)
python -m tools.diag.hdi_patch_autoexec disks/demo-a2.hdi --list
```

## 5. naiz_screendig — 连续截图调试工具

专门用于 NP2kai 模拟器渲染问题的调试工具。支持连续截图、自动分析、基准对比
和 HTML 报告生成。

**位置**：`tools/naiz_screendig/`，通过 `python -m tools.naiz_screendig` 调用。

**优先级**：P0 — 最直接的验证手段。需要截图分析时优先使用此工具而非单张截图。

### 功能概述

- **连续截图序列捕获**：支持 2 秒间隔自动连续截图
- **自动化分析**：检测颜色问题（如青色偏色）、文本层状态
- **会话管理**：自动创建会话目录，保存所有相关数据
- **基准对比**：与基准图像对比差异
- **HTML 报告生成**：可视化调试报告

### 安装依赖

```bash
pip3 install --user --break-system-packages Pillow numpy
```

缺失时截图仍可工作，但分析功能不可用。

### 截图窗口识别

NP2kai 进程创建 3 个 X11 窗口：
- 10×10 托盘图标
- 200×200 工具栏
- 640×459 主显示窗口

工具按窗口标题（包含 `NP21kai` 或 `np21kai`）和尺寸阈值自动选择主显示窗口。

## 6. 串口调试

串口是本项目最关键的调试通道 — 它绕过了 NP2kai SCSI HDI 写不回的限制，
能实时捕获引擎的 `log_write()` 输出。

### 6.1 引擎串口通信原理

引擎通过 uPD8251 USART 芯片的直接端口 I/O 发送串行数据：

```
hal_serial_init():
  outb(0x32, 0x00)      # 复位 uPD8251
  outb(0x32, 0x4E)      # 模式：8 数据位 + 无校验 + 1 停止位 + 16x 波特因子
  outb(0x32, 0x37)      # 命令：Tx/Rx 使能 + DTR + RTS + 错误复位
  inb(0x32)              # 读状态 → 触发 NP2kai rs232c_open() ← 关键步骤

hal_serial_write_char(c):
  poll inb(0x32) bit 6  # 等待 TxEMP（发送器空闲）
  outb(0x30, c)          # 写入数据
```

**关键点**：
- `inb(0x32)` 读状态操作是 NP2kai 打开串口的触发条件
- 串口是逐字节轮询写入的，每字节约 1ms（9600 baud），但引擎可能因 TX 缓冲
  等待而变慢
- 引擎硬编码 9600 baud（`hal_pc98.c:462` 模式寄存器中的波特因子）

### 6.2 PTY 直连法（推荐）

绕过 INT 14h 限制，直接通过伪终端捕获引擎的端口 I/O。

#### TOML 配置参数

NP2kai 的串口行为完全由 `~/.config/wxnp21kai/wxnp21kai.toml` 控制。
**该文件也是 HDI 路径的唯一生效源**，命令行参数无效。

| TOML 键 | 值 | 含义 |
|---------|-----|------|
| `SCSIHDD0` | `"/path/to/game.hdi"` | 启动硬盘路径（唯一生效源） |
| `com1port` | `1` | 启用 COM1（0 = 禁用） |
| `com1para` | `0xE3` | 串口参数：9600 8N1 |
| `com1_bps` | `9600` | 波特率（引擎硬编码） |
| `com1_m_o` | `"/dev/pts/N"` | PTY slave 路径（输出） |
| `com1_m_i` | `"/dev/pts/N"` | PTY slave 路径（输入） |

`com1para` 编码解析 (`0xE3`)：
- bit 0-1: 字长 (`11` = 8 位)
- bit 2: 停止位 (`0` = 1 位)
- bit 3-4: 校验 (`00` = 无校验)
- bit 5: 校验类型 (`1` = 无关)
- bit 6-7: 波特率 (`11` = 9600)

#### 使用 makegame.sh --serial（推荐）

`makegame.sh test <game> --serial` 自动完成所有配置：

```bash
makegame.sh test demo-a2 --serial
```

该命令等价于：
1. 读取 `install_env.py` 的 `cmd_test_hdi(serial=True)`
2. 创建 PTY：`pty.openpty()` → 获取 slave path
3. 写入 TOML：`com1port=1`、`com1para=0xE3`、`com1_m_o=slave`、`com1_m_i=slave`
4. 启动 NP2kai（`subprocess.Popen`，`stdout=DEVNULL`）
5. 线程读取 master_fd，输出到终端 + 保存到 `logs/serial_<game>.log`
6. 等待模拟器退出 → 关闭 PTY

#### 手动 PTY 调试方法

用于需要自定义 TOML 配置或不想通过安装流程的场景：

```python
import pty, os, subprocess, select, threading

# 1. 创建 PTY
master_fd, slave_fd = pty.openpty()
slave_name = os.ttyname(slave_fd)

# 2. 手动写入 TOML（关键步骤）
# ~/.config/wxnp21kai/wxnp21kai.toml 必须包含：
#   [NP21kai]
#   SCSIHDD0 = "/home/user/naiz/disks/demo-a2.hdi"
#   com1port = 1
#   com1para = 227
#   com1_bps = 9600
#   com1_m_o = "/dev/pts/5"
#   com1_m_i = "/dev/pts/5"
# 注意：boolean 必须用小写 true/false；数字不须引号

# 3. 启动 NP2kai
proc = subprocess.Popen(["/usr/local/bin/wxnp21kai"])
os.close(slave_fd)  # 父进程只需 master

# 4. 读取串口数据
def read_serial():
    while True:
        r, _, _ = select.select([master_fd], [], [], 0.5)
        if r:
            data = os.read(master_fd, 4096)
            if not data: break
            print(data.decode("utf-8", errors="replace"), end="", flush=True)

threading.Thread(target=read_serial, daemon=True).start()
proc.wait()
```

**⚠️ PTY 必须在 NP2kai 启动之前创建**，且 slave 路径必须有效。
如果 Python 脚本在 NP2kai 打开串口前退出，PTY 会被销毁，NP2kai 写到
已失效路径的数据会丢失。

#### 串口数据特征

- **逐字节到达**：因 uPD8251 轮询模式，引擎每次写入一个字节
- **约 500ms/byte**：引擎在串口和 GDC 操作之间可能存在长间隔
- **输出标记**：引擎输出的第一行总是 `Naiz engine starting`
- **串口日志**：通过 `--serial` 自动保存到 `logs/serial_<game>.log`

#### 引擎串口控制

引擎内部通过以下函数控制串口输出：

```c
log_enable_serial();      // 启用串口输出
log_disable_serial();     // 禁用串口输出
log_write("message");     // 写入日志（同时输出到串口、ENGINE.LOG、文本 VRAM）
```

串口输出默认关闭，引擎初始化完成后通过 `log_enable_serial()` 开启。

### 6.3 INT 14h 法（工具 np2kai_serial）

旧工具，通过 `serialwrite.com`（使用 INT 14h）发送串行数据。

#### np2kai_serial 用法

```bash
# 完整流程：生成 COM → 注入 HDI → 打补丁 AUTOEXEC → 启动 → 捕获 → 恢复
python -m tools.diag.np2kai_serial --game demo-a2 --timeout 20

# 仅监听（手动配置 HDI 和 TOML）
python -m tools.diag.np2kai_serial --hdi disks/demo-a2.hdi --listen-only

# 指定输出文件
python -m tools.diag.np2kai_serial --game demo-a2 -o /tmp/serial.log
```

#### 使用限制

- PC-9821 BIOS ROM 不含 INT 14h 处理函数（已扫描验证，零处 `CD 14`）
- NP2kai IA-32 核心可能在模拟层提供 INT 14h；实测 `serialwrite.com` 在外层工作
- **引擎不使用 INT 14h**，使用直接端口 I/O（6.2 节），因此引擎串口不依赖此工具

### 6.4 串口调试注意事项

#### TOML boolean 陷阱

**症状**：`cfg={}` — `save_toml()` 在 `tomllib.load()` 失败时清空配置，
仅写入 NP21kai 段的 7 个串口键，导致 `ExMemory`、`pc_model`、`DIPswtch`、
`MEMswtch` 等关键仿真参数丢失，模拟器行为异常。

**原因**：Python 的 `False` 序列化为 `False`（首字母大写），TOML 标准要求
布尔值必须小写 `true`/`false`。如果 TOML 文件中有 `= False`，`tomllib.load()`
会抛出 `TOMLDecodeError`，触发 `cfg = {}` 分支。

**解决方案**：`install_env.py` 和 `np2kai_serial.py` 均使用自定义 `_toml_val()`
函数将 `bool` 转为小写字符串。手动编辑 TOML 时务必使用小写。

**备份建议**：修改 TOML 前备份：
```bash
cp ~/.config/wxnp21kai/wxnp21kai.toml ~/.config/wxnp21kai/wxnp21kai.toml.bak
```

#### 配置丢失的完整影响

当 `cfg` 被清空时，以下配置项丢失：
| 配置项 | 影响 |
|--------|------|
| `ExMemory` | 扩展内存量（默认可能导致引擎 alloc 失败） |
| `pc_model` | 机种设定（影响 VRAM/GDC 行为） |
| `DIPswtch` | DIP 开关（影响启动选项） |
| `MEMswtch` | 内存开关（影响 RAM/ROM 映射） |
| `biosrom` / `fontrom` | ROM 路径（可能用默认路径） |

#### PTY 生命周期

1. PTY slave 路径（如 `/dev/pts/5`）仅在有进程持有 fd 时有效
2. 脚本必须在 `subprocess.Popen(EMULATOR)` **之前**创建 PTY
3. NP2kai 在 `inb(0x32)` 时打开串口（引擎的 `hal_serial_init` 触发）
4. 如果脚本在 NP2kai 打开串口前退出，PTY 被销毁 → 数据丢失
5. `install_env.py` 和 `np2kai_serial.py` 均通过 `proc.wait()` 阻塞等待
   模拟器退出，保证 PTY 在调试期间始终有效

#### 波特率限制

引擎硬编码 9600 baud（`hal_pc98.c:462` 模式寄存器中的波特因子）。
如需更高波特率，需修改 `core/plat/pc98/hal_pc98.c` 的 `hal_serial_init()`：

```c
// 9600:  outb(0x32, 0x4E);  // 模式字 = 0100 1110
// 19200: outb(0x32, 0x4F);  // 模式字 = 0100 1111
// 38400: outb(0x32, 0x4E);  // 时钟输入需配合
```

uPD8251 的波特率由时钟输入和模式字的波特因子（bits 6-7）共同决定。

## 7. Known Limitations

| Issue | Description |
|-------|-------------|
| HDI not written back | NP2kai may not flush INT 13h writes to the `.hdi` file on non-graceful exit. Workaround: use `--serial` or text VRAM for real-time output. |
| AUTOEXEC not picked up | If `CD` in AUTOEXEC fails (e.g. unfresh directory cluster), DOS may not find the game files. Use `read_fat16` to verify the FAT directory structure. |
| COM file path | AUTOEXEC.BAT runs from root; use `CD \GAMEDIR` and relative paths, or absolute `\GAMEDIR\FILE.COM`. |
| TOML boolean case | Python `False` serializes as `False` (capital F), which is invalid TOML. Always use lowercase `true`/`false`. Invalid TOML causes `save_toml()` to discard all config and rewrite only serial keys. |
| INT 14h unavailable | PC-9821 BIOS ROM has no INT 14h handler. Engine uses direct port I/O (0x30/0x32 uPD8251) for serial output, bypassing this limitation. |
| Serial data timing | Engine polls TxEMP bit 6 at port 0x32, writing one byte at a time. Output may arrive slowly (~500ms/byte) due to interleaved GDC operations. |
| PTY must outlive emulator | PTY slave path becomes invalid when the creating process exits. The debug script must block (`proc.wait()`) until the emulator terminates. |
| Make backup of TOML | Always back up `~/.config/wxnp21kai/wxnp21kai.toml` before running any tool that modifies it, to prevent loss of `ExMemory`, `pc_model`, and other critical settings. |
| Screenshot window name | NP2kai windows have title `wxnp21kai` (not `NP21kai`). Tools search by substring. |
| SCSIHDD0 is the only boot source | NP2kai ignores command-line HDI paths. The `SCSIHDD0` key in `wxnp21kai.toml` is the sole boot source. |
| 19200+ baud untested | Engine hardcodes 9600 baud. Higher rates require changes to `core/plat/pc98/hal_pc98.c`. |
| Desktop environment required | Screenshot tools (xdotool + ImageMagick) and window detection require a running X11 desktop. |
