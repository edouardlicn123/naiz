# B02 — 显示管线规范

> **状态**：活跃维护
> **最后更新**：2026-06-27（全线同步 render.h API 和 NB 解释器）
>
> 本文定义引擎显示管线的完整规范——从 CRT BIOS 模式设置到 VRAM 像素绘制到 NP2kai 渲染合成。
> NP2kai 兼容性讨论见 `docs/B09-引擎开发与调试全流程.md` §4。

---

## 1. 概述

### 1.1 显示管线角色

引擎的所有可见输出通过**VRAM 图形层像素操作**实现。DOS 文本层（`printf`/`putchar`）在 DOS/4GW + VEM486 DPMI 保护模式下对用户不可见，**严禁用于输出文本**。

> **2026-06-12 更新**：引擎切换到 PEGC 640×400 256 色 packed-pixel 模式。旧 16-color 4-plane 管线不再使用。以下为当前 256c 管线。

```
引擎 C 代码（render.c）
  │ outb(0xE0004, bank) → PEGC bank 选择
  │ outb(0xA8000+off, pixel) → packed-pixel 写（每字节 = 1 像素）
  ▼
NP2kai VGA 内存模拟（mem/memvga.c VGAWR8 宏） [P1]
  │ gdcs.grphdisp |= 5         ← 触发合成 + 使能
  │ vramex[(bank<<15)+off] = pixel  ← 存入 vramex[]
  ▼
NP2kai 图形合成（vram/makegrex.c）
  │ makegrphex() → 读取 vramex[] packed-pixel 数据
  │ 直接拷贝 32bit 值到 np2_vram[]
  ▼
NP2kai 调色板（vram/palettes.c）
  │ pal_make9821() → gdc.anareg[48+] 8bit 分量 → np2_pal16[]
  ▼
NP2kai 渲染器（vram/sdraw.mcr）
  │ sdraw16p_2 → SDSETPIXEL(ptr, np2_pal16[pixel_idx]) → 16bpp RGB565 pixbuf
  ▼
wx 面板 → 屏幕显示
```

### 1.2 硬性约束

以下源自 `AGENTS.md` §十一，未经明确许可不得更改：

- **显示管线固定**：`video_init(CRT BIOS)` → `hal_set_palette` → VRAM 像素绘图
- **禁止 printf 文本输出**：只能用 `render.h` / `render.c` 提供的 VRAM 像素函数
- **启动固定为 AUTOEXEC.BAT**：禁止 CONFIG.SYS `INSTALL=` 方式

## 2. 初始化顺序（固定）

所有函数调用顺序不可更改：

| 序 | 调用 | 功能 | 副作用 |
|----|------|------|--------|
| 1 | `hal_init()` | 平台初始化（含串口） | `hal_log()` 可用 |
| 2 | `font_init("FONT.DAT")` | 8×16 字形加载 | `font_get_glyph()` 可用 |
| 3 | `cjk_init("CJK.DAT")` | 16×16 CJK 字形加载 | `cjk_get_glyph()` 可用 |
| 4 | `kbd_init()` | 键盘 BIOS 缓冲 → 本地环形缓冲 | `kbd_is_down()` 等可用 |
| 5 | **`video_init()`** | INT 18h AH=30h AL=0x08 (640×400 256c PEGC) + PEGC MMIO 设 | 256c 模式 + VRAM 窗口映射 |
| 6 | `hal_set_palette(0/7/248, ...)` | 设置调色板索引：0=黑, 7=白, 248=黑（对话框底色） | 8-bit 分量写入 anareg[48+] |
| 7 | `image_init("IMAGE.DAT")` | 加载 MAG 图像归档到内存 | `image_load()` 可用 |
| 8 | `nb_init()` | 加载 NB 剧本引擎 | NB 解释器就绪 |
| 9 | `nb_process()` 循环 | 执行 NB 脚本命令 | VRAM 像素变化 |
| 10 | `for(;;) {}` | 空闲死循环 | 保持画面 |

**关键设计决定**：
- **步骤 3 必须在步骤 5-6 之前**：VRAM 写入在显示模式未激活时无效
- **步骤 2 在步骤 3 之前即可**：`font_init()` 只涉及文件读写，不需要显示模式
- **步骤 1 最优先**：任何后续阶段的错误信息必须通过串口输出

### 2.1 初始化源代码

来自 `core/engine/main.c:main()`：

```c
hal_init();                                       // 1 — 含 serial_init
font_init("FONT.DAT");                            // 2
cjk_init("CJK.DAT");                              // 3
kbd_init();                                       // 4
video_init();                                     // 5 — 256c PEGC 模式

/* 启动调色板：0=黑, 1=蓝, 2=绿, 3=红, 7=白, 15=白(透明), 248=黑(对话框) */
hal_set_palette(0,  0x00, 0x00, 0x00);
fill_rect(0, 0, 640, 400, 0);                    // 全屏黑底
hal_set_palette(1,  0x00, 0x00, 0xFF);
hal_set_palette(2,  0x00, 0xFF, 0x00);
hal_set_palette(3,  0xFF, 0x00, 0x00);
hal_set_palette(7,  0xFF, 0xFF, 0xFF);
hal_set_palette(15, 0xFF, 0xFF, 0xFF);
hal_set_palette(248, 0x00, 0x00, 0x00);

fill_rect(0, 0, 640, 400, 0);                    // 二次清屏（保险）
video_check_palette();                            // 调色板回读自检

image_init("IMAGE.DAT");                          // 7 — 含 palette 一致校验
if (nb_init() != 0) goto idle;                    // 8 — NB 脚本引擎初始化
nb_process() 循环                                  // 9
for(;;) {}                                        // 10
```

> **注意**：引擎不再设 palette 1（蓝）或执行全屏 `fill_rect` 蓝底。蓝色背景由场景中第一个 bg 命令加载的 MAG 图像提供。若 IMAGE.DAT 加载失败，屏幕将保留 VRAM 未初始化状态（全黑或随机）。

## 3. CRT BIOS 模式设置

### 3.1 `video_init()`（当前 256c 实现）

**文件**：`core/plat/video.c`

```c
void video_init(void)
{
    union REGS regs;
    int i, bank;

    /* 1. PEGC MMIO — 最先设置，确保硬件在正确模式下启动 */
    *PEGC_MODE_PORT   = 0x00;
    *PEGC_VRAM_ENABLE = 0x01;

    /* 2. BIOS: 640x400 256c graphics (PEGC) via DPMI */
    regs.h.ah = 0x30;
    regs.h.al = 0x08;
    regs.h.bh = 0x01;
    regs.h.al = 0x01;   /* AL=0x01 表示图形层 */
    regs.h.bh = 0x00;   /* BH=0x00 子功能 0 */
    int386(0x18, &regs, &regs);

    /* 3. 启用图形显示层 (AH=0x40) */
    regs.h.ah = 0x40;
    regs.h.al = 0x01;   /* AL=0x01 图形层 */
    regs.h.bh = 0x00;   /* BH=0x00 */
    int386(0x18, &regs, &regs);

    /* 4. 强制 analog ext 模式 (NP2kai) */
    outb(0x6A, 0x21);

    /* 5. 逐 bank 清 VRAM */
    for (bank = 0; bank < 8; bank++) {
        *PEGC_BANK_PORT = (uint16_t)bank;
        for (i = 0; i < 32768; i++)
            ((volatile uint8_t *)0xA8000L)[i] = 0;
    }
}
```

> **修复记录**（2026-06-19）：`INT 18h AH=0x30` 和 `AH=0x40` 调用前，`regs.h.al` 和 `regs.h.bh` 被显式清零。NP2kai 的 `bios18.c` 依赖这两个寄存器选择显示层和子功能；若上层调用残留脏值，会导致 BIOS 调用被忽略，显示模式设置失败。

| 步骤 | 代码 | 作用 |
|------|------|------|
| 1 | `*PEGC_MODE_PORT = 0x00` | PEGC packed-pixel 模式（必须最先） |
| 2 | `*PEGC_VRAM_ENABLE = 0x01` | VRAM 窗口使能 |
| 3 | `INT 18h AH=30h (AL=0x08, BH=0x00)` | 640×400 256c 模式设置 |
| 4 | `INT 18h AH=40h (AL=0x01, BH=0x00)` | 启用图形显示层 |
| 5 | `outb(0x6A, 0x21)` | 强制 analog ext (NP2kai) |
| 6 | VRAM bank 清除 | 消除启动残留像素 |

### 3.2 为什么用 CRT BIOS 而非端口写

- CRT BIOS (`int 0x18`) **同时初始化文本层 + 图形层 + 调色板**
- 端口直接写 GDC 寄存器（`outb 0xA0/0xA2`）仅配图形 GDC，文本层未初始化
- NP2kai 的文本层在未初始化状态下会与图形层冲突（强制显示残留字符）
- `outb(0x6A, 0x21)` 是 NP2kai 特有后备，真机 PC-98 上不需要（FC9846 BIOS 的 INT 18h AH=30h 已包含 EGCC/VGA 初始化）

### 3.3 PC-98 显示模式表（AH=42h 传统模式，参考用）

> 当前引擎用 `INT 18h AH=30h`（256c 扩展）。以下 AH=42h 模式仅作参考。

| CX 值 | 分辨率 | 颜色 | 用途 |
|-------|--------|------|------|
| `0xC0` | 640×400 | 16 色 | PC-98 标准图形模式 |
| `0xC1` | 640×200 | 16 色 | 低分辨率（行倍关） |
| `0x40` | 640×400 | 单色 | 纯图形（无文本层） |

### 3.4 INT 18h AH=30h 256c 模式表

| AL 值 | 分辨率 | 颜色 | 说明 |
|-------|--------|------|------|
| `0x04` | 640×480 | 256 色 | 标准 VGA 模式 |
| `0x08` | 640×400 | 256 色 | **当前引擎使用** — PEGC bank-switched packed-pixel |
| `0x0C` | 640×480 | 256 色 | 31kHz 高分辨率（部分 PC-9821 支持） |

## 4. GDC 寄存器配置

### 4.1 `gdc_init()` — 完整寄存器序列

**文件**：`core/plat/gdc.c`

```c
void gdc_init(void)
{
    /* 关闭图形以便配置 */
    gfx_param(GDC_MODE1_DISPLAY_OFF);        // 0x0E
    gfx_cmd(GDC_CMD_START);                  // 0x0D

    /* R00: 水平总周期 = 80 字符 - 1 */
    gfx_param(0x4F);  gfx_cmd(0x40);
    /* R01: 水平显示 = 80 字符 */
    gfx_param(0x4F);  gfx_cmd(0x41);
    /* R02: 水平同步位置 */
    gfx_param(0x53);  gfx_cmd(0x42);
    /* R03: 同步宽度 + 垂直总周期低位 */
    gfx_param(0x07);  gfx_cmd(0x43);

    /* R04: 显示起始地址 = 0 */
    gfx_param(0x00); gfx_param(0x00); gfx_cmd(0x44);

    /* R06: 显示行数 = 400 */
    gfx_param(0x8F); gfx_param(0x01);
    gfx_cmd(GDC_CMD_ZOOM);                  // 0x46

    /* R07: 间距 = 40 字 */
    gfx_param(40);  gfx_cmd(GDC_CMD_PITCH); // 0x47

    /* R11: 隐藏光标 */
    gfx_param(0x00); gfx_param(0x10); gfx_param(0x10);
    gfx_cmd(GDC_CMD_CSRFORM);               // 0x4B

    /* 模式 2: 16 色 + 控制位 4 */
    gfx_param(0x11);  gfx_cmd(GDC_CMD_ZOOM);// 0x46

    /* 模式 1: 彩色 + 行加倍 + 显示开 + 显示使能 */
    gfx_param(0x8F);  gfx_cmd(GDC_CMD_START);// 0x0D

    /* CRT 显示模式寄存器：触发 NP2kai CRTC→MEMM_VRAM */
    outb(0x6A, 0x00);
}
```

### 4.2 GDC 端口一览

| 端口 | 方向 | 用途 |
|------|------|------|
| `0xA0` | W/R | 图形 GDC 参数 / 状态 |
| `0xA2` | W/R | 图形 GDC 命令 / 模式 1 回读 |
| `0x60` | W/R | 文本 GDC 参数 / 状态 |
| `0x62` | W/R | 文本 GDC 命令 |
| `0x6A` | W | CRT 显示模式寄存器 |
| `0xA4` | W | GDC 显示页选择（0 或 1） |

### 4.3 GDC 命令码

| 命令 | 值 | 参数 | 用途 |
|------|-----|------|------|
| `START` | `0x0D` | 1（模式设定值） | 启动显示 / 应用模式 1 |
| `STOP` | `0x0C` | — | 停止显示 |
| `CSRFORM` | `0x4B` | 3（上/下/底） | 光标形状 |
| `PITCH` | `0x47` | 1（字数） | 每行像素字数 |
| `ZOOM` | `0x46` | 2（行数 lo/hi） | 显示行数 / 模式 2 |
| 寄存器设置 | `0x40-0x4F` | 1-3 | 设 R00-R11 等内部寄存器 |
| CURL | `0x4E` | 2（X lo/hi） | 设光标 X 坐标 |
| CURH | `0x4F` | 1（Y） | 设光标 Y 坐标 |
| WDAT | `0x20` | — | 开始像素写入模式 |

### 4.4 GDC 模式 1 / 模式 2 位定义

**模式 1**（`outb 0xA2, mode1` after `outb 0xA0; outb 0xA2, 0x0D`）：

| 位 | 值 | 含义 |
|----|-----|------|
| 0 | `0x01` | 文本显示启用 |
| 1 | `0x02` | 彩色/单色（1=彩色） |
| 3 | `0x08` | 行加倍（0=关 1=开） |
| 3-0 | `0x0F` | 组合：显示开 (`0x0F`) / 显示关 (`0x0E`) |
| 7 | `0x80` | 显示使能（直接写模式） |

**当前值**：`0x8F` = 彩色 + 行加倍 + 显示开 + 显示使能

**模式 2**（`outb 0x6A, mode2`）：

| 位 | 值 | 含义 |
|----|-----|------|
| 0 | `0x01` | 16 色（analog）/ 8 色（digital） |

**当前值**：`0x00` = 8 色 digital 模式（与 `gdc_init` 中的 `0x11` 配合生效）

## 5. 调色板

### 5.1 `hal_set_palette()`

**文件**：`core/plat/hal_pc98.c`

PC-98 256 色模拟调色板端口（VM 内，NP2kai 通过 `gdc.analog & 2` 检测 analog 模式）：

```c
void hal_set_palette(int idx, uint8_t r, uint8_t g, uint8_t b)
{
    outb(0xA8, (uint8_t)idx);         // 选择索引 (0–255)
    outb(0xAA, g);                     // G 分量（8-bit, 0–255）
    outb(0xAC, r);                     // R 分量（8-bit, 0–255）
    outb(0xAE, b);                     // B 分量（8-bit, 0–255）
}
```

> **注意**：256 色 PEGC 模式下，端口顺序为 G→R→B（PC-98 约定），分量直写 8-bit 值。NP2kai 内部经 `pal_make9821()` 将 `anareg[48+]` 的 8bpc 值转换为 RGB565 用于显示。
>
> **RGB565 精度损耗**：NP2kai 的 16-bit framebuffer 使用 RGB565（R=5b, G=6b, B=5b），R 通道仅 32 级（G 通道 64 级），导致肤色高光区出现偏青趋势（G/R 比在显示管线中上升约 3-6%）。
>
> **补偿措施**：构建管线 `pack_images.py:build_shared_palette()` 在 PIL 中位切割后对肤色范围（R>200, 160<G<245, 120<B<220, G<R）做预补偿：**R+4, G-2**，降低 G/R 比约 2-4%。此补偿仅针对 NP2kai 模拟器，**实机 PEGC 8bpc DAC 无此问题**。

| 端口 | 方向 | 含义 |
|------|------|------|
| `0xA8` | W | 调色板索引（0-255） |
| `0xAA` | W | 绿色分量（8bpc） |
| `0xAC` | W | 红色分量（8bpc） |
| `0xAE` | W | 蓝色分量（8bpc） |

### 5.2 当前注册的颜色（引擎初始化阶段）

| 索引 | G | R | B | 颜色 | 用途 |
|------|---|---|---|------|------|
| 0 | `0x00` | `0x00` | `0x00` | 黑 | 对话框背景 |
| 7 | `0xFF` | `0xFF` | `0xFF` | 白 | 文字 + 对话框边框 |
| 248 | `0x00` | `0x00` | `0x00` | 黑 | 对话框底色（运行时动态改色） |

> 其他索引（1–6, 8–247, 249–255）在初始化阶段未设置，由 `image_set_palette()` 在 `bg` 命令加载背景 MAG 时动态填充。索引 249–255 为 UI 保留（见 B11 §12），其中 250/251 由菜单运行时使用，图像数据永不占用这些索引。

**Agent 强制规则**：任何新增 UI 元素必须使用保留 palette 索引（≥248）。不得修改引擎核心索引（0, 1, 2, 3, 7, 15, 248）的色值，否则会导致场景图片颜色错乱。

### 5.3 [已归档] NP2kai 数字调色板默认值（16c 模式参考）

> 以下描述针对 16c 数字调色板模式（当前引擎使用 256c analog，不适用）。

模拟调色板端口写入后，NP2kai 通过 `gdc.analog` 标志判断使用 digital 还是 analog 表。默认 digital 表 `deftbl = {0x04, 0x15, 0x26, 0x37}` 输出：

| 索引 | 值 | R | G | B | 颜色 |
|------|-----|---|---|---|------|
| 0 | `0x04` | 0 | 0 | 0 | 黑 |
| 1 | `0x15` | 0 | 0 | 170 | 蓝 |
| 7 | `0x37` | 170 | 170 | 170 | 灰白 |
| 15 | `0x37` | 170 | 170 | 170 | 高亮白 |

## 6. VRAM 布局

> **2026-06-12 更新**：引擎当前使用 **PEGC 640×400 256 色 packed-pixel 模式**，VRAM 写入通过 bank 窗口（非 4-plane）。以下 §6.1-6.3 为 4-plane 旧布局参考，**当前不活跃**。256c 实际布局见 §6.4。

### 6.1 [归档] 四平面结构（16c 模式，不再活跃）

PC-98 传统图形 VRAM 由 4 个独立**位平面**组成，每平面 1bpp × 640×400 = 32,000 字节（32KB）。

```
VRAM 图形平面 (linear, 保护模式):
┌──────────┬──────────┬──────────┬──────────┐
│  Plane B  │  Plane R  │  Plane G  │  Plane E  │
│  0xA8000  │  0xB0000  │  0xB8000  │  0xE0000  │
│  32KB     │  32KB     │  32KB     │  32KB     │
│  蓝色分量  │  红色分量  │  绿色分量  │  强度分量  │
└──────────┴──────────┴──────────┴──────────┘
```

### 6.2 [归档] 平面基址定义（16c 模式，不再活跃）

```c
#define VRAM_B  ((volatile uint8_t *)0xA8000L)
#define VRAM_R  ((volatile uint8_t *)0xB0000L)
#define VRAM_G  ((volatile uint8_t *)0xB8000L)
#define VRAM_E  ((volatile uint8_t *)0xE0000L)
```

### 6.3 [归档] 4-plane 地址计算（16c 模式，不再活跃）

每平面内，一个字节编码 8 个相邻水平像素：

```
字节偏移 = y * 80 + (x >> 3)       // y∈[0,399], x∈[0,639]
像素位   = 0x80 >> (x & 7)          // 第 7 位 = 最左像素
```

### 6.4 PEGC 256c packed-pixel 布局（当前活跃）

256 色模式下，VRAM 通过 **32KB bank 窗口**（0xA8000–0xAFFFF）以 packed-pixel 格式访问。每个字节 = 1 个像素（0-255 索引值）。全帧 640×400 = 256,000 字节，拆为 8 个 bank（每 bank 32KB）。

```
PEGC Bank 窗口:
┌──────┬──────────────┬──────────────────────────────┐
│ Bank │ 端口 0xE0004  │ 窗口 0xA8000-0xA7FFF 映射范围 │
├──────┼──────────────┼──────────────────────────────┤
│  0   │      0       │ vramex[0x00000..0x07FFF]     │
│  1   │      1       │ vramex[0x08000..0x0FFFF]     │
│  2   │      2       │ vramex[0x10000..0x17FFF]     │
│  3   │      3       │ vramex[0x18000..0x1FFFF]     │
│  4   │      4       │ vramex[0x20000..0x27FFF]     │
│  5   │      5       │ vramex[0x28000..0x2FFFF]     │
│  6   │      6       │ vramex[0x30000..0x37FFF]     │
│  7   │      7       │ vramex[0x38000..0x3FFFF]     │
└──────┴──────────────┴──────────────────────────────┘
```

**引擎侧定义**（`core/engine/render.c`）：

```c
#define PEGC_BANK  ((volatile uint16_t *)0xE0004L)
#define VRAM_WIN   ((volatile uint8_t  *)0xA8000L)
```

**写操作**：

```c
// 单像素
*PEGC_BANK = bank;              // 选 bank
VRAM_WIN[offset] = pixel;       // 写像素值 0-255

// 批量（按行切 bank，每 bank 一次端口写）
for each row y:
    addr = y * 640;
    while addr < (y+1) * 640:
        bank = addr >> 15;
        *PEGC_BANK = bank;
        chunk_end = min((y+1)*640, (bank+1)<<15);
        for i = 0 to chunk_end - addr:
            VRAM_WIN[addr & 0x7FFF] = pixel;
            addr++;
```

### 6.5 NP2kai 内 VRAM 路由（256c）

引擎的 `outb(0xE0004, bank); outb(0xA8000+off, pixel)` 在 NP2kai 中的路由：

```
outb(0xE0004, bank) → memvgaio_wr8()
  → vramop.mio1[0] = bank        PEGC bank 寄存器
outb(0xA8000+off, pixel) → VGAWR8 宏
  → vramex[(bank<<15) + off] = pixel   256c packed-pixel 缓冲
  → gdcs.grphdisp |= 5                 触发合成 (MAKE) + 使能 (ENABLE)
```

256 色 PEGC 模式下，VRAM 通过 **32KB bank 窗口**（0xA8000–0xAFFFF）以 packed-pixel 访问。引擎侧定义：

### 7.2 `pset()` — 单像素写入

```c
void pset(int x, int y, uint8_t color)
{
    int addr;
    if (x < 0 || x >= 640 || y < 0 || y >= 400) return;
    addr = y * 640 + x;
    bank_select(addr);
    VRAM_WIN[addr & (BANK_SZ - 1)] = color;
}
```

> **注**：`pset()` 函数已从引擎中移除（无调用者）。`video.c` 的调色板自检函数 `video_check_palette()` 使用 `hal_log()` + 静态 `video_puthex()` 而非直接调用 `serial_puts()` / `serial_puthex()`，确保位于 `core/engine/` 以外的 HAL 边界代码不绕过 `hal.h`。

**性能注意**：每像素 1 次 bank 端口写 + 1 次 VRAM 写。对于批量填充应使用按行分块的批量写入（见 §7.7）。

### 7.3 `fill_rect()` — 填充矩形

```c
void fill_rect(int x, int y, int w, int h, uint8_t color)
{
    int py, px, addr;
    for (py = 0; py < h; py++) {
        if (y + py >= 400) break;
        for (px = 0; px < w; px++) {
            if (x + px >= 640) break;
            addr = (y + py) * 640 + (x + px);
            *PEGC_BANK = (uint16_t)(addr >> 15);
            VRAM_WIN[addr & (BANK_SZ - 1)] = color;
        }
    }
}
```

### 7.4 `draw_rect()` — 描边矩形

```c
void draw_rect(int x, int y, int w, int h, int t, uint8_t color)
{
    int i;
    for (i = 0; i < t; i++) {
        fill_rect(x, y + i, w, 1, color);            /* 上边 */
        fill_rect(x, y + h - 1 - i, w, 1, color);    /* 下边 */
        fill_rect(x + i, y, 1, h, color);            /* 左边 */
        fill_rect(x + w - 1 - i, y, 1, h, color);    /* 右边 */
    }
}
```

| 参数 | 含义 |
|------|------|
| `x`, `y` | 左上角坐标 |
| `w`, `h` | 边框外尺寸（宽 × 高） |
| `t` | 边框线宽（像素） |
| `color` | 边框颜色 |

### 7.5 字形绘制（内部宏）

`draw_glyph_internal()` 是 `render.c` 内部静态函数，通过宏 `draw_ascii`/`draw_ascii_b`/`draw_cjk`/`draw_cjk_b` 包装。字形数据 32 字节（= 16 行 × 2 字节/行），每行 16-bit big-endian，MSB 对应第 0 列。ASCII 8×16 固定，CJK 16×16 固定。

### 7.6 `draw_text()` — UTF-8 字符串绘制

```c
int draw_text(const char *s, int byte_start, int x, int y,
              int max_width, int max_y, int bold, uint8_t color)
{
    int cx = x;
    const unsigned char *p = (const unsigned char *)s + byte_start;
    while (*p) {
        if (*p < 0x80) {
            const uint8_t *g = font_get_glyph(*p);
            if (g) {
                draw_ascii(g, cx, y, color);
                cx += 8;
            }
            p++;
        } else {
            int cp;
            if ((*p & 0xE0) == 0xC0 && p[1]) {
                cp = (*p++ & 0x1F) << 6;
                cp |= (*p++ & 0x3F);
            } else if ((*p & 0xF0) == 0xE0 && p[1] && p[2]) {
                cp = (*p++ & 0x0F) << 12;
                cp |= (*p++ & 0x3F) << 6;
                cp |= (*p++ & 0x3F);
            } else { p++; continue; }
            const uint8_t *g = cjk_get_glyph(cp);
            if (g) {
                draw_cjk(g, cx, y, color);
                cx += 16;
            }
        }
    }
    return -1;
}
```

- ASCII 字符：8×16 字形，等宽 8px
- CJK 字符（UTF-8 3 字节）：16×16 字形，等宽 16px
- 不自动换行；超出 640 像素会被 `pset()` 边界裁剪

### 7.7 批量写入优化

256 色模式下 VRAM 通过 **32KB bank 窗口**（0xA8000–0xAFFFF）访问，bank 由 `0xE0004` 端口选择。每个 bank 覆盖 32KB 连续像素，全帧 256 KB 共 8 个 bank。

**优化实现**：按行切割为 bank 内连续块，每块只写一次 bank 寄存器：

```c
for each row:
    while addr < end:
        bank     = addr >> 15
        bank_end = (bank + 1) << 15
        chunk    = min(end, bank_end)
        *PEGC_BANK = bank          // 1 次 bank 选择
        for i = 0 to chunk-addr:
            VRAM_WIN[offset + i] = pixel
```

**当前状态**：`vram_blit()` 和 `vram_blit_sprite()` 已实现按行分块。`fill_rect()`, `fill_rect_pattern()`, `draw_text()` 仍使用逐像素 bank 切换（当前场景下性能足够）。

### 7.8 VRAM Blit：`vram_blit()` — 全屏背景

```c
void vram_blit(const MagImage *img, int x, int y)
{
    int py, px, addr;
    for (py = 0; py < img->height && y + py < 400; py++) {
        for (px = 0; px < img->width && x + px < 640; px++) {
            addr = (y + py) * 640 + (x + px);
            *PEGC_BANK = (uint16_t)(addr >> 15);
            VRAM_WIN[addr & (BANK_SZ - 1)] =
                img->pixels[py * img->width + px];
        }
    }
}
```

MAG 解码后的 `pixels[]` 值为 0–255 的 8-bit 调色板索引，**直接对应硬件调色板索引**——无需额外颜色映射。

### 7.9 Sprite Blit：`vram_blit_sprite()`

```c
void vram_blit_sprite(const MagImage *img, int x, int y,
                      uint8_t transparent_idx, int mirror, int clip_h)
{
    int py, px, addr, sx;
    uint8_t c;
    int max_h = (clip_h > 0 && clip_h < img->height) ? clip_h : img->height;
    for (py = 0; py < max_h && y + py < 400; py++) {
        for (px = 0; px < img->width && x + px < 640; px++) {
            c = img->pixels[py * img->width + px];
            if (c == transparent_idx) continue;
            sx = mirror ? (img->width - 1 - px) : px;
            addr = (y + py) * 640 + (x + sx);
            *PEGC_BANK = (uint16_t)(addr >> 15);
            VRAM_WIN[addr & (BANK_SZ - 1)] = c;
        }
    }
}
```

**关键设计点**：
- 透明像素**完全跳过** VRAM 访问——保留背景或对话框像素
- `transparent_idx` 引擎约定为 **索引 15**
- 水平翻转（`mirror=1`）：像素 X 坐标从右向左映射
- `clip_h` 限制绘制行数，防止 sprite 写入对话框区域

### 7.10 `fill_rect_pattern()` — 图案掩码填充

```c
void fill_rect_pattern(int x, int y, int w, int h,
                       const uint8_t pattern[8], uint8_t color)
{
    int px, py, addr;
    uint8_t byte;
    for (py = 0; py < h; py++) {
        byte = pattern[(y + py) & 7];
        for (px = 0; px < w; px++) {
            if (!(byte & (0x80 >> (px & 7))))
                continue;
            addr = (y + py) * 640 + (x + px);
            *PEGC_BANK = (uint16_t)(addr >> 15);
            VRAM_WIN[addr & (BANK_SZ - 1)] = color;
        }
    }
}
```

**设计要点**：
- 8×8 图案位图，pattern[0..7] 每字节对应一行，MSB 为最左像素
- 图案 bit=1 → 写覆盖色；bit=0 → 完全跳过 VRAM 访问
- 跳过像素不产生 VRAM 访问，性能节省 25%–75%

### 7.11 颜色常量（256c 模式参考）

### 9.1 `dialog_show()` — 当前 NB 实现

**文件**：`core/engine/nb_dialog.c`

```c
void dialog_show(const char *charname, const char *text)
{
    int mw = LAYER_DIALOG_W - LAYER_DIALOG_INDENT - LAYER_DIALOG_RIGHT_INDENT;

    if (dialog_state.text_offset < 0) {
        dialog_state.charname = charname;
        strncpy(dialog_text_buf, text, sizeof(dialog_text_buf) - 1);
        dialog_text_buf[sizeof(dialog_text_buf) - 1] = '\0';
        dialog_state.text = dialog_text_buf;
        dialog_state.text_offset = 0;
    }

    if (!layer_dialog_drawn()) {
        layer_dialog_open();      /* 首次：绘制对话框 + 保存 dialog_snapshot */
    } else {
        layer_dialog_snap();      /* 后续：更新 dialog_snapshot（防立绘覆盖） */
    }
    layer_dialog_restore();       /* 从快照恢复干净对话框 */

    if (dialog_state.charname)
        draw_text(dialog_state.charname, 0, /* 角色名头部，粗体 */
                  LAYER_DIALOG_X + LAYER_DIALOG_INDENT, LAYER_DIALOG_Y + LAYER_DIALOG_HEADER_Y,
                  mw, LAYER_DIALOG_BOTTOM, 1, PAL_WHITE);

    int next = draw_text(dialog_state.text, dialog_state.text_offset,
                         LAYER_DIALOG_X + LAYER_DIALOG_INDENT, LAYER_DIALOG_Y + LAYER_DIALOG_TEXT_Y,
                         mw, LAYER_DIALOG_Y + LAYER_DIALOG_TEXT_Y + 60, 0, PAL_WHITE);
    if (next >= 0) {
        dialog_state.text_offset = next;
        vm_flags &= (unsigned char)~VMFLAG_PROCESS;  /* 暂停等待翻页 */
    } else {
        dialog_state.text_offset = -1;
        dialog_state.text = NULL;
        vm_flags &= (unsigned char)~VMFLAG_PROCESS;
    }
}
```

### 10.1 图形合成：`makegrphex()`

**位置**：`/tmp/NP2kai/vram/makegrex.c:279-318`

引擎写入 `vramex[]`（通过 VGAWR8 宏）→ `makegrphex()` 读取并拷贝到 `np2_vram[]`：

```
VGAWR8 → vramex[] (packed-pixel 8bpp, bank 索引)
        │
        ▼ makegrphex(page, alldraw)
        │  读取 vramex[] @ GDC 滚动寄存器地址
        │  直接拷贝 32-bit 值 → np2_vram[]
        │
        ▼ np2_vram[0][y*640+x] = packed-pixel 8bpp 索引值
        │
        ▼ sdraw16p_2 → SDSETPIXEL(ptr, np2_pal16[pixel_idx + NP2PAL_GRPHEX])
        │
        ▼ 16bpp RGB565 pixbuf → 屏幕
```

### 10.2 调色板更新：`pal_make9821()`

**位置**：`/tmp/NP2kai/vram/palettes.c:494-498`

每帧 `pal_change()` 检测 `gdc.analog & 2`（`GDCANALOG_256`）后调用：

```c
if (gdc.analog & 2) {
    pal_make9821(gdc.anareg + (16 * 3));     // 从 anareg[48..] 读取 256×4 字节
    scrndraw_changepalette();
    return;
}

// pal_make9821 逻辑:
p = np2_pal32 + NP2PAL_GRPHEX;  // np2_pal32[200..455]
for (i=0; i<256; i++) {
    p[i].p.g = pal[i*4+0];      // Green
    p[i].p.r = pal[i*4+1];      // Red
    p[i].p.b = pal[i*4+2];      // Blue
}
// → np2_pal16[] from scrnmng_makepal16 (RGB565)
```

> **NP2kai 特有**：`scrnmng_makepal16` 将 `np2_pal32` 的 8bpc 值量化为 RGB565（R 截断到 5 位，G 到 6 位，B 到 5 位），再经 `(R5<<11)|(G6<<5)|B5` 组合为 16-bit 值。R 精度只有 32 级（G 有 64 级），导致偏青。构建管线在共享调色板中对肤色做了预补偿（R+4, G-2），见 §5.1 注意。

### 10.3 数据结构关键字段

| 字段 | 类型 | 含义 |
|------|------|------|
| `vramex[]` | `UINT8[0x80000]` | 512KB VGA VRAM 扩展，packed-pixel 数据 |
| `vramop.mio1[0]` | `UINT8` | PEGC bank 寄存器（低 4 位选 bank 0-7） |
| `np2_vram[0]` | `UINT8[640×480]` | 合成图形层（8bpp 索引） |
| `np2_pal32[NP2PAL_GRPHEX+i]` | `RGB32` | 256 色 8bpc 调色板（`NP2PAL_GRPHEX=200`） |
| `np2_pal16[NP2PAL_GRPHEX+i]` | `UINT16` | RGB565 调色板（由 `np2_pal32` 转换） |
| `np2_tram` | `UINT8[307200]` | 文本层（字符代码） |
| `sdraw.dirty[480]` | `UINT8[480]` | 逐行脏标志；0=跳过渲染 |
| `gdcs.grphdisp` | `UINT8` | 图形层标志（bit0=`GDCSCRN_MAKE`, bit2=`GDCSCRN_ENABLE`） |

### 11.3 常见问题排查

| 症状 | 可能原因 | 检查 |
|------|----------|------|
| 全黑屏 | NP2kai 补丁未应用（P1/P2/P3） | 检查 `grphdisp |= 5`、`gdc_analogext()`、port 6A 门控 |
| 全黑屏（补丁已应用） | `video_init()` 序列或 MMIO 缺失 | 确保 INT 18h AH=30h 后写 `PEGC_MODE_PORT=0` + `PEGC_VRAM_ENABLE=1` |
| 花屏/白线 | P3 缺失 → `GDCANALOG_256` 未置位 | `grep -n 'analogext' bios/bios18.c` 确认补丁 |
| 文字不显示 | `font_get_glyph()` 返回 NULL | 检查 FONT.DAT 存在于 HDI |
| 文字颜色错误 | 调色板未设置 | 检查 `hal_set_palette(7, 0xFF, 0xFF, 0xFF)` 是否调用 |
| 对话框不显示 | 未调用 `scene_draw_dialog()` | 确认场景中至少有一个 `text` 指令触发首次绘制 |
| 窗口僵死 (Wayland) | SDL Wayland 键盘独占 | 不设 `SDL_VIDEODRIVER=wayland` |
| 画面闪烁 | 全帧 dirty 强制逐行重绘 | 正常——当前设计的代价 |
| engine.exe 崩溃 | DOS4GW.EXE 缺失 | 确认根目录存在 |
