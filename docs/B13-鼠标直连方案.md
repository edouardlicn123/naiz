# B13 — PC-98 鼠标 8255 直连方案

## 1. 架构总览

鼠标通过 PC-98 系统板载 **8255 PPI**（并行接口）直接连接，无需外部 TSR（如 QMOUSE）。
引擎通过 `inp()`/`outp()` 端口 I/O 在 DOS/4GW ring 1 保护模式下直接轮询硬件。

```
引擎 (ring 1)
  │
  ├─ inp(0x7FD9)  ← 按钮 + 数据半字节
  ├─ outp(0x7FDD) → 控制（HC/SX/SH/IN）
  └─ outp(0x7FDF) → 8255 模式设置
       │
       └─ 8255 PPI
            │
            └─ 鼠标计数器 / 按钮
```

### 端口映射

| 端口 | 方向 | 用途 |
|------|------|------|
| `0x7FD9` | 读 | 按钮状态(bit7-6) + 数据半字节(bit3-0) |
| `0x7FDD` | 写 | 控制：HC(7)/SX(6)/SH(5)/IN(4) |
| `0x7FDF` | 写 | 8255 模式设置 (0x93) |

## 2. 硬件协议 — 4 步握手

鼠标内部有 X/Y 相对位移累加器。HC↑ 将当前值锁存到读取寄存器，读取完成后 HC↓ 释放。

```
outp(0x7FDD, HC | IN)         // lock + 选择 X 低半字节
inp(0x7FD9) → X_low_nibble

outp(0x7FDD, HC | SH | IN)    // 选择 X 高半字节
inp(0x7FD9) → X_high_nibble

outp(0x7FDD, HC | SX | IN)    // 选择 Y 低半字节
inp(0x7FD9) → Y_low_nibble

outp(0x7FDD, HC | SX | SH | IN) // 选择 Y 高半字节
inp(0x7FD9) → Y_high_nibble

outp(0x7FDD, IN)              // 释放锁存
```

各半字节组合为有符号 8-bit 值：

```
dx = (X_high << 4) | X_low
dy = (Y_high << 4) | Y_low
if (dx & 0x80) dx |= 0xFFFFFF00  // 符号扩展
if (dy & 0x80) dy |= 0xFFFFFF00
```

## 3. 按钮编码

PORTA 读入值 bit7-6 为按钮，active low：

| bit7 | bit6 | 含义 |
|------|------|------|
| 0 | 0 | 双键按下 |
| 0 | 1 | 左键按下 |
| 1 | 0 | 右键按下 |
| 1 | 1 | 无按键 |

引擎内部使用 active-high bit0(left)/bit1(right)：

```c
mouse_buttons_now = 0;
if (!(raw & 0x80)) mouse_buttons_now |= 1;  // left
if (!(raw & 0x40)) mouse_buttons_now |= 2;  // right
```

## 4. 死区滤波

由于鼠标传感器噪声，静止时可能产生 ±1~2 mickey 的虚假位移。
`mouse_update()` 中对原始 dx/dy 做死区滤波，`|v|<3` 时视为 0：

```c
if (dx > -3 && dx < 3) dx = 0;
if (dy > -3 && dy < 3) dy = 0;
```

## 5. 软件光标

PC-98 GDC 硬件光标仅支持 16×16 2 色简单图案。本引擎使用 24×24 白底黑手形软件光标。

### 实现机制

```
每帧 mouse_draw_cursor():
  1. 如果光标未移动且缓存有效 → 跳过（优化，消除静止闪烁）
  2. 从 save_buffer 恢复旧位置的干净背景
  3. 读取新位置的 VRAM 内容到 save_buffer
  4. 在新位置绘制 24×24 手形光标
```

### 缓存失效

所有修改 VRAM 的函数（`layer_dialog_open`、`layer_sprite_show`、`cmd_bg` 等）在写入前调用 `mouse_invalidate_cursor()`，设 `valid=0`。下一次 `mouse_draw_cursor()` 重新走 save+draw 流程。

`mouse_invalidate_cursor()` **不写回** save_buffer 到 VRAM，避免恢复过期背景（改为由后续场景绘制自然覆盖旧光标像素）。

### 潜在问题

- 光标移动时 `vram_write`(restore) → `vram_read`(save) → `draw_cursor_shape`(draw) 的 bank 切换可能在活动显示区造成 artifact
- 建议改进：VBLANK 同步（查询 GDC 垂直回扫状态，在 VBLANK 期内完成所有光标 VRAM 操作）

## 6. 数据流

```
main 循环每帧:
  mouse_update()              // 8255 4 步握手 → dx, dy
    ↓
  累加: mouse_x_now += dx    // 绝对坐标
  钳位: [0, 639] × [0, 399]
  按钮边缘检测 → FIFO
    ↓
  nb_process() / text_animate()
    ↓
  mouse_draw_cursor()         // 软件光标绘制（帧末）
```

## 7. 设计约束

- **无 QMOUSE.COM 依赖** — AUTOEXEC.BAT 不再加载 QMOUSE
- **无 INT 33h** — 不使用 `int386()` 中断调用
- **无 TSR** — 不需要任何驻留程序
- **DOS/4GW ring 1 I/O** — IN/OUT 指令在保护模式下直接执行，无需 DPMI 实模式转发
- **8255 模式** — `outp(0x7FDF, 0x93)`：PORTA=input, PORTB=input, PORTC_high=output, PORTC_low=input
- **中断屏蔽** — `IN=1` 抑制 IRQ 0x0d，纯轮询

## 8. NP2kai 系统端口绝对坐标（P5 补丁）

NP2kai 有专有 NP2 系统端口协议（0x7ED/0x7EF），用于模拟器与客户机之间的信息交换。P5 补丁利用此协议添加**鼠标绝对坐标** I/O 端口。

### 8.1 端口映射

| 端口 | 方向 | 用途 |
|------|------|------|
| `0x7ED` | 写 | 模式选择：1=命令模式, 0=数据模式 |
| `0x7EF` | 写 | 命令字符串（命令模式）或数据（数据模式） |
| `0x7EF` | 读 | 输出字符串（数据模式） |
| `0x7E0` | 读 | X 坐标低字节 |
| `0x7E1` | 读 | X 坐标高字节 |
| `0x7E2` | 读 | Y 坐标低字节 |
| `0x7E3` | 读 | Y 坐标高字节 |

### 8.2 检测 + 坐标读取协议

```c
/* 检测 NP2kai */
outb(0x7ED, 1);                     // 进入命令模式
outb(0x7EF, 'N'); outb(0x7EF, 'P'); outb(0x7EF, '2');  // 发送 "NP2"
outb(0x7ED, 0);                     // 回到数据模式
inb(0x7EF); inb(0x7EF); inb(0x7EF); // 读回 "NP2\0"

/* 读绝对坐标 */
int x = inb(0x7E0) | (inb(0x7E1) << 8);
int y = inb(0x7E2) | (inb(0x7E3) << 8);
```

### 8.3 坐标缩放

`np2panel.cpp` 的 `OnMouseMove` 中将 wx 面板像素坐标缩放到 640×400 屏幕坐标，并钳位到有效范围：

```c
wxSize sz = GetClientSize();
int sx = pos.x * 640 / sz.GetWidth();
int sy = pos.y * 400 / sz.GetHeight();
// 钳位 [0,639] × [0,399]
```

> **OnMouseMove 不再调用 `WarpPointer()`**。NP2kai 原版为支持相对模式，每次
> 移动后把宿主指针 warp 回窗口中心；在 Deepin 的 dde-kwin 合成器上，这个 warp
> 被重投递为一系列非零 delta 的合成 motion 事件，被当成真实移动拉回光标，
> 导致虚拟鼠标被限制在窗口中心小区域。改为去掉 warp、`m_lastMousePos = pos`，
> 宿主指针与模拟屏 1:1 跟随（窗口边缘 = 模拟屏边缘）。仅在 `CaptureMouse()` 捕获
> 瞬间保留一次性 warp 到中心作为初始化。修复记录见
> `devdocs/70-deepin鼠标中央限制问题诊断与修复.md`。

### 8.4 依赖

- NP2kai（非其他模拟器或实体硬件）
- P5 补丁 `tools/np2kaipatch/05-wx-mouse-abspos.patch`（重编译后生效；含去 warp 修改，需基于 `wx_alpha` 分支重新编译，见 `docs/B91-构建环境与参考速查.md`）

### 8.5 非 NP2kai 平台行为

端口 0x7E0-0x7E3 和 0x7ED/0x7EF 在非 NP2kai 平台上未映射：
- `inb()` 返回 0xFF（浮空总线）
- `outb()` 被静默忽略
- 检测函数 `mouse_np2_detect()` 返回 0，引擎自动回退到 INT33 或 8255 路径

## 9. 三路优先级

```c
// mouse_init() 中依次检测
mouse_8255_init();             // 始终执行
mouse_int33_detect();          // NP2kai 检测前，用作回退
mouse_np2kai = mouse_np2_detect(); // 优先路径

// mouse_update() 中按优先级选择
if (mouse_np2kai) {
    // 路径 1: NP2 系统端口绝对坐标（最高优先级）
    mouse_np2_getpos(&x, &y);  // 0x7E0-0x7E3
    mouse_read_8255(..., &btn); // 仅读按钮状态
} else if (mouse_int33_available) {
    // 路径 2: INT33h 绝对坐标（中优先级）
    mouse_int33_asm(0x0003, ...);
} else {
    // 路径 3: 8255 增量（回退）
    mouse_read_8255(&dx, &dy, &btn);
    // 死区 → 帧限幅 → 累加 → 方向滤波 → 校准 → recenter
}
```

## 10. 平台兼容

| 平台 | 8255 | NP2 端口 | INT33 | 驱动路径 |
|------|------|----------|-------|---------|
| NP2kai (P5 已装) | ✓ | ✓ | ✗ | NP2 端口（无漂移） |
| NP2kai (无 P5) | ✓ | ✗ | ✗ | 8255 回退（有漂移） |
| 实机 PC-98 | ✓ | ✗ | ✓（有 QMOUSE） | INT33（预期无漂移） |
| 其他模拟器 | ✓ | ✗ | 视情况 | 8255 回退 |
