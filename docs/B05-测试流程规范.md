# 测试流程规范

## 1. 概述

Naiz 引擎的测试全流程为：**编译 → 注入 → 模拟器运行 → 日志提取 → 验证**。
本文档定义各环节的标准操作和验证方法。

### 数据流

```
projects/<name>/
       │
       ▼ wcl386 编译（Open Watcom v2.0）
       │
       ▼ makegame.sh build → 数据文件
games/<name>/engine.exe
       │
       ▼ makegame.sh make → 注入 HDI
disks/<name>.hdi
       │
       ▼ makegame.sh test → NP2kai (wxnp21kai)
hal_log() → COM1 串口输出（9600 8N1）
       │
       ▼ makegame.sh test --serial → PTY 管道
tools/diag/np2kai_serial.py → 串口日志
```

---

## 2. 测试级别

### 2.1 单元测试（宿主机）

引擎代码使用 Open Watcom wcl386 交叉编译（目标 DOS/4GW），宿主机上无法直接运行。
工具链（`tools/naiz_img/`）的单元测试通过 Python 直接执行：

```bash
# 验证 FAT 解析
python3 -c "
from naiz_img import open_image
from naiz_img.fat import NAIZFatFS
img = open_image('tools_commercial/base_msdos5_scsi_48m_clean.hdi')
fs = NAIZFatFS(img)
assert fs.fat_type in (12, 16)
print('FAT fs OK:', fs.fat_type, 'clusters')
"

# 遍历文件验证
python3 -c "
from naiz_img import open_image
from naiz_img.fat import NAIZFatFS
img = open_image('tools_commercial/base_msdos5_scsi_48m_clean.hdi')
fs = NAIZFatFS(img)
for path, e in fs.walk():
    if path.upper() == '/IO.SYS':
        print('IO.SYS found')
        break
"
```

### 2.2 冒烟测试（engine.exe）

验证引擎能在 DOS 下启动并正确返回：

```bash
# 使用 test_hang.c（最小退出测试）
cd projects/demo-a2 && make clean && make

# 检查 DOS/4GW LE 格式（Open Watcom 生成）
python3 -c "
import struct
with open('games/demo-a2/engine.exe','rb') as f:
    e=f.read()
# Open Watcom 生成 MZ stub + LE body，MZ 头指向 LE 入口
mz_offset = struct.unpack_from('<H',e,0x08)[0] * 16
print(f'MZ header at offset 0x{mz_offset:x}, LE body present')
# 检查 DOS4GW.EXE 签名（引擎依赖）
with open('tools_commercial/dos_system/DOS4GW.EXE','rb') as f:
    d=f.read()
print(f'DOS4GW.EXE: {len(d)} bytes')
"
```

### 2.3 集成测试（NP2kai）

完整端到端测试：编译 → 注入 → 模拟器运行 → 串口验证。

#### 标准流程

```bash
# 1. 编译
make -C core clean all

# 2. 构建游戏数据 + 注入 HDI
makegame.sh build demo-a2
makegame.sh make demo-a2

# 3. 运行 NP2kai（带串口）
makegame.sh test demo-a2 --serial

# 4. 查看串口日志
cat /tmp/serial.log
```

#### 通过标准

| 检查点 | 方法 | 预期 |
|--------|------|------|
| LE 格式正确 | python | MZ stub + LE body 存在 |
| NP2kai 不崩溃 | 无 `interrupt: num = 0x06` | 模拟器正常运行 |
| 串口输出 | `--serial` 有输出 | 含 "Pal chk OK" 等标记 |
| 画面显示 | 截图 | 查看对话框 + 立绘 + 背景 |

## 4. 测试工具

### makegame.sh test

```bash
./makegame.sh test                # 交互选择 HDI
./makegame.sh test demo-a2        # 直接运行 demo-a2
```

内部调用 `install_env.py` 的 `cmd_test_hdi()`：

1. 生成 TOML 配置（`SCSIHDD0` 指向所选 HDI）
2. 复制 BIOS/Font ROM 到配置目录
3. 直接启动 wxnp21kai
4. 记录日志到 `logs/test_<game>_<timestamp>.log`

### makegame.sh test --serial

串口输出捕获：

```bash
makegame.sh test demo-a2 --serial
# 自动启动 wxnp21kai + PTY 串口管道
# 输出: /tmp/serial.log
```

### diag/check_palette（已并入 naiz_lib）

调色板一致性校验由 `naiz_lib/image_dat.verify_shared_palette()` 承担（`pack_images.py` 构建时自动执行）：

```python
from naiz_lib import image_dat
errors = image_dat.verify_shared_palette(img)
```

## 5. 常见问题诊断

| 症状 | 可能原因 | 排查方法 |
|------|----------|----------|
| UD 异常 (int 0x06) | DOS4GW 或 VEM486 缺失 | 检查 CONFIG.SYS 含 VEM486，根目录含 DOS4GW.EXE |
| 黑屏无反应 | BIOS/核心不匹配 | 确认使用 IA32 核心 + PC-9821 BIOS |
| 键盘卡死 | Wayland 输入抓取 | `SDL_VIDEODRIVER=x11` |
| 日志为空 | 未调用 `log_close()` | 确认退出前 flush + close |
| 无 C: 盘 | SASI 未启用 | 确认 `SUPPORT_SASI` 已定义 |
| HDI 无法启动 | IO.SYS 不在根目录第一 | 用 `--list-files` 检查 |

## 6. 快速参考

```bash
# 完整测试循环
cd ~/naiz/projects/demo-a2 && make clean && make && \
cd ~/naiz && ./makegame.sh make demo-a2 && \
./makegame.sh test demo-a2

# 仅注入 HDI
./makegame.sh make demo-a2

# 仅启动模拟器
./makegame.sh test demo-a2

# 提取日志
python3 -m tools.naiz_img.inject --game demo-a2 --extract DEMO-A1/ENGINE.LOG

# 检查 MZ 头
# Open Watcom 无 objdump；用 python 检查 LE 头部
python3 -c "
with open('games/demo-a2/engine.exe','rb') as f:
    e=f.read()
mz_off = (e[0x08] | (e[0x09]<<8)) * 16
# LE signature at offset mz_off
print('LE' if e[mz_off:mz_off+2]==b'LE' else 'Not LE')
"
```
