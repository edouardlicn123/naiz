# B15 — 图层渲染与换装机制

> **状态**：活跃维护（2026-06-27：术语更新 op_bgload→bg、op_text→dialog_show、SpriteReg→SpriteEntry、scene_init→nb_load）。
> **创建**：2026-06-12（原 C04）/ 2026-06-18 迁入 B 类
> **依赖**：`B02-显示管线规范.md`（VRAM 布局、图元函数）、`B11-MAG图片加载与显示规范.md`（MAG 格式）、`B12-VRAM渲染策略.md`（四趟渲染）、`C03-立绘与角色.md`（200×400 立绘标准）
>
> 本文定义 `scene_layers.{c,h}` 模块的完整设计——对话框状态机、背景快照、精灵注册表、换表情/换装/换位置的裁剪策略、对话框样式底层编码、惰性截图机制、clean reset 与 hideall。

---

## 1. 概述

### 1.1 解决的问题

PC-98 只有单层 VRAM，所有像素共享同一块 packed-pixel 缓冲区。实现"立绘在对话框之下"和"换表情不重绘对话框"需要一套统一的调度层。

### 1.2 核心思想

```
┌──────────────────┐
│  精灵注册表       │ ← 跟踪每个精灵的 id/位置/mirror
├──────────────────┤
│  bg_snapshot     │ ← 256KB 全屏背景快照（bgload 时保存）
├──────────────────┤
│  bg_dialog_snapshot    │ ← 55KB 对话框区域纯背景截图（bgload 时捕获）
├──────────────────┤
│  dialog_snapshot  │ ← 55KB 对话框 PAT75+背景+立绘（无文字）
├──────────────────┤
│  dialog_drawn    │ ← 0/1 标志：对话框是否已绘
├──────────────────┤
│  dialog_dirty    │ ← 0/1 标志：需在下次 dialog_show 前重建 snapshot
├──────────────────┤
│  决策分发         │ ← show / face / replace / hide 自动选择策略
└──────────────────┘
```

## 2. 对话框样式底层实现

### 2.1 全局变量

```c
unsigned char g_dialog_style = 0;   /* SOLID_BLACK */
```

### 2.2 运行时切换

```
opcode 0x31 → g_dialog_style = operand (uint8)
```

`dlgstyle` 只改变 `g_dialog_style` 的值，**不重绘现有对话框**。若需立即生效，应在新行打印之前调用。可用 style 值 0-9。

### 2.3 与 `bg` 的交互

```
顺序（固定）：
1. bg(id)              → vram_blit 全屏新背景
2. if !dialog_drawn      → layer_capture_bg_dialog() 截纯背景对话框区
3. layer_capture_bg()   → 保存全屏快照
4. (之后首次 dialog_show) → layer_dialog_open() 按当前 g_dialog_style 绘制对话框
```

### 2.4 调制色板

所有样式共用 palette 248 作为对话框底色。引擎通过 `dlg_update_palette()` 在 `dlgstyle` 切换或 `bg` 后动态改色：

```c
static const uint8_t DIALOG_COLORS[5][3] = {
    {0x00, 0x00, 0x00},   /* 0: black   */
    {0x00, 0x00, 0xFF},   /* 1: blue    */
    {0x80, 0x00, 0x00},   /* 2: dark red */
    {0x00, 0x80, 0x00},   /* 3: green   */
    {0x80, 0x00, 0x80},   /* 4: purple  */
};
```

样式判断：
- 抖动/实心：`g_dialog_style & 1`（1=抖动，0=实心）
- 颜色索引：`g_dialog_style >> 1`（0-4）

### 2.5 调色板保护

| 索引 | 默认色 | 用途 |
|------|--------|------|
| 7 | `#FFFFFF` 白 | 文字、边框 |
| 15 | `#000000` 黑 | 精灵透明色 |
| **248** | 动态 | 对话框底色（由 DIALOG_COLORS 决定） |
| 250–251 | 白/黄 | 菜单文字 |

### 2.6 边框

边框始终保持 2px 白实线，不随样式变化。

## 3. API 参考

### 3.1 生命周期

```c
void layer_init(void);
```
`nb_init()` → `layer_init()` 时调用。释放 `bg_snapshot`、`dialog_snapshot`、`bg_dialog_snapshot`，清空精灵注册表，`dialog_drawn=0`, `dialog_dirty=0`。

```c
void layer_capture_bg(void);
```
`cmd_bg()` 内 `vram_blit` 之后调用。申请 256KB 缓冲区，`memcpy` 全屏 VRAM 到 `bg_snapshot`。重置 `dialog_drawn=0`、`dialog_dirty=0`。

```c
void layer_capture_bg_dialog(void);
```
捕获对话框区域 [80,280,480,115] 的纯背景到 `bg_dialog_snapshot`（55KB）。仅在 `bg()` 执行且对话框尚未显示时调用（`dialog_drawn==0`），否则跳过。

### 3.2 对话框

```c
void layer_dialog_open(void);
```
首次 `dialog_show()` 时调用（`dialog_drawn==0`）。执行 `scene_draw_dialog()` 绘制全对话框（PAT75 + 白边），随后 `vram_read()` 截图到 `dialog_snapshot`，`dialog_drawn=1`。

```c
void layer_dialog_refresh(void);
```
换装/换位置后调用。在现有 VRAM 上直接重绘对话框底色 + 白边 + 当前文字，覆盖精灵延伸入对话框区域的像素。设置 `dialog_dirty=1`。

```c
void layer_dialog_restore(void);
```
从 `dialog_snapshot` 写回 VRAM（无条件写），恢复无文字的干净对话框。每次 `dialog_show()` 调用。

```c
void layer_dialog_snap(void);
```
惰性截图函数。仅在 `dialog_dirty==1` 时执行：清对话区 → 重绘精灵 → `dialog_refresh` → 更新 `dialog_snapshot`。`dialog_dirty==0` 时直接返回（no-op）。

```c
void layer_dialog_hide(void);
```
`bg(hidedialog)` 调用。从 `bg_dialog_snapshot` 写回对话框区域（恢复纯背景），重置 `dialog_drawn=0`、`dialog_dirty=0`。

### 3.3 精灵操作

```c
void layer_sprite_show(int sprite_id, int asset_id, int x, int y, int mirror);
```
初始化阶段使用（`dialog_drawn==0`）。全幅 200×400 绘制，同时记入精灵注册表。无裁剪，无背景恢复。
`sprite_id` 为精灵注册表 ID（NB 解释器中传角色 ID），`asset_id` 为 IMAGE.DAT 中的图片 ID。

```c
void layer_sprite_face(int sprite_id, int asset_id, int x, int y, int mirror);
```
换表情（`dialog_drawn==1`）。仅重绘 `y < DIALOG_Y`（<280）的区域。从 `bg_snapshot` 恢复该区域后绘制新表情。**不碰对话框**。

```c
void layer_sprite_replace(int sprite_id, int asset_id, int x, int y, int mirror);
```
换装/换位置（`dialog_drawn==1`）。全幅更新：从 `bg_snapshot` 恢复旧位∪新位的整块矩形，全幅绘制新立绘，然后 `layer_dialog_refresh()` 重绘对话框。

```c
void layer_sprite_hide(int id);
```
隐藏指定 id 的精灵。从精灵注册表取出旧位置，从 `bg_snapshot` 恢复该矩形区域。若已绘对话框且隐藏区域在 DIALOG_Y 以下，调用 `layer_dialog_refresh()` 修补对话框区域。

如果隐藏后场景中无其他活跃精灵（1→0 过渡），执行 full-screen `bg_restore_rect` + 重新 `layer_capture_bg_dialog()`，确保切换时对话框区域干净。

```c
void layer_sprite_hide_all(void);
```
隐藏所有活跃精灵。遍历精灵注册表，逐个调用 `layer_sprite_hide()`。NB 中通过 `char(hideall)` 触发。

## 4. 内部数据结构

### 4.1 背景快照

```c
static uint8_t *bg_snapshot;          // 640×400 = 256,000 字节
static uint8_t *dialog_snapshot;      // 480×115 = 55,200 字节（PAT75 写定后、画文字前）
static uint8_t *bg_dialog_snapshot;   // 480×115 = 55,200 字节（纯背景，无对话框）
static uint8_t snapshot_valid;        // 0/1
```

`layer_capture_bg()` 时 `malloc(256000)` + `memcpy(bg_snapshot, VRAM, 256000)`。
`layer_capture_bg_dialog()` 时 `malloc(55200)` + `vram_read(80,280,480,115,...)`。
`layer_dialog_open()` / `layer_dialog_snap()` 时 `vram_read(80,280,480,115,...)` 更新 `dialog_snapshot`。

### 4.2 精灵注册表

```c
#define MAX_SPRITES 16

typedef struct {
    unsigned char active;   // 0=空闲, 1=使用中
    int  id;                // 精灵注册表 ID（NB 中为角色 ID）
    int  asset_id;          // IMAGE.DAT 中的图片 ID
    int  x, y;              // 当前绘制位置
    int  mirror;            // 水平翻转
} SpriteEntry;

static SpriteEntry sprite_tbl[MAX_SPRITES];
```

### 4.3 对话框标志

```c
static unsigned char dialog_drawn;  // 0=尚未绘制, 1=已绘
static unsigned char dialog_dirty;  // 0=snapshot 干净, 1=需在下次 dialog_show 时重建
```

## 5. 决策表（核心逻辑）

```
事件                     dialog_drawn  →  行为
────────────────────────────────────────────────────────────
bg + vram_blit          无关            layer_capture_bg()
                                        if !dialog_drawn → layer_capture_bg_dialog()
                                        dialog_drawn=0, dialog_dirty=0
bg(hidedialog)          0/1             vram_write(bg_dialog_snapshot)
                                        dialog_drawn=0, dialog_dirty=0
────────────────────────────────────────────────────────────
首次 dialog_show        0              layer_dialog_open()  ← PAT75 + vram_read
翻页 dialog_show        1              if dialog_dirty → layer_dialog_snap()
                                        layer_dialog_restore()
────────────────────────────────────────────────────────────
layer_sprite_show()     0              全幅 blit + 注册
                        1              if 0→1 first sprite:
                                           vram_write(bg_dialog_snapshot) clean
                                        else → 回退到 replace
────────────────────────────────────────────────────────────
layer_sprite_face()     0              → 回退到 show
                        1              裁剪 y [0, DIALOG_Y)
                                       bg_restore_rect(x,y,200,DIALOG_Y-y)
                                       vram_blit_sprite_cropped()
                                       不碰对话框 ✅
────────────────────────────────────────────────────────────
layer_sprite_replace()  0              → 回退到 show
                        1              union(旧位,新位) 整块恢复
                                       全幅 blit 新立绘
                                       layer_dialog_refresh()
                                       dialog_dirty=1
────────────────────────────────────────────────────────────
layer_sprite_hide()     0              注销即可
                        1              bg_restore_rect(旧位)
                                       if 旧位 y < DIALOG_Y:
                                           layer_dialog_refresh()
                                           dialog_dirty=1
                                       if 1→0 last sprite:
                                           bg_restore_rect full screen
                                           layer_capture_bg_dialog()
                                           dialog_dirty=1
────────────────────────────────────────────────────────────
layer_sprite_hide_all() 0/1            反复 layer_sprite_hide()
```

### 5.1 `bg_restore_rect` 辅助函数

```c
// 从 bg_snapshot 恢复指定矩形到 VRAM
// 若 rect 与对话框 [80,280,480,115] 重叠，裁剪掉重叠区域
static void bg_restore_rect(int x, int y, int w, int h, int clip_dialog);
```

`clip_dialog` 参数：
- `0`：不裁剪（用于 `replace`/`hide`，因为之后会重绘对话框）
- `1`：裁剪掉对话框矩形（用于 `face`，因为不重绘对话框）

## 6. 场景字节码操作码

### 6.1 立绘操作码

当前引擎运行在 NB 解释器路径下（`nb.c`），场景逻辑由 `cmd_bg`、`cmd_body`、`cmd_face` 等 NB 命令处理，不经过旧 `scene.c` 的字节码分发表。旧操作码表（`0x32`–`0x3A`）保留在 `scene.c` 中作为 MHVN98 协议兼容参考：

| 操作码 | 名称 | 参数 | 行为 |
|-------|------|------|------|
| `0x32` | `SPRITE_SHOW` | `uint16 id, uint16 x, uint16 y` | 自动分发：已存在 → `layer_sprite_replace(id, id, x, y, mirror)`，不存在 → `layer_sprite_show(id, id, x, y, mirror)` |
| `0x34` | `SPRITE_MIRROR` | `uint8 mirror` | 设置 `g_sprite_mirror`，影响后续精灵操作 |
| `0x38` | `SPRITE_HIDE` | `uint16 id` | `layer_sprite_hide(id)` |
| `0x39` | `SPRITE_FACE` | `uint16 id, uint16 x, uint16 y` | `layer_sprite_face(id, id, x, y, g_mirror)` |
| `0x3A` | `SPRITE_REPLACE` | `uint16 id, uint16 x, uint16 y` | `layer_sprite_replace(id, id, x, y, g_mirror)` |

**场景脚本示例**：

```sca
; 初始加载
bgload 0
sprite 1 10 0      ; 立绘 A（初始化阶段）
sprite 2 220 0
sprite 3 430 0
text 0             ; 对话框出现

; 换表情（只改脸）
sprite_face 1 10 0  ; 不重绘对话框 ✅

; 换装（全幅）
sprite_replace 1 10 0  ; 自动重绘对话框 ✅

; 隐藏
sprite_hide 1
```

### 6.2 精灵 MAG 调色板

精灵 MAG 中嵌有自己的调色板（索引 0–14 为角色实际色、索引 15 为透明色），但引擎**忽略它**——精灵渲染时使用背景的调色板。转换工具的调色板仅用于验证目的。

## 7. 渲染顺序（完整场景生命周期）

```
               ┌── bg_snapshot ──┐     ┌── dialog_snapshot ──┐     ┌── bg_dialog_snapshot ──┐
               │  640×400 快照   │     │  480×115 PAT75+立绘 │     │  480×115 纯背景        │
               └────────────────┘     └────────────────────┘     └───────────────────────┘

(1) bg 0
      vram_blit(背景, 0, 0)          ← 全屏背景
      layer_capture_bg()             ← 保存快照
      dialog_drawn = 0

(2) char fei l face                  ← show：全幅
      vram_blit_sprite(..., 15, clip_h) ← 跳过透明索引 15

(3) host{对话文字}
      dialog_drawn == 0
      → dialog_show() → layer_dialog_open()
        scene_draw_dialog()          ← 对话框盖住立绘重叠区
      dialog_drawn = 1
      draw_text(...)                 ← 写对白

(4) 后续翻页
      dialog_drawn == 1
      layer_dialog_restore() + draw_text(...) ← 不动边框和底色

(5) face 1 x y  (换表情)
      dialog_drawn == 1
      bg_restore_rect(x, y, 200, DIALOG_Y-y, clip=1)
      vram_blit_sprite_cropped(...)  ← 仅 y<DIALOG_Y
      ← 对话框不碰 ✅

(6) replace 1 x y  (换装/换位置)
      dialog_drawn == 1
      bg_restore_rect(union_bbox, clip=0)
      vram_blit_sprite(...)          ← 全幅
      layer_dialog_refresh()         ← 重绘对话框

(7) bg(hidedialog)
      vram_write(bg_dialog_snapshot) ← 对话框区域恢复纯背景
      dialog_drawn = 0, dialog_dirty = 0

(8) char(hideall)
      layer_sprite_hide_all()        ← 逐个隐藏精灵
      (最后一只 1→0 时 full bg restore + recapture bg_dialog)
```

## 8. 性能分析

### 8.1 各操作耗时估计（486/33MHz）

| 操作 | 像素操作量 | 耗时估算 | 帧预算占比 |
|------|-----------|---------|-----------|
| `capture_bg` | 256KB memcpy | ~0.8ms | 5% |
| `dialog_open` | 55KB fill + 边 | ~3ms | 18% |
| `dialog_refresh` | 55KB fill + 边 | ~3ms | 18% |
| `sprite_show` | ~40KB blit | ~2ms | 12% |
| `sprite_face` | ~22KB restore + ~12KB blit | ~1.5ms | 9% |
| `sprite_replace` | ~40KB restore + ~40KB blit + 55KB dialog | ~5.5ms | 33% |
| `sprite_hide` | ~40KB restore | ~1.2ms | 7% |
| `sprite_hide_all` | 多帧 hide 累加 | ~1-3ms | ~10% |
| `dialog_snap` | 55KB fill + 55KB read | ~3.5ms | 21% |
| `dialog_hide` | 55KB write | ~1ms | 6% |
| `capture_bg_dialog` | 55KB read | ~1ms | 6% |

所有操作远低于 16.6ms 帧预算，不需要异步处理或双缓冲。

### 8.2 内存开销

| 项目 | 大小 | 时机 |
|------|------|------|
| `bg_snapshot` | 256,000 B | bgload ~ next bgload |
| `dialog_snapshot` | 55,200 B | dialog_open ~ dialog_snap |
| `bg_dialog_snapshot` | 55,200 B | bgload ~ next bgload |
| 精灵注册表 | 16 × 8 B = 128 B | 始终 |

## 9. 边界情况

| 场景 | 行为 |
|------|------|
| `face` 时 `dialog_drawn==0` | 回退到 `show`（全幅） |
| `replace` 时 `bg_snapshot` 无效 | 回退到 `show`（丢弃旧位置恢复） |
| 多帧叠加（连续多个 `sprite`） | 每个 sprite 独立注册，互不冲突 |
| 同一 id 重复注册 | 更新注册表条目，旧位置用于 `replace` 恢复 |
| DITHER 半透明对话框下 `face` | 重叠区角色不变 → 视觉正确 ✅ |
| DITHER 下 `replace` | `dialog_refresh` 重新应用 dither pattern → 正确 ✅ |
| 0→1 精灵过渡 | 用 `bg_dialog_snapshot` clean 对话框后可画 ✅ |
| 1→0（最后精灵隐藏） | full bg restore + 重截图 bg_dialog ✅ |
| `bg(hidedialog)` 时对话框已闭 | `vram_write` 仍然是安全的 no-op ✅ |
| `dialog_snap` 时 dirty=0 | 直接返回，无开销 ✅ |
