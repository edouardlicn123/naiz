## 1. 板卡构成

PC-9801-86(通称「86 音源」「86 板」)在 26K 的 OPN 基础上换用 OPNA,并**另加一条与 FM 完全独立的 8bit PCM 通路**:

| 器件 | 作用 |
|------|------|
| YM2608(OPNA) | FM 合成器:6 声 FM + 3 声 SSG + ADPCM;端口 `0188h`–`018Fh`(DIP 可选 `0288h`–`028Fh`) |
| YM3433B | PCM 数据/声道分离 |
| Burr-Brown PCM61P × 2 | PCM 用 18bit D/A 转换器(左右各一) |
| NEC uPC1406HA × 6 | 各路音量控制 |
| Oki 32KB DRAM | PCM 播放用 FIFO 缓冲 |
| HD641180X0 | MCU |

**与本项目相关的两个关键结论**

1. **PCM 通路与 FM 通路在硬件上分离**:PCM 的 DAC 是上面两颗 PCM61P,电平由 A466/A66E 控制;FM 走 OPNA 寄存器,与 A4xx 端口无任何共用。
2. **MIDI(BGM)在另一块卡上**:本项目用的是 MPU-401 / MPU-PC98 / MPU-98II,端口 `0xC0D0` / `0xC0D2`,与 86 板 A4xx 无交集。⇒ **BGM 与 PCM 语音不构成资源冲突**。

> 历史上「一边播 BGM 一边放语音会互相打断」的说法是错的(见 `devdocs/118` §八)。真正会互相打断的是**音效与语音**:两者共用同一条 PCM 通路。

## 2. 端口一览

PCM 相关端口固定为 A4xx 段(不受 DIP 的 `0188h`/`0288h` 影响——DIP 只改 OPNA 基址):

| 端口 | 读 | 写 |
|------|----|----|
| `A460h` | 音源功能 ID + OPNA mask | OPNA mask 设置 |
| `A462h` | — | μPD6380 控制(仅 PC-9801-73) |
| `A464h` | — | μPD6380 数据(仅 PC-9801-73) |
| `A466h` | FIFO 状态 | **电子音量控制** |
| `A468h` | FIFO 控制 | FIFO 控制 |
| `A46Ah` | D/A 转换器控制 | **双用途**,见 §4.4 |
| `A46Ch` | FIFO 数据 | FIFO 数据 |
| `A66Eh` | 音源输出静音 | 音源输出静音 |

## 3. A460h — 音源功能 ID / OPNA mask

### 3.1 读:bit 7~4 = 音源功能 ID

| 值 | 机型 |
|----|------|
| `0000b` | PC-98DO+ 内置 |
| `0001b` | PC-98GS 内置 |
| `0010b` | PC-9801-73/-76,I/O 基址 `$188` |
| `0011b` | PC-9801-73/-76,I/O 基址 `$288` |
| `0100b` | **PC-9801-86,I/O 基址 `$188`**;PC-9821 Multi / A Mate / 早期 CanBe(Ce/Cs2/Ce2) |
| `0101b` | **PC-9801-86,I/O 基址 `$288`** |
| `0110b` | PC-9821Nf/Np 内置 |
| `0111b` | PC-9821 X Mate |
| `1000b` | PC-9821 后期 CanBe / Na7 / Nx 内置 |
| `1111b` | 未支持,或为 PC-9801-26 |

MAME 的构造方式可作校验:`id = ((DIP_PORT_BASE & 1) << 4) | 0x40`,再或上 mask 两位。即基址 `$188` ⇒ `0x40`(ID 4)、`$288` ⇒ `0x50`(ID 5),与上表吻合。

### 3.2 读 bit 1~0 与写:OPNA mask

| 位 | 含义 |
|----|------|
| bit 1 | 为 1 时**强制 OPNA 输出静音** |
| bit 0 | 选择 OPNA/OPN:1 = OPNA,0 = OPN |

写 A460h 即设置这两位。**注意 A460h 写不是「板卡使能」**——本项目 `hal_audio.c:120` 的注释写作 "board enable" 属术语错误(见 §5)。

**本项目从不读 A460h**,因此引擎不校验音源 ID:若目标机只有 26K 而无 86 板,PCM 写入会落到别的设备上而无任何诊断。

## 4. A466h / A468h / A46Ah — FIFO、D/A 与电子音量

### 4.1 A466h 读:FIFO 状态

| 位 | 含义 |
|----|------|
| bit 7 | FIFO 满(1 = 已满,精确为 32KB) |
| bit 6 | FIFO 空 |
| bit 5 | FIFO 溢出(**仅录音时**有效) |
| bit 4~1 | 未使用 |
| bit 0 | L/R 时钟,随 A468h 设定采样率同步翻转 |

### 4.2 A466h 写:电子音量控制 ★

**bit 7~5 = 选择要控制的音量通路**

| 值 | 通路 |
|----|------|
| `000b` | VOL1 —— FM 音源**直接**输出电平 |
| `001b` | VOL2 —— FM 音源**间接**输出电平 |
| `010b` | VOL3 —— CD-DA(仅 MULTi 机型)LINE 直接输出 |
| `011b` | VOL4 —— CD-DA(仅 MULTi 机型)LINE 间接输出 |
| `101b` | **VOL6 —— PCM 音源直接输出电平** |
| `100b` / `110b` / `111b` | 未记载,勿用 |

**bit 3~0 = 衰减量**

| 值 | 含义 |
|----|------|
| `0000b` | **最大音量** |
| `1111b` | **最小音量** |

MAME 的解码与之逐字一致:`line_select = data >> 5; m_vol[line_select] = data & 0x0f;`

**三条必须记住的性质**

1. **倒序**:值越大越小声,与「音量数值」直觉相反。
2. **只有 4 bit = 16 档**,不是连续量。
3. **`1111b` 是「最小」不是「静音」——此路径不存在 0 音量。** 真静音在 A66Eh(§4.6)。

⇒ 要控制 PCM 音量,写 `0xA0 | step`,`step` 为 0(最响)~15(最轻)。`0xA0` 本身即「VOL6 + 零衰减 = 满音量」。

### 4.3 A468h 读写:FIFO 控制

| 位 | 含义 |
|----|------|
| bit 7 | FIFO 使能(1 = 允许) |
| bit 6 | FIFO 方向:1 = FIFO→CPU(**录音**),0 = CPU→FIFO(**播放**) |
| bit 5 | FIFO 中断许可(1 = 允许) |
| bit 4 | FIFO 中断请求标志(**写 0 清除**) |
| bit 3 | FIFO 初始化(写 1 复位 FIFO,之后须写回 0) |
| bit 2~0 | 采样频率 |

**采样频率(bit 2~0)**

| 值 | 频率 |
|----|------|
| `000b` | 44.10 kHz |
| `001b` | 33.08 kHz |
| `010b` | 22.05 kHz |
| `011b` | 16.54 kHz |
| `100b` | 11.03 kHz |
| `101b` | 8.27 kHz |
| `110b` | 5.52 kHz |
| `111b` | 4.13 kHz |

MAME 由 25.4MHz/16 的时钟按 `{36,48,72,96,144,192,288,384}` 分频得到,与上表吻合。

> **bit 5 的连带效应**:`bit5 = 1` 时,A46Ah 被解释为**FIFO 中断间隔**而非 D/A 控制。见 §4.4。

### 4.4 A46Ah —— 双用途端口 ★★

同一个地址有两种语义,**由 A468h 的 bit 5 决定**:

| A468h bit 5 | A46Ah 语义 |
|--------------|------------|
| 0 | **D/A 转换器控制**(可读可写) |
| 1 | **FIFO 中断间隔设置**(仅写) |

**bit5 = 0 → D/A 转换器控制**

| 位 | 含义 |
|----|------|
| bit 7 | 时钟(音源) |
| bit 6 | 量化位数:1 = 16bit,0 = 8bit |
| bit 5~4 | 输出模式:`11b` 立体声 / `10b` 仅左 / `01b` 仅右 / `00b` 无 PCM 输出 |
| bit 1~0 | 用途未明,通常为 2(MAME 注明驱动 AVSDRV 取值不同) |

故「8bit 仅右声道」= `0x50`。

**bit5 = 1 → FIFO 中断间隔**

写入值 `d` 表示中断间隔 `(d + 1) × 128`(字节)。`0xFF` ⇒ `32768`,恰好等于 32KB FIFO 全满。

**⇒ 完整初始化协议(不可跳步)**

1. A468h ← `0x80 | 0x20 | 0x08 | rate` —— 置 bit5 使 A46h 变中断间隔;置 bit3 复位 FIFO
2. A468h ← `0x80 | 0x20 | rate` —— 把 bit3 写回 0
3. A46Ah ← 中断间隔(例如 `0xFF` = 32KB)
4. A468h ← `0x80 | rate` —— **清 bit5,A46Ah 恢复为 D/A 控制**
5. A46Ah ← D/A 控制值(例如 `0x50` = 8bit 仅右)
6. A466h ← `0xA0 | step` —— 电子音量

跳过第 4 步,第 5 步的 `0x50` 会被当成中断间隔(81×128),**D/A 转换器将停留在上电默认状态**。这是本节最易踩的坑。

### 4.5 A46Ch — FIFO 数据

8bit 数据口,FIFO 容量 **32KB**。传输方向由 A468h bit 6 决定(0 = CPU→FIFO 播放,1 = FIFO→CPU 录音)。播放时每消费一个样本向 A46Ch 写一字节,溢出行为见 §7。

### 4.6 A66Eh — 音源输出静音

| 位 | 含义 |
|----|------|
| bit 0 | PCM 静音 |
| 其余 | 未使用 |

MAME 的实现显示该位**只作用于两颗 PCM61P DAC 的输出增益**,不影响 OPNA/FM,也与 MPU-401 无关。这是实现「PCM 硬静音」的正确端口,且**不依赖 FIFO 状态**。

## 5. 本项目现状对照(`core/plat/hal_audio.c`)

### 5.1 实际写入序列与逐步对照

| 行 | 写入 | 对照本文件 | 判定 |
|----|------|-----------|------|
| 120 | `A460h ← 0x01` | §3.2 bit0 = 选 OPNA | 行为正确,注释 "board enable" **术语错** |
| 123 | `A468h ← 0x80\|0x20\|0x08\|rate` | §4.4 步骤 1 | 正确 |
| 124 | `A468h ← 0x80\|0x20\|rate` | §4.4 步骤 2(清 bit3) | 正确 |
| 125 | `A46Ah ← 0xFF` | §4.4 步骤 3 ⇒ 32768 阈值 | 正确,宏名 "FIFOSIZE" **术语错** |
| 128 | `A468h ← 0x80\|rate` | §4.4 步骤 4(**清 bit5**) | 正确 |
| 129 | `A46Ah ← 0x50` | §4.4 步骤 5 = 8bit 仅右 | 正确 |
| 131 | `A466h ← 0xA0` | §4.2 = VOL6 + 零衰减 = 满音量 | 正确 |

**结论:`hal_pcm_play` 的写入序列完整实现了 §4.4 的六步协议,无一处错误。**

### 5.2 三处术语错误(代码对、注释错)

这类「代码正确但心智模型错误」最危险:后来人照注释改代码必然踩雷。

| 位置 | 现有写法 | 实际语义 |
|------|---------|---------|
| `hal_audio.c:83` | `PCM_CTRL_A46A_FIFO 0x20` / 注释 `bit5: A46A programs fifosize` | bit5 是**FIFO 中断许可**;置 1 使 A46Ah 变为**中断间隔**寄存器,与 "fifosize" 无关 |
| `hal_audio.c:88` | `PCM_CTRL_FIFOSIZE_MAX 0xFF` / 注释 `~32KB threshold` | 数值 0xFF 正确((0xFF+1)×128 = 32768),但它写的是**中断间隔**寄存器,不是 fifosize |
| `hal_audio.c:120` | 注释 `board enable` | A460h 写是 **OPNA mask**(bit1 强制 FM 静音 / bit0 选 OPNA),无「板卡使能」语义 |

**根因**:`hal_audio.c:12-18` 的头部注释把 A466h 写作 `write 0xA0.. = volume`,只给了魔数没给位域;A468h bit5 的连带效应则完全未提。

### 5.3 尚未使用的硬件能力

| 能力 | 端口 | 现状 |
|------|------|------|
| 电子音量(4bit 倒序) | A466h 写 | **硬编码满音量**(第 131 行) |
| PCM 硬静音 | A66Eh bit0 | **完全未使用** |
| 音源 ID 校验 | A460h 读 | **从不读取** |
| 16bit / 立体声输出 | A46Ah bit6、bit5~4 | 固定 8bit 仅右(第 129 行) |

## 6. 陷阱清单

1. **A468h bit5 决定 A46Ah 的语义**。不先置位再清位,`A46Ah ← 0x50` 会被解释为中断间隔而非 D/A 控制(§4.4)。
2. **A466h 的衰减是倒序且只有 4 bit,没有 0 音量**。按「音量 0~100 线性」的直觉实现必然错向;静音要走 A66Eh(§4.2)。
3. **音效与语音共用一条 PCM 通路**。FIFO 是一次性的:新样本流会**直接换绑**掉正在播的流。因此起播一个音效会打断正在播的语音。这是硬件与协议的固有行为,**不是 bug**,与开关设置无关。
4. **BGM 与 PCM 无冲突**:分属 MPU-401(`0xC0D0`/`0xC0D2`)与 86 板(`A4xx` + PCM61P),A66Eh 也只静音 PCM 通路(§1、§4.6)。
5. **A460h 写不是板卡使能**,且本项目从不读 ID(§3.2、§5.2)。
6. **FIFO 溢出/下溢行为未文档化**:32KB 缓冲的边界行为只有模拟器的 HACK 式处理可参照,MAME 自己标了 TODO(§7)。

## 8. MPU-401 侧(对照用)

本项目 BGM 走 MPU-401 / MPU-PC98 / MPU-98II,与上文的 86 板 PCM 无关:

| 项 | 值 |
|----|----|
| 数据口 | `0xC0D0` |
| 状态口 | `0xC0D2` |
| 状态 bit 6 | MIDI OUT 忙(轮询至清零再写) |
| 状态 bit 7 | 有字节待读 |
| 握手字节 | `0xFE` |
| 初始化 | 复位 `0xFF` → UART 模式 `0x3F`,各等一次 `0xFE` |

**CC7(控制器 7,通道音量)是标准 GM 消息**,值域 0(静音)~127(最响),与 A466h 的 4bit 倒序衰减**量程方向相反、精度不同**。本项目实现见 `core/engine/audio.c` 的 `audio_bgm_start` / `audio_bgm_stop`;`audio_bgm_stop` 内已有「遍历 16 通道逐个发控制消息」的现成范式可复用。

> 未确认:CC7 是否真被 MPU-98II 内部合成器采纳(标准 GM 行为,MAME 的 mpu401 已实现,但本项目机型需实机验证);若 SMF 自身含 CC7 事件,会覆盖程序发出的值。
