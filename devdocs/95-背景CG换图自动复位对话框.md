# 95-背景CG换图自动复位对话框与hidedialog指令保留

> 组一优化方案：消除"每次刷写背景/加载 CG 后必须尾随 `bg(hidedialog)`/`cg(hidedialog)`"的脚本负担——让系统在换图命令本身完成对话框的全套复位；同时**保留两指令供日后独立使用**。
>
> **本档为方案文档，本轮不落代码**（用户决定"只写 devdoc，不动代码"）。实施状态见 §七，实施完成后回填核销。

## §一 背景与问题

`bg(){asset}` / `cg(){asset}` 走统一入口 `layer_bg_change()`（layer_bg.c:176）：

```
vram_blit(img, 0, 0)        // 全屏 640×400 写显存 —— 物理覆盖对话框区像素
layer_capture_bg_dialog()   // 对话框区 480×115 快照重采（对齐 R11 根修：blit 后必重采）
layer_redraw_sprites()      // 重绘活动精灵
dlg_update_palette()        // 对话框/按钮调色板寄存器写
btn_update_palette()
layer_capture_bg()          // 全屏快照 = 层状态复位（含 layer_dialog_clear()）
```

关键事实链：

1. 全屏 blit 已**物理销毁**对话框像素；
2. `layer_capture_bg()` → `layer_dialog_clear()`（layer_dialog.c:221）已把**图层状态** `dialog_drawn/dialog_dirty` 清 0；
3. 但 **NB 脚本引擎的翻页状态 `DialogState`（nb_dialog.c:21-25，text/text_offset/charname）未被清** ——它只被 `nb_dialog_reset()`（nb_dialog.c:107）复位。

因此旧流程要求脚本在每个 show 之后尾随一条 `hidedialog` 指令来补齐第 3 项。这条尾随调用在当前实现下的实际开销：

- `layer_dialog_hide()`（layer_dialog.c:192）:**无条件**对对话框区做一次 55KB `vram_write`（从 `bg_dialog_snapshot` 还原）。而换图时该快照已被 `layer_capture_bg_dialog()` 刷成**新图**，对话框区显存展示的也正是新图 → **自写自读的冗余写**；
- `nb_dialog_reset()`:3 字段复位（O(1)）。

结论：show 后尾随的 hidedialog，其唯一真实作用 = `nb_dialog_reset()`；那 55KB 写是纯浪费。

## §二 设计（待实施）

### 2.1 换图命令自动复位 NB 翻页状态

- `cmd_bg`（nb_commands.c:148）资产分支（~:186）：`layer_bg_change(img)` + `mag_release(img)` 之后补 `nb_dialog_reset();`
- `cmd_cg`（nb_cg.c:28）资产分支（~:85）：同样补 `nb_dialog_reset();`

两命令均已 include 并在 hidedialog 分支调用过 `nb_dialog_reset()`，无新依赖。

效果：`bg(){x}` / `cg(){x}` 由"只复位图层"升级为"**图层 + NB 翻页全套复位**"，show 之后无需任何尾随指令。

### 2.2 `layer_dialog_hide()` 加 `!dialog_drawn` 早退

layer_dialog.c:192 现任为无条件执行（快照存在即写 55KB）。改为：

```c
void layer_dialog_hide(void)
{
    hal_mouse_invalidate_cursor();
    if (!dialog_drawn) {                 /* 无对话框可关：O(1) 复位 */
        dialog_dirty = 0;
        layer_set_active(LAYER_Z_DIALOG, 0);
        layer_set_active(LAYER_Z_TEXT, 0);
        return;
    }
    /* 现存：bg_snap → vram_write(480×115) + 四标志复位 */
}
```

Ssignature 不变；`layer_dialog_drawn()` 是既有查询（layer_dialog.c:209）。

语义：对话框**确实开着**才需 55KB 还原（真关）；**未绘制**时 VRAM 对话框区已是正确背景，写还原反而是错的——顺带修掉一个潜在 bug：对话框关闭状态下若有精灵压着对话框区，旧代码会拿纯背景把精灵区域盖掉（`char(hideall)` 路径可达，呼应 C30）。

## §三 指令保留决策

按用户要求，`bg(hidedialog)` / `cg(hidedialog)` **保留备用**：

- 不改语法、不改 `nb_validator.py` 签名、**不清已有脚本**；
- 保留为**独立指令**："不换场景、仅关闭对话框还原背景"（VNM 常见：翻页后不切换场景直接收起对话）；
- show 后尾随 = 无害空转：2.1 已自动复位，2.2 早退使其为 O(1)；
- `char(hideall)` 语义不变，同享 2.2 早退。

## §四 生效语义对比

| 场景 | 现状 | 实施后 |
|------|------|--------|
| `bg(){x}` 后尾随 `bg(hidedialog)` | hide 冗余写 55KB + reset | reset 已由 show 自动做；hide 早退 O(1) |
| 独立 `bg(hidedialog)`（对话框开着） | 55KB 还原 + reset | 同左（真关，无法更省） |
| 独立 `bg(hidedialog)`（对话框没开） | 冗余写 55KB（含精灵被盖隐患） | O(1) 复位，隐患消除 |
| 对话框开着换图 | 像素被覆盖 + 图层清 + NB 未清（需补指令） | 像素被覆盖 + 图层清 + **NB 自动清** |
