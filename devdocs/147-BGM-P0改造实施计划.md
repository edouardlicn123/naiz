## 一、目标

修掉 `146` §四所列四个**确定的 BGM 正确性缺陷**中可在主机单测的三项，并把第四项（pump 覆盖）固化为既有守卫的核对项：

| 项 | 缺陷（`146` §四） | 本计划动作 | 可主机验证 |
|---|---|---|---|
| A1 | 循环接缝早断（曲长丢失） | `midi_parse` 记录曲长 | 是 |
| A2 | 回卷丢相位 | 按曲长循环 + `wall0 += len_ms` | 是 |
| A3 | 事件突发齐发 | 每次派发设预算 | 部分（手感需实机） |
| A4 | pump 覆盖靠约定 | 核对既有 `PUMP_CALLERS` 守卫 | 是（pytest） |

**版本策略（默认）**：A1+A2+A3+A4 合为一轮 `0.3.038`；A3 采用**保守预算**（详见 §五），实机试听后再决定是否收紧。

## 三、A1 — `midi_parse` 记录曲长

**改动**
- `core/lib/midi.h`：原型加末参 `uint32_t *out_len_ms`（**允许传 `NULL`**，降低调用方改动量；文档注明单位 ms、含义为「EOT 与末事件 tick 的较大者换算值」）。
- `core/lib/midi.c`：
  1. 解析中跟踪 `song_end_tick` = 所有轨道 EOT 绝对 tick 的**最大值**（现为全局合并表，需在遇到 `0x2F` 时按 `abs_tick` 更新，而非直接丢弃）；
  2. 若全曲无 EOT，回落 `song_end_tick = 全局末事件 tick`；
  3. 第二遍 tick→ms 换算后，`*out_len_ms = max(EOT_ms, last_event_tick_ms)`；
  4. `out_len_ms == NULL` 时跳过。
- `core/engine/audio.c:249`：调用改为传 `&len`，并存入 `g_bgm.len_ms`（结构见 §四）。

**验证（`tools/tests/test_fm_seq.py`）**
- 更新 `lib.midi_parse.argtypes`（`:97-99`）与调用点（`:407-408`），补第五参 `POINTER(c_uint32)`。
- 新增用例：
  - 尾部带静默的 SMF（EOT 晚于末音符）⇒ `len_ms > 末事件 tick_ms`；
  - 无 EOT 的 SMF ⇒ `len_ms == 末事件 tick_ms`。

**风险 / 回退**：低（纯库）。若换算有误，测试先红；回退即还原签名并删用例。

## 四、A2 — 按曲长循环 + 保留相位

**改动（`core/engine/audio.c`）**
- `BgmState` 增字段 `unsigned long len_ms;`（`audio.c:43-50`）。
- `bgm_release()` 增加 `g_bgm.len_ms = 0;`（`audio.c:70-81`）。
- `audio_bgm_start()` 写入 `g_bgm.len_ms`（由 A1 获得）。
- **FM 路径**（`audio.c:523-540`）：完成判据改为 `cur >= g_bgm.len_ms && fmseq_finished(g_fm_seq)`；回卷时用整曲推进：
  ```
  g_bgm.wall0 += g_bgm.len_ms;      /* preserve phase */
  while (now - g_bgm.wall0 >= g_bgm.len_ms)  /* long stall: skip whole songs */
      g_bgm.wall0 += g_bgm.len_ms;
  if (g_bgm.wall0 > now) g_bgm.wall0 = now;  /* guard */
  fmseq_stop(g_fm_seq, &g_fm_sink);
  ```
  保留既有 `ring` 诊断日志。
- **MPU 路径**（`audio.c:542-571`）：把结束判据从「`idx >= count` 即回卷」改为 `cur >= g_bgm.len_ms`（所有事件 `tick <= len_ms`，故到时必已发完）；回卷 `wall0` 同 FM 路径的整曲推进；`idx = 0`。

**边界定义**
- `len_ms == 0`（空曲/无事件）：`audio_bgm_start` 视为无效，记 `halt` 诊断并不置 `active`（避免回卷死循环）；需在实现轮确认现有 `count==0` 分支。
- `cur` 回绕/负值：沿用既有 `unsigned long` 语义，`now - wall0` 下溢由「整曲推进」循环不触发（`now >= wall0` 恒成立时 `wall0` 只增）。

**验证**
- 新增用例（建议进 `test_fm_seq.py` 新增 `test_bgm_loop_phase.py` 或就地扩展）：
  - 以曲长 L 连续 pump 多个循环，`wall0` 每次恰好 `+= L`，无累积漂移；
  - 末音符在 `tick_ms == L` 附近不被裁（事件在回卷前已派发）；
  - 长时间未 pump（模拟加载）后不产生负 `cur`，且跳过整曲而非回绕到错误相位。

**风险 / 回退**：低。回退即恢复 `wall0 = now`。

## 五、A3 — 事件派发分片（保守预算）

**动机**：`146` §四.3 —— 一整窗积压会在同一 pass 齐发（MPU 串行轮询、FM 单帧写爆寄存器）。

**改动**
- **不改函数签名**（避免 `test_fm_seq.py:88-89` 的 ctypes `argtypes` churn）：
  - `core/lib/fmseq.{c,h}`：在 `fmseq_pump` 内部加**每次调用派发上限**常量 `FMSEQ_PUMP_MAX_PER_CALL`（保守大值，建议 32；`h` 中注释「防整窗突发齐发」）。超限即从 `while` 退出，剩余事件留待下次 `pump`。
  - `core/engine/audio.c` MPU 路径（`:552-563`）：`while` 加**每 pass 事件上限**（同保守量），限制单帧 `hal_midi_out` 字节数。
- **保守取值理由**：稳态每帧只跨 0~1 个事件，32 的上限对正常播放零影响，仅在跳变/积压时削峰。

**验证**
- 新增用例：构造一次跨多个事件的时钟跳变，反复 `pump` 观察 `cursor` 逐次递增且**不丢事件**（最终 `cursor == count`）；单次 `pump` 派发数 ≤ 上限。

**风险 / 回退**：唯一**无法纯单测确认手感**的项 —— 预算过小会让密集段落迟滞，需**用户实机试听**。回退即把上限设为足够大（等效不生效）。

## 十一、实施结果（0.3.038）

**A1（`core/lib/midi.c` / `midi.h`）**：新增纯函数 `midi_tick_to_ms()`（`midi.c:145`）并让原 tick→ms 循环复用它；`midi_parse_track()` 增 `uint32_t *song_end_tick` 末参（`midi.c:171`），遇 `0x2F` 记 `abs_tick` 最大值（原为直接丢弃）；`midi_parse()` 增 `uint32_t *out_len_ms` 末参（`midi.c:286`），先置 0，成功路径在 `midi.c:376-386` 取 `max(末事件 tick, song_end_tick)` 经同一 tempo map 换算（>0xFFFFFFFF 夹顶）。**偏差**：计划 §三 的「回落 song_end_tick = 全局末事件 tick」未在 `midi_parse_track` 内做，而是在 `midi_parse` 出口取 `max(evts[evt_n-1].tick, song_end_tick)`——效果等价，且当**无任何事件**时提前 `rc=0` 返回、`out_len_ms` 保持 0（空流）。

**A2（`core/engine/audio.c`）**：`BgmState` 增 `unsigned long len_ms`（`audio.c:48`）；`bgm_release()` 清零（`audio.c:87`）；`audio_bgm_start()` 局部 `len_ms` + `midi_parse(...,&len_ms)`（`audio.c:259`）、空流判据 `count<=0||len_ms==0`（`audio.c:267`）、存入 `g_bgm.len_ms`（`audio.c:277`）；新增 `static bgm_rewind_phase()`（`audio.c:526`）；`audio_tick()` FM 判据（`audio.c:562`）与 MPU 判据（`audio.c:602`）均改「到曲长 + 已发完」。**偏差**：计划 §四 的整曲推进内联循环改为**纯函数 `fmseq_loop_start(last_start, song_len, now)`**（`core/lib/fmseq.c:554`，声明 `fmseq.h:126`）——为**可主机单测**（相位算术零 I/O）；语义与计划等价（`next = last_start+song_len`，饥饿多曲一次除法跳整段，结果恒落 `[now, now+song_len)`，`song_len==0` 退化回 `now`）。该纯函数随 `core/lib/fmseq.c` 一并编译进引擎（`core/Makefile` 以 `wildcard lib/*.c` 收集），**无新增文件**。

**A3（`core/lib/fmseq.{c,h}` + `core/engine/audio.c`）**：`fmseq.h:42` 新增 `#define FMSEQ_PUMP_MAX_PER_CALL 32`，`fmseq_pump()` 内加 `int budget` 上限（`fmseq.c:497,507-512`）；`audio.c:70` 新增 `#define AUDIO_BGM_MAX_EVENTS_PER_TICK 32`，MPU `while` 加 `budget>0`（`audio.c:584-597`）。**签名零改动**（如计划 §五 所愿，ctypes `argtypes` 无 churn）。
