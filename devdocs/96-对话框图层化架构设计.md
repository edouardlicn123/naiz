# 96-对话框图层化架构设计

> 组二架构方案：把对话文字与对话框从"盖写显存 + 快照还原"模型升级为**软件图层 + z 序合成**模型，消灭整套防腐/惰性重采账本，并解锁**对话框跨 bg/cg 存活**能力。
>
> 本档为设计 + 分阶段路线图，**本次仍不落代码**。可行性复查（v2）修正了三处原始论断并冻结两项语义裁决，见 §0。
>
> 实施需按 §七 分阶段单独授权（触及 §十一 显示管线硬性区）。

## §0 可行性复查结论（v2 修订）

原文三处关键论断经逐代码核对不成立，已按下述修正；另依用户两项裁决冻结语义：

| # | 原论断 | 实测结论 | 修订 |
|---|--------|----------|------|
| 1 | `clip_h` 保证精灵永不写入对话框矩形 | **假**。clip_h 仅约束 `layer_sprite_face`（layer_sprite.c:181）与 `layer_redraw_sprites`（:357）；`layer_sprite_show`（:112）/`layer_sprite_replace`（:255）全身路径满高直写、进对话框区，靠事后 `layer_dialog_refresh()` 把对话框盖回（:124/259/301） | 真不变量=**对话框矩形内 dialog 图层恒最后画**（z 序天然保证）；全身路径在对话框开启时也剪到 y<280（**Option X**，贯彻 layer.c:83-87 既有 Z_SPRITE bounds） |

## §一 动机与目标

### 1.1 现状痛点

"对话框以裸像素盖写在单块 VRAM 上"导致零散账本林立（devdoc 95 已削一层，根因仍在）：

- 全屏 blit 物理销毁对话框 → 每次换图必须重采对话框区（55KB VRAM 回读）；
- 对话框像素可被全身精灵"挖走" → 需要 `dialog_snapshot` 防腐快照 + `dialog_dirty` + `layer_dialog_snap` 惰性重建三重账本（layer_sprite.c:123-125/259-260/300-303）；
- 精灵对对话框的交错依赖"先擦后画再盖"的运训（layer_sprite.c:97-108）；
- `bg_snapshot` 捕获顺序（layer_bg.c:181 redraw → :184 capture）致全屏快照**混入精灵**，还原语义脆弱；
- 对话框无法跨 bg/cg 存活，换图天然丢文字。

### 1.2 目标

1. **对话框（框 + 文字）成为独立软件图层**，按 z 序合成到 VRAM，**跨 bg/cg 存活**（裁决 A）；
2. **消灭防腐/惰性重采账本**（符号清单见 §四），换图**全部 VRAM 回读归零**；
3. 换场景仍由 `layer_init` 全量复位（layer.c:53-59）——"跨图存活、跨场景清空"，语义精确且无需新机制；
4. 不依赖硬件 alpha（PC-98 无），框+文字合成一块不透明缓冲；
5. 字节级 VRAM 写入流量不增不减（诚实约束），收益在结构性账本与语义能力。

### 2.1 为何防腐账本存在（当前必须防的事）

`clip_h`（layer_sprite.c:66）只挡面部路径；全身 show/replace 会把精灵画进对话框矩形（layer_sprite.c:112/255），对话框像素被"挖走"后必须靠 snapshot 检测 + 惰性重建。layer.c:83-87 已有 **Z_SPRITE/ANIM bounds 在对话框激活时剪到 y<280 的概念定义**——问题只是全身路径没有贯彻它。

## §三 目标架构：软件图层 + z 序合成

### 3.1 z 序（低→高）与合成面

```
vram 合成顺序（对话框矩形内 dialog 恒最后画 —— 真不变量）
  1. BG 层（blit 或 bg_snapshot/源图直取）        全屏
  2. 精灵层（对话框开启时整层剪到 y<280，Option X） 全屏（下半不入框）
  3. UNDER_DIALOG 层 = bg 源图/动画帧的框下矩形    480×115（可推导，不存屏上）
  4. Dialog 合成层（框+文字，不透）               480×115（持久缓冲）
```

> 框下不再需要"独立的屏上状态"：`under_dialog` 缓存 = 由 BG/动画源图派生的纯净矩形，精灵永不写入（Option X）。对话框关闭后的完整还原 = `under_dialog` 覆盖 + 精灵全身重绘（裁决 B）。

| 事件 | 合成动作 |
|------|----------|
| 换图 `bg(){x}`/`cg(){x}` | blit BG 全屏 → `under_dialog`←源图直取 → redraw_sprites（剪裁）→ **若 dialog 存活：blit dialog 缓冲** → 调色板 |
| 对话框开 | `dialog_paint_box`+文字入缓冲 → blit 55KB |
| 对话框打字翻页 | 文字重绘入缓冲 → blit 55KB（不再画 VRAM） |
| 对话框关 | blit `under_dialog`（55KB）→ **redraw_sprites 全身**（裁决 B） |
| 精灵面部/全身替换 | 一律剪到 y<280（Option X）；无需再 refresh dialog —— 对话框根本没被碰 |
| 动画帧 | `under_dialog`←帧像素直取（既有 from_image，nb_anim.c:167）；dialog 存活则 blit |

### 3.2 关键设计论点

1. **真不变量只有一个：对话框矩形内 dialog 图层恒最后画**（z 序合成保证）。这让 layer_sprite.c:97-126/219-274 的"先擦背景→画精灵→refresh 盖回"整体退化为一行"照常画（剪裁）+ z 序"，防腐重建链条整组消失（§2.1 的结构性病因被拔除）。
2. **框下 = 可推导，不存屏上状态**：Option X 保证精灵永不进框矩形，`under_dialog` 仅由 BG/动画源图直取，恒纯净。隐藏/获取框下无需读 VRAM。
3. **对话框缓冲 = 透明无关**：框为纯填充（`fill_rect`/`fill_rect_pattern(PAT75)`/白边）+ 文字，内存缓冲按'先框后字'两趟绘成一块 480×115 不透明图再整体 blit；不需要 alpha/透明索引。
4. **合成事件驱动**：静态帧零额外流量；框 blending 不需要通用 fill 重构（本地 `dialog_paint_box` 即可）。
5. **文本写入用文件级渲染目标**（仿既有 `text_set_blackletter` 模式，render_text.c:15），只影响 3 个调用点（§五）：nb_dialog.c:58/63、nb_save_dialog.c:190/195 的"恢复存文字"。

### 3.3 VRAM 流量对比（诚实表）

| 操作 | 现状 | 图层化 |
|------|------|--------|
| 换图 `bg(){x}` | BG 写 256KB + 框回读 55KB + 全屏回读 256KB +（trailing hidedialog 55KB 写） | BG 写 256KB + dialog blit 55KB（存活时）+ **VRAM 读为 0** |
| 关对话框 | 55KB 写（框下） | 55KB 写（under_dialog）+ 精灵全身重绘（数 KB～数十 KB） |
| 开对话框 | 框+字 VRAM 写 + 回读 55KB | 框+字入缓冲 + blit 55KB（纯写） |
| 静态帧 | 0 | 0 |

量级持平、**回读方向全灭**。

## §四 符号变更清单

**保留改名**：`bg_dialog_snapshot` → `under_dialog`（480×115 纯净缓存，源=bg 源图/动画帧）；`layer_capture_bg_dialog_from_image()` 升格为主通道。

**新增**：
- `dialog_layer`（480×115 缓冲，layer_dialog.c 私有，静态/一段分配）；
- `dialog_paint_box(buf)`（本地画框入缓冲，不动 fill_rect 通用机制）；
- `text_set_target(buf, stride, offx, offy)` / `text_set_target_vram()`（render_text.c 文件级目标，仿 text_set_blackletter）；
- `dialog_layer_blit()`（缓冲→VRAM 矩形，即 vram_write 封装）；
- `layer_dialog_close()`（= under_dialog 覆盖 + 精灵全身重绘，替代 hide 的裸快照写）。

## §五 最深改动点：文本渲染目标（不是通用 RenderTarget）

`draw_glyph_internal()`（render_text.c:39）当前硬编码 VRAM：

```c
volatile uint8_t *win = hal_vram_get_window();
...
int addr = py * LAYER_SCREEN_W + px;    /* 全局跨距 640,绝对坐标 */
VRAM_SET_BANK(addr, cur_bank);
win[addr & (VRAM_BANK_SZ - 1)] = color;
```

对话框文字要绘入 480×115 缓冲（坐标/跨距都不同），最小改动 = **文件级切换目标**（与 `text_set_blackletter` 同模式，render_text.c:15）：

```c
static uint8_t *text_tgt_buf = NULL;      /* NULL = VRAM 模式(现状) */
static int      text_tgt_stride;          /* 缓冲跨距(VRAM 模式=LAYER_SCREEN_W) */
static int      text_tgt_offx, text_tgt_offy;   /* 缓冲系原点(VRAM 模式=0,0) */

void text_set_target(uint8_t *buf, int stride, int offx, int offy);
void text_set_target_vram(void);
```

- `draw_glyph_internal` 唯一改动：末级写语句分流（VRAM：现路径；缓冲：`text_tgt_buf[(py-offy)*stride+(px-offx)] = color`，越界跳过同 VRAM 分支）；
- 换行/折行/返回偏移逻辑**零改动**（只换末级写），`draw_glyph_scaled`/`draw_title_large` 不受影响（永走 VRAM）；
- 调用方只有 2 处：`nb_dialog.c:58/63`（角色名/正文绘入缓冲）+ `nb_save_dialog.c:190/195`（读取档后重绘存文字）；
- 不必引入通用 `RenderTarget` 结构体——更小、更贴合现有代码风格。

## §七 分阶段路线图

> 每阶段独立可验证、可独立合入；顺序自低风险到高风险。

### 阶段 A：文本渲染目标 + 本地画框
- `text_set_target()`/`text_set_target_vram()` + `draw_glyph_internal` 末级写分流；新增 `dialog_paint_box`（临时导出做目检）；
- 行为零变化（默认 VRAM）；
- 验收：make 0err/0warn、pytest、fullaudit、全量目检文本渲染无差异。

### 阶段 B：对话框合成层
- `dialog_layer` 缓冲 + open/打字/翻页改 `text_set_target(缓冲)` + `dialog_paint_box` + `dialog_layer_blit`；
- `layer_dialog_show` 简化；删 `dialog_snapshot`、`dialog_snapshot_valid`、`dialog_dirty`、`dialog_snapshot_capture`、`layer_dialog_snap`、`mark_dirty`；
- 验收：对话开/打字/翻页/关对话无回归；防腐账本移除后 face 精灵场景目检无残影（z 序已兜底）。

### 阶段 C：BG 接缝 + sprite 收口（Option X）
- `under_dialog` 换源直取，删 `layer_capture_bg_dialog()`（vram_read 版）与 `from_bg`；
- `layer_bg_change`/`layer_capture_bg` 新仪式 + **删 `layer_dialog_clear`**（survival）；
- 全身路径在对话框开启时一律 clip（Option X）；`layer_sprite_hide` 删重采；
- `layer_dialog_close` = under_dialog 覆盖 + **精灵全身重绘**（裁决 B）；
- 验收：换图对话框**存活**（新能力）；关对话框精灵恢复完整躯体（行为变化目检）；精灵+对话框全组合无残影。

### 阶段 D：消费者联动 + 语义回退收口
- save 菜单简化、question 确认、动画 path、画廊；
- **回退 R17**：`cmd_bg`/`cmd_cg` 两处 `nb_dialog_reset()`（nb_commands.c:188 / nb_cg.c:88）；**B92 两句"show 已自动复位"回滚**；AGENTS.md 头部在实施轮次中一并记账（bump_version 同步）；
- 更新 `docs/B90` 符号表、devdoc 96→完成后归史；
- 验收：make/pytest/fullaudit + demo 全路径目检（跨图存活、hidedialog 独立可用、精灵全身恢复）。

## §八 风险与开放问题

1. **§十一 硬性区**：显示管线/图层模型变更需显式许可——本档 v2 即申请记录，实施前再确认范围。
