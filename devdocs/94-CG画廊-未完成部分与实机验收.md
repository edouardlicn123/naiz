### 3.2 Bug 修复：DOWN 导航无法到达 Back（0.2.077 → 0.2.078）

**问题**：`cmd_cgvmenu` DOWN 键处理中，`sel/GAL_COLS >= GAL_ROWS-1` 条件在 `CG_COUNT ≤ GAL_COLS`（≤4 个 CG）时永不成立。原因是 Down handler 先检查行边界再 clamp sel，但 `sel` 始终在第 0 行（sel=0,1,2,3 → sel/4=0 < 2），Back 按钮永远无法通过 DOWN 键到达。

**修复**（nb_mainmenu.c:319-325）：
- 旧：`if (sel/GAL_COLS >= GAL_ROWS-1) focus_on_back=1; else { sel+=GAL_COLS; if(sel>last_idx) sel=last_idx; }`
- 新：`if (sel+GAL_COLS > last_idx) focus_on_back=1; else { sel+=GAL_COLS; }`

效果：当按下 DOWN 时若目标位置超出最后一个有效 CG 格子，直接进入 Back 按钮聚焦（而非 clamp 回最后有效格）。此条件在任何 `CG_COUNT` 下均正确——满了整页时 Bottom row 自然触发；不满整页时超出边界也触发。

**变更范围**：`core/engine/nb_mainmenu.c` 1 处（3 行替换）。
**版本**：0.2.077 → 0.2.078（全部项目同步）。
**编译**：`make -C core` 0 errors / 0 warnings。

## §四 挂起项二：二期真缩略图

### 4.1 现状与目标

- 现状：`gallery_draw_cell`（nb_mainmenu.c:170 区）用 `fill_rect`（蓝底=解锁 / 深色=锁定）+ `draw_text`（`CG 01` / `[LOCKED]`）绘制占位框。
- 目标：解锁格显示该 CG 的**真实缩略图**，替代编号占位框。

### 4.2 执行方案（源自 devdoc 92 §八）

在 `gallery_draw_cell` 中，将解锁分支的 `fill_rect + draw_text` 位置替换为缩略图 blit：

1. **缩略图资产**：新增 type 为缩略图的资产（或从原 CG MAG 降采样生成），登记进 ASSETS.DB / IMAGE.DAT。
2. **加载路径**：`gallery_draw_cell` 内 `image_load(缩略图 id)` → 以 `vram_blit`/`vram_blit_sprite` 缩到格内（144×100）。
3. **网格布局与导航逻辑不改动**（devdoc 92 §二 坐标、§四 导航已定稿）。
4. 锁定格仍保持深色占位框 + `[LOCKED]`（缩略图仅解锁格）。

### 4.3 边界与约束

- 内存/加载：画廊一次显示 ≤12 格，需在进入页面时预载或按需加载缩略图，避免每次 `gallery_draw_cell` 重复 `image_load`（对照 C18 快路径副作用规约）。
- 调色板：缩略图 blit 不得污染画廊网格调色板（devdoc 92 §四 E8 的 `menu_save/restore_item_palette` 机制）。
- 越界：与现有 `gallery_cell_xy` hit-test、`CG_COUNT` 边界一致。
- 缩略图未解锁时不预览（沿用 §2.3 h 语义）。
