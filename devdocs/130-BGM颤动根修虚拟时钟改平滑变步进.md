# 130 — BGM 颤动根修：虚拟时钟改平滑变步进（废止 floor/ceiling 钳制）

> 状态：`实现完成待实机验证`
> 版本：`0.3.028`
> 相关：devdoc 129（帧泵，`bd2093e`）、107（smooth 时钟由来）、B19 §3.1（时钟契约）、F03 §4.2
> 前序：devdoc 125–129（FM 地址修复 → 可闻 → 闸门 → 颤动）

## 1. 症状（用户实机反馈）

正式 BGM 可闻、能连续播放（devdoc 129 的冻结已修），但**节拍不稳，呈颤动**——不是停表，而是音符起奏时刻抖动。

## 2. 根因：帧泵暴露了旧钳制的量化误差

### 2.1 旧设计

0.2.134（devdoc 107）为解决 NP2kai 的 DOS 时钟洞，把每 pass 增量钳制到 `[SMOOTH_CLOCK_MIN_MS=40, SMOOTH_CLOCK_MAX_MS=100]`（`hal.h`），累计成虚拟时钟。三个消费方（BGM/打字机/动画）各自读它。

钳制语义：`delta==0 → 40`；`delta>100 → 100`；否则原样。

### 2.2 devdoc 129 改变了什么

帧泵把 `hal_wallclock_smooth_advance()` 收敛为**每 pass 恰好一次**（此前每 pass 被 3 个消费方各调用一次，3 次钳制值在 pass 内互相平均）。这是正确的修复，但同时把钳制的**单步量化误差直接暴露给唯一的消费方**。

### 2.3 为什么暴露成「颤动」

NP2kai 上 DOS 时钟（INT 21h AH=2Ch）**秒级量化**（`dl` 恒 0，devdoc 107 实测）且成块交付。于是一个真实秒内：

- 秒未落地的各 pass：`delta == 0` → 步进 **40ms**
- 秒落地的那一拍：`delta == 1000` → 钳到 **100ms**

两种步长 **2.5:1 交替**。BGM 调度是 `fmseq_pump(cur)`、`cur = now - wall0` 的绝对时间表，`cur` 增量不等 ⇒ 音符起奏间隔不等 ⇒ **颤动**。

用 NP2kai 真实参数建模（秒级量化 + 20–28Hz pass）可测得该钳制的速率误差 −24.5%..+7.1%（见 §4 的 `test_vclock.py` 同类断言）。

**关键点：这不是新增缺陷，是 devdoc 129 把既有缺陷从「被平均掉」变成「直接可闻」。**

## 3. 修复：改钳制为平滑变步进

时钟的职责是「给出稳定的微节拍」，而 BGM 是**闭环播放**（MIDI 表从 t=0 到 end，无外部同步源），所以：

> **只有速率重要，相位不重要。** 这允许步长平滑变化，而不必追逐瞬时相位误差。

新模块 `core/lib/vclock.{c,h}`（纯整型、零 I/O、零平台调用，沿用 fmopn/fmseq 的主机穷举范式）：

- `step` 以 1/16 ms 为单位，向「平台实测速率」**平滑收敛**，每 pass 最多挪 `VCLOCK_SLEW_UNITS`（8 单位 = 0.5ms）；
- 一个「窗口」= 两次平台时钟移动之间的所有 pass。窗口闭合时用 `delta / passes` 反推真实每 pass 速率；
- 平台不动（时钟洞）→ 吐固定 idle 步，**不停**（守住 devdoc 129 的修复）；
- 单步上限 `VCLOCK_MAX_ADVANCE_MS=100`，大跳变被摊到覆盖它的那些 pass 上，**不爆**；
- 长期平均追踪真实时间 ⇒ **音高/速度正确**，歌曲不赶不拖。

### 3.1 与旧设计的区别

| | 旧（钳制） | 新（变步进） |
|---|---|---|
| 步长来源 | raw delta 钳到 [40,100] | 实测速率平滑收敛 |
| 洞内行为 | 固定 40 | 固定 idle（同） |
| 大跳变 | 单拍钳到 100（丢 surplus） | 摊到覆盖 pass |
| 相邻步差 | **0 或 60ms（2.5:1）** | **≤ 0.5ms** |

最后一行就是颤动的消失处。

### 3.2 HAL 职责收缩

`hal_pc98.c` 只保留 wiring 与 writer/reader 切分：

```c
static VClock g_vclock;                       /* 单一状态 */
unsigned long hal_wallclock_smooth_ms(void)   { return vclock_ms(&g_vclock); }
void hal_wallclock_smooth_advance(void)      { vclock_advance(&g_vclock, hal_wallclock_ms()); }
```

`hal.h` 的 `SMOOTH_CLOCK_MIN_MS/MAX_MS` 常量**已删除**（它们是颤动的直接成因，留常量就会有人再引）。

## 4. 验证

### 4.1 主机穷举（新 `tools/tests/test_vclock.py`，9 项）

`gcc -shared` 编译 `core/lib/vclock.c`，ctypes 驱动。断言：

- **相邻 advance 差 ≤ 1ms**（钉死的正是缺陷本身：旧钳制交替 40/100）
- 冻结时钟仍稳定推进（**不回到 devdoc 129 前的停表**）
- 大跳变不单拍倾泻（`<= VCLOCK_MAX_ADVANCE_MS`）
- pass 率 15/20/25/30Hz 下长期追踪真实时间（±5%）
- 时间倒退 → 重新同步，不炸

**变异验证**（4 组均被对应项捕获，非碰巧通过）：

| 变异 | 结果 |
|---|---|
| 去掉 slew 有界性（直接 `step=target`） | `test_rate_change_converges_without_lurch` FAIL |
| 恢复 floor/ceiling 钳制 | `test_tempo_at_various_pass_rates` FAIL |
| 冻结时钟不推进 | `test_long_run_tracks_real_time` + `test_tempo_*` FAIL |
| 删除 advance 写入 | 编译即失败 |

### 4.2 回归

`./start.sh fullaudit` 全绿：pytest **760 passed / 1 skipped**、`make -C core` 0 err/0 warn、symbol_audit A/B 节空。既有 `test_reveal_final_page.py::test_smooth_wallclock_bounds_in_hal` 的断言从「钳制定居 HAL」订正为「钳制已废止 + vclock slew 有界」（见 §5）。

## 6. 遗留

- 实机音质确认（速率/音高/无颤动）由用户在真机/NP2kai 完成。
- `VCLOCK_SLEW_UNITS=8`（0.5ms/pass）：在 20→28Hz pass 率变化时约 1s 收敛。若实机仍有可闻的渐快/渐慢，调大该值（代价是相邻步差上界上升）。
- 真机 60Hz 下 idle 步（16ms）会略慢于真实节奏；若将来以原生硬件为目标，按 B19 §3.1 的既有约定重新校准 `VCLOCK_INIT_STEP_UNITS`。
