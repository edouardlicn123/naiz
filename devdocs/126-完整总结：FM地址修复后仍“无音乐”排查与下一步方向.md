## 1. 问题回顾

用户反馈：修复 `fm_op_addr`（`base + 4*r`）并做 FMP 微调后，**主观上仍然“没有音乐”的声音**。

实测数据（`precise*.raw`，提前后台启动 parec + monitor 源）：
- `BGM start 'melody_town' (310 events) (FM)` 正常触发（串口日志）
- 首音瞬态：从 pre-fix ~ -54 dBFS 提升至 ~ -24 dBFS（峰值 2048）——**地址修复已生效（寄存器写到正确算子）**
- 持续段：双声道有能量（R 声道更明显），活动段落 rms ~ 600–1100（约 -29 dBFS），整体 RMS 仍偏低
- FMP SL 分布 2–9（并非此前推断的 14）。flute 族 TL 微调（-6）改善声道平衡但主观改善有限，已恢复原值

结论：**波形上有 FM 信号输出，但主观听感偏弱甚至“没听到音乐”。**

## 3. 核心矛盾与可能原因

波形存在≠主观可听。排查方向：

- **A. 主机音量/平衡**：信号主要在 R 声道。模拟器音量、系统音量、PulseAudio 平衡、扬声器/耳机单侧都可能导致“听不到”。
- **B. hal_audio.c 临时诊断态残留（最高怀疑）**：先前为诊断保留的改动（`FM_TRACE_ENABLED=1`、`hal_fm_init()` 中写 `0x0F/0x2F`、`hal_fm_set_volume()` 固定写 `0x0F`）可能导致 FM 整体衰减。波形 rms 偏低（持续段 ~-29 dBFS）很可能与此相关。
- **C. A466 音量路径（VOL1/VOL2）**：devdoc 123 指出 A466 各路径独立（VOL1/VOL2/VOL6）。`bgm_apply_volume()` 对 FM 写 `hal_fm_set_volume(15-atten)`。需确认 `hal_fm_set_volume` 当前实现是否正确选通 **VOL1** 路径且未错误覆盖其他值。
- **D. FM 初始化顺序（A460 bit0）**：`hal_fm_init()` 必须先置 A460 bit0 才能让 `0x18C/0x18E`（扩展组 ch4-6）路由生效。melody_town 是否只用 ch0–3 尚未确认，但顺序仍需核对。
- **E. fmseq finished 判定过早导致提前停播**：FM 模式下 `audio_tick()` 在 `fmseq_finished()` 时 `fmseq_stop()+rewind`（不重载事件）。若平滑时钟导致 `cur` 超出总时长，可能触发 finished→stop，只剩极短脉冲。需观察串口是否出现 `FM loop: ...` 或 finished 相关日志。
- **F. MIDI 事件解析/族映射**：melody_town 仅检测到 program 73（flute）。是否存在其他轨道/程序变更？fmp_gm_map 正确性已由 devdoc 124 验证，但仍可复核。
- **G. PCM 路径干扰？**：音频三通路独立，但需确认无意写入影响 FM 的寄存器。

## 4. 下一步排查计划（按优先级）

### 步骤 A：主观直试听（零改动，最快）
- 在 wxNP21kai 直接运行 `disks/demo-a2.hdi`，提高系统/模拟器音量，左右声道平衡居中，试听到 nbook001 场景（melody_town）。
- 用耳机重试。同步用宿主 `aplay /tmp/opencode/precise5.raw`（stereo s16le 44100）确认录音本身能听见旋律。

**预期结果**：若宿主能听见但模拟器几乎听不见 → 更倾向模拟器设置/hal_audio.c 音量路径问题。若宿主也听不清 → 更倾向整体电平偏低。

### 步骤 B：还原 hal_audio.c 临时诊断态（最可能）
检查并还原以下临时改动：

- `#define FM_TRACE_ENABLED 1` → **恢复为 0**（或按原始非诊断值）。trace 本身不改音量，但保持开启会持续刷日志；更关键是确认原本预期值。
- `hal_fm_init()`：先前写 `outb(PCM_STATUS_PORT, 0x0F); outb(PCM_STATUS_PORT, 0x2F);`（诊断用）。应恢复为**仅按需**写入，并且 `hal_fm_set_volume()` 要正确选通 VOL1 路径（A466 bit7-5 = 000b？F02 §4.2：VOL1 path 需正确的 path code）。当前 PCM 用 `PCM_VOL_PATH_PCM = 0xA0`（101b），FM 用 VOL1 路径（000b？）的编码需核对 F03/F02。
- `hal_fm_set_volume()` 当前写死 `0x0F`（临时诊断）——**必须改回**按 atten 正确编码：`outb(PCM_STATUS_PORT, (uint8_t)((VOL1_PATH<<5)|atten_reversed))`，且要与 `bgm_apply_volume()` 的“reversed”语义一致（0=loudest）。

**核对要点**：F03/F02 关于 A466 路径选择（VOL1 = FM direct）。PCM 路径是 101b（0xA0），FM 直接音量路径很可能是 **000b**（VOL1）而不是 101b。若临时把 FM 也写成 0x0F（低4位 atten）却 path 码错，可能选错路径导致无效写入或异常衰减。

**行动**：先比对 git 历史中 hal_audio.c 的“非诊断”版本（devdoc 123 落地前后的原始形态），精确还原。

### 步骤 C：复核 hal_fm_init/A460 顺序
确认：
```c
outb(PCM_ID_PORT, 0x01);  /* A460 bit0 select OPNA; bit1 must be 0 */
...
```
顺序正确（先选 OPNA，再写 A466）。

### 步骤 D：排查 fmseq_finished 过早（加临时日志）
在 `audio.c::audio_tick()` FM 分支的 finished 处加临时串口日志：
```c
if (fmseq_finished(g_fm_seq)) {
  int ring = fmseq_fm_voices(g_fm_seq);
  hal_logf("FM finished: ring=%d idx=%ld/%ld cur=%lu wall0=%lu\r\n", ring, (long)g_bgm.idx, (long)g_bgm.count, cur, g_bgm.wall0);
  ...
}
```
跑串口驱动到 BGM start 后前 5–10 秒，观察是否在 1–3 秒内频繁触发 finished（尤其是首个 note 后很快触发）。

若是，需检查 `fmseq_finished()` 定义（`core/lib/fmseq.c`）和时钟计算（平滑时钟 `hal_wallclock_smooth_ms()`）。

### 步骤 E：pytest 回归
还原诊断态并改动后，跑 FM 相关测试确保无回归：
```bash
tools/env_setup/venv/bin/python -m pytest tools/tests/test_fm_seq.py tools/tests/test_fmopn.py tools/tests/test_audio_asset_paths.py tools/tests/test_audio_settings_invariants.py tools/tests/test_audio_toolchain.py -q
```

### 步骤 F：更精细的 FMP 微调（备选）
若还原后仍偏静，可针对**真正参与旋律的族**（除 flute 外是否还有？目前只确认 program 73）做载波 TL -2/-4 小步，单族验证。优先载波算子而非 SL。

## 5. 推荐立即执行顺序

**B → A（主观对比） → C/D（必要时） → E**

理由：B（还原临时诊断态）改动最小、最有可能直击“波形有但持续电平衰减”这个矛盾。改完后直接主观试听（A）比继续调 FMP 更有效。

## 6. 本文档预期结论

地址修复（base+4*r）是正确的、已验证生效（瞬态提升）。现状“主观没听到音乐”的根因很可能是 **hal_audio.c 临时诊断态残留导致 FM 音量路径写入错误/衰减过大**。按上述顺序排查后再决定是否要调 FMP。
