# 110-光标写入全程零缺窗：对话框合成缓冲预拼光标

> 状态：**已落地**（0.2.137）
>
> 所属：软件光标层（cursor.c / cursor.h / layer_dialog.c）
> 上游：devdoc 108（软件光标层契约与对话框抹字收口）、devdoc 109（写后直绘 + 不透明矩形快路径）；本 doc 为其**写入时长窗口残留缺窗**的根治补充。

## 1. 问题与复现

0.2.136 落地后用户仍报告两症状：

1. **打字机揭示时鼠标停在对话框上仍闪烁**（低频，~20Hz 语义的「一闪一闪/发虚」）；
2. **人物切换表情时鼠标消失**（瞬时「没了」，随后恢复）。

0.2.136 声称消除的「每 pass 满帧缺席」显然只做了**尾部**一半——箭头仍在 pass 中段被清掉、直到 pass 末才回补。

## 2. 根因（0.2.136 只修了一半）

箭头唯一的重建点仍是 **pass 末尾** `hal_mouse_draw_cursor()`（main.c 外/内循环 :127/:143/:205）。pass 中段所有覆盖/擦除它的写入发生后，箭头**全程缺席**直到 pass 末：

- **打字机揭示（光标在对话框内）**：每个 pass 的 `dialog_layer_blit()` 把 480×115 composite 经 **DOS/4GW bank 切换 VRAM 窗口整块 `vram_write`**（NP2kai 上数 ms~十几 ms）。箭头在**写入开始即被覆盖**（opaque touch 只 invalid、不清场，交给写者替光标清场 → 写者一个字节一个字节地把箭头区域冲掉，头几百行一过箭头就没了），而重画要等 pass 末。~20 pass/s 下，每次揭示 pass 箭头都缺席一大段 → 观感「仍闪烁」。
- **切表情（光标停角色/舞台区 y<280）**：`layer_sprite_face`（layer_sprite.c:182）入口 `invalidate`（擦）→ bg restore → 新脸 `vram_blit_sprite`（一次也是数万像素突发）→ 箭头在整段突发期间缺席，pass 末才回补 → 那刻观感「鼠标消失」。

0.2.136 的 stale 同位置直绘只删掉了 `cursor_render` 尾部的 `hal_vblank_wait`（≤16ms），**写入自身的时长窗口从未被缩短**——二者同源：箭头在 pass 中段的写入突发期间没有覆盖，pass 末回补太晚。

## 3. 方案（把光标拼进合成缓冲，写入全程零缺窗）

### `cursor_composite_splice(buf, stride, fx, fy, fw, fh)`

新增（cursor.c / cursor.h，0.2.137）：

```
int cursor_composite_splice(unsigned char *buf, int stride,
                            int fx, int fy, int fw, int fh)
```

当当前光标盒（24×24，以 `hal_mouse_get_display_x/y − CURSOR_HOT` 定盒）**完整落入**上报矩形 `(fx,fy,fw,fh)`：

1. 先从**缓冲 RAM** 把盒区域原文（对话框正文）`memcpy` 为 `cursor_saved.buf` —— 防残影基准（后续 erase 恢复的是这次随帧更新的正文，不是历史快照）；
2. 按 `is_fill_pixel(row,col)→PAL_WHITE` / `is_cursor_pixel(row,col)→PAL_CURSOR_BLACK` / 兼非→ 保留缓冲像素，把箭头**混进缓冲**的盒偏移处（与 `draw_shape` 完全同一混合模型）；
3. `cursor_saved.x/y = draw_x/draw_y; valid = 1; return 1;`。

**无 vblank、无 erase、无额外 VRAM 访问**（纯 RAM 混合）。未命中（鼠标不可用 / 盒未完整落入矩形）返回 0，调用方维持既有路径。

### `dialog_layer_blit` 集成

```
hal_mouse_touch_cursor_opaque(对话框矩形);   // 跨边仍 erase
cursor_composite_splice(dialog_layer, LAYER_DIALOG_W, 对话框矩形); // 完整落入 → 预拼
vram_write(dialog_layer, 对话框矩形);        // 一次写入，全程带箭头
```

→ 经 bank 切换 VRAM 窗口的整块 composite 写入**每行都带着箭头像素**登陆，写入多慢都零缺窗；pass 末 `cursor_render` 因 `valid && 同位` 早退（箭头已在画面）。

### 约束（C18 升级版）

- 只有**全像素不透明**的合成分支可 splice；透明/部分缓冲（`render_blit_transparent`、OOM 部分文本）**禁止**——活箭头会被烘进持久背景，重演 devdoc 108 残影（旧箭头随背景被恢复）。
- 跨边盒（探出矩形）维持 opaque touch 的 erase + pass 末 stale 直绘兜底。
- 使用前 `hal_mouse_available()` 门控，无心智负担。
- **精灵/舞台侧（bug ②）** 不 splice：写入是直绘到 VRAM 的一次性突发（非合成缓冲），保持 0.2.136 pass 末 immediate 直绘兜底（缺窗 = 精灵写入时长，一次性毫秒级）。真机目检复核。

## 4. 守卫测试（+2 = 442）

- `test_dialog_layer_blit_splices_before_vram_write`：`cursor_composite_splice` 调用位于 opaque touch 之后、`vram_write` 之前（顺序既定，防回退）。
- `test_cursor_composite_splice_blends_and_adopts_bg`：实现含 `is_fill_pixel` / `is_cursor_pixel` / `memcpy`（背景先存后拼）/ `valid = 1`，且函数体**不含 `hal_vblank_wait`**。
