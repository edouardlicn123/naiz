## 1. 需求（用户原话）

> 我发现有两个问题，希望你说说看法 1 场景没有 cg 那样的未玩就锁定（不显示）的设计，需要补充 2 执行场景结束，系统是按脚本走，而不是返回 scene 菜单。

澄清后的三条口径（用户选择）：

| 问题 | 决策 |
|---|---|
| 解锁时机 | **进入即解锁**：`nbookNNN.nb` 一载入就置位，不等待该场景跑完 |
| 链式跳转 | 「正常游玩时走脚本，scene 播放返回 scene 菜单」：鉴赏内 `scene(003)` 继续链式播放，`scene(end)` 才回鉴赏 |
| 空菜单 | 构建期空表 → `No scenes available.`；有表但全锁 → 新增 `Play the story to unlock scenes.` |

## 2. 设计决策

| 项 | 决策 | 理由 |
|---|---|---|
| 解锁位 | 复用既有 `SystemSave.scene_flags`（`SCENE_TOTAL=100`），新增 getter `sys_save_is_scene_unlocked()` | 位图与写入函数 0.4.029 前已存在，只缺读侧；CG 画廊同构 |
| 解锁点 | `nb_load()` 载入成功后按 `sscanf(nb.filename, "nbook%u.nb")` 置位 | 唯一场景入口是 `scene_switch → nb_load`，放这里覆盖脚本跳转 / 菜单 / 读档 / 鉴赏全部路径，无需在每个调用点重复 |
| 写入节流 | `sys_save_unlock_scene()` 已置位则直接 return | 解锁改为每次进入触发后，若无条件写盘等于每次切场景写整个 SYSTEM.SAV |
| 重复解锁 | 删除 `scene_target_name()` 的旧解锁块、删除 `save.c` 读档后的旧解锁块 | 单一一处（`nb_load`）即事实源；§十「同一结论只留一份」 |
| 表内解锁 id | 构建期从 `nbookNNN.nb` 解析，写入 `SceneMenuEntry.unlock_id`（1..`SCENE_TOTAL`） | 运行期无法可靠反推 id；onlist 却无 id 的场景会永久不可见，必须构建期硬失败 |
| 可见性 | 进菜单时 `scm_build_visible()` 生成 `scm_visible[]` 下标表，网格 / 翻页 / 焦点 / 命中全部按可见数 | 「不显示」而非「灰显」：与 CG 画廊一致，且避免玩家在锁定格上按 Enter |
| 播放态 | 新增 `SCENE_SWITCH_GALLERY` reason；`scene_switch()` 内 GALLERY 置位、SCRIPT 保持、其余清零 | 播放态属场景切换语义，放唯一入口最稳；`scene(end)` 时 `scene_target_name()` 读 `nb_get_playback_mode()` 改投 `scenes.nb` |
| 结束返回 | `scene(end)` + 播放态 → `scenes.nb` 且以 `SCENE_SWITCH_MENU` 切（顺带清播放态） | 回到鉴赏菜单即复用 208 的网格；`scenes.nb` 再次执行 `scenesmenu()`，`nb_get_menu_return()` 仍指向 special/mainmenu，Back 正常 |
| 泄漏防护 | 任何非 SCRIPT/GALLERY 的切换都清播放态 | 鉴赏中经热键/读档/主菜单离开后，下一次正常游玩不会被误判成鉴赏播放 |

## 3. 实现

### 3.1 持久化（`save_sys.c` / `save.h` / `save.c`）

- `sys_save_unlock_scene()`（`save_sys.c:56`）：已置位早退；`sys_save_is_scene_unlocked()`（`save_sys.c:70`）越界返回 0。
- `save.h:89` 声明 getter。
- `save.c` 读档分支删掉重复的 `sscanf` 解锁块，注释指向 `nb_load`。

### 3.2 进入即解锁（`nb.c:257-264`）

`nb_load()` 在 `str_copy(nb.filename, ...)` 之后：

```c
{
    unsigned int scene_id;
    if (sscanf(nb.filename, "nbook%u.nb", &scene_id) == 1)
        sys_save_unlock_scene((int)scene_id);
}
```

`main.c` 在 `nb_init()` 之前调用 `sys_save_load()`，故不会用零值覆盖既有 CG/结局/场景位。

### 3.3 播放态（`nb.c:325-357`、`nb.h`）

- `nb.h`：`SceneSwitchReason` 增 `SCENE_SWITCH_GALLERY = 5`。
- `nb.c`：`static int g_playback_mode` + `nb_get_playback_mode()`（声明于 `nb_internal.h`）；`scene_switch()` 的 `rname[]` 增 `"gallery"`，并在日志之后：

```c
if (reason == SCENE_SWITCH_GALLERY)
    g_playback_mode = 1;
else if (reason != SCENE_SWITCH_SCRIPT)
    g_playback_mode = 0;
```

### 3.4 结束拦截（`nb_scene.c`）

`scene_target_name()` 改为返回 `int`（1 = 鉴赏返回）：

```c
if (strcmp(target, "end") == 0) {
    if (nb_get_playback_mode()) {
        snprintf(fname, fsize, "scenes.nb");
        return 1;
    }
    snprintf(fname, fsize, "mainmenu.nb");
    return 0;
}
```

`scene_jump()`（`nb_scene.c:73-75`）与 `cmd_jumpscene()`（`nb_scene.c:323-332`）据返回值选 `SCENE_SWITCH_MENU` / `SCENE_SWITCH_SCRIPT`，故 `scene(end)` 与 `jumpscene(...,end)` 行为一致。

### 3.5 可见性过滤（`nb_scene_menu.c`）

- `scm_visible[]` / `scm_visible_count` / `scm_build_visible()`（76-87）：按 `sys_save_is_scene_unlocked(entry.unlock_id)` 建下标表。
- 网格与分页：`menu_pagecount(scm_visible_count, ...)`（155/265）、行截断（175）、局部重绘（197/203）、键盘上下界（287/296/316）、鼠标命中（352）全部改可见数。
- `scm_draw_cell()` 渲染时经 `scene_menu_entries[scm_visible[abs_idx]]` 映射回全表。
- 空态：`scm_empty(const char *msg)` 参数化；`SCENE_MENU_COUNT==0` → `No scenes available.`，否则 `scm_visible_count==0` → `Play the story to unlock scenes.`（257-263）。
- 播放：`scene_switch(scene_menu_entries[scm_visible[chosen]].scene, SCENE_SWITCH_GALLERY)`（374-375）。

### 3.6 构建期（`tools/naiz_build/scene_menu.py`）

- `SCENE_TOTAL = 100`（与 `save.h` 对齐，测试断言相等）。
- `_scene_unlock_id()`：`re.fullmatch(r'nbook(\d+)', stem)`，缺失或超界即 `RuntimeError`（onlist 场景必须可追踪）。
- 表行变 4 字段：`{ "nbook005.nb", "Come with cat", 29, 5 },`；`SceneMenuEntry` 增 `unsigned char unlock_id`。

### 3.7 演示数据

- `nbook005.nb` 保持 onlist；`nbook002.nb` 补 onlist（用户选择「多标一个」），使解锁后网格有 2 项。

## 4. 与 208 的偏差

| 208 原决策 | 209 调整 | 原因 |
|---|---|---|
| 播放 `SCENE_SWITCH_SCRIPT` | `SCENE_SWITCH_GALLERY` | 需要区分「脚本正常推进」与「鉴赏播放」，否则结束无法分流 |
| 「运行期访问器」一律删除 | 新增 `sys_save_is_scene_unlocked()` 与 `nb_get_playback_mode()` | 两者均有真实消费方（可见性过滤 / 结束拦截），不触发 R30 死导出 |
| 空表仅 `No scenes available.` | 追加全锁空态文案 | 有 onlist 但未玩时，空表文案会误导为「没有场景」 |

## 6. 踩坑与防复发

1. **旧解锁点是「离开当前场景时」**：`scene_target_name()` 在解析任意跳转目标时解锁**当前**场景，导致 `scene(end)` 结束的 `nbook005` 从未解锁、且读档路径各自补一份。改为进入即解锁后必须删掉两处旧逻辑，否则「同一语义三份实现」。
2. **解锁改为高频后必须节流**：每次 `nb_load` 都置位，若无早退就是每次切场景写一次 SYSTEM.SAV。
3. **播放态不能放 `NbState`**：`nb_load` 开头 `memset(&nb, 0, sizeof(nb))`，放进去会在每次切场景被清零，`scene(003)` 链式播放立刻丢失。现为 `nb.c` 文件级 static。
4. **行号漂移**：`nb_load` 新增解锁块 + `scene_switch` 新增播放态使 `nb_set_lang` 定义 360 → **387**；`test_devdoc_refs.py` 白名单与 207/208 的校准说明已同步。
5. **CJK 字库守卫会因新译文变红**：新增 `Play the story to unlock scenes.` 译文后必须先 `build`（重生成各语言字库）再跑全量 `pytest`，否则 `test_cjk_font_freshness` 类断言失败。
6. **i18n 宽度是硬约束**：首版德语 31 字符 = 248px > 240px 被守卫拦下，改为 `Spielen zum Freischalten.`（200px）；新增固定宽度区域的译文必须按 `text_width` 规则（非 ASCII 16px/字符）核宽。
