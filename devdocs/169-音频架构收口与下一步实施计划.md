## 一、缘起

用户提问：**「有没有必要重写架构，让 BGM 跟其它功能不冲突？」**

先把「冲突」拆开。当前代码里的「冲突」其实是四件性质完全不同的事，混在一起谈才会得出「要重写」的结论：

| # | 现象 | 真实性质 | 归属 |
|---|---|---|---|
| A | BGM 拖沓、半速；SE/语音断续 | **一个常量错**（129 = 半周期） | `hal_irq.c:66` |
| B | 立绘/场景解码期 BGM 停住 | **CPU 密集期不喂泵**，已有解码泵 | `frame.c:78-89`（+ 各输入循环） |
| C | SE 把语音顶掉、语音把 SE 顶掉 | **86 板只有一条 PCM FIFO**，硬件事实 | `hal_audio.c:176` |
| D | 换曲/调音量时与 ISR 抢 OPNA 寄存器 | **主线程与 ISR 写同一组端口**，已有深度锁 | `audio.c:39-71` |

- **A 是 bug**，不是架构问题。
- **B 已经解过一轮**（`devdocs/129` / `131` / `163`），残留是（A）导致的时间基错误在放大它。
- **C 改不了**：YM3433B 只有一路 PCM 输出，任何软件架构都无法让两路采样同时发声。能做的是**策略**（谁优先、最小播放时长），不是架构。
- **D 已经做对**：`bgm_irq_lock` 是深度计数、可重入、ISR 内自动 no-op（`audio.c:56-72`）。重写不会更好。

**因此：A + ② 修完，用户感知到的「冲突」至少消失九成；剩下的 C 是产品策略题，不是架构题。**

**三处隐性缺陷**（本轮一并处理，见 §五.1.2）：

1. **整毫秒量化在 ISR 路径下是系统性偏差**：`vclock_ms()` 做整除（`vclock.c:166-170`），258 units = 16.125 ms 被读成 **16 ms**，每 tick 少 0.125 ms ⇒ 投料速率恒慢 **0.78%**（取 129 时更极端：8.0625 → 8 ms，与半速故障叠加）。协作路径是「两个时间戳相减」，量化误差在相邻 tick 间互相抵消，**无累积偏差**——所以本轮重点是 ISR 路径，但统一改用 1/16 ms 单位后两条路径口径一致。
2. **`push` 上限截断后余数不回补**（`hal_audio.c:190-191`）：只要出现一次延迟 tick（`elapsed` 累计 32 ms），被 cap 掉的字节**永久丢失**，表现为「卡一次 → 后半拍一直欠喂」。
3. **`1000 ms` 上限不区分「首拍」与「延迟拍」**（`audio.c:678-679`）：首拍截断无害，延迟拍截断会丢时间。

## 三、数值依据（不重推，只列结论与出处）

真机与 NP2kai 的周期公式（`F07` §2/§3/§6）：

```
真机 :  tB = 2304 × (256 − NB) / φM          φM = 7.9872 MHz（86 板，MAME pc9801_86.cpp:85）
NP2  :  tB = 288 × (256 − NB) µs             （代数化简后与宿主无关）
```

`NB = 200`：

| 宿主 | 周期 | 1/16 ms units | 取 258 后的误差 | ISR 频率 |
|---|---|---|---|---|
| 真机 7.9872 MHz | 16.1538 ms | 258.46 | **−0.18%** | 61.90 Hz |
| NP2kai | 16.128 ms | 258.05 | **−0.02%** | 62.00 Hz |
| **现有 129（半周期）** | 8.0625 ms（虚拟钟每 16.128 ms 真实时间只走 8.0625 ms） | 129 | **−50.0%** | 日志误报 124 Hz |

`129` 的来源是把手册的 `tB = 1152·(256−NB)/φM` 里的 **1152 当成了 φM 的个数**；1152 配的是 **φM/2** 时钟。四份独立实现（ymfm / Nuked-OPN2 / BlastEm / NP2kai）与 PMD、MUCOM88 的节拍常数一致给出 2304，逐条对照见 `F07` §3、§4。

**分档方案已作废**（两宿主只差 0.16%，`devdocs/168` 订正表第 4 行）。任何形式的 `#ifdef NP2KAI` 分档都被本计划禁止。

#### 5.1.2 PCM 投料改为「时钟推进量」（`hal_audio.c` + `audio.c`）

**问题**：`audio_tick_isr()` 用 `now - last_pcm_ms`（两个虚拟时间戳相减）当投料时长。协作路径下虚拟钟是**有意 slew** 的（`vclock.c:150-156`，每步最多 ±8 units）并被 `VCLOCK_MAX_ADVANCE_MS` 截断（`vclock.c:158-161`）——拿它的**差值**当速率源，等于把音乐钟的平滑抖动注进 PCM；ISR 路径下虽无 slew，但整毫秒截断自带 **0.78%** 欠喂（§2.3 第 1 条）。改固定增量 + 1/16 ms 单位后，ISR 路径的误差只剩常量本身（0.18%）。

**改法**：

1. **单位化**：`hal_pcm_tick(uint32_t elapsed_ms)` → `hal_pcm_advance_units(uint32_t units)`（`units` 为 1/16 ms，与 `VCLOCK_UNITS_PER_MS` 同单位）。内部 `push = rate_hz * units / (1000 * 16)`。
2. **余数回补**：新增 `static uint32_t g_pcm_debt_bytes`——本次应喂而没喂到的**字节**，**记债到下一次**，不再永久丢弃。用字节而非时间作债的计量单位：债的来源是「cap 截断」与「FIFO 满提前 break」两种，两者天然是字节量，用时间债会在 `units ↔ bytes` 换算里引入 ±1 unit（0.06 ms）的舍入偏差。债必须**有上限** `PCM_DEBT_MAX_BYTES 44100`（1 s @44.1k）：`hal_pcm_stop()` / EOF 时清零，超过上限即丢弃——一次超过 1 s 的停顿不是「迟到 tick」而是流已停，继续背债只会让下一拍灌出一段 DAC 来不及吃的突发。同时 `PCM_TICK_MAX_BYTES` **1024 → 2048**（46 ms @44.1k）：一个 16.15 ms 步进约 711 字节，双周期约 1422 字节，1024 会让迟到 tick 必然欠债。
3. **调用点**（唯一，`audio.c:683`）：
   - ISR 路径：`hal_irq.c` 直接传 `BGM_TIMER_B_UNITS`（258），**不再读虚拟时间戳**；
   - 协作路径：`audio_tick()` 传上一帧实际 emit 的 units。
4. **协作路径的 emit 量从哪来**（**已定案：访问器，不改进 `vclock_advance()` 返回值**）：新增
   ```c
   unsigned long hal_wallclock_last_advance_units(void);
   ```
   在 `hal_pc98.c` 实现，由 `hal_wallclock_smooth_advance()` 与 `hal_wallclock_fixed_advance()` **两者都写**（后者写实际传入的 delta，`vclock_advance_fixed()` 首拍不 emit 时写 0）。选访问器而非返回值的理由：① 帧路径与 `hal_audio_pump()`（第 2 轮）都能直接取用，不必把 emit 值一路穿参；② 不改 `vclock.h` 的既有签名，减少库层改动面。
   - `audio_tick_isr()` 签名随之改为 **`void audio_tick_isr(unsigned long elapsed_units)`**：ISR 传硬件周期、协作路径传访问器值，**PCM 的时间来源从此只有一个入口**。

**明确否决**：改用 `hal_wallclock_ms()`（`hal_pc98.c:87-117`，DOS `INT 21h AH=2Ch`）作为音频速率源。理由两条：① ISR 上下文不可重入（`devdocs/165` B1，AGENTS §十四「Timer-B」第 2 条）；② 粒度 10 ms、在 NP2kai 上实测退化成**秒级**，会让投料呈「一秒一大坨 / 其余全饿」的断续，比现状更差。

#### 5.1.3 G2 的诊断量化（不是永久日志）

`AUDIO_PUMP_TRACE` 已有 `[AP] gap/v/w/d` 机制（`audio.c:738-757`）。第 1 轮增加一个**编译期开关**（默认 0）`PCM_RATE_TRACE`：每 64 次投料打印一次

```
[PCM] t=10000 bytes=441000 want=441000 r=1000/1000
```

（`bytes` 实投累计、`want` 标称累计）。10 s 窗口即可判 G2，**验证完默认关闭**，代价为零。

> **实现位置（与 §八 R4 一致，别弄反）**：`hal_audio.c` 只维护两个 `uint32_t` 累计量 `g_pcm_bytes_pushed` / `g_pcm_bytes_want`（纯整数加法，ISR 安全），**不在里面打印**；由 `audio_tick()`（帧路径，每 64 次）取数后 `hal_logf`。在 ISR 里 `hal_logf` 会违反 AGENTS §十四「Timer-B」第 2 条 B3（串口阻塞 I/O）。

### 5.2 第 2 轮（P1）— 把「谁拥有节拍」收进 HAL

> **这是唯一算得上「架构」的一项**，但它是**收口**不是重写：把散在引擎里的分支搬进 HAL，契约不变、行为不变。

#### 5.2.1 问题

`frame.c` 的 `#if NAIZ_BGM_IRQ`（15、78）实际编码的是 HAL 的内部决策：

> 「Timer-B ISR 已安装 ⇒ 时钟与音频都由它负责，帧路径不许再推进。」

这条规则**属于 HAL**，让引擎来执行有三个后果：

1. 以后换时间源（例如给协作路径加实时累加器）要改引擎三个文件；
2. 两套路径的验证矩阵各写一遍（ISR 看 `[ISR]`，协作看 `[VC]`）；
3. 开关只含半条管线时，引擎与 HAL 的编译视图可能不一致（AGENTS §八 六禁之六的直接土壤）。

#### 5.2.2 目标契约

```c
/* core/plat/hal.h */
/* Sole audio-pump entry for the engine.  The platform owns the decision of
 * who advances the time base (Timer-B ISR or the frame heartbeat), advances
 * it at most once per call, and pumps audio once.  Engine code must not call
 * hal_wallclock_smooth_advance() or audio_tick()/audio_tick_isr() directly. */
void hal_audio_pump(void);
```

实现放 `core/plat/hal_irq.c` **`#if NAIZ_BGM_IRQ` 之外**（该文件从此职责为「节拍所有权」，名字与内容一致）：

```
/* in hal_irq.c, OUTSIDE the file-wide #if */
void hal_audio_pump(void)
{
#if NAIZ_BGM_IRQ
    if (hal_bgm_irq_active()) return;   /* ISR owns the beat: it advances + pumps */
#endif
    hal_wallclock_smooth_advance();
    audio_tick();
}
```

> **实施陷阱**：`hal_bgm_irq_active()` 的**定义**在 `hal_irq.c:240-243`，位于 `#if NAIZ_BGM_IRQ` **之内**（`#endif` 在 `:265`），开关关闭时不存在。所以 `hal_audio_pump()` 的函数体必须**外层无条件、内层 `#if` 包住那一行 `if`**——把 `#if` 挪进 HAL，而不是删掉它。默认构建下这个函数就是「推进 + 泵」，与今天 `frame.c:46-47` 的 `#else` 分支等价。

> `audio_tick()` 内部已直接调用 `audio_tick_isr()`，所以内核仍然只有一份，不产生第三条路径。

#### 5.2.3 引擎侧变化

| 文件 | 变化 |
|---|---|
| `core/engine/frame.c:15-48` | 塌缩为：`vblank_wait(); hal_audio_pump();` + `[ISR]` 采样（`hal_bgm_irq_active()` 是**运行期查询**，不是编译开关，保留）+ `anim_tick()` + `reveal_tick()` |
| `core/engine/frame.c:78-89` | 塌缩为：`hal_audio_pump();` + `vblank_poll()` 后的 `anim_tick()` |
| `core/engine/audio.c:636-642` | `hal_bgm_irq_init()` 的安装调用可留在 `audio_init()`（FM 后端就绪是前置），也可移入 `hal_fm_init()`；**建议保留**，因为「FM 就绪才装 ISR」是引擎侧的语义 |
| `core/engine/frame.c` | `#if NAIZ_BGM_IRQ` 计数 → **0** |

#### 5.2.4 为什么不是「干脆删掉 ISR」

删掉 ISR 能让代码少一半，但会把 B（CPU 密集期饿死音泵）重新暴露在**所有**未挂 `frame_decode_pump()` 的路径上（音色加载、大图 blit、场景重绘、存档写盘）。ISR 的价值正是「不依赖主线程让出 CPU」。**保留 ISR，但只在真机判据失败时启用回退方案**（§八 R1）。

#### 5.2.5 守卫

扩展 `tools/tests/test_frame_pump.py`：

- 断言 `core/engine/frame.c` 中 `NAIZ_BGM_IRQ` 出现次数为 **0**；
- 断言 `core/engine/audio.c` 中保留的 `#if NAIZ_BGM_IRQ` **只**出现在状态互斥位置（锁 / 安装），且每处带注释说明「这是状态互斥，不是时钟所有权」——写死一份允许行号清单，新增一处即失败；
- 断言 `frame.c` 只通过 `hal_audio_pump()` 触达音频（不得直接出现 `audio_tick`、`hal_wallclock_smooth_advance`）；
- 断言 `hal.h` 声明了 `hal_audio_pump`，且 `hal_irq.c` 中该函数的**定义**不在 `#if NAIZ_BGM_IRQ` 内（内层 `#if` 包 `hal_bgm_irq_active()` 那行是允许且必需的，见 §5.2.2 陷阱）。

### 5.3 第 3 轮（P2）— PCM 抢占策略（**条件触发，现在不做**）

**触发条件**（任一出现才开工）：

1. 用户实际反馈「语音被音效顶掉」或「音效打断语音」且影响体验；
2. 剧本需要在同一对白页内同时表达「语音 + 环境音」。

**候选方案**（按代价排序，**不做混音器**）：

| 方案 | 做法 | 代价 | 建议 |
|---|---|---|---|
| a. 构建期警告 | `nb_validator` 检测 `voice`/`sound` 相邻两行（AGENTS §十四「音频」第 1 条的反面教材） | 极低 | **优先** |
| b. 最小播放时长 | `pcm_play()` 拒绝在同一 key 播放后 N ms 内被**同优先级**覆盖 | 低 | 需要时加 |
| c. 优先级 | `voice` > `sound`，高优先级可打断低、反之不可 | 中（要改 `pcm_play` 签名与调用点） | 需要时加 |
| d. 队列 | 后到的排队等前一个播完 | 高（硬件无完成中断，只能靠时长估算，延迟不可控） | **不做** |
| e. 软件混音 | 混合两路采样 | 很高（386/486 实时 44.1k 混音 + 额外缓冲；且 BGM 走 FM 不经过它） | **不做** |

## 六、明确不做的事

| 不做 | 理由 |
|---|---|
| 重写音频架构 / 引入混音器 | 86 板 PCM 只有一路，混音器只服务「SE + 语音叠层」这一窄需求，代价是实时软件混音；BGM 走 FM 寄存器合成，不经过混音器 |
| 跨场景持续 BGM | `scene()` → `audio_stop_all()` 是一行策略，需要时改一行即可（AGENTS §十四「音频」第 6 条） |
| BGM 走 PCM 循环 | 单通道会被任意 SE 掐断且不恢复（AGENTS §十四「音频」第 3 条） |
| 编译期分档（真机 258 / NP2 129） | 两宿主只差 0.16%，分档只会让半速故障在某一档复现（`devdocs/168` 订正表） |
| 改 OPNA 预分频 `$2D-$2F` | 会同时改 FM/SSG 音高（`F04` §8.3，高风险） |
| 改 φM 常量 | 7.9872 MHz 有 MAME 取证；改它等于改模型去迁就实现，违反 §十「独立对照量」原则 |
| 用 `hal_wallclock_ms()` 做音频速率源 | ISR 不可重入 + 粒度 10 ms（NP2kai 秒级）⇒ 更差 |
| 删掉 ISR | 见 §5.2.4 |

## 九、踩坑清单（实施时逐条对照）

1. **`build` 与 `make` 必须成对**，否则跑旧 HDI，旧引擎日志一切正常（AGENTS §八 六禁之二）。
2. **诊断在 `core/*.err`，不在 stdout**（`make -C core` 的 stdout 只有命令行）。
3. **`EXTRA_DEFS` 必须 `export`**（六禁之六），且**换旗标前先 `make -C core clean`**——`make` 不按旗标判新旧，否则整份复用旧对象、旗标静默失效（§八 R8）。
4. **ISR 内禁用**：`hal_wallclock_ms()`、x87/`pow()`、`hal_logf`、`free()`（AGENTS §十四「Timer-B」第 2 条）。
5. **Timer-B 标志清除必须写 `0x2A`**（RESET|ENABLE|LOAD，缺一个就停表/不置位），改动 ISR 时不要顺手「简化」这个写（AGENTS §十四「Timer-B」第 1 条）。
6. **速率断言必须有独立于被测实现的对照量**：拿「假设的周期」自比不构成验证（AGENTS §十 第 3 条，`devdocs/168` 的教训就是这条）。`v/w` 里的 `w` 来自 DOS 时钟，与 Timer-B 不同源，所以它是合格对照量。
7. **IRQ 线是 IRQ12（slave），不是 IRQ3**（AGENTS §十四「Timer-B」第 3 条），改中断相关代码时别动双线自适应。
8. **虚拟钟只有一个写者**：ISR 激活时帧路径必须跳过 `advance`（`frame.c:18-19` 的注释），第 2 轮收口后这条由 `hal_audio_pump()` 内部保证，不要因为「统一入口」而把跳过逻辑弄丢。

#### 12.2.3 `core/plat/hal_audio.c`

```c
/* Upper bound for a single pump, in bytes.  2048 is ~46ms at 44.1kHz: enough
 * to absorb a doubled Timer-B period (~1422 bytes) without a debt, small
 * enough that one ISR stays short. */
#define PCM_TICK_MAX_BYTES 2048

/* Backlog cap: one second at the fastest rate.  A stall longer than this is a
 * stopped stream, not a late tick -- carrying more would dump a burst the DAC
 * cannot use. */
#define PCM_DEBT_MAX_BYTES 44100

static uint32_t g_pcm_debt_bytes;   /* owed bytes, carried to the next pump */

void hal_pcm_advance_units(uint32_t units)
{
    uint32_t push, i;

    if (!g_pcm.active) { g_pcm_debt_bytes = 0; return; }

    /* units is 1/16 ms, so one second is 16000 units.  A zero delta still
     * asks for one millisecond worth so a freshly started sample begins. */
    push = (g_pcm_rate_hz[g_pcm.rate & 7] * (units ? units : 1)) / 16000UL;
    if (push == 0) push = 1;
    push += g_pcm_debt_bytes;
    g_pcm_debt_bytes = 0;

    if (push > PCM_TICK_MAX_BYTES) {          /* keep the excess, do not drop it */
        g_pcm_debt_bytes = push - PCM_TICK_MAX_BYTES;
        push = PCM_TICK_MAX_BYTES;
    }
    if (push > g_pcm.len - g_pcm.pos) {       /* end of sample wins over debt */
        push = g_pcm.len - g_pcm.pos;
        g_pcm_debt_bytes = 0;
    }

    for (i = 0; i < push; i++) {
        if (inb(PCM_STATUS_PORT) & 0x80)      /* FIFO full */
            break;
        outb(PCM_DATA_PORT, g_pcm.data[g_pcm.pos]);
        g_pcm.pos++;
    }
    if (i < push)                             /* FIFO full: carry the rest */
        g_pcm_debt_bytes += push - i;
    if (g_pcm_debt_bytes > PCM_DEBT_MAX_BYTES)
        g_pcm_debt_bytes = PCM_DEBT_MAX_BYTES;

    if (g_pcm.pos >= g_pcm.len) {
        if (g_pcm.loop) {
            g_pcm.pos = 0;
            return;
        }
        outb(PCM_CTRL_PORT, PCM_CTRL_BUF_RESET);
        g_pcm.data = NULL;
        g_pcm.active = 0;
        g_pcm_debt_bytes = 0;
    }
}
```

### 13.6 阶段 5 —— ISR 实测（**唯一能证明修复的判据**）

```bash
export EXTRA_DEFS=-DNAIZ_BGM_IRQ=1
make -C core clean                     # 必须：make 只按源码 mtime 判新旧，换旗标不会重编
./makegame.sh build demo-a2 && ./makegame.sh make demo-a2
unset EXTRA_DEFS

./makegame.sh test demo-a2 --serial    # 让模拟器跑 2~3 分钟后关闭窗口
```

判据命令（两条 awk，见 §5.1.5）：

```bash
ls -l logs/serial_demo-a2.log          # 确认本次抓取非空

# 整体：首行 → 末行
grep '\[ISR\]' logs/serial_demo-a2.log | awk 'NR==1{pt=$2;pv=$3;pw=$4} {lt=$2;lv=$3;lw=$4}
  END{split(pt,a,"=");split(pv,b,"=");split(pw,c,"=");split(lt,d,"=");split(lv,e,"=");split(lw,f,"=");
      printf "ticks +%d  v +%d  w +%d  v/w=%.3f  tick/ms=%.4f\n",
        d[2]-a[2], e[2]-b[2], f[2]-c[2],
        (f[2]>c[2])?(e[2]-b[2])/(f[2]-c[2]):0,
        (f[2]>c[2])?(d[2]-a[2])/(f[2]-c[2]):0}'

# 逐段：相邻两行，看有没有中途掉拍
grep '\[ISR\]' logs/serial_demo-a2.log | awk '
  { split($2,a,"="); split($3,b,"="); split($4,c,"=");
    if (NR>1) { dt=a[2]-pt; dv=b[2]-pv; dw=c[2]-pw;
                if (dw>0) printf "dt=%5d dv=%6d dw=%6d  v/w=%.3f  tick/ms=%.4f\n",
                          dt, dv, dw, dv/dw, dt/dw }
    pt=a[2]; pv=b[2]; pw=c[2] }'
```

| 读数 | 现状（129） | 修正后（258） |
|---|---|---|
| `v/w` | **0.498** | **1.00 ±2%**（NP2kai 期望 0.9998、真机 0.9982）—— **唯一判据** |
| `tick/ms` | 0.0618 | 仍 ~0.0618（≈61.9 Hz）。**不是判据**：ISR 频率由硬件 `NB`+晶振决定，改常量不会动它（详见 §5.1.5） |

> 两条 awk 已用 168 §3 的实测原始行（`ticks=204 v=1636 w=0` → `ticks=6999 v=56421 w=110000`）反算，输出正是 `v/w=0.498 tick/ms=0.0618` —— 所以「读数不对」时先怀疑修复，不要先怀疑脚本。

**G4（两构建行为一致）**：同一场景走一遍默认构建与 ISR 构建，串口功能行（`AUD OPNA OK` / `FM: N patch families ready` / `BGM ...`）应逐条对应，只有 `[ISR]` 行是 ISR 版独有。
