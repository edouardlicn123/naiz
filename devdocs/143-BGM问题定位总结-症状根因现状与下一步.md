## 一、一句话结论

当前 BGM 的「电流声（buzz）」**不是一个原因**，而是**两类不同的问题叠加**：

| 场景 | BGM | 判定 | 状态 |
|---|---|---|---|
| **003 / 004** | `icy_garden`（bell + strings） | **`bell.fmp` 音色编码缺陷**（载波 `op2 mul=8` 过亮）—— 不是仿真 bug | **根因已确认**，待 voicing 轮修 |
| **001 / 002** | `melody_town`（纯 flute 独奏） | 两套 oracle 渲染均干净 ⇒ 系统性成分**不在音色数据内**，最可能是**宿主 / NP2kai 输出层**（或 `139` 节拍，低优先） | **未收敛**，需运行期取证 |

另外：原始报告中的**「音调偏低」已随 `138`（低八度根因修复）由用户实机确认解决**，不再计入遗留。

## 二、症状

用户实机复报：FM BGM 播放**全程**有「类似喇叭振动的电流声（buzz）」，并称**四个场景都有**（001–004）。报告（0.3.035，早于 `138`）**同时**提到「音调似乎偏低」。

- **「偏低」= 已解决**：`138` 定位到引擎 `FMOPN_FNUM_SCALE_N` 隐含 `2^block`、漏 `2^(block-1)` 折半，使每个音符编低一个 block（芯片只给半频）。修复后用户实机确认「音调已回正」。详见 §三。
- **「buzz」= 未收敛**：`137`/`137b` 的「提高 flute 调制器 `tl`」最小改动**未能消除**，故另立本轮诊断（`141`/`142`）。

## 三、已解决项：「音调偏低」（`138`）

**根因（三条证据链交叉确证）**：引擎侧 `core/lib/fmopn.c` 的 `FMOPN_FNUM_SCALE_N` 原为 `18432`（= `(144×2^20)/7987200`），隐含 `2^block`，**漏 `2^(block-1)` 折半**，把每个 MIDI 音符编低一个 block ⇒ 芯片对引擎发出的寄存器只给半频。

- 修复：`N 18432→36864`（A4→block5/fnum520、C4→block4/fnum618），新增 `fmopn_ratio_freq()` 作编码逆（bend / SSG 打击恢复复用），`fmbench.cpp` 镜像同步并**撤销** `×2`。
- 实机确认：**BGM 音高已回正**（用户回传）。
- 另注：`136 §十五` 曾错误地判「引擎正确、ymfm 错」并给 oracle 打 `×2`，**恰好掩盖了引擎 bug**；`138` 已就地订正（`136` 头部留 ERRATA 指 `138`）。

> 该结论对理解 buzz 重要：**音高问题与 buzz 是两根独立的轴**，音高修好不代表 buzz 消失。

## 四、未解决项之一：003/004 —— `bell.fmp` 载波倍频过亮（根因已确认）

### 4.1 根因

`bell.fmp`（`assets/demo-a2/fm/bell.fmp`）的 A 对（alg=4 的两组 2-op 之一）为：

```
op1(dt=0 mul=2  tl=14)  ->  op2(dt=0 mul=8  tl=14)   [载波]
op3(dt=1 mul=5  tl=16)  ->  op4(dt=0 mul=1  tl=22)   [载波]
```

**载波 `op2` 的 `mul=8`** 使这一对输出中心落在 **8×音高**，再由极响的 `mul=2` 调制器（`tl=14`≈−10.5 dB，调制指数很高）展成 `8f±2nf = 4f,6f,8f,10f,12f…` 的密频簇；低基频（1f）只由 B 对（`op4, tl=22`）提供。结果：**频谱重心远高于设计值**。

**这是一处 voicing 缺陷**——把高倍频放在了「**载波**」而非「**调制器**」上。15 族里 `bell` 是**唯一的极端离群值**（其余载波 `mul ∈ {1,2}`）。

### 4.2 证据

**（a）离线 oracle**

| 素材 | oracle | 质心 | `>5kHz` | 判定 |
|---|---|---|---|---|
| `icygarden`（bell×2 + strings） | ymfm | 高音段强分量 | 高音段 33–52% | **过亮** |
| `melodytown`（flute） | ymfm | ~1051 Hz | 0.10% | 干净 |
| bell 单音 | fmgen | 谱峰集中在 4f/6f/10f/12f | 0.31% | **过亮** |

**（b）实机录音（NP2kai，SDL3 `disk` 驱动，`spectrum_report` 口径）**

| 场景 | BGM | 实机 `>5kHz`（med/max） | 实机 centroid（sustain 1/4–3/4） | oracle centroid |
|---|---|---|---|---|
| 001 / 002 | `melody_town` | **0.11% / 0.23%** | ~938 / ~992 Hz | ~886 Hz |
| 003 / 004 | `icy_garden` | **44.4% / 46.5%（max 61%）** | ~1266 / ~1271 Hz | ~1158 Hz |

录音片段：`/tmp/opencode/np2kai_{001..004}.raw.seg`（S16LE / 2ch / 44100）。001/002 与 oracle 基本一致（干净）；003/004 高频能量显著抬升，与 `bell.fmp op2 mul=8` 的预测吻合。

> 说明：`>5kHz` 占比的 44–47% 与「质心 ~1266 Hz」量纲不同——前者是**逐帧 >5kHz 能量占比**（高音段 bell 命中时可达 40%+），后者是 `spectrum_report.analyze()` 在**稳态帧**上的单点质心。两者都指向「bell 在高音区过亮」，与 `141` 的表述一致。

### 4.3 修法（留待 voicing 轮，本轮不执行）

- **主选**：`op2 mul 8→1`，把「8」这个倍频关系**移到调制器 `op1`**（`op1 mul 2→8` 或类似），使 8f 仅作为边带出现而非载波中心；
- **备选**：提高调制器 `op1` 的 `tl` 以收紧边带；
- 目标：把 `[bell]` 的质心拉回其设计带内（见 §六）。
- 注意：`bell.fmp` 是**文本源**，改动后须经 `fm_patch.py::compile_source()` 重编译并 `build` 才生效；`op=N` 语义为**算法算子 N**（非寄存器槽），改动时须对照 `136`/`c66` 的算子顺序结论。

## 五、未解决项之二：001/002 —— 系统性成分（未收敛）

若 buzz 独属 bell，则 001/002（**纯 flute 独奏**）不应 buzz。但**两套互相独立的 oracle 都用引擎自身音色数据渲染 flute，均干净**：

| 素材 | oracle | 质心 | `>5kHz` | 判定 |
|---|---|---|---|---|
| `melodytown`（flute） | ymfm（`song_render2.py`→`fm_render`→fmbench） | ~1051 Hz | 0.10% | 干净 |
| flute 单音 | fmgen（`fmgen_render`） | 131–221 Hz | 0.00% | 干净 |

实机录音 001/002 亦干净（`>5kHz` 0.11%）。**关键推论**：既然「四场景都有」，则**系统性成分必然在音色数据之外**。

剩余候选（按可能性排序）：

1. **宿主 / NP2kai 输出层**：bell 在真实八度下高音段有强分量，44.1 kHz 输出 + 声卡重采样可能把其折返为可闻噪声；NP2kai 配置（`SNDboard`/`DAVOLUME`/`USEFMGEN`）也可能影响听感——**需实机 A/B**。
2. **LFO 的实际听感**：引擎全局使能 `$22`（LFRQ=2≈6.6 Hz），仅对 `AMS/PMS>0` 的通道生效。flute `pms=1`、`ams=0` 只产生轻颤音，理论上不足以称「电流声」；但离线 oracle 对 `$B4`/`$22` 的复现程度需进一步确认。
3. **`139` 节拍尖峰**（**低优先**）：「偏低」已随 `138` 解决，低八度不再是候选；`139` 尚无实机复核，且节拍与 buzz **不同轴**，最多是叠加干扰。

已排除：

- **不是 FM 仿真语义错误**：引擎 / ymfm / fmgen 三方算子↔寄存器槽映射、算法载波集、`$B4`/`$22` 组装均一致且正确（`141` §二）。
- **不是 SSG 无人机音**：SSG 仅用于打击乐，两首 BGM 都无鼓，`ssg_write_mixer()` 把 mixer 置 `0x3F` 全关。
- **不是未关的持续音**：`fmseq_stop()`/`hal_fm_shutdown()` 对每声道写 `$28` keyoff；场景切换经 `audio_stop_all()` 调用二者。

## 六、订正：`142` / `AGENTS.md` 对 `targets.toml` 的一处引用错误

`142`（及 `AGENTS.md` 头部 `c66` 摘要）称 bell 的设计带为 **`[bell] centroid_hz=[900,3500]`**。**该引用有误**——`[900,3500]` 实为 **`[piano]`** 的带：

```toml
# assets/demo-a2/fm/targets.toml
[piano]
centroid_hz = [900, 3500]      # ← 142 误引为 bell

[bell]
centroid_hz = [1500, 5000]     # ← bell 的真实设计带
attack_ms   = [1, 20]
harmonics   = { "2f" = [-18, 10] }
```

**影响评估**：结论**方向不变**（bell 仍过亮），但「远超设计带上限 3500」这一量化表述应改为「**超过 bell 自身带上限 5000**」。`142` §三 实测高音段质心达 6304 Hz，仍**确凿超出 `[1500,5000]`**，故 §四「bell 过亮」的判定**依然成立**。
