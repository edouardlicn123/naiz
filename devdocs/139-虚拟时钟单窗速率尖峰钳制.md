# 139 — 虚拟时钟单窗速率尖峰钳制（修「演奏时快时慢」的残留机制）

> **版本**：`0.3.037`
> **日期**：2026-10-16
> **关联**：130（虚拟时钟改平滑变步进）、133（二轮根修：首窗直采 + 测量平滑）、134（方案 C 定时器中断驱动，独立线）、107（裸墙钟追帧音爆）、B19（NP2kai 时钟全谱）

---

## 一、症状

- 实机：FM BGM 播放中，**偶发一段明显偏快**（数秒），随后回正；静置对白页也可能出现。
- 触发与「DOS 秒成簇交付」相关（B19 §2.3）：NP2kai 平台时钟经 INT 21h AH=2Ch 读回的「秒」是**量化 + 成簇**的，一段时间内读数不变，然后一次跳好几秒。

---

## 二、判定过程

### vclock 的测速机制（`core/lib/vclock.c`）

- 每 **1000ms** 累积窗闭合时，按 `want = accum * 16 / passes`（`vclock.c:105`，`VCLOCK_UNITS_PER_MS=16`）计算「每 pass 应走多少虚拟单位」；`step` 以 **0.5ms/pass**（`VCLOCK_SLEW_UNITS=8`）向 `target` 逼近；`target` 再以一个 IIR 分数（`1/VCLOCK_MEAS_SMOOTH`，=1/4）向 `want` 靠。
- **一次错误测量的代价**：`target` 移动 1/4，而 `step` 追上 `target` 需要多个 pass ⇒ 一次污染要 **~1–5 秒**才恢复。

### 缺口：`VCLOCK_MIN_WINDOW_PASSES=2` 挡不住「短停顿 + 大跳」

- `MIN_WINDOW_PASSES=2` 只拒绝「**单个 pass 吞掉整秒**」的硬停顿窗（`test_a_stalled_window_does_not_move_the_rate` 覆盖此形）。
- 但若窗口先经历**几次 delta=0 的短停顿**、随即吃到一个 `+1000..+6000ms` 的**成簇大跳**，则 `passes` 仍 ≥2 ⇒ 窗被采纳，`want` 飙到 `VCLOCK_RATE_MAX_MS`(100ms/pass ≈2.5×)。`target` 随之移动 1/4，`step` 再用数秒跟随 ⇒ **明显偏快数秒**。
- 现有 `test_vclock.py` 覆盖 1-pass 停顿与「24 pass 后跳」，**恰缺「短停顿后跳」**；`test_jump_is_not_dumped_in_one_pass` 只断言发射步 ≤ `VCLOCK_MAX_ADVANCE_MS`（本被兜底），抓不到**速率尖峰**。

### 复现（宿主可穷举）

- 25Hz 校准（24 pass / +1000ms，`target=666`）后，喂 5 个 delta=0 pass + 一个 `+1000ms` pass：该窗 6 pass 覆盖 1000ms（≈167ms/pass）⇒ 无钳制时 `want=RATE_MAX=1600`，`target 666 → 899`（+35%）；钳制后 `target 666 → 707`（+6%，落 ±25% 带内）。

---

## 三、根因

**单窗测量的**绝对**修正量无上界**：一个跨越「停顿间隙 + 追赶跳」的窗，其 `accum` 覆盖了窗内 pass 并未真正跨越的时间，测出的速率虚高；IIR 会跟随它，而 0.5ms/pass 的 slew 需要数秒才把它拉回——这段就是实机听到的「偏快」。

---

## 四、修复（改动清单）

1. **`core/lib/vclock.h`**（`:115-116`）：新增
   `VCLOCK_MAX_WINDOW_RATIO_NUM 5UL` / `VCLOCK_MAX_WINDOW_RATIO_DEN 4UL`，即单窗修正上界 `5/4`、下界 `4/5`（±25%），附「DOS 秒成簇（B19 §2.3）」与「首窗豁免」的缘由注释。
2. **`core/lib/vclock.c`**（`:118-137`）：在**窗口闭合后、IIR 更新前**，把 `want` 钳制到 `[target*DEN/NUM, target*NUM/DEN]`。**首窗（`calibrated` 之前的采纳窗）不钳**——若整机真实速率本就不等于初值 `VCLOCK_INIT_STEP_UNITS=640`，仍能一次校准到位；既有 `RATE_MIN/MAX`(1/100ms) 绝对钳制保留为外层界。
3. **文件头注释**（`core/lib/vclock.c:39-45`）：新增「devdoc 139 refinement」段，说明残留缺陷与修法。

**兼容性（既有用例逐条核对）**：`test_first_window_is_adopted_not_ramped`（首窗免钳，不受影响）、`test_rate_change_converges_without_lurch`（只断言 slew 界，不受影响）、`test_tempo_at_various_pass_rates`（稳态在带内）、`test_quantised_jitter_is_smoothed`（±5% ≪ 25%）全部仍过。

## 七、遗留

- **实机验证未执行**：需 `./makegame.sh build demo-a2 && ./makegame.sh make demo-a2` 后实机确认「偏快数秒」消失。**判据**：串口 `[VC]` 行（`hal_pc98.c`，每 64 pass 打印）中 `tgt=` 不再出现一次性大跳后缓降；`001/002` 为 flute 试听源、`003/004` 对照。
