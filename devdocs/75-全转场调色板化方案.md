# 75-全转场调色板化方案

> ⚠️ **已过时，仅供参考。** 已由 `devdocs/77-动画与转场系统统一文档.md` 取代并合并（其中全转场 palette 化已实现并 C3 拆分，含新增 CHECKER），仅存留作历史记录，勿作为实施依据。
>
> 状态：方案定稿，未实现。等待实施指令。
> 关联：devdoc 74 已交付 palette 原语（`palette_get_all/set_all/interp`）与 `TRANSITION_PFADE` 淡出及 scene_end 清屏修复。本文档承接其后的**全转场 palette 化重构**：放弃旧 VRAM 逐像素覆盖式转场（dither fade、几何百叶窗/斜条、BLEND 模式），全部改为 palette 驱动实现。
> 决策记录（已与用户确认）：
> 1. `fade` 类型字符串删除，只保留 `pfade`（全屏 palette 淡出）。
> 2. BLEND mode 及 `buf_bg` 参数删除（无调用方）。
> 3. 条带数 N = 8。
> 4. 接受视觉近似：vblinds 等由「边线几何收拢」改为「整条亮度依次熄灭」。

## 一、需求与目标

1. 所有转场类型统一收敛到 palette 驱动：每帧仅端口 I/O（调色板条目改写），不再大面积写 VRAM。
2. 删除全部旧转场实现（Bayer 抖动、几何 blinds/slants、BLEND 备份/回写），`transition.c` 大幅瘦身。
3. 保持配置兼容：`config.toml [transition] type` 现有字符串（除 `fade`）继续有效，语义升级为 palette 版本。
4. 性能基准：`scene_end` 每场景切换必经转场，是全引擎最高频的显示热点；palette 化后每帧成本从「几十万像素 VRAM 写」降为「每帧 ≤8×3 字节端口」。

## 二、现状与依据（调研结论）

### 2.1 旧实现开销（将被删除）

`transition.c`（当前 338 行）内：
- `transition_fade_solid`（Bayer 8×8 抖动 `fill_rect_pattern`）：逐像素判断+覆盖目标色，全屏每步写 VRAM。
- `transition_blind_solid` / `transition_diagonal_solid`：逐条带/逐行 `fill_rect`，每帧部分覆盖，累计跨多 vblank。
- BLEND 三件套 + `transition_run` 的 `work` 分支：`malloc(w*h)` + `vram_read` 备份 + `memcpy` 合成 + `vram_write` 回写——最重路径，且仅 mode=BLEND 使用（`scene_end` 从不传 BLEND）。
- `BAYER8[64]` 表。

### 2.2 palette 原语已就绪（devdoc 74）

- `palette_get_all(uint8_t[256][3])`：经 `hal_read_palette` 读全表。
- `palette_set_all`：经 `hal_set_palette` 写全表。
- `palette_interp(from, to, step, div, out)`：整数插值 + clamp，自然适用「向黑渐变」。
- `TRANSITION_PFADE` 已实现且落地（首帧捕获 basis → 逐帧 `interp(basis, black)` → `set_all`；末帧强制全黑）；`scene_end` 已于 transition 后 `fill_rect` 清屏。

### 2.3 固定 palette 索引占用清单（PBLINDS 避让依据）

| 索引 | 用途 | 定义处 |
|---|---|---|
| 1 / 3 / 7 / 15 | 蓝/红/白/透明（引擎保留） | render.h |
| 248 | PAL_DIALOG_FILL | render.h |
| 249 | BTN_FILL_IDX | scene_layers.h |
| 250 / 251 | MENU_PAL_WHITE / YELLOW | nb_internal.h |
| 252 / 253 | BTN_HIGHLIGHT / BTN_SHADOW | scene_layers.h |
| 254 | PAL_CURSOR_BLACK | render.h |
| 255 | PAL_NO_TRANSPARENCY（sentinel） | render.h |

**结论**：`240–247` 连续 8 条为可用保留区间，不与任何固定条目冲突 → `PBLINDS_BASE 240`。

## 三、方案总览

| config type | 枚举 | 新实现 | 效果 |
|---|---|---|---|
| `pfade` | PFADE | palette 全屏淡出（保留 74 实现） | 全屏统一渐暗至黑 |
| `vblinds` | VBLINDS | palette 竖条纹 | 8 条竖亮带依次熄灭 |
| `hblinds` | HBLINDS | palette 横条纹 | 8 条横亮带依次熄灭 |
| `dblinds` | DBLINDS | palette 斜条纹 `/` | 对角亮带潮推进 |
| `rdblinds` | RDBLINDS | palette 反斜条纹 `\` | 反对角亮带潮推进 |
| `cut` | CUT | 保留（瞬时直切，无渐进） | 直黑 |

统一手法（两种方向族共用一个驱动，参数化）：
1. 首帧：按方向把屏幕划分为 N=8 条带，`fill_rect` 把每条带区域填成 `PBLINDS_BASE + i` 索引（一次性全屏写入，共 N 次 fill 合计覆盖全屏）。
2. 首帧后每帧：palette 改写 `PBLINDS_BASE + i`（i=0..N-1）的 RGB，按错峰公式从亮灰向黑递减 → 条带呈「暗潮推进」依次熄灭。
3. 末帧：`palette_set_all(PFADE_BLACK)` 兜底 + `scene_end` 既有 `fill_rect` 清屏。
4. **铁律（顺序）**：必须先 `fill_rect` 填条带、后改 palette。若先改 palette，图像原有像素若用到 240–247 索引会瞬时杂色；先填满整屏条带色后，无残留像素可闪，彻底规避。

### 4.2 transition.c（实施后 156 行）

结构：
- 保留：`PFADE_BLACK`、`pfade_basis/pfade_cur` 静态缓冲、`transition_pfade_solid`、PFADE 分发 case、末帧强制 black。
- 新增常量：
  ```c
  #define PBLINDS_BASE  240   /* 转场专用条带索引基址（避让清单见 §2.3） */
  #define PBLINDS_BANDS 8     /* 条带数 N */
  #define PBLINDS_LIT   200   /* 条带初始亮灰（r=g=b） */
  ```
- 新增 `transition_pblinds_fill(x, y, w, h, type)`：仅 step==0 调用，按方向 fill_rect 填条带索引。
- 新增 `transition_pblinds_advance(type, step, frames)`：每帧改写 8 个条目（见 §4.3 公式）。
- `transition_run`：删除 `work`/BLEND 分支；SOLID switch 只剩五种 case：
  - `CUT`：`fill_rect` 黑，return（同旧）。
  - `V/H/D/RD BLINDS`：首帧调 `pblinds_fill` + `pblinds_advance`，后续帧仅 `pblinds_advance`。
  - `PFADE`：`transition_pfade_solid`。
  - `default`：`NB_DEBUG` WARN。
  - 末帧统一 `palette_set_all(PFADE_BLACK)`。

### 4.3 错峰公式（palette 亮度条带）

**实施修正**：早期草案的 `g_i = step*N - i` 在 step< i 时全钳到 0，首帧即全黑，无推进。最终采用**窗口滑动法**（实现即自此）：

设条带 i ∈ [0, N)，帧 step ∈ [0, frames)。条带 i 的熄灭窗口 `[t0, t1)`：

```
t0 = i * frames / N                    /* 带 i 开始变暗的帧 */
t1 = (i + 1) * frames / N              /* 带 i 完全熄灭的帧；若 t1<=t0 则 t1=t0+1 */
factor = 255           若 step <= t0   /* 仍全亮 */
factor = 0             若 step >= t1   /* 已黑 */
factor = (t1 - step) * 255 / (t1 - t0) 否则   /* 窗口内线性减亮 */
条目 (PBLINDS_BASE+i) := (r,g,b) = (PBLINDS_LIT*factor/255) x3
hal_set_palette(PBLINDS_BASE+i, r, r, r)
```

- 效果：带 0 先熄灭、带 N-1 最后熄灭 →「暗潮」逐条扫过整屏（用户确认的视觉语义）。
- `frames=N` 时每带一帧内熄灭；`frames=16` 时两帧/带。末帧带 N-1 的 t1=frames 恰未达——靠「末帧 `palette_set_all(PFADE_BLACK)`」兜底保证整屏纯黑（§四.2 末帧统一处理）。

方向 → 条带划分（fill_rect 用）：
- `VBLINDS`：等宽竖条 8 条，`x + s*(w/8)`，宽 `w/8`（末条补余）。
- `HBLINDS`：等高横条 8 条，`y + s*(h/8)`，高 `h/8`。
- `DBLINDS` / `RDBLINDS`：斜带——按列相位分组：`band = ((px + py) / k) % 8`（`/`）或 `((px - py) / k) % 8`（`\`），k 为带斜宽（初值 16 像素纵距）。实现以「行内列偏移取带号」等价 fill_rect 逐行小矩形或按行 `fill_rect` 近似：**实现细节以 `fill_rect` 逐行分带为准，避免逐像素**。

### 4.4 layer.c（scene_end 适配）

```
transition_run(0, 0, LAYER_SCREEN_W, LAYER_SCREEN_H,
               NAIZ_TRANSITION_TYPE, NAIZ_TRANSITION_FRAMES, 0);   /* 去掉 SOLID/0/NULL */
```
其后既有 `fill_rect(全屏黑)` 清屏保留（fade 后立即清理场景，防 palette 恢复时旧画面闪现——devdoc 74 已修复项，继续生效）。

### 4.5 边界与安全

- **首帧顺序铁律**：`pblinds_fill`（VRAM）→ `pblinds_advance`（palette），永不可逆；注释注明。
- **条目安全**：240–247 转场期间被覆盖为亮灰/渐黑；转场结束后新场景 `image_load`→`image_set_palette` 全表恢复图像调色板、`dlg_update_palette`/`btn_update_palette` 恢复固定条目，无残留。
- **光标**：转场循环仍每步 `hal_mouse_update` + `hal_mouse_draw_cursor`（沿用现有 step loop 逻辑）；`scene_end` 已先 `hal_mouse_invalidate_cursor`。

## 八、收益与局限

收益：
- **带宽**：旧 fade = 每帧数十万像素 VRAM 写 + 跨 vblank；palette 版 = 每帧 8×3（条带）或 256×3（pfade）字节端口 I/O。差距约 2–3 个数量级。
- **删码**：transition.c 338 → 156 行（删 BAYER8、fade_solid、blind/diagonal solid+blend、work/BLEND）；transition.h 42 → 40 行（删 FADE/MODE）。
- **统一**：全部转场收敛到 `palette_*` 原语；未来新增 palette 效果（flash/色温）同一框架。

局限：
- 视觉近似：vblinds 等不再是「边线宽度收拢」，而是「整条定宽条带亮度渐灭」（用户已确认）。
- palette 转场只能在「全屏统一」维度做文章；空间图案必须是「预先 fill 固定形状 + palette 亮度推进」，无法逐帧改形状。
- 条带专用索引 240–247 属引擎保留约定，图像素材若占用会在一瞬的转场首帧被覆盖（无残留，见 §4.5）。

## 九、防复发要点

- **首帧顺序铁律**：`pblinds_fill` 在 `pblinds_advance` 之前；翻转会导致 240–247 瞬时杂色（C18 副作用复核）。
- **末帧强制全黑**：错峰公式末帧带 N-1 未达纯黑，必须 `palette_set_all(PFADE_BLACK)` 兜底（消灭静默不黑）。
- **无未用 static**：删除旧实现后确认 `BAYER8`、BLEND 相关无残留引用（C13）；Macro `TRANSITION_FADE/MODE_*` 全项目无引用后再删（先 `grep -rn`）。
- **枚举重编号**：`nb_config.h` 必须重生成，避免类型值错位（6→5）。
- 整数错峰公式防溢出：`step*N ≤ 16*8、frames*N ≤ 128`，`g*255 ≤ 128*255 < int32` 安全。
