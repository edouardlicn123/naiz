## 1. 背景

从网上调研 Ren'Py 架构（官方文档 `save_load_rollback.html`/`displaying_images.html`/`screens`、
源码 `ast.py`/`execution.py`/`rollback.py`/`python.py`/`display/core.py`/`display/scenelists.py`、
`statements.py`、DeepWiki 2.1 脚本执行与界面），对照当前 naiz 引擎逐项映射，评估
"类似前后端分离"的改造空间。结论：引擎已具备相当多分离基础（`nb_parser.c` 纯解析零渲染依赖、
`vm.c` 独占执行标志、`scene_layers.h` 四层拆分、`render_set_target/text_set_target` RAM 合成目标、
`audio.c` 与旧命令层解耦、存档只存"模型"不存显示），但存在 7 处前后端互相越界，需分阶段收口。

治理原则沿用 devdoc 99/102：**行为等价**（本方案全部阶段无语义变更，除 B 的屡警告升级）、
**单一事实源**、**外科手术**、**先借后造**（复用已有封装，见 §3/§4）。

## 2. Ren'Py 前后端模型（调研参考）

| 层 | Ren'Py 实现 | naiz 对应物 | 差距 |
|---|---|---|---|
| 脚本 AST | `ast.py` `Node` 链 + parser；`next`/`filename`/`rollback` 属性 | `nb_parser.c` 运行时逐行解析（无 AST）| 不需要引入 AST，C 逐行可保持 |
| 执行 | `execution.py` `Context` 栈，`Node.execute()` | `nb_process` 循环 + `vm.c` 标志 | 等价；问题在 handler 内直绘/阻塞 |
| 状态 | `python.py` `StoreDict`（可回滚 store） | `nb_vars.c` `var_values[]` + `nb_var_get_state/set_state` | 已隔离 + 已入档 |
| 回滚/存档 | `rollback.py` `Rollback`/`checkpoint`；语句起点快照 | SaveData = filename + vars + lang + chapter_title | 无 pc 级检查点（**本方案不做**，见 §6） |
| 交互边界 | `Interface.interact_core()` 事件循环返回结果给脚本 | question/menu/confirm 输入循环内嵌 handler（§3.4）| **最大合同**：无"让位→结果回传"原语 |
| 显示 | `SceneLists` 分层 + zorder/behind；render projection | layer_bg/sprite/dialog + `dialog_render_*` 渲染投影 | 投影机制已有雏形（§3.2） |
| 音频 | `audio/` 通道管理 | audio.c BGM/SND/VC，绝无 NB 依赖 | 已干净 |
| 翻译 | `translation/` | `tr()` sys/role/game 表 | 已干净 |

## 3. 现状审计（证据）

### 3.1 解析/执行/渲染三合一 per line

`nb_process`（nb.c:327-438）每帧逐行：`nb_get_line` → 剥注释 → `nb_parse_line`（含
`;` 重解析 question/scene）→ `nb_commands_dispatch` → handler **立即绘制**。解析器已纯
（nb_parser.c:4-6 注明无 render/hal/layer 依赖），执行与渲染仍耦合。

### 3.2 对话框每帧重绘 + 显示侧反控执行流

- `nb.c:348-352`：`nb_process` 每帧对未翻页对话框重调 `dialog_show()`（执行循环直驱渲染器）；
- `nb_dialog.c:75/79/85`：`dialog_show()` 内部 `vm_pause_process()` —— **前端模块反向控制执行流**，
  且 `dialog_render_*` 渲染投影（layer_dialog.c:39-42）已能让显示侧自重组，逐帧重绘多余。

### 3.3 命令 handler 直接越界操作显示内部

| 位置 | 越界动作 |
|---|---|
| `nb_commands.c:149-190` `cmd_bg` | `anim_stop` + `image_load` + `palette_reset_reserved` + `layer_bg_change` + `mag_release` |
| `nb_commands.c:204-261` `cmd_char` | `layer_sprite_hide_all` / `layer_dialog_hide` / `nb_dialog_reset` / `layer_sprite_update|face` |
| `nb_commands.c:263-271` `cmd_dialogue` | `tr()` + `dialog_show` |
| `main.c:163-180` | 主循环 F5/F6/ESC 直接调 `save_game_temp()`/`save_dialog_menu()`/`nb_load()` |
| `layer.c:29` | `scene_end()` 内 `audio_stop_all()`（前端管音频 teardown）|
| `nb_anim.c` | 动画帧直接写 ANIM 层 + `layer_capture_bg_dialog_from_image` |

### 3.4 阻塞 UI 循环住在 handler 内

- `nb_question.c:65-186` `cmd_question`：**自身阻塞输入循环** + 直接 `draw_text`/emboss +
  `layer_dialog_clear()`，且截断选项>4、`apply_option()`（R21 已合一变量应用）。
- `nb_mainmenu.c` / `nb_cggallery.c` / `nb_saveload.c`：整套菜单 UI（menu_layer + 输入循环）在
  handler 内。`nb_saveload.c` 的确认框与 `nb_question` 交互形态重复。

### 3.5 换场多入口

`nb_load()`（含 `scene_end` 清屏重置）由 `nb_load`（脚本内 `scene` 命令）、`main.c` 热键、
`save_apply`（save.c:31-42）、各菜单跳转分别触发——清屏/键盘排空/音频停止散落各处。

### 3.6 显示状态无单一归属

背景（`bg_snapshot`/`under_dialog`，layer_bg.c）、16 槽立绘表（layer_sprite.c）、对话框页
（`dialog_render_*` 投影）各自为政；`layer_bg_change` 尾部通过 `layer_redraw_sprites` +
recompose 协调——"当前该显示什么"无一张总账，导致换语言/读档/换场后重绘路径多。

### 3.7 未知命令静默

`nb_commands_dispatch` 未知命令仅 `NB_DEBUG`（需开 `NAIZ_DEBUG` 才可见），不符合"消灭静默失败"。

## 4. 改造方案

### 阶段 1 —— 交互抽象 `ui_interact()`（随带 A）

新增交互收口模块（建议 nb_menu.c 侧或新 `nb_interact.c`，声明进 `nb_internal.h`）：

```c
/* 提交 UI 请求并暂停 VM；前端事件循环跑完后回传选择码并恢复执行。
 * 复用 waitanima 既有的"暂停→等待→恢复"原语（nb.c:342-345 anim_waiting/anim_stop_internal）。 */
typedef struct {
    const char *const *labels;   /* 选项文本（已 tr()） */
    int  n;                      /* 选项数；0 = 纯确认框（Yes/No 由调用方画） */
    int  focus0;                 /* 初始焦点 */
} UiRequest;

int ui_interact(const UiRequest *req);   /* 返回 0..n-1 选择码，或 -1 取消 */
```

- 收敛对象：`cmd_question` 的选项阻塞循环（nb_question.c:65-186）、存档确认框
  （`save_dlg_confirm_action`/`save_load_confirm_action`，P3 已有 `menu_confirm_input` 基础）、
  后续菜单复用；
- 鼠标/键盘/翻页三输入单点分发（对齐 Ren'Py `ui.interact` 返回值的语义）；
- 全程行为等价：选项渲染（含 >4 截断）、confirm 布局、命中测试原样保留，仅把"循环+输入读取"
  换为"请求→暂停→回传"。

**A 存档请求收口**：`main.c:163-180` F5/F6/ESC 与菜单内保存/读档，统一为
`save_request(SlotOp op, int slot)`；不再直接调 `save_game_temp()`/`save_dialog_menu()`/直接 `nb_load()`。

### 阶段 2 —— 显示 op 化（随带 C/E/G）

1. **显示侧场景状态单一归属**：新建 `scene_display` 状态（bg 资产 id、立绘表、对话框页投影），
  显示模块自持；`layer_bg_change`/`layer_sprite_*`/`layer_dialog_*` 的"当前显示"账收口一处；
2. **命令改经窄接口提交状态**：`cmd_bg`/`cmd_char`/`cmd_dialogue` 改为 `display_apply(...)`
  （提 bg 资产/立绘/对话页），渲染与调色板等副作用移进显示侧统一出口；
3. **删 `nb.c:348-352` 逐帧重绘**：翻页停留期间由对话框自重组（`layer_dialog_recompose`，
  layer_dialog.c:347-359）+ `dialog_render_*` 投影驱动；`dialog_show` 不再内部 `vm_pause_process`
  （改由 `nb_process` 依据 `dialog_pending` 主动让位）；
4. **C 命令元数据表**：`cmd_table` 条目增声明位
  `blocking / needs_input / touches_display / touches_audio / terminates_scene`；
  审计/测试校验 `touches_display=0` 的 handler 不调渲染接口（防未来破坏边界）；
5. **E 音频停止归属**：`layer.c:29 scene_end()` 内 `audio_stop_all()` 移入换场/显示应用统一逻辑；
6. **G 场景切换单入口**：新增 `scene_switch(const char *name, int reason)` 统一接管
  「黑屏 + `kbd_drain_advance()` + 音频停止 + 显示重置 + `nb_load`」；`main.c` 热键、
  `save_apply`、各菜单跳转全部改走此入口。

### 独立小项

- **B 未知命令常开 WARN**：`nb_commands_dispatch` 未知命令改为无条件 `hal_log`（不依赖 NAIZ_DEBUG）；
- **F 命令表 ↔ 文档防漂移测试**：新增 `tools/tests/test_cmd_doc_sync.py`，`cmd_table` 命令集
  （nb_commands.c:384-410）↔ B92 §1 命令表比对，漂移即红（对标 `test_langdefs_sync`）；
- **K 存档 slot 元数据侧车**：读档列表页走纯数据 `save_read_slot()`（基于 `save_read_header`，
  save_io.c 既有能力），不触碰全局状态、不触发重跑。
