## 一、动机

- fmseq 的离线验证目前靠 pytest sink 断言寄存器序列（`test_fm_seq.py` ctypes harness）——**可断言但不可听**。S98 是 OPN 寄存器流的事实标准容器，导出后可用 98fmplayer/libopna 等外部回放器渲染 WAV，形成「引擎寄存器流 → 任意回放器」的离线取证通道（与 `fm_render.py`/ymfm 正交：ymfm 是引擎内嵌 oracle，S98 dump 是与引擎解耦的跨回放器对账）。
- 音色文本化：`.fmp` 源是文本、二进制在 `AUDIO.DAT` 内 —— **打包后审计**需要反向导出（VOPM/FMP 文本），用于「部署态 patch 与源一致」的抽查与音色交流（F03 §5：业界音色交换格式）。

## 二、S98 格式要点（从 `s98gen.c` 解析器反推，写侧唯一依据）

来源：`98fmplayer/libopna/s98gen.c`（BSD-2），读侧校验逻辑：

| 偏移 | 内容 |
|---|---|
| `0x00-0x02` | magic `S98` |
| `0x03` | 版本字符 `'1'` 或 `'3'` |
| `0x04` | timer numerator（LE32，0 回落 10） |
| `0x08` | timer denominator（LE32，0 回落 1000） |
| `0x0C` | 压缩标志，必须 0 |
| `0x14` | 初始数据偏移（LE32） |
| `0x1C` | v3：device info 存在标志 |
| `0x20` | v3：devicetype（LE32，`0x04`=OPN / `0x02`=OPNA；OPN 时 clock×2） |
| `0x24` | v3：clock（LE32） |

事件流（从初始偏移起）：

- `0x00 reg val` — bank0 写（naiz 只用 bank0：FM/SSG/RHYTHM 全在 0088h 普通组）
- `0x01 reg val` — bank1 写（`reg|0x100`；naiz 不用）
- `0xFE` + VLQ(n) — 延时 n+2 tick（读侧 `getvv` 读 VLQ 后 +2）
- `0xFF` — 延时 1 tick

**naiz 导出参数**：version `'3'`、`numerator=1, denominator=1000`（tick=ms，对齐 fmseq 事件的 `tick_ms`）、devicetype=2（OPNA）、clock=7987200、无压缩、bank0-only。VLQ 写侧：延时 ≥2 用 `0xFE`+VLQ(d−2)；恰 1 用 `0xFF`。

## 三、工具方案

### A. S98 导出器 `tools/naiz_audio/s98_dump.py`

- 复用 `test_fm_seq.py` 的 ctypes harness 模式：加载 `libfmseq`/`libfmopn`（或经 `fm_render.py` 既有加载封装），以**记录型 sink** 跑 `fmseq_pump`（全曲 ms 时间轴，含回绕），产出 `(time_ms, bank, reg, val)` 序列 → 按 §二 写 `.s98`。
- 输入：MIDI + FMP patch 目录（与 `fm_render.py` 同参）；输出：单文件 `.s98`。
- 校验：内置 S98 读回器（Python 复刻 `s98gen_getvv` + 头校验）断言自产文件可被解析、事件数与 sink 计数一致。
- 对账用法：`98fmplayer` 侧 `s98gen.c` 回放 WAV ↔ `fm_render.py`（ymfm）WAV 互 diff（容差由两回放器差异决定，先记录基线不做硬阈值）。

### B. FMP→文本导出器 `tools/naiz_audio/fmp_export.py`

- 输入：32 字节二进制 FMP（`compile_source()` 产物或从 `AUDIO.DAT` 抽出的 patch 条目）；输出：VOPM 文本 与 FMP(`@`) 文本。
- 字段映射（以 `fm_patch.py` 二进制布局为单一事实源）：bytes0–35 为 4×(ar,dr,sr,rr,sl,tl,ks,ml,dt)（**算法算子序**，c66 语义）、36=alg、37=fb、38=pan、39=ams、40=pms。
- VOPM 文本格式照抄 `tonedata.c:97-131` 模板：`@:n` + `LFO:` 行（pms/ams 填入）+ `CH: 64 fb alg …` + `M1/C1/M2/C2` 四行（ar dr sr rr sl tl ks ml dt 0 0）。算子序一一对应（VOPM 的 M1/C1/M2/C2 即算法算子序 —— 实施时用 `bell.fmp`（c70 载波定位案例）做一次 round-trip 人读核对）。
- FMP 文本格式照抄 `tonedata.c:73-96` 的 `@` 行模板。
- **不做**反向 import（文本→二进制已有 `fm_patch.py::compile_source`）。

### C. libopna 第三 oracle 评估（不 vendor）

- 对象：`98fmplayer/libopna`（`opna.c/h`，BSD-2）+ `s98gen.c`。卖点：按限条件下位精确（`README.md:40`），且与 98fmplayer 同源的 OPN 实现可作 S98 侧独立回放器。
- 评估项（记录进本文件实施后的附录节，不改引擎）：① 构建复杂度（需 C11 + wav 注入）② 与 fmgen/ymfm 的渲染差异量级 ③ 若第三 oracle 有价值的触发条件（fmgen vs ymfm 出现分歧、需要第三票时）。
- 默认结论倾向：**不 vendor、不进 `tools/` 构建图**；S98 导出器本身已提供「外部任意回放器」通道，第三 oracle 的边际价值待评估后定。

## 五、不做什么

- 不改 `fm_patch.py`/`pack_audio.py`/`export_asset_table.py`（导出是旁路只读）。
- 不做 S98 回放器（回放用外部工具）；不做 bank1/ADPCM dump（引擎无此路径）。
- 不 vendor libopna（评估结论若反转，另开实施轮）。
