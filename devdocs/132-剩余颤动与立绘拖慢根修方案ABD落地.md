## 1. 症状（承 devdoc 131 §1.2）

正式 BGM 已可闻且不再冻结（devdoc 129/130 之后），但：

1. **颤动**：节拍仍会抖，尤其在立绘（`char`/`cg`）解码窗口内更明显；
2. **拖**：一次立绘解码期间画面/GDC 刷新被 CPU 独占，表现为「卡一下」。

两者同源（131 §5）：音乐/时间泵 = 主循环协作轮询，任何长 CPU 操作都会让节拍与画面一起停摆。

## 2. 根因（承 devdoc 131 §2）

- **§2.2 时钟链**：`hal_wallclock_smooth_advance()` 是虚拟时钟唯一写者，帧泵每 pass 调一次；消费方（BGM/打字机/动画）只读。
- **§2.3 解码路径**：`mag_decode()` 的进度钩子（`mag.c` 四处调用点）此前直接挂 `audio_tick()`，**只读**时钟，不推进它。
- **§2.4 为什么还颤**：解码期间推进停摆 → 事件表积压 → 解码结束后一次性排空（爆发），即听感上的抖。
- **§2.5 为什么还拖**：解码是纯 CPU 密集，期间不让出，GDC 刷新被饿。

## 3. 本轮修复（方案 A / B / D）

> 用户决策：C 单独立项（见 §6），E 不做。A+B+D 组合即 devdoc 131 §9.1 第 1–3 步的合并落地。

### 3.1 方案 A — `audio_tick()` 内节流让出 CPU

`core/engine/audio.c:500` 新增 `AUDIO_YIELD_EVERY 16` 与 `g_audio_yield_ctr`；`audio_tick()`（`audio.c:504`）开头：

```c
if (++g_audio_yield_ctr >= AUDIO_YIELD_EVERY) {
    g_audio_yield_ctr = 0;
    hal_vblank_wait();
}
```

- **目的**：长 CPU 路径（解码钩子）会远高于显示刷新率地调用 `audio_tick()`，每 16 次阻塞等一次 VBLANK，既让出 CPU 又顺带与显示重新同步。
- **取值 16 的理由**：devdoc 131 §10「A 专属」指出 `hal_vblank_wait()` 在 NP2kai 下是 VSYNC 轮询（pass 率低），**节流过密会过减速**，故取大值、只在解码这类密集路径才触发。
- **不治颤、只缓解拖**（131 §6 方案 A 定义）：时序逻辑不变，仍只读 `vclock`。

### 3.2 方案 B — 解码期帧分片：边沿门控的 `frame_decode_pump()`

**契约障碍与合规改法**（131 §6 方案 B 明确要求）：`hal_wallclock_smooth_advance()` 不能每解码扫描都调，否则时钟飙速。本轮采用 **VBLANK 上升沿门控**：解码期时钟按**真实显示帧**步进，既不冻结也不跑快。

1. **HAL 新增非阻塞边沿探测** `hal_vblank_poll()`（`core/plat/hal_pc98.c:154`，声明 `core/plat/hal.h:126`）：

   ```c
   int now = (inb(GDC_GFX_PARAM) & GDC_VSYNC) ? 1 : 0;
   int prev = g_vs_level;
   g_vs_level = now;
   if (prev < 0) return 0;          /* 建立基线 */
   return (prev == 0 && now == 1);  /* 每帧恰好一次上升沿 */
   ```

   静态 `g_vs_level`（`hal_pc98.c:136`）在 `hal_vblank_wait()` 末尾被置 `1`（`hal_pc98.c:143`），使**阻塞泵与轮询解码不会重复计同一帧**。

2. **解码期帧泵** `frame_decode_pump()`（`core/engine/frame.c:36`，声明 `core/engine/frame.h:35`）：

   ```c
   if (hal_vblank_poll()) {           /* 显示确实进了一帧？ */
       hal_wallclock_smooth_advance();/* 为这一帧推进一次时钟 */
       anim_tick();
   }
   audio_tick();                      /* 持续泵 BGM/PCM（含 A 的周期性让出） */
   nb_dialog_reveal_tick();
   ```

   - **非阻塞**（用 `hal_vblank_poll` 而非 `vblank_wait`）：否则每 4KB 扫描等一整帧，加载一张立绘要数秒。
   - **只读时钟的旧行为被替换**：`mag` 进度钩子现在指向 `frame_decode_pump`（`audio_init` 注册，`audio.c:457`），解码期间时钟按显示帧流动（治颤）、`audio_tick` 的节流让出 CPU（缓解拖）。
   - **帧计数仅作边界探测，绝不作时基**：NP2kai 下 ≈20.5Hz（B19 §2.3），作时基会 3 倍慢；作边界则无此问题——这是本方案与已被否决的「VSYNC 计帧时钟」的关键区别。

3. `engine_frame_pump()` 本体**未改**（`frame.c:24`，token 顺序不动），其 `test_frame_pump.py` 契约继续成立；新增的 `frame_decode_pump()` 是并列入口。

### 3.3 方案 D — 对白空闲期预解码下一批显示图

把解码成本藏进玩家的阅读时间里（131 §6 方案 D）。

1. **预取原语** `image_prefetch()`（`core/engine/image.c:197`，声明 `core/engine/image.h:34`）：与 `image_load()` 同解码路径，但
   - 命中缓存直接返回 0，不重复解码；
   - 未命中则解码并 `image_cache_insert`（缓存持有该槽引用），**不 retain 给调用者**；
   - **不调用 `image_set_palette()`**——预取发生在立绘真正显示之前，不能改当前调色板；
   - 失败静默返回 -1（后续 `image_load()` 会自行再解一次）。

2. **键解析** `nb_prefetch_key(cmd, key)`（`core/engine/nb_commands.c:100`，声明 `core/engine/nb_commands.h:14`）：把显示命令的花括号键解析为 IMAGE.DAT id——`cg`→`cg_map`、`bg`→`nb_asset_id()`（含 SPR 回落）、`char`→`resolve_expr(char_id, "normal")`（默认表情立绘），其余命令返回 -1。

3. **前瞻扫描** `nb_prefetch_lookahead()`（`core/engine/nb.c:366`）：在脚本停在对话框页时，从 `nb.pc` 起向后扫 `NB_PREFETCH_LOOKAHEAD`(=24) 行，复用**真正的解析器** `nb_parse_line()` 取命令名与 brace 键（不另写语法），命中 `cg/bg/char` 即预取；`done_pc == nb.pc` 保证**每个脚本位置最多跑一次**（不逐帧重扫）。调用点在 `nb_process()` 的对话框空闲分支（`nb.c:439`）。

## 5. 验证

- **编译**：`make -C core` 通过，`core/*.err` 无非空文件（诊断走 `.err`，不在 stdout）。
- **测试**：`pytest tools/tests/` → **766 passed, 1 skipped**（较基线 760 增 6 项）。
- **本环境不可验证项（诚实标注）**：实机/NP2kai 上的**听感差异**（颤是否消除、拖是否缓解）与 `hal_vblank_poll` 在 NP2kai 的 VSYNC 旗标可信度，须按 §八 五禁用串口/确定性标记实测：
  1. `./makegame.sh build <game> && ./makegame.sh make <game>`（禁只 build 不 make，跑旧引擎的 A/B 会假通过）；
  2. 立绘解码窗口内 `audio_tick` 派发点的串口时间戳序列应连续（禁点击计数判颤，竞态）；
  3. `hal_vblank_poll` 的边沿计数应 ≈ 显示帧率而非解码扫描次数（可用串口戳 `NB_PREFETCH`/边沿计数验证）。
- **方案 A 的 N 若过减速**：NP2kai pass 率低时回调 §10「A 专属」，把 `AUDIO_YIELD_EVERY` 调大。

## 6. 遗留：方案 C（单独立项，本轮不做）

**用户决策：C 单独立项**（devdoc 131 §9.1 亦建议「必须独立立项」）。C = OPNA Timer-B 中断驱动音泵（复刻 PMD，131 §6 方案 C）：

- 需 YM2608 Timer-B 初始化（`$26`/`$27`/`$29`，见 `docs/refdocs/F04`）、DOS/4GW 下 DPMI 挂中断 + 锁内存（`docs/refdocs/G08`）、正确的 IRQ EOI 含级联 ACK（`docs/refdocs/G09`）；
- **本环境无法验证中断投递与 ACK**，写错会静默卡死（131 §4.9 / §10「C 专属」）；
- 该方案同时会触及帧泵 + `vclock` 所有权 + `audio_tick` 单消费方假设，须独立 devdoc 与实机探针先行。

方案 E（固定 tick 音序）沿用 131 结论：**不建议**（速度绑定 pass 率，模拟器/真机不一致）。
