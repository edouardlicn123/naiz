# 109-光标揭示顿闪消除：写后直绘与不透明矩形快路径收口

> 状态：**已落地**（0.2.136）
>
> 所属：软件光标层（cursor.c / cursor.h / hal_mouse / layer_dialog）
> 上游：devdoc 108（软件光标层契约与对话框抹字收口）；本 doc 为其绩效/视觉质回归补充。

## 1. 问题与复现

用户 bug 报告：「**文字逐个打出的时候（打字机揭示），鼠标在聊天框会闪烁**」。

光谱现象：修复 0.2.135 之前是「鼠标停字幕上把文字抹去」（108 契约修复）；修复后字符不再被抹，但打字机揭示期间光标以约 20Hz 「闪没-重现」。两者同源于 108 的 touch 路径，只是时序窗口不同。

## 2. 根因（代码阅读证据链）

reveal 激活期间，主循环每 pass：

1. pass 顶部 `vblank_wait()` 同步消隐；
2. `nb_dialog_reveal_tick()` → `dialog_layer_blit()`（layer_dialog.c:217）**每 pass 无条件**执行（即使该 pass 未推进字符）；其前置 `hal_mouse_touch_cursor(LAYER_DIALOG_X,Y,W,H)` 与光标 24×24 保存区重叠 → `cursor_erase()` **立即**把旧背景写回 VRAM —— 光标箭头像素此刻就从扫描管消失（此写**不与 vblank 同步**，发生在 pass 中部）；
3. `vram_write(新文字)` 覆盖对话框区；
4. pass 末尾 `hal_mouse_draw_cursor()` → `cursor_render()`（cursor.c:138）**先 `hal_vblank_wait()` 等下一次垂直消隐（至多 ~16ms）**，再 `cursor_draw()` 重画箭头。

于是每条揭示 pass，箭头在扫描管缺席 **≈一整帧**（步 2 → 步 4 之间）。reveal 约 20 pass/s → 持续 ~20Hz 的「闪没→重现」，即用户看到的闪烁。

一句话：**擦除发生在 pass 中部（异步、无同步），重画被 cursor_render 的 vblank 等待拖到一帧之后**——两段时间窗叠加成每帧完整缺席。

## 3. 方案 B：写后直绘 + 不透明矩形快路径

两处各取一刀：

### 3.1 `cursor_render` stale 同位置直绘（杀掉缺席窗口）

```c
stale_same_pos = (!cursor_saved.valid &&
                  draw_x == cursor_saved.x && draw_y == cursor_saved.y);
if (stale_same_pos) {
    cursor_draw(&cursor_saved, draw_x, draw_y);
    return;
}
hal_vblank_wait();   /* 移动/传送/force 保留 */
```

判据：保存态已失效且绘制位置与失效前**相同**。位置相同意味着不是移动（移动会改变坐标；传送也在 HAL 层 invalidate + set_pos 改坐标）——即只可能是「写者 touch 后尚未重画的稳态」。此时擦除已发生（straddle 情形）

或写者已覆盖整盒（opaque 全内情形），**背景已在 VRAM 中定稿**，重画无需再与 erase 配对同步 → 直接 `cursor_draw()`（内部先 vram_read 捕获新背景再画箭头，且把 valid 置回 1、位置更新）。缺席区间从 ~16ms 缩到微秒级。

防撕裂不变式不动：**移动/传送/force 仍走 vblank 同步的 erase+draw 对**，保证扫描管永不出半画光标。代价（已接受）：稳态直绘箭头本人当帧至多撕裂 1 行——24×24 极小、下帧自愈，且 reveal 的写本身也是 pass 中部非同步写，远好于每帧整箭头缺席。

### 3.2 `cursor_touch_opaque` 不透明变体（热路径省掉恢复写 + 给直绘让路）

```c
static int cursor_covered_fully(const CursorBg *bg, int x, int y, int w, int h)
{
    return x <= bg->x && bg->x + CURSOR_SAVED_W <= x + w &&
           y <= bg->y && bg->y + CURSOR_SAVED_H <= y + h;
}

void cursor_touch_opaque(int x, int y, int w, int h)
{
    if (!hal_mouse_available()) return;
    if (!cursor_overlap_rect(&cursor_saved, x, y, w, h)) return;
    if (!cursor_covered_fully(&cursor_saved, x, y, w, h))
        cursor_erase(&cursor_saved, cursor_saved.x, cursor_saved.y);
    cursor_saved.valid = 0;
}
```

契约：**调用方断言其写入会逐像素覆盖整个上报矩形**（composite `vram_write` 等全像素写；透明/部分写者务必继续用 `cursor_touch`）。

- **全内**（24×24 盒完整落在上报矩形内）：`cursor_covered_fully` 为真 → **跳过前置 erase**，仅 `valid=0`——写者像素替光标清场（每 pass 省 576 次恢复写），随后 `cursor_render` stale 直绘重新捕获新文字背景。
- **跨边**（盒探出矩形边界）：维持 `cursor_erase`+invalid → 写者只清一部分 → stale 直绘对跨边也成立（erase 已恢复旧背景整盒，局部写后再捕获，无残影）。

**为什么不能对所有写者一律跳过 erase**（C18 纪律）：若授予部分/透明写者（`render_blit_transparent`——透明像素不覆盖旧箭头；OOM 部分文本 `draw_text`），箭头像素可能没被写者覆盖，直绘时 `vram_read` 会把**活箭头快照进背景** → 下次移动恢复出幽灵（正是 108 拒绝 `cursor_refresh` 的同一残影类别）。因此「跳过 erase」的权利只授予真正的全像素不透明写者，且集中在 `cursor_touch_opaque` 一处。

### 3.3 调用点改造

`dialog_layer_blit()`（layer_dialog.c）改用 `hal_mouse_touch_cursor_opaque(LAYER_DIALOG_X, ...)`——它是 reveal 唯一热路径，其 composite `vram_write` 本就逐像素覆盖整个对话框矩形。其余全部写者保持 `cursor_touch` 语义不变：

| 调用点 | 实际写入 | opaque? |
|---|---|---|
| `dialog_layer_blit` vram_write | 全矩形 | ✅ 改用 opaque |
| `fill_dialog_bg` fill_rect / fill_rect_pattern | 全矩形 | ✅ 但非热路径，维持 touch |
| `layer_dialog_show` OOM box 全填+描边 | 全矩形 | ✅ 维持 touch |
| `layer_dialog_render_page` OOM draw_text | 部分 | ❌ 维持 touch |
| `menu_layer_blit` render_blit_transparent / vram_write | 混合 | ❌ 维持 touch（透明像素不覆盖） |
| `menu_layer_blit_rect` / `menu_layer_close` vram_write | 全矩形 | ✅ 非热路径，维持 touch |

## 4. 性能

- 全内热路径（光标停在对话框内 + reveal 激活）：每 pass 省 576 次恢复写，仅增两处整数比较（重叠 + 含载）与一次分支。
- `dialog_layer_blit` 本体 480×115 ≈ 5.5 万像素写，24×24 开销 <1% 量级，pass 预算 20–49ms 内可忽略。
