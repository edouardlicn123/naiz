# devdocs/137b-实机反馈续：flute buzz 持久且方案 1 无效（需降低调制强度）

## 一、问题描述

用户反馈：`flute.fmp` `pms 2→1`（方案 1）**修改后毫无改善**。已重新编译测试。

这说明导致整段播放期间都存在的「电流声/buzz」以及感知音高偏低的主因**不是 LFO/PMS 深度**，而是**正确 op 映射下的稳态 FM 调制指数偏高**。

## 二、根因分析

- **方案 1 失效**：只调 `pms` 不影响稳态调制。若 buzz 是「整个播放期间都有」（连续性），降低颤动深度自然没作用。
- **调制强度偏高**：op 映射现为恒等 `[0,1,2,3]`，与 NP2kai fmgen 一致，是正确的（必须保留）。在正确映射下，`op=1`（调制器，`tl=52`）对 `op=2`（载波，`tl=2`）的调制指数可能偏强，持续产生边带，整段都听得到「buzz」。
- **感知偏低也由此导致**：边带过多会改变频谱重心，容易让人感知音高中心偏低。
- **不回退映射**：`tools/naiz_audio/fm_patch.py::OP_FILE` 必须保持 `[0,1,2,3]`。正确方向是在正确映射下重新平衡 voicing。

## 三、改动方案（单步）

### 方案 2a（最保守，首选）：提高调制器衰减 `tl 52→54`

**文件**：`assets/demo-a2/fm/flute.fmp` 第 17 行

```diff
- op=1 dt=0 mul=1 tl=52 ks=1 ar=12 am=0 d1r=5 d2r=3 sl=10 rr=8
+ op=1 dt=0 mul=1 tl=54 ks=1 ar=12 am=0 d1r=5 d2r=3 sl=10 rr=8
```

**理由**：`tl` 越大 = 调制器输出越弱 = 调制指数越低。优先调 `op1`（调制器）而非 `op2`（载波），尽量保留笛子的气声质感。

### 方案 2b（若 2a 无明显改善）：提高到 `tl 54→56`

**文件**：`assets/demo-a2/fm/flute.fmp` 第 17 行

```diff
- op=1 dt=0 mul=1 tl=54 ks=1 ar=12 am=0 d1r=5 d2r=3 sl=10 rr=8
+ op=1 dt=0 mul=1 tl=56 ks=1 ar=12 am=0 d1r=5 d2r=3 sl=10 rr=8
```

### 备选（必要时再用）：若 2b 仍无明显改善，可试 `tl=60`，或微调 `op2 tl`（载波略衰减）。但首轮先用 54→56 单步。

## 四、测试流程

1. **方案 2a**：改 `tl 52→54` →  
   ```bash
   ./makegame.sh build demo-a2 && ./makegame.sh make demo-a2
   ```
   → 单步试听场景 1（Melody Town Theme）的笛子段落。重点：整段 buzz 是否减轻？感知音高是否改善？
2. **若无明显改善**：再做 **方案 2b**（`tl 54→56`）→ rebuild+单步试听。
3. **若仍无改善**：再评估是否上到 `tl=60` 或调 `op2 tl`。此时也可顺带评估其他族（方案 3）但**先定 flute**。
4. **收尾**：保留最小且最有效的改动组合。**绝不回退** `fm_patch.py::OP_FILE`。
