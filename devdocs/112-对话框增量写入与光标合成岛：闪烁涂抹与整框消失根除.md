# 112-对话框增量写入与光标合成岛：闪烁涂抹与整框消失根除

> 状态：**已落地**
>
> 所属：软件光标层（cursor.c / cursor.h / layer_dialog.c / plat/hal.h）
> 上游：devdoc 110（对话框合成缓冲预拼光标）、devdoc 111（splice 只进一次性书写副本）；本 doc 以**增量 diff 写入 + 光标合成岛** 取代 splice 链路，并对 diff 基准失效（整框消失）收口。

## 1. 问题与 A/B 实验结论（111 落地后）

0.2.138（devdoc 111）落地后，用户逐一反馈并完成多轮 A/B：

| 构建 | 行为 | 反馈 |
|------|------|------|
| 无 splice | 慢速全幅 480×115 `vram_write` | 残影全消，**打字与移动闪烁依旧/无改善** |
| 无 splice + 写后立即 `cursor_render()` | 同上 | 残影 0、闪烁无改善**
| 移动路径 vblank 重读 | 同上 | 移动+打字都闪 |
| 恢复 splice（flash 不动 saved.x/y） | 预拼快路径 | 残影回归、闪烁依旧 |

**结论**（两条链路独立）：
1. **残影 ↔ splice**：splice 把活箭头烙进持久缓冲 / 被采作背景基准，是残影的必要条件；封死它残影即 0。
2. **闪烁（撕裂）↔ 全幅写**：57 (cyc) × 480 宽 × 115 行的 bank 切换 `vram_write` 比 CRT 扫描线慢，扫描追上半写帧即撕裂 → 打字/移动都闪。增量写是唯一根治，任何预拼/调序都无法补偿「全幅写必然撕裂」。

0.2.139 采用**方案 A**：对话框增量 diff 写 + 光标作为独立合成岛覆盖层，splice 链路整体删除。

## 2. 方案 A：增量写入 + 光标合成岛

### 2.1 增量 diff 写入（撕裂缝/源根治）

`dialog_layer_blit()` 放弃整块写，改为**逐行 diff**：

- 新增持久基线快照 `dialog_blit_prev`（480×115，`layer_dialog_show` 分配、`layer_dialog_reset` 释放，OOM 降级为每次全幅写）。
- 每次 blit：逐行 `memcmp(dialog_layer, dialog_blit_prev, W)` 求「变化行 band」，只把 band 内行写 VRAM（`dialog_write_rows`），随后 `memcpy` 同步 prev。
- 打字 reveal 每 pass 只改 1~3 个字形行 → 从「几千次 I/O、毫秒级」降至「几次单行写、微秒级」→ 扫描线永远追不上 → 打字/移动闪烁根除。

### 2.2 光标合成岛（composite island）

光标盒**完全在对话框 rect 内**时：

- `dialog_write_rows` 对 island 行**跳过盒列**（左右两段分别 `vram_write`）——盒 VRAM 归光标层所有，任何写入都不碰它。
- 盒背景权威 = 对话框合成缓冲：`cursor_draw` 从 `layer_dialog_composite()` capture（最新文本），`cursor_erase` 写回 composite → 盒内文字永远最新，残影无源。
- diff band 与光标盒 y 相交 → `cursor_dialog_rows(y1,y2)` 触发盒 erase+draw，reveal 推进到盒下时盒内文字跟新。
- 盒**跨越** rect 边界的行 → 回退经典 `cursor_touch` 契约（erase+invalidate，pass 末重画），低频率路径。

### 2.3 混合背景（修复描画涂抹）

光标盒与对话框**部分相交**时，旧实现 erase 用 draw 时刻捕获的快照恢复——快照里框内部分是**旧文本**，而 diff blit 已抢先写入新文本 → 把旧文字涂回画面（「移动鼠标如画笔涂抹」）。修法：`box_background()` 混合背景 = **框内列从 composite 取（权威最新文本）+ 框外列从快照取**，capture 与 restore 对称使用 → 跨框边移动不会涂抹旧文本。`box_in_dialog`（整盒在内）判定保留给 island 列跳；相交判定 `box_overlap_dialog`（含部分）驱动混合背景。

## 3. 整框消失根因与基准失效收口（0.2.137→下版）

方案 A 落地后残留新症状：

> 「a day passed 那句时几乎整个对话框没了，仅剩文字区附近」「下一场景新加载的对话框又缺失下方的部分」

**根因**：diff 的基线 `dialog_blit_prev` 隐含假设「对话框 rect 的 VRAM 只被 `dialog_layer_blit` 动过」，而 **`layer_dialog_hide()`**（`display_apply_cg()` / `scene_display.c` 场景切换 / `nb_commands` cg/bg 过场调用）恢复 under 时**只清 `dialog_drawn`，不清 prev**。之后对话框重新打开（`layer_dialog_show` + `render_page` + blit）走 diff：以 hide 前的旧页为基准，与新页字节相同的行（框、dither、文本重叠区）被误判「未变」→ 跳过不写，而 VRAM 那些行已是 hide 后的 under/新背景 → 整框缺失、只余真正不同的文字行。**基准漂移无 self-heal，之后永不补写。**

**收口**：新增单个失效位 `dialog_blit_baseline_valid`，语义 = 「上次 blit 后 VRAM rect 是否仍与 composite 连续同步」。四个触点：

1. `dialog_layer_blit()`：首幅条件 `if (!dialog_blit_prev || !dialog_blit_baseline_valid)` → 整幅 `dialog_write_rows(0,H)` + `cursor_dialog_rows` + 更新 prev + 置位；OOM（prev 分配失败）仍退回「本次已写全，下帧重试」。
2. `layer_dialog_hide()`：恢复 under 后置 `= 0`（VRAM 不再是 composite）。
3. `layer_dialog_show()` 的 `if (!dialog_drawn)` 分支：置 `= 0`（曾隐藏/首次 alloc 后重新打开一律整幅重发；save 菜单关闭走 show 同语义）。
4. `layer_dialog_reset()`：置 `= 0`（与 free prev 双保险）。

另随本轮删除已无调用方的 `hal_mouse_touch_cursor_opaque`（HAL 声明 + `hal_mouse.c` wrapper，消灭死导出；devdoc 109 的 opaque 快路径已被 island 机制取代）。

**日志澄清**：串口 `[CT]nnn r N` 的 `r` 是 `dialog_state.reveal_end`（已揭示**字符偏移**），不是 diff 行数，不能用作 diff 行为观测。
