## 一、背景与目标

现有 NB 脚本只有 `scene` 能改变执行位置，且目标粒度是**整个场景**；`question` 只能做变量加减，无法根据选项跳到指定台词。由此带来两个写法缺陷：

1. 想在一个场景内按选项分支，只能拆成多个 `.nb` 文件，或用变量 + 多级 `scene` 条件链，剧本不可读；
2. 从选项直接进入另一场景的**中间位置**（例如章节内跳过前情）无法表达，`scene` 只能从头播。

本轮新增三条指令，目标是在**不改动现有指令语义**的前提下，提供场景内锚点与选项驱动的跳转：

| 指令 | 一句话语义 |
|---|---|
| `tag(name)` | 在场景内标记一个位置 |
| `jump(prompt;label,tag;...)` | 弹选项，选中后跳到**本场景**的 tag |
| `jumpscene(prompt;label,scene[,tag];...)` | 弹选项，选中后切到目标场景（可落到目标场景的 tag），当前场景剩余内容丢弃 |

## 二、语法（EBNF）

```ebnf
line            := "tag" tag_args
                 | "jump" jump_args
                 | "jumpscene" jumpscene_args ;

tag_args        := "(" TAG ")" ;                    (* 必须单独一行 *)
jump_args       := "(" prompt ( ";" option )+ ")" ;
option          := label "," TAG ;
jumpscene_args  := "(" prompt ( ";" scene_option )+ ")" ;
scene_option    := label "," SCENE [ "," TAG ] ;

prompt          := text ;                           (* 第一个 ';' 之前的整段，逗号是字面量 *)
label           := field ;                          (* 支持 "\," 与 "\\" 转义，与 question 一致 *)
TAG             := 1*( ALPHA / DIGIT / "_" ) ;
SCENE           := "003" | "nb003" | "nbook003" | "nbook003.nb"
                 | "end" | "logo" | "op" | "mainmenu" ;
```

示例：

```nb
tag(m1)
fei{林间小路}

# 场景内分支：只允许跳到本场景的 tag
jump(要去哪？;森林,m1;城镇,m2)
fei{选错了}
tag(m2)

# 跨场景：第三段是可选的落点 tag
jumpscene(要继续吗？;森林,nb003;城镇,nb004,m2)
```

## 三、语义

### 3.1 `tag(name)`

- **纯标记，运行时无操作**：解释器执行到该行时 `pc` 已自增，命令处理器不改变任何状态。
- 必须单独一行；写在其它命令同一行不会生效（解析器只认行首命令）。
- 重复 tag 合法；查找时**首个命中优先**。
- 注册进 `cmd_table` 的唯一目的是避免旧逻辑把 `tag(...)` 当成未知命令打 WARN。

### 3.2 `jump(prompt;label,tag;...)`

- 交互与 `question` **完全同源**：同一套对话框选项渲染、鼠标/键盘输入、30 s 挂钟超时、400 ms 输入就绪门。
- 选中第 i 项 → 在当前场景内查找 `tag`，命中则把 `pc` 设为该 tag 行的**下一行**；未命中 → 打 WARN，不跳，继续执行 `jump` 行之后的内容。
- 超时（`ui_interact` 返回 -1）→ 不跳，脚本继续，行为与 `question` 超时一致。
- **禁止跨场景**：查找范围固定为当前 `nb.buf`。写法上也不提供场景字段。
- 允许向前/向后跳；向后跳会重新执行 tag 之前的台词（循环分支依赖此行为）。
- 选项不带变量操作尾段（明确不实现）。

### 3.3 `jumpscene(prompt;label,scene[,tag];...)`

- 交互同上；选中后调用场景切换单入口，当前场景剩余内容被丢弃。
- `scene` 归一化规则（与 `scene` 命令的解析共用一套）：

  | 写法 | 目标文件 |
  |---|---|
  | `003` / `nb003` / `nbook003` / `nbook003.nb` | `nbook003.nb` |
  | `end` | `mainmenu.nb` |
  | `logo` / `op` / `mainmenu` | `{name}.nb` |

- 第三段存在 → 新场景加载完成后定位到该 tag（`pc = tag 行 + 1`），**不播放场景开头**。
- 第三段缺省 → 从目标场景第一行开始。
- 目标 tag 缺失 → WARN，并从场景开头执行（不报错停机）。

### 3.4 选项数量与截断

与 `question` 保持一致：解析上限 10 段，界面最多显示 4 段；超过 10 段截断并 WARN。被截断的选项不可见亦不可选。

## 四、错误处理

| 情况 | 行为 |
|---|---|
| `argc < 2`（无 prompt 或无可选项） | WARN，命令忽略，继续 |
| 选项段缺 tag（`jump`）或缺 scene（`jumpscene`） | 该段跳过并 WARN；有效选项为 0 时不弹窗、继续 |
| 选项超过 10 | 截断保留前 10，WARN |
| 交互超时 | 返回 -1，不跳，继续 |
| `jump` 的 tag 不存在 | WARN，不跳，继续 |
| `jumpscene` 的 scene 文件不存在 | 走现有场景加载失败路径（`vm_set_error`），与 `scene` 一致 |
| `jumpscene` 的 tag 不在目标场景 | WARN，从目标场景开头执行 |
| 重复 tag | 首个命中，不报错 |

运行时错误一律 WARN + 继续，只有场景文件打不开才进入现有错误路径。

## 五、实现设计

### 5.1 解释器（`core/engine/nb.c`）

- 新增 `nb_seek_tag(tag)`：线性扫描当前 `nb.buf`，用 `nb_get_line` + `nb_parse_line` 识别 `tag(name)` 行，命中则 `pc = line + 1`。**不建 tag 表**，避免 BSS 增长（64 KB 余量约束）；扫描仅发生在跳转时。
  - 行缓冲取 256 B：命令名与 tag 参数都在行首，长行截断不会造成误判。
- 新增 `nb_scene_switch_tagged(filename, reason, tag)`：把 tag 存入 one-shot `g_pending_tag`，再调用 `scene_switch` 单入口。
- `nb_load` 入口即取走并清空 `g_pending_tag`（本地副本），保证：
  - 失败打开文件时 tag 不会泄漏到下一次无关加载；
  - 新场景加载完成后（`num_lines` 与缓冲就绪）执行 `nb_seek_tag`。
- `nb_process` 的 `;` 重解析命令列表从 `question/scene` 扩展为 `question/jump/jumpscene/scene`。

### 5.2 共享选项交互（`core/engine/nb_question.c`）

抽出 `nb_prompt_options(prompt, labels, n)`：清对话框 → 存 palette → 画 prompt → `tr()` 标签 → `ui_interact` → 还原 palette → `nb_set_last_choice(sel)` → 返回 sel。`cmd_question` 改为调用该函数，三条命令共用同一套交互与超时常量。

### 5.3 命令处理器

- `core/engine/nb_scene.c`：
  - `cmd_jump` / `cmd_jumpscene`，段解析复用 `nb_next_field`（转义规则与 `question` 一致），末字段取剩余串并裁剪首尾空白；
  - 场景目标归一化抽成共用函数，`scene` 与 `jumpscene` 共用。
- `core/engine/nb_commands.c`：`cmd_tag` 为 no-op；表项：

  | 命令 | flags |
  |---|---|
  | `tag` | `0` |
  | `jump` | `CMD_BLOCKING \| CMD_NEEDS_INPUT \| CMD_TOUCHES_DISPLAY` |
  | `jumpscene` | 同上 `\| CMD_TERMINATES_SCENE` |

- `nb_commands.h` 增加三个 handler 与 `nb_prompt_options` 的声明；`nb_internal.h` 增加 `nb_seek_tag` / `nb_scene_switch_tagged`。

## 八、风险与约束

| 风险 | 处置 |
|---|---|
| BSS 64 KB 余量 | 不建 tag 表，跳转时线性扫描；新增全局仅 `g_pending_tag[32]` |
| 栈占用 | tag 扫描缓冲 256 B，位于主线程调用链，无 ISR 路径 |
| pending tag 残留 | `nb_load` 入口即取走并清空，失败加载不泄漏 |
| 与 `question` 交互漂移 | 三命令共用 `nb_prompt_options`，超时/输入门常量单点维护 |
| 旧脚本兼容 | `tag/jump/jumpscene` 为新命令；既有命令语义、参数、flags 不变 |
| tag 命名冲突 | 查找为精确字符串比较（大小写敏感），首个命中优先 |

## 九、非目标

- 不给 `jump` / `jumpscene` 增加变量操作尾段（会显著提高解析复杂度，已明确拒绝）。
- 不实现 `jump` 的跨场景跳转（跨场景一律走 `jumpscene`）。
- 不提供 tag 枚举/动态 tag 名，不做运行期 tag 缓存。
- 不改动 `question` / `scene` 的既有参数形态与错误语义。
