# devdocs/137-修复用户实机反馈：flute及其他族感知音调偏低与buzz问题

> 状态：**实施中**（0.3.035）
> 创建于：2026-10-14
> 最新修改：2026-10-14

## 一、问题描述

用户实机验证 P1b（`op=` 语义修复、fmbench/oracle 对齐、P1b 三件套落地）后反馈：
- 「音调似乎过低而且有不正常的类似喇叭振动的电流声」
- 补充：「部分音乐似乎严重偏低；整个播放期间都有；新出现，与先前的电子琴音似乎关系不是很大」

这与之前的「像电子琴」和「静音」不同，是 op 语义修复后暴露出的**voicing 平衡问题**。

## 二、根因分析

### 2.1 为什么是「新出现」的 buzz/感知偏低

- **修复前（错映射）**：`tools/naiz_audio/fm_patch.py` 的 `OP_FILE` 用 `[0,2,1,3]`（把算法算子写到错误寄存器槽）。这种错配产生了一种较干净的「电子琴音」（掩盖了边带）。
- **修复后（正映射）**：改为恒等 `[0,1,2,3]`，并且引擎侧 `fmopn_op_slot = {0,2,1,3}` 与 NP2kai fmgen `slottable = {0,2,1,3}` 一致。现在**调制器↔载波的角色真正对应到硬件**。所以音色更接近设计的「近正弦笛子」，但也暴露出：在**正确映射**下，目前的 voicing 会产生较明显的边带，在整个播放期间都能听到，因而被感知为「电流声/buzz」。
- **修复后算子映射是对的**。devdoc 136 §十三 已交叉验证（ymfm + NP2kai fmgen），不应回退 `OP_FILE`。

### 2.2 关于「音调过低」

- **绝对音高**：从代码上看 `fmopn_note_ratio` 计算 `block/fnum` 正确（C4→block3/fnum618），写入 `$A4=(block<<3)|(fnum>>8)`、`$A0=fnum&0xFF` 格式正确。理论绝对音高应约 **261.6 Hz**。
- **感知偏低**：flute 带 `pms=2`（OPNA 全局 LFO，LFRQ≈2→~6.6Hz）。在较干净的近正弦音上，6.6Hz 颤音本身会让人**感知音高中心偏低**，再叠加边带较明显，就给人「部分音乐严重偏低」的印象。
- **范围不限于 flute**：其他带 LFO 的族（`strings/reeds/ethnic/synfx pms=3`、`synpad pms=2`、`brass/synlead pms=1`）也可能在正确映射下产生类似的感知偏移。

### 2.3 验证假设（仅用于理解，不强制测量）

用户明确表示：「我不确定我的描述与你的理解是否一致，我计划让你尝试修改后，我自己听听效果再算。」  
因此本 devdoc 的思路是**最小改动→单步试听→再决定下一步**，而非先做大规模量化。

## 三、修改方案（最小、可回滚）

所有改动只针对 `.fmp` 文本（纯参数），可随时 `git checkout` 回滚。

### 方案 1（最小、风险最低）：flute 降低 LFO 深度 `pms 2→1`

**文件**：`assets/demo-a2/fm/flute.fmp` 第 16 行

```diff
- alg=4 fb=0 pan=0xc0 ams=0 pms=2
+ alg=4 fb=0 pan=0xc0 ams=0 pms=1
```

**理由**：buzz 在整个播放期间都有。LFO（pms=2）让近正弦笛音产生明显边带/抖动，被听成 buzz 的同时也导致感知音高偏低。降深（pms 1）能削弱这两个效应，同时保留自然颤音。

**预期**：buzz 明显减轻，感知音高「没那么低」。

**回滚**：改回 `pms=2`。

### 方案 2（若方案 1 仍有 buzz）：flute 降低调制强度（削减边带）

**文件**：`assets/demo-a2/fm/flute.fmp` 第 17 行

```diff
- op=1 dt=0 mul=1 tl=52 ks=1 ar=12 am=0 d1r=5 d2r=3 sl=10 rr=8
+ op=1 dt=0 mul=1 tl=56 ks=1 ar=12 am=0 d1r=5 d2r=3 sl=10 rr=8
```

（更保守可先试 `tl=54`，再试 `tl=56`。`tl` 越大=调制器越弱=buzz 越少，但气声感也会减弱。）

**理由**：若降低 LFO 后 buzz 仍有，说明正确映射下的调制指数偏高。提高调制器衰减（TL）可降低调制强度、削减边带。

**预期**：buzz 减轻，音色更干净。

**回滚**：改回 `tl=52`。

> 建议顺序：先 **方案 1** → rebuild+试听 → 若仍有 buzz 再做 **方案 2**。两者可叠加，但推荐单步验证。

### 方案 3（针对「部分音乐严重偏低」的其他族，谨慎、逐族尝试）

其他带 LFO 的族在正确映射下也可能出现感知偏移。**不要一次全改**，优先针对最明显的那一族做最小降深。

| 族文件 | 当前 `pms` | 建议改动 | 理由 |
|---|---|---|---|
| `strings.fmp` | 3 | `pms=2` | pms=3 在正确映射下容易被感知成「抖动+buzz」，导致音高感偏低 |
| `reeds.fmp` | 3 | `pms=2` | 同上 |
| `ethnic.fmp` | 3 | `pms=2` | 同上 |
| `synfx.fmp` | 3 | `pms=2` | 同上 |
| `synpad.fmp` | 2 | `pms=1` | 与 flute 类似，降低感知偏移 |
| `brass.fmp` | 1 | **不建议改** | 已经较浅，收益可能不明显 |
| `synlead.fmp` | 1 | **不建议改** | 同上 |

**原则**：找出最明显偏低的段落对应的族（按 GM 映射推断），**每次只改 1 个族**，修改→`build+make`→试听，再决定下一步。

## 四、测试流程

1. **保存现场**（可选）：`git diff --name-only`，随时可 `git checkout .` 或 `git diff` 回滚。
2. **方案 1**：改 `flute.fmp` `pms 2→1` →  
   ```bash
   ./makegame.sh build demo-a2 && ./makegame.sh make demo-a2
   ```
   → 试听场景 1（Melody Town Theme）的笛子段落。重点感受：buzz 是否减轻？音高感是否正常了？
3. **若仍有 buzz**：按方案 2 改 `flute.fmp` `tl 52→56`（或 54）→ rebuild+试听。
4. **若整体仍有「部分音乐严重偏低」**：按方案 3，**每次只改 1 个族**→rebuild+试听。
5. **收尾**：保留最小且效果最好的改动组合即可。**不回退 op 映射**（`fm_patch.py::OP_FILE` 必须保持恒等 `[0,1,2,3]`）。

## 六、遗留

- **绝对音高排查（可选）**：如果实在想排除绝对音高，可录制 `/tmp/flute.raw` 并用 `tools/naiz_audio/spectrum_report.py --f0` 测 `f0_hz`（预期 ~261.6）。但按用户意愿，**首选主观试听迭代**。
- **其他族的系统性平衡**：P2 阶段再统一梳理带 LFO 族的 `pms`，本轮只处理最明显的感受。
- **`bass.fmp` 等串行 patch**：devdoc 136 已标注其载波系数待 P2 重估，不在本轮范围内。
