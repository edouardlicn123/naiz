# BGM 不可打断性：阻塞段取证与音泵解耦（三阶段：取证 → 快赢 → 中断驱动音泵）

> **状态**：已完结（Phase 1 取证打点 + Phase 2 快赢 B2 + Phase 3 C1 探针已交付；Phase 3 的 ISR 本体（C2）待探针判定后另轮实施，总纲见 §五）
> **版本**：0.3.048（实施）／0.3.047 起草
> **日期**：2026-10-20
> **前序**：`devdocs/129`（vclock 诞生）/ `130`（vclock 重构）/ `131`（帧泵 + 解码泵 + 方案 A–E）/ `133`（首窗直采 + 测量平滑）/ `134`（方案 C：中断驱动音泵**立项**）/ `139`（窗口比率钳制）/ `148`（vclock 诊断记录）；`B19 §2`（时钟源谱系）；`G08`（DOS/4GW 中断 API）/ `G09`（vsync IRQ + 级联 ACK 清单）/ `F04`（OPNA Timer 规格）/ `C01`（VSYNC 中断端口事实）
> **症状环境**：NP2kai 模拟器（用户实测）；实机列为复验
> **用户三拍板**：①症状 = 「任何操作（对白翻页/立绘/SE/voice/菜单）→ BGM 停住，操作结束**原地续播**」；②环境 = NP2kai；③三阶段全立项（Phase 3 = `134` 实施轮，接受中断风险）

---

## 一 症状与定性

任何引擎操作期间 BGM 停住，操作结束后从停住的位置继续播放（不跳段、不慢放、不断链）。SE/voice 与 BGM 分立（`nb_audio.c`：PCM 走 `g_pcm_buf` 单通道、BGM 走 fmseq/MPU，互不掐断），故症状属 **BGM 时基通路**。

**定性：设计缺陷（协作式音泵 + 虚拟时钟「每 pass 定步进、相位不受控」），CPU 慢放大。** 非单点 bug——三条机制并存，Phase 1 取证判主次（见 §三）。

---

## 二 机制清单（本文件全部坐标经 0.3.047 代码逐条核对）

### M1 主嫌：慢 pass 时间债（vclock 相位不受控）

- 音泵 = 协作式轮询：`fmseq_pump` 仅由 `audio_tick()`（`core/engine/audio.c:572` 起，FM 分支 `:618`/`fmseq_pump` 在 `:621`）驱动；`audio_tick` 仅在 `engine_frame_pump()`（`core/engine/frame.c:12`）与 `frame_decode_pump()`（`frame.c:44`）中被调。
- 虚拟时钟 `vclock_advance()`（`core/lib/vclock.c:70`）**每次调用只发 `step`（`vclock.c:150-163`，与本次 `delta` 无关）**；真实流逝只用于窗口测速（`accum/passes`，`vclock.c:96-98`），**相位差从不补偿**——`vclock.h:35-40` 明文「only the clock's *rate* matters, never its phase against the platform's reading（闭环节拍器只需速率）」。
- 后果：一次慢 pass（如对白整页重绘的 VRAM 密集写、NP2kai 模拟器放大）墙钟走了 300 ms，虚拟钟只走 `step`≈36 ms ⇒ 差额 = **音乐时间债**，此后只有被 5/4 窗口比率钳制的瞬态速率追赶（`vclock.c:123-136`）、**无相位偿还** ⇒ 听感 = 操作期停住、操作后原地续播（位置落后墙钟）。与用户症状精确吻合。
- 既有 `[VC]` 串口行（`core/plat/hal_pc98.c:136`）只打 `v/step/tgt/cal`，**无法直接读债**——Phase 1 补 `w=`（墙钟）。

### M2 次嫌：同步读盘段零泵

- `pcm_play()` 的 `farchive_read_alloc()`（`core/engine/audio.c:393`，PCM 读取段）是阻塞读，期间无任何泵。文件小（SE/voice ≈6–9 KB），量级待 Phase 1 实测。
- 其余阻塞段审计：`scene()` 路径由 `audio_stop_all()`（`nb.c:300`）自动停音频（AGENTS §十四.6 既定设计，视为「下令停止」，**不在本文件症状范围**）；CG/立绘解码已由 mag 进度钩 → `frame_decode_pump` 覆盖（`audio_init` 中 `mag_set_progress_hook(frame_decode_pump)`，`audio.c:518`，stride 4096 = `mag.c:14` `MAG_PROGRESS_STRIDE`）。

### M3 结构疑点：解码泵时钟门控两头错

`frame_decode_pump`（`frame.c:44-51`）曾把 `hal_wallclock_smooth_advance()` 关在 `hal_vblank_poll()`（`hal_pc98.c:176-184`，GDC 状态口 `0xA0` bit5）门后：

- 若该轮询在 NP2kai 上**失效**（恒 0）⇒ 解码期时钟**完全冻结** = 立绘加载期 BGM 硬停（M3a）；
- 若**有效** ⇒ 解码 stride 率（每 4 KB 一次）× 主循环标定的 `step` ≈ **2× 快进跳段**（M3b）。

`131` 当年的「按 stride 数快进」担心**不成立于自测量时钟**：vclock 窗口 `want=accum*16/passes` 按调用率自归一（`vclock.c:101-136`），任意调用率下每秒发出的虚拟时间恒 ≈ 真实秒。但门控使两头都错。**c61 遗留「边沿计数 ≈ 显示帧率」的实机验证从未执行**（AGENTS c62 遗留条目），本文件 Phase 1 收口。

## 三 Phase 1 取证（零行为改动，NP2kai 为主）

**目标**：逐操作给出「冻结时长 → 债 → 机制归属」表，判 M1/M2/M3 主次。取证不过不进 Phase 2 对应项。

### 3.1 泵间隔 + 债打点（`AUDIO_PUMP_TRACE`，默认开）

`audio_tick()` 入口插入（编译开关同 `BGM_TICK_TRACE`/`VCLOCK_TRACE_ENABLED` 先例，`-DAUDIO_PUMP_TRACE=0` 关）：

- `gap = wall_ms − last_wall_ms`；`gap >= AUDIO_PUMP_TRACE_GAP_MS`（150 ms，听感停顿阈值）才打点，防串口刷屏；
- 行格式：`[AP] gap=%lu v=%lu w=%lu d=%+ld`——`v`=虚拟钟、`w`=墙钟、`d=w−v`=**累计债**（正 = BGM 落后）。
- 每次入口无条件刷新 `last_wall_ms`（测的是「上一次泵到现在」）。

### 3.2 `[VC]` 行补墙钟（`hal_pc98.c`）

`[VC] v=… w=… step=… tgt=… cal=…`——长跑中 `w−v` 即债趋势（每 64 次 advance 一点）。

### 3.3 采样矩阵（串口 + `--forbid` 确定性判据，守 §八五禁）

| 操作 | 剧本动作 | 判据 |
|---|---|---|
| 对白整页翻页 | 多页行确认键 | `[AP]` gap ≥ 1 次、`d` 跳升 ⇒ **M1** |
| 立绘（char） | 场景立绘切换 | 解码期若出现 gap 连发 ⇒ **M3a**；`d` 平滑 ⇒ 已被 decode pump 覆盖 |
| CG | `cg{}` 大图 | 同上 |
| SE/voice | `sound(){}`/`voice(){}` | gap 与读盘重合 ⇒ **M2** |
| 菜单开合 | 设置/存读档 | `[AP]` gap、`d` 跳升 ⇒ M1 类 |

### 3.4 `hal_vblank_poll` 边沿计数（c61 遗留收口）

同轮串口日志中加边沿计数（或独立探针）：解码 4 s 内 `hal_vblank_poll()` 返回 1 的次数 ≈ 显示帧率（NP2kai ~20–55 Hz）则 M3b 成立；恒 0 则 M3a 成立。

**产出**：§3.3 表格填实测数字。M1 属结构性（任何慢 pass 都欠债，Phase 3 根治）；M2/M3 属可定点消除的快赢。

## 四 Phase 2 快赢（NP2kai 可验，低风险）

### B1 无泵段补泵（按 Phase 1 清单，逐点评估）

- `pcm_play` 读盘：只可在**读盘前**插泵（读盘后 `g_pcm_buf` 已装载，`audio_tick` 的收尾 free 判定 `audio.c:605` 有 UAF 风险）；读前泵只保 FIFO 连续、不消读盘 stall。**量级由 Phase 1 实测决定，不做盲改。**

### B2 解码泵时钟去门控（本轮已实施）

`frame_decode_pump` 改为**无条件** `hal_wallclock_smooth_advance()`；`anim_tick` 仍留 `hal_vblank_poll` 边沿门控（动画保持显示节拍，解码 stride 率下不得快进）。依据 §二 M3：vclock 自测量使任意调用率速率正确；门控只造成冻结/2× 两头错。守卫：`test_frame_pump.py::test_decode_pump_advances_clock_unconditionally_and_stays_nonblocking`（旧 `test_decode_pump_is_edge_gated_and_nonblocking` 重写为新语义）。

### B3 有界相位追赶（**暂缓**，不实施）

vclock 债超阈值后以受控超速在 N 个 pass 内偿还（沿用 133/139 夹逼教训）。**暂缓理由**：①追赶只缩短恢复、**不消操作期的停顿**（停顿发生在慢 pass 内部）；②M1 类停顿的根治是 Phase 3（泵频率与主循环解耦后债不再产生）；③133/139 两次「追太快=新颤音」的前科。若 Phase 3 后仍有可闻残留债再启。

## 五 Phase 3 结构根治 = `devdocs/134` 实施轮（本文件只写总纲与本轮探针）

`134` 蓝本不重复；本文件落地其**第一步：vsync IRQ 探针**。

### C1 本轮已实施：GDC vsync IRQ 探针（`NAIZ_IRQ_PROBE`，默认关）

**事实基础**（已核）：IRQ2 = INT `0Ah`（`C01:310`；向量基 0x08 由 `keyboard.c:7`「INT 09h=键盘」与 `G01:87`「IRQ0=INT 08h」交叉印证）；写 `0x64` 任意值 = 手动触发/唤醒 vsync 中断（`C01:311-312`、`G09:38-39`）；Master PIC 口 `00h`(cmd)/`02h`(data)（`G01:78`）。**「NP2kai 是否投递 vsync IRQ」= `G09 §2` 明列未实测项，本探针就是它的判决器。**

**探针设计（安全优先，零向量改挂）**：

- `hal_irq_probe_run()`（`hal_pc98.c`，`#if NAIZ_IRQ_PROBE`）：`outb(0x64,0)` 唤醒 → 读 master IMR 备案 → 2 s 紧循环采样 Master PIC **IRR bit2**（OCW3：`outb(0x00,0x0A)` 后读 `0x02`）→ 打 `[IRQP] hits=%lu samples=%lu imr=%02lx`。
- **不动 IMR、不改 INT 0Ah 向量**——电平触发的 IRR 无论 mask 与否都显示挂起请求，故对 DOS 零副作用；无 `dpmi.h`（本机 Watcom 安装缺）也无需 DPMI 向量 API。
- 判定：`hits/samples` ≈ 显示帧率 ⇒ **NP2kai 投递 vsync IRQ，Phase 3 走 IRQ2 路线成立**；恒 0 ⇒ 转 OPNA Timer-B（`F04`，QEMU 事实 IRQ3；`G09 §3` 级联 ACK 清单为硬前置）。
- 调用点：`main.c` `hal_video_init()` 后（探针需 GDC 已初始化；`hal_log` 已可用）。默认构建全编译排除，符号审计/链接零负担。

### C2 后续轮（探针判定后）：ISR 音泵本体总纲

1. DPMI `int 31h`（经 `int386(0x31,…)`）取/设 PM 向量（AX=0204h/0205h）挂 INT 0Ah；handler 代码+数据经 AX=0600h 锁页；`__interrupt` 调用约定（Watcom）。
2. ISR 内只做：`hal_wallclock_smooth_advance()` + `fmseq_pump`（预算沿用 `FMSEQ_PUMP_MAX_PER_CALL`）+ `hal_pcm_tick()`——纯时钟读 + outb，有界循环，无 malloc/fopen。
3. EOI：Master `outb(0x00,0x20)`；PC-98 级联线归属（IRQ2 vs IRQ7）未定，**双发**（先 slave `outb(0x08,0x20)` 再 master）无害覆盖（`G09 §3` 硬约束 1）。
4. 并发：`audio_bgm_start/stop` 改状态位 + 短临界区（中断短暂屏蔽）防与 ISR 竞态；`engine_frame_pump` 移除时钟 advance 所有权（移交 ISR），`audio_tick` 去 fmseq/PCM 泵职责，防双泵。
5. 回退路径：`NAIZ_BGM_IRQ` 编译开关默认关 = 现协作路径原样；开关开而探针式平台无 IRQ 投递 ⇒ boot 探针回落（运行时自检 + 串口告警）。
6. 鼠标（IRQ13，优先级高于 FM，`G09:49`）与本 ISR 的共存、NP2kai 投递抖动——实机/模拟器各验一轮。

## 七 边界与不做的事

- `scene()` 自动停音频（AGENTS §十四.6）保持——属「下令停止」，不是被打断。
- B3 相位追赶暂缓（§四 B3）；RHYTHM/CC/vibrato 等 158–160 立项与本文件无耦合。
- NP2kai 模拟器自身 VRAM/GDC 慢速（引擎管不着的宿主开销）若在 Phase 1 被证实为主要成分：引擎侧无解，Phase 3 中断仍可消「引擎 pass 稀疏」分量，模拟器侧缓解（如 `makegame.sh audio` 同类）另立。
- 不引入 PIT/INT 1Ch 等 PC heritage 时源（B19 已淘汰谱系）；不碰 `USER.CFG`/配置。
