# 107-虚拟时钟下沉与时钟隐患收口

> 版本：0.2.133（上一轮）→ 已落地 0.2.134
> 日期：2026-09-21
> 状态：**已落地** —— 将 devdoc 106（打字机逐字节拍去抖）的本地虚拟时钟下沉为 HAL 层 `hal_wallclock_smooth_ms()` 单一事实源，收口 H1（动画 freeze-burst）/H2（BGM 静默-连发）/H4（时钟契约缺口）；H3（delay/选项超时 pass 计数）登记为已接受语义不动。

## 1. 背景

### 1.1 上一轮的成果与遗留

devdoc 106 / 0.2.133 在 `nb_dialog.c` 的 `nb_dialog_reveal_tick()` 内置了一个**本地虚拟时钟**：相邻两次 `hal_wallclock_ms()` 的原始增量被钳制到 `[REVEAL_PASS_MIN_MS=40, REVEAL_PASS_MAX_MS=100]`，保证 NP2kai 整秒量子化 + 成块交付的 DOS 2Ch 时钟在"冻结 3–6s → +1000..+6000ms 一次跳"时，reveal 既不冻结也不爆页。实测逐字 max/avg=2.09 ≤ 2.5 门限。

但该修复只覆盖了打字机**一处**。动画（`anim_tick`）与 BGM/MIDI 调度（`audio_bgm_poll`）仍然直接消费 **raw 单次 delta**，在 NP2kai 的时钟洞里同样被波及——这就是本轮要收口的隐患。

### 1.2 四个隐患（H1–H4）

| # | 位置 | 症状（NP2kai，时钟洞 ~3–6s） | 性质 |
|---|------|------------------------------|------|
| H1 | `nb_anim.c:554-578` `anim_tick` | `delta = now - last_ms`：洞内 δ=0 → 动画冻结；补齐瞬间 `steps`~250 → 被 `>180` clamp → 整 3s 动画 1 帧内跳完；同时 `duration_ticks` 净损失（时长漂移） | **修** |
| H2 | `audio.c:107` `audio_bgm_play`、`audio.c:224-247` `audio_bgm_poll` | `cur = now - wall0`：洞内 cur 停滞 → 音乐静默；补齐后事件背靠背连发；loop 复位 `wall0 = now` 同样吃洞 | **修** |
| H3 | `nb_commands.c:355` `frames = sec*60`；`nb_interact.c:58` 选项 600 帧超时 | NP2kai pass ~20–28Hz 下 `delay 1.0`≈3s 实、选项名义 10s→~30s 实 | **只登记，不动**（按 pass 计数系原生语义，拉长已接受） |
| H4 | `hal_pc98.c:62-92` 契约 | `hal_wallclock_ms()` 返回宏观平滑累计值，但**单次调用 delta 在 NP2kai 上是 chunked**（chunk 洞内 δ=0）；`now==0` 兜底在 NP2kai 上是死代码 | 补注释 + B19 契约 |

### 1.3 治理原则

- **单一事实源**：虚拟时钟（逐 pass 增量钳制）下沉到 HAL 层，只实现一份，reveal/anim/audio 统一改走它，删掉 nb_dialog 的本地钳制常量与逻辑——不再允许各模块各自再造一遍虚拟时钟。
- **按 pass 节奏推进**：NP2kai 唯一平滑节拍 = 主循环 pass 节奏（~20–28Hz）。smooth 时钟保证宏观 ≈ raw（秒级正确），微观每 pass 增量有界。
- **H3 不动**：delay/选项超时的 pass 计数语义已接受（先问再做原则下用户拍板），只做文档登记。
- **真机预留校准**：MIN_MS=40 与主循环 pass 率耦合（见 §3.4），本次按 NP2kai 标定，真机实测时调整，不做 pass 自适应（复杂度高）。

## 2. 现状审计（证据）

### 2.1 H1 —— anim 消失-连环爆发

`anim_tick()`（nb_anim.c:530-578）以 10-bit 定点把 δms 折算 tick（`ms_frac += delta*61`；`steps = ms_frac/1024`）。`hal_wallclock_ms()` 在洞内每 pass 返回同一秒值 → `delta=0` → `steps<=0` 直接 return，动画停在当前帧。补齐瞬间 raw 一次跳 +1000..+6000ms → `ms_frac` 爆表 → `steps`~250 → `>180` clamp 后立即吃掉剩余全部帧。已在用：`animatest scene/op.nb:2`、`nbook001.nb:4/8` playanima。

### 2.2 H2 —— BGM/voice 静默-连发

`audio_bgm_poll`（audio.c:224-247）用 `cur = now - wall0` 对照事件表时间选发 MIDI 事件。洞内 `cur` 停滞 → 到点事件不发出；补齐瞬间 `cur` 猛涨 → `while` 把所有滞积事件一口气连发。`audio_bgm_play`（audio.c:107）与循环复位（audio.c:244）的 `wall0 = now` 都把洞尾当作起点，摊薄/吞掉洞内的音乐时间。

### 2.3 H3 —— delay 与选项超时（登记）

- `nb_commands.c:355`：`delay` 命令按 `frames = sec*60` 逐 pass 递减；NP2kai ~20Hz → `delay 1.0` 实际约 3s。
- `nb_interact.c:58`：选项等待 600 帧 ≈ 名义 10s，实际 ~30s。

**决策**：`delay`/选项超时按"pass 计数"是引擎的原生语义（真机 60Hz 下即名义值），NP2kai 拉长属可接受行为，**不动代码**。已在 FAQ 与 B19 §2 决策表登记。

### 2.4 H4 —— 契约缺口

`hal_wallclock_ms()` 的文档声称"毫秒时钟（MIDI 时序调度 / PCM 泵节流）"，但实际保证的只是**宏观秒级正确**：累计值单调、跨洞正确；**单次调用 delta 不保证平滑**（NP2kai 上成块）。任何以相邻两次调用的差值作节拍的消费方都会踩坑。需要补契约注释并收敛到 dedicated 平滑接口。

### 2.5 时钟源一览（累计，devdoc 106 §3.4 复述）

| 源 | 结论 |
|---|---|
| 8253 PIT（0x71/0x77） | 0.2.130 实测非单调否决（NP2kai `nevent_getremain` 缩放） |
| vblank 帧计数 | pass 率 20.5Hz → 每实秒仅推进 ~342ms，慢 3 倍否决 |
| DOS 2Ch raw | 秒级正确可作宏观钟；单次 delta chunked，不可作微观节拍 |
| **主循环 pass** | **唯一平滑节拍（~20–28Hz）**，smooth 时钟的底层量 |

## 3. 方案：`hal_wallclock_smooth_ms()`

### 3.1 hal 层实现（H4 载体）

`core/plat/hal.h`：

```c
#define SMOOTH_CLOCK_MIN_MS 40UL   /* stall floor: virtual ms per pass while
                                    * raw reports delta==0 (NP2kai ~40ms/pass) */
#define SMOOTH_CLOCK_MAX_MS 100UL  /* catch-up ceiling: bounded by one pass's
                                    * real cadence regardless of raw jump */
unsigned long hal_wallclock_smooth_ms(void);
```

`core/plat/hal_pc98.c`：

```c
static unsigned long smooth_clock_total = 0;
static unsigned long smooth_raw_prev = 0;
static int          smooth_inited = 0;

unsigned long hal_wallclock_smooth_ms(void)
{
    unsigned long raw = hal_wallclock_ms();
    unsigned long delta;
    if (!smooth_inited) {
        smooth_raw_prev = raw;
        smooth_inited = 1;
        return 0UL;
    }
    delta = raw - smooth_raw_prev;         /* raw 单调（调方保证），无负数 */
    smooth_raw_prev = raw;
    if (delta == 0) delta = SMOOTH_CLOCK_MIN_MS;
    else if (delta > SMOOTH_CLOCK_MAX_MS) delta = SMOOTH_CLOCK_MAX_MS;
    smooth_clock_total += delta;
    return smooth_clock_total;
}
```

**契约**：宏观 ≈ raw + ≤0.1s/洞 误差；微观单调且每 pass 增量 ∈ [MIN,MAX]，无跳变。首 pass 返回 0（基线）。真机 DL 节拍 ~55ms，MAX 不触发。

### 3.2 三消费方统一迁移

| 文件 | 改动 |
|---|---|
| `nb_dialog.c` | `now = hal_wallclock_smooth_ms()`；删 `reveal_vnow`/`delta_raw`/`delta_eff`/`reveal_last_ms` 与 `REVEAL_PASS_*_MS` 常量、回绕分支；保留 `reveal_page_ms`/`reveal_char_count` 页级基线重锚（arm 分支 `reveal_page_ms = now`） |
| `nb_anim.c` | `now = hal_wallclock_smooth_ms()`；删 `now==0` 兜底（smooth 首 call 后有界递增，永不重置 0）与 `now < last_ms` 回绕分支（smooth 单调）；`tick_armed`/`steps>180` clamp 保留（后者为纯防御安全上限，平滑后不可达） |
| `audio.c` | `g_bgm.wall0 = hal_wallclock_smooth_ms()`、poll 内 `now` 换 smooth；loop 复位同源 |

迁移后 nb_dialog 函数体不再含 `"advanced"`、`"REVEAL_PASS_*"`、`"reveal_vnow"`——测试随之更新（§4）。

### 3.3 与 0.2.133 reveal 语义对齐

smooth 时钟与旧 reveal 本地虚拟钟参数一致（40/100），reveal 迁移后行为不变：洞内按 pass 节奏推进、补齐不爆页；预期 NP2kai 逐字指标持平 2.09。迁移完成后 reveal 不再自带钳制逻辑——防复发由 hal 层统一承载。

### 3.4 已知权衡：MIN_MS=40 与主循环 pass 率耦合（校准旋钮）

smooth 钟在洞内按 MIN_MS/pass 推进。NP2kai pass ~20–28Hz → 洞内约 1s 实时间隔内 sink 累计 ≈ 40ms×pass ≈ 1s，**恰好 1s/s**；但真机 60Hz 主循环里 `delta==0` 的 pass 依然计 40ms → 虚拟钟偏快 ~2.4x。因此：

- 这是**固有 pass-rate 耦合**，不是 bug；MIN/MAX 是校准旋钮，按目标平台标定（本次按 NP2kai）。
- 迁移会让本耦合从 reveal 一处扩散到 anim/audio 三处消费方——已接受，B19 契约段记录"真机实测需另标定"。
- 兜底可选的 pass 自适应（EWMA 平均 pass 间隔）留作未来旋钮，本轮不做。

### 3.5 不动项

H3（delay/选项超时）既不改代码也不改测试；`hal_wallclock_ms()` 本身语义不变（宏观钟，供页面级/秒级语义）。
