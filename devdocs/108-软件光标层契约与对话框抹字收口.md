# 108-软件光标层契约与对话框抹字收口

> 版本：0.2.134（上一轮）→ 已落地 0.2.135
> 日期：2026-09-21
> 状态：**已落地** —— 基于用户 bug 报告「鼠标在剧情字幕上时，有时候会把文字抹去」完成的调查结论与修复：cursor.c 升级为带四向重叠检测的**软件光标层契约**（`cursor_touch` + hal 透传 `hal_mouse_touch_cursor`），根治 `dialog_layer_blit` 漏前置 invalidate 的缺口，全对话框/菜单 VRAM 写入路径补齐上报，守卫测试 `test_cursor_layer.py` 5 例锁定契约。

## 1. 背景

### 1.1 用户 bug 报告

> 鼠标在剧情字幕上时，有时候会把文字抹去。

现象通常在 NP2kai 下复现：鼠标停驻在打字机字幕上（不移动），等打字机推进或翻页，再移动鼠标——`cursor_erase` 恢复出**旧一帧**的字幕内容，覆盖掉刚揭示的新字。伴随现象：静止时光标会从字幕区域「消失」。

### 1.2 鼠标当前有无独立图层？—— 没有（软、硬双层原因）

| 维度 | 结论 | 证据 |
|------|------|------|
| 软件图层系统 | 光标**不是**图层系统成员。layer.c 的 LAYER_Z 只维护 `g_layer_active[]` 布尔标志（layer.c:18），真正的渲染是各子系统各自向 VRAM 直写（dialog 合成区、menu_layer、sprite 各 blit 各的），**无每帧扫描合成器**，自然无光标 z 条目 | layer.c:18；menu_layer.h:26 「transient overlay：不注册 LAYER_Z_*、不碰 g_layer_active」 |
| 光标实现 | cursor.c 是一个裸 **VRAM save/restore 重叠层**：`cursor_draw` 先 `vram_read` 存 24×24 背景（cursor.c:111-118），`cursor_erase` 再 `vram_write` 恢复（cursor.c:120-127） | cursor.c:111-127 |
| 硬件平台 | PC-98 GDC 直接扫描 VRAM，**无硬件光标/sprite 覆盖平面**（无 SVGA 式硬件光标寄存器），refdocs 亦无此能力 → 光标像素必须落在 VRAM 里 → save/restore 机制存在的根因 | refdocs 检索无 cursor/sprite 硬件条目 |

**结论**：真正的「扫描级独立光标层」（与内容像素分离、硬件合成在光标之上）在 PC-98 GDC 上**做不到**。可行的是把 save/restore + 前置无效化纪律升级为**软件光标层契约**（见 §3）。

### 1.3 现有 invalidate 纪律（B13 及散点）

历史约定（B13-鼠标直连方案.md:102）：「所有修改 VRAM 的函数在写入前调用 `mouse_invalidate_cursor()`，设 valid=0，下一次 `mouse_draw_cursor()` 重新走 save+draw 流程」。当前守约位点：

| 位点 | 调用 | 覆盖写 |
|------|------|--------|
| `layer_sprite.c` :162/188/260/298/314 | `hal_mouse_invalidate_cursor` | sprite 写入 |
| `scene_display.c` :28/47 | 同上 | bg/cg 应用 |
| `layer_dialog_hide` `layer_dialog.c:315` | 同上 | 关闭对话框恢复 underneath |
| `layer.c` `scene_end` :29 | 同上 | 场景切换整屏重建 |
| `nb_anim.c` :238/249 | `cursor_refresh`（blit 后） | 整帧 vram_blit |

**漏网点**：`dialog_layer_blit()`（layer_dialog.c:209-215）把对话框合成区整块 `vram_write` 到 VRAM，是全项目对话框文字的唯一写入漏斗，却**没有**任何前置 invalidate——三处 OOM 直写路径（`dialog_paint_box` buf==NULL、`layer_dialog_render_page` OOM、`fill_dialog_bg`）同样缺失。这正是本次 bug 的温床，也说明散点纪律不可靠——缺位的成本由用户直接看到。

## 2. 根因（证据链）

### 2.1 机制

1. **快照**：光标停驻字幕上时，`cursor_draw()` 把光标下 24×24 VRAM 快照存入 `cursor_saved.buf`（cursor.c:113）。
2. **覆盖**：打字机推进 / 翻页 / `dialog_show` 时 `dialog_layer_blit()` 把 480×115 合成区直接 vram_write（layer_dialog.c:212-213），**覆盖光标所在像素**；`cursor_render()` 首行 early-return（cursor.c:149-150）不重画 → 静止光标凭空消失。
3. **恢复过期背景 = 抹字**：用户一动鼠标，`cursor_render()` → `cursor_erase()` 把 `cursor_saved.buf`（**旧字幕内容**）写回（cursor.c:125），把刚揭示的新字抹回旧帧 → 「文字被抹去」。

主循环顺序（main.c）：`nb_dialog_reveal_tick()` 推进 → 末尾 `hal_mouse_draw_cursor()`，故每帧 typing 推进都会踩中第 2 步。

### 2.2 为什么「blit 后 cursor_refresh」备选被否决

`cursor_refresh`（cursor.c:192-212，nb_anim 满屏 blit 后用）不擦除、假设 blit 已冲掉旧光标像素、重新读背景再画。**当光标优势点位于对话框内而 24×24 形状伸出上/左边界时**，探出部分未被对话框 blit 覆盖 → 残影像素被读进新快照 → 光标移走后恢复成幽灵残影。`cursor_touch`（重叠即擦整块）无此窗口。

### 2.3 顺手验证的对照：为什么「无脑 invalidate」也正确但更费

无条件 `hal_mouse_invalidate_cursor`（B13 现约）在**光标不在写区域时也强制 erase+redraw**（含 `hal_vblank_wait`）。`cursor_touch` 用四向相交检测，非重叠一律 no-op——语义等价、开销只在重叠时发生。

## 3. 方案：软件光标层契约

### 3.1 核心 API

把 cursor.c（光标本体）就地升级为**软件光标层**模块，新增带重叠检测的上报入口：

```c
/* cursor.h */
void cursor_touch(int x, int y, int w, int h);
```

实现语义（cursor.c 内部新增四向相交判定）：

```
重叠 = valid && x < bg.x+CURSOR_SAVED_W && bg.x < x+w
            && y < bg.y+CURSOR_SAVED_H && bg.y < y+h
```

- 重叠 → 整块 erase + `valid=0`（同 `cursor_invalidate` 的擦除动作，但仅按矩形判断）；
- 不重叠 → 纯 no-op（不 erase、不 vblank、不改状态）；
- 半溢出边界 → 因是「重叠即擦整块」，无残影窗口（§2.2）。

hal 透传（与既有 `hal_mouse_*_cursor` 同款，hal_mouse.c:35-42 模式）：

```c
/* hal.h */
void hal_mouse_touch_cursor(int x, int y, int w, int h);
/* hal_mouse.c */
void hal_mouse_touch_cursor(int x, int y, int w, int h) { cursor_touch(x, y, w, h); }
```

### 3.2 契约（架构纪律，替代散点记忆）

> **任何向 VRAM 写像素的模块，必须先经 `hal_mouse_touch_cursor(x,y,w,h)`（或用更强的不定界 `hal_mouse_invalidate_cursor`）上报其写矩形**；光标层自省自擦，不再依赖每个调用点「记得」前置无效化。

`cursor_invalidate` 保留为「全屏/未知范围写」的强形式；`cursor_refresh` 保留给满屏 vram_blit（nb_anim 已有先例）。

### 3.3 落地清单（按依赖顺序）

| # | 位置 | 改动 |
|---|------|------|
| 1 | `cursor.c` / `cursor.h` | 新增四向重叠助手 + `cursor_touch`；头文件补契约注释 |
| 2 | `hal.h` / `hal_mouse.c` | 新增 `hal_mouse_touch_cursor` 透传 |
| 3 | `layer_dialog.c` `dialog_layer_blit()` :209 | **根治位**：vram_write 前插 `hal_mouse_touch_cursor(LAYER_DIALOG_X, LAYER_DIALOG_Y, LAYER_DIALOG_W, LAYER_DIALOG_H)` |
| 4 | `layer_dialog.c` OOM 直写路径 | `layer_dialog_show()` buf==NULL :230（`dialog_paint_box` :146-148）、`layer_dialog_render_page()` OOM :266-272 → touch 对话框矩形 |
| 5 | `layer_dialog.c` `fill_dialog_bg()` :129 | 顶部 touch(x,y,w,h)（覆盖 `nb_save_dialog.c:225` 存档槽位直写） |
| 6 | `menu_layer.c` `menu_layer_blit` :110/114、`menu_layer_blit_rect` :133/137、`menu_layer_close` :187 | blit 前 touch 对应区域（流式覆盖层统一契约） |
| 7 | 既有 `layer_sprite.c`/`scene_display.c`/`layer.c`/`layer_dialog_hide` invalidate | **保留不动**（更强形式，满足契约）；本轮不强行 touch 化，见 §7 |

### 3.4 决策记录

| 候选 | 结论 | 理由 |
|------|------|------|
| 真扫描级独立光标层 | **不可行** | PC-98 GDC 无光标/sprite 平面，像素必须进 VRAM |
| blit 后 `cursor_refresh` | 否决 | 光标的 24×24 形状探出对话框上/左边界时残影被存为背景，移动产生幽灵（§2.2） |
| 无条件 invalidate（现约） | 正确但费 | 非重叠写也强制 erase+redraw+vblank_wait |
| **`cursor_touch` 重叠检测** | **采纳** | 语义等价、开销仅重叠时发生、半溢出正确、契约可被守卫测试锁定 |

## 6. 风险与开销

- **开销**：仅当写矩形与光标区域重叠才 erase+redraw（含一次 `hal_vblank_wait`）。热路径 = typing 推进且光标停字幕上（约 25 字/s 节奏，40–100ms/字），每字一次，无掉帧风险；光标不在对话框时 touch 为纯 no-op。
- **行为兼容**：`cursor_invalidate`/`cursor_refresh`/`cursor_render` 语义不变，全部既有调用点不动 → 无回归面。
- **C17 规约**：本变更即修复 C17 反例（覆盖旧光标区域前未无效化）；新增 `cursor_touch` 使该纪律可在测试层强制。
