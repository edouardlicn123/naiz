## 一、背景与目标

B94 已给出 8 条规则与 5 个工具（`read_slice` / `batch_read` / `preflight` / `batch_edit` / `token_budget`），规则层没有缺口。本轮实测发现 token 浪费集中在**往返次数**：

| 实测浪费 | 次数 | 原因 |
|---|---|---|
| 同一符号反复 grep | 2–3 次/符号 | 没有“符号 → 文件:行”的一次性查询 |
| 同一文件分多次读 | 5 次（`mag.c`） | `read_slice` 只能按 offset/limit 手算，无法按函数名切片 |
| 整篇读长文档 | 3 篇（`B90` 60 行、`B03` 58 行、`FAQ` 多段） | 文档没有稳定锚点，无法按小节取 |
| 读审计日志全文 | 2 份（13 KB / 5 KB） | 日志没有 `--summary` 模式 |
| 无效命令往返 | 3 次 | 5 个工具分散，命令名/参数易错 |

目标：把“任务 → 文件 → 函数”的定位压缩到 **1–2 次工具调用**，并让长输出默认给出摘要。

## 三、详细设计

### 3.1 `tools/diag/code_map.py`

**扫描范围**：`core/engine/*.c`、`core/lib/*.c`、`core/plat/*.c`。

**解析规则**（不依赖编译器，正则 + 行扫描）：

1. 文件职责：取前 16 行注释块中首个 `—` 后的句子；缺失则取文件名。
2. 公共符号：匹配行首 `<type> <name>(` 且不含 `static`；类型集合与 `symbol_audit.py` 保持一致。
3. 所属规范：在 `docs/B*.md` 中查找该文件名，命中最多者记为“相关文档”。

**三种模式**：

```bash
python -m tools.diag.code_map                 # 生成 docs/CODE_MAP.auto.md
python -m tools.diag.code_map --find mag_     # 输出 file:line  name（前缀/正则匹配）
python -m tools.diag.code_map --check         # 生成物是否最新，退出码 1 表示过期
```

**输出格式**（`CODE_MAP.auto.md`，不含行号，避免漂移）：

```markdown
# CODE_MAP（自动生成，勿手改）
> 生成命令：python -m tools.diag.code_map ；校验：--check

## core/engine
| 文件 | 职责 | 公共符号（数量） | 相关规范 |
|---|---|---|---|
| nb_interact.c | 选择题交互 | hal_mouse_was_clicked, hal_kbd_is_down (18) | B92 |
```

`--find` 输出直接给 agent 用：

```
core/engine/image_cache.c:44  image_cache_init
core/engine/image_cache.c:56  image_cache_clear
```

**验收**：`--check` 在未改动 `.c` 时返回 0；改动任一 `.c` 后返回 1；`--find mag_close` 在删除后应无输出（当前已删，正好验证）。

### 3.3 `audit.py --summary`

### 3.4 `read_slice.py --symbol / --section`

```bash
python -m tools.diag.read_slice core/lib/mag.c --symbol mag_decode
python -m tools.diag.read_slice docs/B97-场景过渡状态机规范.md --section "## 三"
```

- `--symbol NAME`：定位行首定义（`NAME(`），向下读到缩进回退到定义列的 `}`，最多 150 行。
- `--section PREFIX`：从匹配行打到下一个同级 `## ` 前，最多 150 行。
- 两者与 `--offset/--limit` 互斥，优先使用 symbol/section。
