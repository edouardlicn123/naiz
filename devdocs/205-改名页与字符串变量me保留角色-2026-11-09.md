## 1. 需求与已确认决策

### 1.1 原始需求

1. 在 `projects/demo-a2/variables.json` 中加入名为 `myname` 的变量，默认值为 `me`。
2. 新建 `rename` 场景，入口为 **New Game**，或 **Continue 且没有任何存档**；脚本结构模仿主菜单，界面外观模仿 LOAD 页，用于修改主角姓名 `myname`。
3. 在 `config.toml` 中增加“是否启用 rename 场景”的开关。
4. 把 NB 语法中的角色名 `me` 作为**保留角色**固定加入。
5. 改名界面**不输入任何名称**时自动填入 `me` 并直接使用。
6. 改名可输入**日语或英语**，键盘提供**语言切换键**。

### 1.2 已确认的技术选型（用户已逐项确认）

| 决策点 | 结论 | 说明 |
|---|---|---|
| `myname` 存储方式 | **扩展 `variables.json` 支持 string 型** | 不采用“借整数变量存索引”的绕道方案 |
| 输入方式 | **物理键盘 + 屏幕字母键盘** | 两者共用同一编辑缓冲 |
| `myname` 接入对白 | **增加 `%myname%` 文本插值** | 除 `me` 署名外，正文也能出现姓名 |
| `me` 形态 | **仅对白署名，不需要立绘** | 不登记 `characters.json`，不产生 `char(){me}` 素材 |
| 日文范围 | **仅假名，不需要汉字选字** | 不做 IME / 候选字，屏幕键盘直出假名 |

### 1.3 本次明确不做（范围外）

- 汉字选字 / 罗马字→假名转换（物理键盘在日文模式下仍只产生 ASCII）。
- 姓名语音朗读、姓名笔迹、姓名敏感词过滤。
- 对 `question` / 菜单选项文本做 `%myname%` 插值（仅对白 `host` / 角色行生效）。
- 旧版引擎读取 v4 存档（降级不兼容，只保证 v2/v3/v4 向上读取）。

**关键坑（必须在实现中显式处理）**：

1. **单档 `min_size` 无法同时容纳 v2 与 v3**。v2 文件比 v3 短 64 字节（缺 `chapter_title`）。若直接 `SAVE_VERSION=4` 且 `min_size = offsetof(SaveData, var_strings)`（= v3 全长），读取一个真实的 v2 文件时 `fread` 会因 EOF 失败（`save_io.c:115` 返回 `-1`）。因此读取长度必须是**三档**：v2 → v2 长度，v3 → v3 长度，v4 → 全结构。
2. **`memset(p, 0, bufsz)`（`save_io.c:113`）会让旧档的字符串槽变成空串**，而不是 `variables.json` 里的 `initial: "me"`。必须在 `save_apply()`（`save.c:31-42`）这一个共同入口做默认值归一，否则“旧存档读进来主角姓名为空”。
3. **校验和按 `read_sz` 计算**（`save_io.c:123`），所以三档长度必须与各版本写入时的全长严格相等，否则旧档一律 `checksum fail`。

## 4. 总体设计

### 4.1 数据流

```text
variables.json ──export_vars.py──> nb_var_table.h / nb_var_defs.h
     │                                     │
     │ (type=string, initial="me")         ▼
     │                          nb_vars.c: int 槽 + char 槽
     │                                     │
     ├──> nb_var_get_str/set_str ──────────┤
     │                                     │
     │                                     ├──> SaveData.var_strings ──> SAVE??.SAV (v4)
     │                                     └──> resolve_display_name("me") / %myname% 插值
     │
mainmenu (New Game / Continue 无存档)
     └── scene_switch("rename.nb")  [NAIZ_FLOW_RENAME=1]
              └── rename.nb: sceneconf / bg / nameinput()
                        └── 阻塞 UI 循环（鼠标 + 键盘 + 屏幕键盘）
                                  ├─ OK   → 写 myname → scene_switch("nbook001.nb")
                                  └─ Back → scene_switch("mainmenu.nb")
```

### 4.2 关键设计原则

1. **单一事实源**：字符串变量的默认值只存在 `variables.json` 的 `initial`，不在 C 代码里再写一份 `"me"`。
2. **入口单点**：rename 只能由 `nb_mainmenu.c` 的 `scene_switch` 进入（`scene(rename)` 不可用，见 §3.4）。
3. **`me` 是语法层保留名，不是素材角色**：不进 `characters.json`（否则会生成 `char_map` 项、`char(){me}` 会去找立绘），只在命令分派与显示名解析两处特判。
4. **UI 复用 LOAD 的视觉语言**：全屏菜单层、`draw_title_large`、`draw_rounded_emboss` 槽位、`menu_back_draw` / `menu_finish`。
5. **所有失败必须可见**：缺 `rename.nb`、配置文件缺失、字符串变量缺失、字符 FIFO 溢出，一律 `hal_log` / `NB_DEBUG`，不得静默降级。

## 5. 字符串变量

### 5.1 `variables.json` 扩展

`projects/demo-a2/variables.json` 追加一项（保持既有 3 项不变）：

```json
{
  "id": "myname",
  "name": "主角姓名",
  "desc": "玩家自定义的主角名，默认 me",
  "type": "string",
  "initial": "me",
  "maxlen": 12
}
```

**兼容规则**：
- 缺 `type` → 视为 `"int"`（现有 3 项无需改动）。
- `type == "int"` → 沿用 `initial/min/max` 整数语义。
- `type == "string"` → 使用 `initial`（字符串）与 `maxlen`（码位上限），`min/max` 忽略。

### 5.2 生成器变更（`tools/naiz_build/export_vars.py`）

`nb_var_table.h` 除 `NB_VAR_COUNT` 外新增：

```c
#define NB_STRVAR_COUNT   1     /* 字符串变量槽数量 */
#define NB_VAR_STR_MAX    40    /* 每槽字节数（含 NUL） */
#define NB_VAR_MAXLEN     12    /* 码位上限（全局统一取最大值） */

typedef struct {
    const char *id;
    const char *name;
    const char *desc;
    int         is_string;      /* 1 = string slot, 0 = int */
    int         initial;        /* int 型默认值 */
    const char *initial_str;    /* string 型默认值；int 型为 "" */
    int         min;
    int         max;
    int         maxlen;
} NbVarDef;
```

`nb_var_defs.h` 追加字符串槽映射表与字符串默认值：

```c
/* int 变量索引 -> 字符串槽号；-1 表示该变量不是字符串型 */
static const int var_str_slot[NB_VAR_COUNT] = { -1, -1, -1, 0 };
```

`NB_VAR_STR_MAX` 取 40 的理由：允许字符集限定为 **ASCII 可见字符 + 假名（U+3040–U+30FF）**，单码位最多 3 字节，12×3 + NUL = 37 ≤ 40。若日后放开汉字（4 字节/码位），必须同步把该值抬到 ≥ 49。

### 5.3 引擎 API（`core/engine/nb_vars.h/.c`）

新增（现有 int API 一律不动）：

```c
const char *nb_var_get_str(int idx);           /* 越界/非字符串 -> "" */
void        nb_var_set_str(int idx, const char *val);
const char (*nb_var_get_str_state(void))[NB_VAR_STR_MAX];
void        nb_var_set_str_state(const char (*state)[NB_VAR_STR_MAX]);
const char *nb_var_default_str(int idx);
```

`nb_var_str_slot()` 的实现保持为 `nb_vars.c` 内部 `static`，不导出到 `nb_vars.h`——`symbol_audit` A 节（未使用导出）已在 0.4.016 收口中判定其唯一调用方在同文件内。

语义规定：

- `nb_var_init()` 同时把每个字符串槽写入 `var_defs[i].initial_str`。
- `nb_var_set_str()`：
  - 裁剪到 `NB_VAR_STR_MAX - 1` 字节，且必须在 UTF-8 码位边界截断（不得留下半个续字节）。
  - 码位数超过 `maxlen` 时拒绝写入并 `hal_log`（不是静默截断）。
  - `val` 为空串时写入该变量的 `initial_str`（即 `"me"`）——对应需求“不输入任何名称自动填入 me”。
- `nb_var_set_str_state()`：对每个槽，若传入串为空（旧档 `memset` 的结果）则回落 `initial_str`；否则按 `nb_var_set_str()` 的裁剪规则写入。

**UTF-8 码位裁剪需要一个共用函数**：建议在 `core/lib/strutil.c` 增加 `int utf8_len_cps(const char *s)` 与 `void utf8_truncate_cps(char *s, int max_cps, int max_bytes)`，而不是在 `nb_vars.c` 里内联（§九.10“先借后造”）。`nb_dialog.c` 已有类似的“裁掉尾部续字节”逻辑（`nb_dialog.c:115-120`），实现时应评估能否复用同一工具函数。

## 6. 存档格式 v4

### 6.1 结构变更

`core/engine/save.h`：

```c
#define SAVE_VERSION      4
#define SAVE_VERSION_MIN  2

typedef struct {
    unsigned int magic;
    unsigned int version;
    char         slot_name[32];
    char         timestamp[20];
    unsigned int checksum;
    int          var_values[NB_VAR_COUNT];
    char         filename[64];
    char         lang[8];
    char         chapter_title[64];
    char         var_strings[NB_STRVAR_COUNT][NB_VAR_STR_MAX];   /* v4 追加，必须在末尾 */
} SaveData;
```

**约束**：`var_strings` 必须是**最后一个字段**。这样 `offsetof(SaveData, var_strings)` 恰好等于 v3 布局全长，三档长度关系成立：

| 版本 | 布局 | 读取长度表达式 |
|---|---|---|
| v2 | v3 去掉 `chapter_title` | `offsetof(SaveData, chapter_title)` |
| v3 | v4 去掉 `var_strings` | `offsetof(SaveData, var_strings)` |
| v4 | 全结构 | `sizeof(SaveData)` |

### 6.2 读取长度三档化（`core/engine/save_io.c`）

当前实现（`save_io.c:111`）只有一个 `min_size`，无法区分 v2/v3。计划改为**显式三档参数**：

```c
int save_file_read(const char *path, void *buf, size_t bufsz,
                   size_t v2_size, size_t v3_size,
                   unsigned int expected_magic, unsigned int max_version,
                   size_t cs_offset, const char *tag);
```

读取长度：

```c
if (ver == 2)            read_sz = v2_size;
else if (ver == 3)       read_sz = v3_size;
else                     read_sz = bufsz;
if (read_sz > bufsz)     read_sz = bufsz;
```

调用点调整：

| 调用点 | 传参 |
|---|---|
| `save.c:58`（`save_read`） | `v2_size = offsetof(SaveData, chapter_title)`；`v3_size = offsetof(SaveData, var_strings)`；`bufsz = sizeof(SaveData)` |
| `core/engine/save_sys.c:27`（`SystemSave`） | `v2_size = v3_size = sizeof(SystemSave)`（其布局在 v2/v3 未变） |

**说明**：这里选择“两个具名长度参数”而非版本-长度映射表，原因是本仓库只有 `SaveData` 需要三档、`SystemSave` 恒等；引入表结构对当前规模属于过度设计。若日后出现 v5，再升级为表。

**`save_file_read` 的版本检查**：`ver > max_version` 仍拒绝（`save_io.c:106-110`），因此旧引擎读 v4 会明确失败，符合“降级不兼容”。

### 6.3 写入与读取的对称改动

| 文件 | 改动 |
|---|---|
| `save.c:15-29` `save_collect()` | 追加循环：`s->var_strings[i] = nb_var_get_str_state()[i]`（逐槽 `str_copy`） |
| `save.c:31-42` `save_apply()` | 追加 `nb_var_set_str_state(s->var_strings);`，位置在 `nb_var_set_state()` 之后、`scene_switch()` 之前 |
| `save.h:66-71` 声明 | `save_file_read` 增加 `v2_size` / `v3_size` 参数 |

**为什么归一化放在 `save_apply()`**：它是“存档数据 → 运行时状态”的唯一入口（`save.c:31`），放在这里可以同时覆盖“读旧档”和“未来的临时存档回滚”（`load_game_temp` 同样走这条路径，实现时确认）。

### 6.4 校验和

`save_file_write` 对 `sizeof(SaveData)` 计算校验和（`save.c:46`），`save_file_read` 对 `read_sz` 计算（`save_io.c:123`）。三档长度各等于对应版本写入时的全长，故：
- v4 新档：写读都是 `sizeof(SaveData)`，一致。
- v3 旧档：写时长度即 v3 全长，读时 `v3_size` 相等，一致。
- v2 旧档：写时长度即 v2 全长，读时 `v2_size` 相等，一致。

### 6.5 存档槽信息

`SaveHeader`（`save.h:56-63`）与 `SlotInfo`（`save.h:35-42`）不含字符串字段，`save_read_header()` 只解析既有偏移，**不需改动**。实现后须实机验证 LOAD 页四槽能正常列出 v3 旧档。

## 7. `me` 保留角色

### 7.1 分派表

`core/engine/nb_commands.c` 的 `cmd_table[]`（约 `:492-513`）追加：

```c

```

其余标志与 `fei`/`ira`/`neon` 保持一致（不设 `CMD_BLOCKING`）。

### 7.2 显示名解析

`resolve_display_name()`（`nb_commands.c:128-141`）新增最前置分支：

```c
if (strcmp(key, "me") == 0) {
    int idx = nb_var_lookup("myname");
    if (idx >= 0) return nb_var_get_str(idx);
    hal_log("WARN: 'me' speaker but variable 'myname' missing\r\n");
    return "me";

```

**顺序要求**：该分支必须位于 `tr(key)` 之前。否则若某语言误把 `me` 登记进 `role_<lang>.txt`，保留角色会被翻译成固定人名，违背“显示玩家姓名”的语义。

### 7.3 不进入 `characters.json`

`me` **不**写入 `projects/demo-a2/characters.json`，理由：
- `characters.json` 会被 `export_asset_table` 转成 `char_map`，一旦登记，`char(){me}` 会尝试解析素材 id（`nb_commands.c:58-65` 的 `resolve_char_id`）；
- `i18n_gen` 会据此生成 `role_<lang>.txt` 的 `me=` 键，产生无意义的可翻译署名。

**代价**：`nb_validator.py` 需要把 `me` 加进“已知对白角色”判断（`nb_validator.py:591` 附近当前只认 `char_keys`），否则 `rename`/后续剧本里的 `me(){...}` 会在 build 阶段被报未知命令。

### 7.4 与 `%myname%` 的分工

- `me(){...}`：只影响**署名**（charname）。
- `%myname%`：只影响**正文**（text）。
- 两者可同时使用：`me(){你好，我是 %myname%。}`。

## 9. `rename.nb` 与 `nameinput` 命令

### 9.1 场景文件

新增 `projects/demo-a2/scene/rename.nb`（基名 6 字符，满足 8.3）：

```text
# rename.nb — 主角改名页。入口仅由引擎 nb_mainmenu.c 的 scene_switch 提供。
sceneconf(){, menu}
bg(normal){bg_load}
nameinput()
```

**设计说明**：

- `sceneconf` 的标题留空（与 `mainmenu.nb:1` 的 `sceneconf(){, menu}` 一致）；页面标题由 `nameinput` 自己用 `tr("RENAME")` 绘制，避免同一文案出现两处来源。
- `bg(normal){bg_load}`：`bg_load` 是 `ASSETS.DB` 中已有的背景键（已核对）。全屏菜单层随后覆盖它，视觉上等价于 LOAD 页的“浮在当前画面上”的效果；选用固定背景可避免进入时上一场景画面残留差异。
- `nameinput()` 是**阻塞命令**，自建输入循环并**自行完成场景切换**（见 §9.2）。因此脚本在它之后不需要 `scene()`，也不会出现“返回后继续执行剩余脚本”的时序问题。
- 场景内**不写** `scene(rename)`（会解析成 `nbookrename.nb`，§3.4）。

### 9.2 `nameinput` 命令契约

| 项 | 规定 |
|---|---|
| 语法 | `nameinput()`（无参数；可选参数留作未来扩展，当前忽略并 `NB_DEBUG` 警告） |
| 分派标志 | `CMD_BLOCKING \| CMD_NEEDS_INPUT \| CMD_TOUCHES_DISPLAY` |
| 入口 | `input_drain_boundary()`（禁止裸调 `hal_kbd_drain_advance()`，§十四.1） |
| 编辑缓冲 | 初始值 = `nb_var_get_str(myname_idx)`（缺变量时 `"me"`） |
| 退出 OK | `nb_var_set_str(myname_idx, buf)`（空缓冲自动写 `"me"`）→ `menu_finish()` → `scene_switch("nbook001.nb", SCENE_SWITCH_MENU)` |
| 退出 Back | 不写变量 → `menu_finish()` → `scene_switch("mainmenu.nb", SCENE_SWITCH_MENU)` |
| `NAIZ_FLOW_RENAME == 0` | 该命令仍可编译（供手动场景使用），但不被入口调用 |
| AUTOEXIT | 无输入环境直接写 `"me"` 并切到 `nbook001.nb`，防止 CI/headless 挂死（参照 `nb_dialog.c` 的 AUTOEXIT 分支思路） |

**为什么由命令自己切换场景**：NB 脚本没有 `if` 条件命令，OK/Back 二选一无法在脚本层表达。既有先例是 `cmd_mainmenu`（`nb_mainmenu.c:80-83`、`:87-89`）同样在命令内部直接 `scene_switch`。让 `nameinput` 承担两个出口，脚本保持“一行命令”即完成，符合“脚本模仿主菜单”的要求。

### 9.3 引擎侧输入循环（伪代码规格，非实现）

```text

hal_mouse_erase_cursor()
menu_layer_open(0, 0, 640, 400, opaque)
绘制一次全量静态层（标题 / 姓名槽框 / 提示 / 键盘 / 底部按钮）
menu_layer_commit(); menu_layer_blit(); hal_mouse_draw_cursor_force()

loop:
    engine_frame_pump()
    hal_kbd_update()
    hal_mouse_update()

    # 1) 物理字符
    while ((ch = hal_kbd_get_char()) != 0) 接受字符/回退/翻转键盘布局
    # 2) 扫描码语义键
    if hal_kbd_is_down(KC_ESC)      -> Back
    if hal_kbd_is_down(KC_TAB)      -> 切换 EN/JP 布局
    if hal_kbd_is_down(KC_HOME)     -> 循环键盘分页
    if hal_kbd_is_down(KC_UP/DOWN/LEFT/RIGHT) -> 移动高亮格
    if hal_kbd_is_down(KC_ENTER/SPACE/XFER)   -> 选中高亮格
    if hal_kbd_is_down(KC_BS)       -> 删除末码位
    # 3) 鼠标
    if hal_mouse_was_clicked(LBUTTON)
        hit-test 键盘格 / Back / EN-JP / PAGE / VOICE / OK
    # 4) 增量重绘
    若缓冲/高亮/布局/分页变化：
        hal_mouse_erase_cursor()

```

**两阶段绘制要求**（§十四 菜单 UI）：`draw_rounded_emboss` 等昂贵原语只画一次；循环内只改文字颜色、光标与高亮框；禁止循环内 `fill_rect(0,0,640,400,0)` 或整页重绘。

### 9.4 退出后的输入边界

`menu_finish()` 之后、`scene_switch()` 之前必须再调一次 `input_drain_boundary()`，防止“点 OK 的那一次按下”泄漏到新场景的首个对白页（§十四.1 的同型问题）。`scene_switch()` → `nb_load()` → `scene_end()` 内部已有一次 drain（`nb.c:306-307`、`scene_end` 内的 `input_drain_boundary()` 位于 `layer.c:45`），但显式再清一次成本极低且语义明确。

### 10.4 姓名显示与限宽

- `LAYER_DIALOG_CONTENT_W` 与 LOAD 槽内宽均按 480 量级；12 个假名 = 12×16 = 192 px，12 个 ASCII = 96 px，均远小于 480，安全。
- 姓名字符串必须在 UTF-8 码位边界裁剪（§5.3），且**渲染前**再校验一次字节长度，防止 40 字节上限被手工编辑的存档突破。
- 槽内文本超宽时 `draw_text` 会**静默裁剪**（§十四 系统界面 i18n 规则 5），因此 UI 层必须自己做码位计数上限，而不是依赖渲染器兜底。

### 10.5 字符集与保留字符

| 规则 | 说明 |
|---|---|
| 允许 ASCII | `0x20–0x7E`，**排除 `%`** |
| 排除 `%` 的理由 | `%myname%` 插值以 `%` 为定界符；姓名含 `%` 会产生歧义（`%%myname%%`） |
| 允许假名 | `U+3040–U+30FF`（含小写、浊音、半浊音） |
| 允许空格 | 是（英文布局提供 `SPACE` 键） |
| 控制字符 | 一律拒绝（`hal_kbd_get_char()` 只返回可打印 ASCII） |
| 姓名首尾空格 | 保存前 trim；trim 后为空 → `"me"` |

## 11. 字符输入 API（HAL 层）

### 11.1 现状与目标

`hal_kbd_update()`（`keyboard.c:109-176`）只把 BIOS 事件的**高字节**（扫描码）写入 `kbd_buf`（`:150`、`:156-165`），低字节字符码 `mem[head]` 被丢弃。改名页需要原始字符，因此新增：

```c
/* hal.h */
unsigned char hal_kbd_get_char(void);   /* 0 = 队列空；消费一个字符 */
```

### 11.2 实现规格（待实施）

- 新增并行 FIFO：`static unsigned char kbd_char_buf[KBD_BUF_SIZE]; static int kbd_char_len;`。
- `hal_kbd_update()` 的 MAKE 分支（`keyboard.c:154-166`）在写 `sc` 的同时，若 `mem[head]` 落在 `0x20–0x7E`，把字符追加到 `kbd_char_buf`；溢出策略与 `kbd_buf` 完全一致（`memmove` 丢最旧，`hal_log` 一次）。
- **所有清空路径必须同步清空字符 FIFO**：
  - `hal_kbd_flush()`（`keyboard.c:211-217`）→ `kbd_char_len = 0;`
  - `hal_kbd_drain_advance()`（`keyboard.c:336-346`）→ `kbd_char_len = 0;`
  - `hal_kbd_update()` 的 ignore-frames 丢帧分支（`keyboard.c:117-135`）→ `kbd_char_len = 0;`（进入丢帧时就清，而不是退出时）
  - 溢出分支（`keyboard.c:156-165`）
- 保留原有 `kbd_buf` 语义与所有扫描码 API（`hal_kbd_is_down` 等），**不改结构体/不改类型**，避免波及全文输入循环。

### 11.3 编码假设与验证

**假设**：PC-98 BIOS 键盘缓冲低字节为字符码（ASCII / JIS）。这一点必须在实机上确认，不能凭手册推断（§八 禁一、§十 速率/时序教训）。

**验证方式**：

1. 在 `keyboard.c` 的 MAKE 分支临时增加串口日志 `KBD_LOG("MAKE sc=0x%02X ch=0x%02X\r\n", sc, mem[head]);`
2. `./makegame.sh build demo-a2 && ./makegame.sh make demo-a2`
3. `./makegame.sh test demo-a2 --serial`，敲 `A` / `1` / 空格 / `TAB`，确认 `ch` 分别约为 `0x41` / `0x31` / `0x20` / `0x09`。
4. 若低字节并非字符码（例如恒为 0 或扫描码），则**改用扫描码→ASCII 映射表**（PC-98 键位表），并重写本节；不得在没有实机证据的情况下假设成功。

### 11.4 日文物理输入

日文模式下的物理键盘**仍只产生 ASCII**（低字节即 ASCII），屏幕假名键盘是唯一的假名来源。这是本次明确的范围约定（§1.3）。若日后要支持罗马字→假名，应单独开文档设计转换表与转换状态机，不在本规格内。

### 12.1 假名区段并入所有语言

`tools/naiz_font/gen_cjk_font.py:195` 的 `lang_base_ranges(lang)` 计划改为：


**体积代价**：每种语言固定多 192 个码位 × 32 字节 ≈ 6 KB；10 种语言 ≈ 60 KB（未压缩字库）。可接受，且只在 `CJK_<LANG>.DAT` 内。

## 13. `%myname%` 文本插值

### 13.1 插入点

`core/engine/scene_display.c:70-75` 的 `display_apply_dialog()`：

```c
int display_apply_dialog(const char *charname, const char *text)
{
    const char *expanded = nb_text_expand_vars(text);   /* 新增 */
    audio_pump_once();
    dialog_show(charname, expanded);
    audio_pump_once();
    return 0;
}
```

**为什么在这里而不是 `cmd_dialogue`**：该函数同时服务 `cmd_dialogue`（`nb_commands.c:336-344`）与 `cmd_host`（`nb_commands.c:264-269`），一次覆盖两条对白通路；并且它在 `tr()` 之后、`dialog_show()` 分页/打字机之前，保证分页按**展开后**的文本计算。

### 13.2 展开函数规格

建议放在 `core/engine/nb_dialog.c` + `nb_dialog.h`（该文件已持有 `dialog_text_buf` 与 `TR_VAL_LEN` 语义）：

```c
const char *nb_text_expand_vars(const char *text);
```

- 无 `%myname%` 时**直接返回原指针**（零拷贝，避免无谓开销）。
- 含 `%myname%` 时写入模块内静态缓冲，长度上限 `TR_VAL_LEN`；超限按 UTF-8 码位边界截断并 `hal_log("WARN: text expand truncated\r\n")`。
- 变量缺失（`nb_var_lookup("myname") < 0`）时保留字面 `%myname%` 并 `hal_log` 一次，不静默替换成空串。
- **只展开 `%myname%`**，不做通用 `%var%` 语法，避免把剧情文本里的普通 `%` 误判为占位符。

### 13.3 与分页/打字机的交互

`dialog_show()` 的 `page_start` / `page_end` / `reveal_end` 全部基于展开后的字节流（`nb_dialog.c:129-131` 之后的分页逻辑），因此无需改动 `nb_dialog.c` 的 paging 代码。唯一要求是：**展开必须发生在 `dialog_show()` 调用之前**。

### 13.4 存档与姓名变更的一致性

- 姓名保存于存档槽，因此“改名前存过档、改名后读旧档”会回到旧姓名——这是**预期行为**（存档应恢复当时的完整状态）。
- `nb_var_init()` 在 New Game 时把 `myname` 重置为 `"me"`，随后 rename 页再覆盖。

## 16. 验收标准

### 16.1 功能

1. New Game → 出现改名页；默认显示 `me`；直接点 OK → 进入 `nbook001.nb`，且 `myname == "me"`。
2. Continue 且**无任何存档** → 同样进入改名页；Continue 且**有存档** → 直接载入存档，**不**出现改名页。
3. 改名页点 Back → 回主菜单，`myname` **不变**。
4. 输入 `Akira` → OK → 对白中 `me(){...}` 的署名显示 `Akira`；正文 `%myname%` 展开为 `Akira`。
5. 日文布局下输入 `あきら` → OK → 署名与 `%myname%` 均显示 `あきら`（无豆腐块）。
6. `[flow] rename = false` 的工程（animatest）New Game 仍直接进 `nbook001.nb`，行为与 0.4.015 一致。
7. 存档 → 退出 → 重进 → Continue → 姓名恢复；LOAD 页四槽的 v3 旧档仍可正常读取。

### 16.2 存档兼容

## 17. 风险与回退

| 风险 | 影响 | 缓解 |
|---|---|---|
| PC-98 BIOS 低字节不是字符码 | 物理键盘无法输入 | §11.3 先做实机串口取证，再决定是否改为扫描码映射表 |
| 假名并入所有语言使字库超限 | `gen_cjk_font` 的 max_ranges 守卫触发 | 192 码位远小于上限；若触发，把假名仅并入实际需要的语言并记录理由 |
| 存档三档读长写错 | 旧档全部 `checksum fail` | `test_save_layout.py` + 验收 16.2 的 v2/v3 手工档 |
| `[flow] rename` 默认值选错 | 其它工程跳到不存在的场景 | 默认 false + 构建期硬校验 |
| 菜单循环内全量重绘 | PC-98 掉帧、光标残影 | §十四 两阶段绘制 + `test_nameinput_boundary.py` 静态检查 |
| `me` 被误登记进 `characters.json` | `char(){me}` 找立绘失败、i18n 产生无意义键 | §7.3 明确禁止；代码审查时检查 `characters.json` diff |
| 字符 FIFO 未随 flush/drain 清空 | 陈旧字符泄漏到下一场景 | §11.2 逐条列出四个清空点；实现时逐一对照 |
| `%myname%` 译文丢失 | 部分语言下正文出现字面占位符 | `test_i18n_name_placeholder.py` |

**回退方案**：把 `[flow] rename` 置 false 即可完全回到旧入口行为；存档 v4 为纯追加字段，回退到旧引擎时旧档仍可读（新档旧引擎明确拒读，不产生半读状态）。
