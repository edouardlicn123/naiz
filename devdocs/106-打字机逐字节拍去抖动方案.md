# 106-打字机逐字节拍去抖动方案

> 版本：0.2.132（现状）→ 已落地 0.2.133
> 日期：2026-09-21
> 状态：**已落地** —— 解决打字机 reveal"输出到一定字数卡一下再继续"的微观节拍抖动问题。Step 0 探针证实根因为 **NP2kai DOS 时钟整秒量子化 + 成块交付**（见 §2.2 与 §3.2），实施方案为 **A+（绝对期望位置 + 虚拟时钟钳制）**，实测 max/avg 比值 2.09 ≤ 2.5 门限（见 §6）。

## 1. 背景

### 1.1 症状

用户实测（0.2.131 交付后，NP2kai 目检）：**剧情文字逐字输出到一定字数时会"卡一下"再继续输出，长句尤其明显**。经询问确认三个特征：

1. **同一页内中途**卡顿（非 3 行页脚翻页处）；
2. 卡顿位置不固定地落在行内（未到行尾）；
3. **自动继续**（无需任何输入，过一小会儿自己再出字）。

已排除"对话框翻页需人工确认"的解释——翻页语义（nb.c:379-389 / main.c:161-202）必须输入才续，与"自动继续"矛盾；页容量 3 行（讲解见 §2.2）与"行内中途"不符。

### 1.2 参照（Ren'Py typewriter 的手感基准）

105 号方案定义的对齐基准：`typewriter(slow_cps)`，N 字/秒**平滑连续**逐字出现，揭示中点击跳满整页、整页后点击翻页。0.2.125-0.2.131 已把"逐字揭示/四档速率/点击跳满"全部落地，但**逐字推进的微观节奏**在本轮才暴露问题：聚合速率正确 ≠ 每字间隔平滑。

### 1.3 治理原则

- **不改时钟源**：PIT 已被 0.2.129 实测非单调否决；DOS 2Ch 已是可用时钟中唯一单调可用的（详见 §3.4）。
- **不动渲染层**：`draw_text` / `layer_dialog_render_page` 核心零改动，延续 105 方案 A"调用侧截断串"。
- **重放测序**：先加串口探针把"Δ=0 停拍 + Δ 猛增追字"的微观证据钉死，再实施，避免靠目测猜。
- **至简至上**：优先增量式小改（累加器改为绝对期望位置），不另造时钟/不走预测插值重逻辑。

## 2. 现状审计（证据）

### 2.1 reveal 步进（nb_dialog.c:189-246）

```c
void nb_dialog_reveal_tick(void)
{
    ...
    now = hal_wallclock_ms();                      /* :215 */
    if (!reveal_armed) { reveal_last_ms = now; ... }/* 首 pass 只记基线 */
    ...
    delta = now - reveal_last_ms;                  /* 相邻两次墙钟差值 */
    reveal_last_ms = now;
    reveal_ms_frac += (unsigned long)speed * delta; /* 累加器 */
    while (reveal_ms_frac >= 1000UL) {             /* 满 1000 推 1 字 */
        reveal_ms_frac -= 1000UL;
        if (reveal_end >= page_end) break;
        reveal_end = utf8_step_forward(reveal_end, page_end);
    }
    dialog_render_reveal();                        /* 截断串整页重画 */
    dialog_layer_blit();
    if (reveal_end >= page_end) nb_dialog_reveal_finish();
}
```

**关键事实**：reveal 速度只依赖**相邻两次 `hal_wallclock_ms()` 的差值 delta**。Δ=0 的 pass 无推进；Δ 大时 while 一次追多字。clock 读数若被量化到粗刻度，节拍必然呈"跳-停-跳"。

### 2.2 时钟源量化（hal_pc98.c:62-92）

```c
unsigned long hal_wallclock_ms(void)
{
    regs.h.ah = WALLCLOCK_DOS_AH_GET_TIME;   /* 2Ch */
    int386(WALLCLOCK_DOS_TIME_INT, &regs, &regs);  /* INT 21h */
    now = (CH*3600+CL*60+DH)*1000 + DL*10UL; /* DL=百分秒，×10ms */
    ...折叠回绕，返回单调累计 wallclock_ms_total
}
```

- `INT 21h AH=2Ch` 的 DL 是**百分秒**（×10ms 粒度）。
- 真实 DOS 上百分秒由 **8254 PIT 18.2Hz tick（≈55ms）** 派生，DL 每次 tick 跳 5-6 ——有效更新时间步长**粗于 32 字/s 的 31.25ms/字**。
- **NP2kai pass 率实测 ~20.5Hz（每 pass ≈49ms）**（devdoc 82 §5.2；0.2.130 串口探针复验）。主循环双挂 reveal（main.c:136 外层 + :156 wait loop，节拍以 vblank 为准）。

**Step 0 探针实测（0.2.133 落地前置，钉死根因）**：NP2kai 上 `INT 21h AH=2Ch` 的 **`DL` 恒为 0**（一次性 `[CK]` 探针 6/6 次采样），百分秒字段在模拟器上不可用；BIOS tick `0x40:0x6C` 在 DOS/4GW 保护模式下恒读 0。因此可用读数只剩**整秒**，且秒值并非平滑推进而是**成块交付**：时钟冻结 3-6 真实秒后一次跳 +1000…+6000ms（序列 `0→1000→2000→3000→7000→10000→11000→15000→19000`）。原始 delta 直方图 `{1000×172, 0×18, 16×4}`。→ 根因是**时钟源本身**（不止"DL 粒度粗"），见 §3.2 结论。

两者不对齐 → delta 序列呈 `50, 0, 55, 5, 60 …` 等抖动：某些 pass 读到 Δ=0（本 pass 无推进=**停一拍**），随后一个 pass Δ 猛增、while 一次追 1-2 字。屏幕表现即"几个字、停一拍、追几个字"（NP2kai 上叠加"冻结 3-6s + 追字爆发"成冰点）。

### 2.3 为何 0.2.128-0.2.131 没暴露

| 版本 | 修的 | 验证方式 | 局限 |
|---|---|---|---|
| 0.2.127 | 末页不显示/页界守卫 | 逻辑推演 + 无头回归 | 不涉节拍 |
| 0.2.128 | 聚合速率慢 3 倍（60Hz 分母错） | 逻辑推演 | 换了时钟后未测节拍 |
| 0.2.129 | PIT 端口错误（0x44→0x43、除数 298295） | 串口探针 | 只测了"墙钟每秒推进量" |
| 0.2.130 | 帧节拍墙钟（漏计 VSYNC） | 串口探针：pass 率 20.5Hz | 聚合速率错 |
| 0.2.131 | DOS 2Ch 墙钟 | **58s 聚合速率对拍**（53 样本 +1000ms↔host~0.99s，±2.5%）| **未测逐字微观节拍**——CHANGELOG 留"实测 @32/s 真 32 字/秒留人工目检"尾巴 |

聚合正确（0.2.131 达成）+ 微观节拍粗（本次暴露），两者由同一时钟源的不同时间尺度表现：58s 平均把抖动抹平，而相邻 pass 的 Δ 量化直接决定了单字之间的停顿。

### 2.4 排除项（已人工核对，均不是根因）

- **翻页等待输入**（恐 3 行页脚）→ 与"自动继续"矛盾，排除。
- **`dialog_render_reveal` 每 tick 重画成本随前缀增长**（截断串越长重画越久）→ 真实存在但只影响 pass 时长（Δ 变大 → 每 pass 追更多字），不产生"停拍了自动续"的特征；且长句卡顿位置不特定。列为次要放大因素（方案 A 顺带缓解）。
- **时基 `now==0` 兜底 / 午夜回绕**（nb_dialog.c:221-228）→ 低频一次，不符合"周期性、每长句都有"。
- **`hal_wallclock_ms()` 本身逐次调用开销** → int386 反射耗时可观但恒定，不产生节拍型停顿。

## 3. 方案

### 3.1 目标与判定标准

- 行为目标：32 字/s 档在 NP2kai 下应**近似一字一拍**（间隔≈31ms±量化），不出现"同页内停一拍再自动续"。
- 成功标准：串口探针（见 §3.2）连续 10s 记录中，**相邻两次真实出字间隔的 max/avg 比值 ≤2.5**（修复前预计 >5）；目检长句流畅。
- 语义不变：点击跳满/翻页、四档速度、AUTOEXIT 直通、截断串渲染全部维持 105/125 语义。

### 3.2 实证探针（落地第 0 步，先钉死根因）

仿 0.2.130/131 `[CLK]` 打法，**临时**在 `nb_dialog_reveal_tick` 每次实际推进 `reveal_end` 后输出一行串口：

```
[RV] vnow=<虚拟时钟ms> de=<delta_eff> target=<目标字数> end=<reveal_end>
```

（A+ 实施后探针复测用此格式；`de` 恒为 40/100 即可证明钳制生效。）

NP2kai 跑长句场景 ≥10s，宿主 `time.monotonic` 对拍；分析相邻两行 `end` 变化间隔与 `delta` 序列，确认"Δ=0 停一拍、Δ 猛增追多字"的微观形态。探针用毕移除（C 源零残留，参照 0.2.131 清理纪律）。

> 若探针显示节拍已尚可（比值 ≤2.5），本方案降级为"不落地，仅记录"，避免无谓改动——按数据说话，不按猜测量改。

### 3.3 方案 A+：绝对期望位置 + 虚拟时钟钳制（落地实施方案）

Step 0 证据（§2.2）把方案改为 **A+**：单独"绝对期望位置"（A）仍受困——NP2kai 的整秒时钟冻结 3-6s 后一旦开始流逝，`elapsed` 单次 +4000 → `target` 一次欠 128 字，仍是"冻结-爆发"。故在 A 之上追加**虚拟时钟**：绝对目标（=速度 × 虚拟流逝/1000）不变，但喂给它的每个 pass 增量 **delta_eff 被钳制到 [REVEAL_PASS_MIN_MS, REVEAL_PASS_MAX_MS]**：

```c
/* 新增常量 */
#define REVEAL_PASS_MIN_MS 40UL   /* delta_raw==0 时地板：时钟洞内仍按 pass 节奏出字 */
#define REVEAL_PASS_MAX_MS 100UL  /* delta_raw>100ms 时天花板：丢弃追赶盈余，消除爆发 */

delta_raw = now - reveal_last_ms;
if (delta_raw == 0)            delta_eff = REVEAL_PASS_MIN_MS;
else if (delta_raw > REVEAL_PASS_MAX_MS) delta_eff = REVEAL_PASS_MAX_MS;
else                           delta_eff = delta_raw;
reveal_vnow += delta_eff;                              /* 虚拟时钟（单调、有界） */
target = (unsigned long)speed * (reveal_vnow - reveal_page_ms) / 1000UL;
/* while (reveal_char_count < target ...) utf8_step_forward —— 逐字补差额 */
```

- **去掉** `reveal_ms_frac` 累加器与 `while(>=1000)` 循环；改为每 pass 直接算 `target`，与 `reveal_char_count` 比对、逐字前进差额（单次至多差 1-3 字）。
- **地板防冻结**：时钟洞里（`delta_raw==0`：整秒边界内相邻 pass 读到同一秒）虚拟时钟仍 +40ms/pass → 汉字按 pass 节奏推出，不再"停拍拍"。
- **天花板防爆发**：时钟补齐那一下（raw 一次 +1000..6000）被压成 +100ms → `target` 只 +3-4 字，绝无瞬间满页。
- 真实硬件（DL≈55ms tick）两界都不触发，行为与 A 一致。
- `AUTOEXIT` 直通、点击跳满（`nb_dialog_reveal_finish`）路径不变；`reveal_armed` 校准保留；翻页 `reveal_page_ms` 重锚（`now - reveal_char_count*1000/speed`）；回绕走 `now < reveal_last_ms` 分支重锚。
- **顺带疗效**：每 pass 都走到 render 分支，重画频率稳定；长句前缀重画成本不再被 Δ 放大。

缺点与防护：虚拟时钟与真墙钟存在微量速率偏差（NP2kai 洞内=pass 节奏而非真秒），肉眼不可见；机构时钟恢复后差值被天花板丢弃，无累积爆发。FLOOR/CEIL 数值可在 NP2kai 复测后微调（0.2.133 用 40/100 实测达标，见 §6）。

### 3.4 方案 B / 方案 C（否决，记录在案）

- **方案 B：保留累加器 + Δ=0 插值**：为 Δ=0 的 pass 补"上次均值"预测一拍。逻辑在累加器上加平滑层，边界（首 pass/回绕/换行）处理多、复杂度高于 A，收益与 A 相同。不做。
- **方案 C：接更细时钟（PIT 8253）**：0.2.129 已实测 NP2kai IA32 核心 PIT 读数由模拟 CPU 时钟驱动、非单调（`nevent_getremain/cpumulti`），任何端口下皆非真墙钟。**永久否决**，不改时钟源。

### 3.5 复用与边界

- 复用：`hal_wallclock_ms()`（时钟源）、`utf8_step_forward`（字符步进）、`page_start/page_end/reveal_end` 状态、`dialog_render_reveal` 截断串渲染、`reveal_armed` 校准模式、串口探针纪律（0.2.130/131 先例）。
- 边界：**不改** `hal_pc98.c` 时钟源、**不改** `draw_text`/render 层、**不改** settings/菜单（速度档位不动）、**不改** NB VM/指令/存档、**不新增** NB 命令。
- 改动文件面预估：仅 `core/engine/nb_dialog.c`（+ 临时探针，用毕移除）+ 回归测试文件。
