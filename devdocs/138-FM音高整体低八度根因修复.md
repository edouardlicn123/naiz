# 138 — FM 音高整体低八度根因修复（引擎编码遗漏 `2^(block-1)`，devdoc 136 §十五订正）

> **状态**：`实现完成待实机验证`
> **版本**：`0.3.036`
> **日期**：2026-10-15
> **关联**：136（BGM 音质长远方案，**本文订正其 §十五 的低八度判定**）、123（MIDI→FM 通路 S0–S5）、135（S7 OPNA LFO 接入）、134（方案 C 定时器，独立线）
> **参考**：`docs/refdocs/F03_opna_fm_and_bgm_routes.md` §3.8（F-number 公式，本轮已就地订正）、YM2608 Application Manual（联网取得）、`NP2kai/sound/fmgen/fmgen_opna.cpp`、`NP2kai/sound/fmgen/fmgen_fmgen.cpp`、`tools/vendor/ymfm`
> **前置**：用户实机反馈 BGM「音调偏低」；本会话首次自检 ff flute 渲染时发现**绝对音高比目标低整整一个八度（×0.5）**，追根到引擎 `fmopn.c` 的音符→寄存器编码。

---

## 一、症状

- 实机：BGM（FM 通路，NP2kai）听感**音调偏低**，不止 flute，全部音符系统性低一个八度。
- 离线：oracle（fmbench/ymfm）渲染纯音参考 patch，C4→130.6（目标 261.6）、A4→220.2（目标 440）、C5→261.7（目标 523.3），比率恒 **0.5**。
- devdoc 136 §十五 曾把这个 0.5 判为「**ymfm 低八度**」，并给 fmbench 打了一个 `FNUM ×2` 的补丁（`write_patch_and_keyon()`）。**该判定方向错了**（§四）。

---

## 二、判定过程（三条独立证据链，互相印证）

判定目标是：**同一个 (block, fnum) 寄存器值，芯片（= NP2kai 实听）与 ymfm 各渲染多高？引擎为某音符发出的 (block, fnum) 是否正确？**

### 证据①：YM2608 官方手册

F-Number 公式为

```
fnote = F-Number × 2^(block-1) × φM / (144 × 2^20)          φM = 7.9872 MHz
```

即 **`f = (fnum << (block-1)) × 7987200 / (144 × 2^20)`**。A4(440Hz) ⇒ **block 5 + fnum 520**（`520×2^4×7987200/(144×2^20) = 440.0`）。

### 证据②：NP2kai 的 fmgen（= 用户实听通路），逐行核算 + 实测

- `fmgen_opna.cpp:525` `OPNABase::SetRate()` 内 **`c /= 2`**（注释「従来版との互換性を重視したけりゃコメントアウトしよう」）⇒ NP2kai `opna.c:123` 传入的 `OPNA_CLOCK*2 = 7987200` 在 fmgen 内部变成 **3993600**。
- `fmgen_opna.cpp:122` `SetPrescaler(0)`：`fmclock = clock / 6 / 12 = 3993600/72 = 55466.7 Hz`。
- `fmgen_fmgen.cpp:607` `Operator::SetFNum()`：`dp_ = (f & 2047) << ((f >> 11) & 7)` ⇒ `dp_ = fnum << block`（**fnum 取 11 bit**）。
- 合成频率 = `dp_ × fmclock / 2^21`。

**用仓库现成的 fmgen 宿主渲染器实测**（`/tmp/opencode/fm/fmgen_render`，仅作离线核算，不进引擎/HDI）：

| 寄存器 | `dp_` | `dp_ × 55466.7 / 2^21` | 实测 dominant |
|---|---|---|---|
| block4 / fnum520 | 8320 | 220.0 Hz | **220.0 Hz** |
| block5 / fnum520 | 16640 | 440.1 Hz | **440.0 Hz** |

结论：**真实芯片（fmgen）对 block4/fnum520 输出的就是 220Hz**，对 block5/fnum520 输出 440Hz。与手册完全一致。

### 证据③：ymfm

`tools/vendor/ymfm` 的 OPN `compute_phase_step` 净效果为 `(fnum<<1<<block) >> 2 = fnum << (block-1)`，**恰是手册的 `2^(block-1)`**。ymfm 与 fmgen、手册**三方一致**。

### 证据链收口：引擎发的寄存器不对

引擎（改前）`core/lib/fmopn.c` 用 `fnum<<block = freq × 18432/975`，其 **`18432/975 = (144×2^20)/7987200`**，即隐含 `f = (fnum<<block) × 7987200/(144×2^20)`——**用的是 `2^block`，漏掉了 `2^(block-1)` 的折半**。于是 A4 被编成 **block4/fnum520**，芯片按证据①②把它渲染成 **220 Hz** ⇒ **用户实听的就是低一个八度**。

> 交叉验证：`(18432/975) × (7987200/(144×2^20)) = 1.0`，即旧编码恒使「寄存器隐含频率 = 目标频率」，但那个「寄存器隐含频率」所用的正是错的 `2^block` 公式。

---

## 三、根因

**单点根因**：`core/lib/fmopn.c` 的音符编码常量 `FMOPN_FNUM_SCALE_N = 18432` 少了 `2^(block-1)` 的因子，应为 **`36864`**（`= 2 × 18432 = 288 × 2^20 / 7987200 × 975`）。这使**所有** MIDI 音符被编码低一个 block，芯片遂整体低一个八度。

`FMOPN_FNUM_SCALE_D = 975` 不变（`N/D` 整体乘 2）。

修复后锚点：

- A4(440) → **block5 / fnum520**
- C4(261.63) → **block4 / fnum618**（`618×2^3×7987200/(144×2^20) = 261.5` ✓）

## 四、devdoc 136 §十五 的错判与订正

136 §十五 的判定表（原文）：

| 136 §十五 原判定 | 错在哪 | 正确结论 |
|---|---|---|
| 「① **引擎公式正确** `f=(fnum<<block)*7987200/(144*2^20)`，A4=block4/fnum520=440」 | **这是错的**。该「公式」漏了 `2^(block-1)`；据此算出的 440 是「按错公式自洽」，芯片实际给 220 | 引擎公式**错**（漏折半）；A4 应为 **block5/fnum520** |
| 「② **fmgen 正确**…给出同一频率（= 440）= 用户实听」 | 半对半错：fmgen 确实正确，但正确值对 block4/fnum520 是 **220**（证据②），不是 440。136 把 fmgen 的**正确输出**当成了引擎的期望值 | fmgen = 220（block4）/440（block5），与手册、ymfm 一致 |
| 「③ ymfm `>>1` 恰半数 ⇒ ymfm 错」 | ymfm 的 `fnum<<(block-1)` **不是错，是手册公式本身** | ymfm **正确**，无需补偿 |
| 「**修复**：fmbench 写 `$A4/$A0` 时 FNUM ×2」 | **这是错误补偿**：它把 oracle 拉高到 440，使 oracle 与**用户真实听到的 220** 脱钩——`×2` 掩盖了引擎的 bug，而非修复它 | 撤销 `×2`；改为**修引擎**编码 |

**关键量纲分辨**（教训）：oracle 的职责是**忠实再现芯片对给定寄存器的输出**，**不是**「输出作曲者心里的那个音高」。136 把「oracle 应输出目标音高」当成了判据，于是把「忠实 = 220」误读成「bug」。**绝对音高在寄存器层面可被引擎单方面搞错**——修引擎，不是修 oracle。

> 注：`×2` 期间 oracle 的**谐波比值 / inharm / centroid / 颤音率**等**八度不变量**仍然有效（136 §十五遗留里的 flute `3f=−51.1dB` 等比值结论不受影响）；受影响的只是**绝对音高（f0）**及任何依赖绝对 Hz 的量。

## 八、遗留

- **实机试听未验证**：需用户 `./makegame.sh build demo-a2 && ./makegame.sh make demo-a2` 后，实机确认 BGM 音高回到正确八度（不再偏低）。场景 001/002 为 flute 试听源；003/004 为对照。
- **`fnum` 位宽**：引擎 `FMOPN_FNUM_MAX=1023`（10 bit），fmgen/ymfm 按 11 bit 读。修 octave 后 10 bit 上限对应约 **3463 Hz**（block7/fnum1023），MIDI 高端音符（> 约 A6）会夹顶。当前 demo 音域（≤ D6≈1175Hz）不受影响；是否放宽到 11 bit 另议（涉及 `$A4` bit2 语义，未实测）。
- **P2 音色调音**：八度修正后回到 136 的 P1c/P2 流程（fmgen oracle 对齐 + flute 等族 TL 调音）。
