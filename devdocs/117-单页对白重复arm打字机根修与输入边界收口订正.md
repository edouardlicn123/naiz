# 117 — 单页对白重复 arm 打字机根修与输入边界收口订正

> **状态**：完结
> **日期**：2026-09-29
> **起因**：`0.3.008` 定案的「点击 FIFO 堆积」根因被实机 A/B 推翻，需重新定案并订正 116 / c39
> **关联版本**：`0.3.009`（前序 `0.3.008` 为输入边界收口 + anim 幽灵唤醒门控）
> **订正对象**：`devdocs/116-输入边界收口与阻塞语义陷阱修正.md`、`CHANGELOG.md` 的 `c39`

## 一、症状

`projects/demo-a2/scene/nbook004.nb` 第 10 行（串口日志 0 基 `line[9]`，紧随 `line[8] cg(){cg01}`）：

```
neon(){Hey,you really have a great figure.}
```

CG 之后这句对白的**首击无效**，需再点一下才翻页。0.3.008 记录的症状是「无输入自动翻页」，与用户后续实测的「首击被吞、要两下」方向相反——这个矛盾是本轮重新定案的起点。

> 行号留痕：文件第 10 行 = 日志 `line[9]`（0 基）。此前文档中的 `line[10] fei(){Sorry?}` 是**其后**一行，勿混。

## 二、0.3.008 判定为何被推翻

`0.3.008` 认定：`cmd_cg` 的整屏 blit 期间不调 `hal_mouse_update()`，点击堆积在 `mouse_click_fifo`，遂被当作新页输入。

**物理上不成立**：`mouse_update()` 是纯轮询、无 IRQ 路径，鼠标状态只在轮询瞬间被采样。一次完整的「按下 + 释放」若整体落在两次轮询之间，**根本不会被采到**——blit 期间不轮询不是「堆积」，而是「漏采」。

原始证据 `logs/serial_demo-a2_trace.log` 支持后者：CG 之后、对白页打开之后，先出现 **37 次 `b=0` 轮询**，随后才是两次真实点击的 `b=1`。即**无输入自动翻页从未发生**，那两次点击是用户真实操作。

## 三、真实根因

`core/engine/nb_dialog.c` `dialog_show()`：

1. `layer_dialog_render_page()` 对「能装进一页的整句」**一次性完整绘制**，返回 `next < 0`，此时 `text_offset = -1`、`text = NULL`、`page_end = strlen(dialog_text_buf)`；
2. 但 `reveal_active` 仍按「非 INSTANT 速度」**无条件置位**，于是进入「Typewriter on」分支调用 `dialog_render_reveal()`，**用空前缀覆盖刚画好的整页**（只剩对话框盒 + 角色名），随后逐字重打。

两个后果，正好对应用户描述：

| 后果 | 机制 |
|------|------|
| **视觉「一闪而过」** | 整页文字 → 瞬间清空 → 逐字重现 |
| **首击被吞** | `main.c:165-168`（鼠标）与 `main.c:198-201`（键盘）**共用同一判定**：`nb_dialog_reveal_active()` 为真时首击走 `nb_dialog_reveal_finish()`（补完打字、**不翻页**），第二次才 `vm_request_process()` |

**这解释了「两下」与「无输入自动翻页」两个矛盾自述**：行为**随点击时机而变**——打字机进行中点击 = 两下；打字已打完点击 = 一下。短句约 0.6s 打完，故「点得慢就正常、点得快就要两下」。也正因如此，用点击计数做 A/B 判别本身就是**竞态**（见 §五）。

## 四、修复

```c
int single_page = (dialog_state.page_start == 0 && next < 0);
dialog_state.reveal_active =
    (settings_get_text_speed() != TEXT_SPEED_INSTANT &&
     !single_page) ? 1 : 0;
NB_DEBUG("dialog_show: typewriter %s (%s page)\r\n", ...);
```

- 单页行不再 arm 打字机，整句一次显示，**首击即翻页**；
- **多页行所有页（含末页）保持打字机**，效果统一不变；
- 条件提取为 `single_page` 局部标志（C89 要求块首声明），使 arming 分支能同时报告页型。

**新增运行时标记 `dialog_show: typewriter armed|off (single|paged page)`** 是本次 A/B 能成立的关键：此前该回归只能靠点击计数观察，而点击计数是竞态（§三末）。标记把「单页行是否 arm 打字机」变成串口日志里的确定性事实。

## 五、诊断工具 `tools/diag/np2kai_ab.py`

NP2kai + xdotool 串口 A/B 探针。以下均为**实测踩坑后固化**的经验，写下来是为了不再重走：

| 坑 | 现象 | 定论 |
|----|------|------|
| **只认鼠标采样标记** | 键盘轮次明明成功，却被报 `INPUT_NOT_SAMPLED` | 采样标记须按通道取：键盘 `[INPUT] Key confirmed`、鼠标 `b=1` |
| **XSendEvent 被丢弃** | `--window` 发键，开机菜单毫无反应 | 按键走 **XTEST**（不带 `--window`），wxWidgets 只认真事件 |
| **按下太短采不到** | `xdotool key` 的按下+抬起约 12ms，落在两次 BIOS 端口轮询之间 | `keydown`/`keyup` 显式保持 **150ms** |
| **点击落点靠猜** | 硬编码 `(640,300)` 落在 640px 宽窗口的**右边界**上 | 由窗口几何算中心点；且菜单只认三个窄热区，键盘才是正解 |
| **target 永远等不到** | 从「当前末尾」开始找 `--target`，而目标行已在 advance 的 sleep 期间写完 | 从 **advance 标记的匹配结束位置**开始找 |
| **假通过** | 探针自证 PASS，实则跑的是**旧 HDI 里的旧引擎** | 每次改引擎后必须 `makegame.sh build` **+ `make`**（注入 HDI），只 build 不 make 等于没改 |
| **点击计数是竞态** | 回退版有时也 PASS | 用 `--forbid` 否定断言（确定性），点击计数仅作辅助 |

**门控设计**：任一门控不成立就**不报判定**（`STUCK_BOOT_MENU` / `NEVER_REACHED_ADVANCE_TARGET` / `NEVER_REACHED_TARGET` / `INPUT_NOT_SAMPLED` / `BUG_SIGNATURE_PRESENT`），并在失败时打印输入采样数与窗口片段以便自解释。宁可空报，不可假报。

## 六、A/B 实证

`disks/demo-a2.hdi`，同一场景、同一参数，**仅回退/应用 `!single_page` 一处**：

```
--advance-to 'cg: id=' --target 'line\[9\]:' \
--forbid 'typewriter armed .single page' --expect 'line\[10\]:' --clicks 1
```

| 构建 | 标记 | 1 次输入后 `line[10]:` | 判定 |
|------|------|----------------------|------|
| 回退 | `typewriter armed (single page)` | 未出现 | `BUG_SIGNATURE_PRESENT` |
| 修复 | `typewriter off (single page)` | 出现 | `PASS` |

> 注：shell 单引号不剥离 Python 的 `r''` 前缀——写 `r'line\[9\]:'` 会把字面量 `rline\[9\]:` 传给 argparse，正则将要求 `line` 前存在一个 `r`，永不匹配。探针 docstring 的示例已改正。
