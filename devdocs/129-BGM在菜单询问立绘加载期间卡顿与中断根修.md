# 129 — BGM 在菜单/询问/立绘加载期间卡顿与中断根修（时钟单点化 + 统一帧泵 + 分块解码）

> 状态：`进行中`
> 版本：`0.3.027`
> 相关：devdoc 107（平滑虚拟时钟）、122（PCM 单通道）、123（MIDI→FM）、F03（OPNA 寄存器）
> 前序：devdoc 126–128（FM 地址修复已提交 `7480959`；默认 FMP 音色内容过静已判定）

## 1. 症状

用户实机反馈（正式 BGM 上机后可闻，但）：

1. **音乐有严重卡顿** —— 节拍不稳、忽快忽慢、段落推进有停顿感。
2. **打开「问题询问」（question）时 BGM 被打断**，直到做出选择才恢复。
3. **首次加载「立绘」（char/cg）时 BGM 被打断**，加载完成后才接回。

## 2. 根因（三处，均有代码位置）

### 2.1 所有游戏内菜单/询问的输入循环根本不泵音频

`audio_tick()`（`core/engine/audio.c:496`）是 FM/PCM 推进的**唯一**入口。接入前它只被 `core/engine/main.c` 的三处循环调用（接入后为 `main.c:125/138/156`）：

而每一个自带输入循环的菜单/交互点都**没有**它（也没有 `vblank_wait`）：

| 位置（接入 `engine_frame_pump()` 之） | 用途 |
|---|---|
| `nb_interact.c:85` | `question` 选项询问（用户点名） |
| `nb_menu.c:281` | 游戏内通用菜单 |
| `nb_setting.c:379` | 游戏内设置 |
| `nb_saveload.c:277` | 存取档 |
| `nb_save_dialog.c:136` | 存读档对话框 |
| `nb_cggallery.c:329/360` | CG 画廊 |
| `nb_special.c:143` | 特殊界面 |

只要这些循环在跑，`nb_process()` 不返回、外循环不转，`audio_tick()` 整段不执行 ⇒ **BGM 完全冻结**，直到玩家退出该界面。这是「问题询问时会打断」的确证。

### 2.2 耗时命令在单个 `nb_process()` pass 内跑完，期间不泵音频

外循环顺序是 `engine_frame_pump()`（含 `audio_tick()`）→ `nb_process()`。`nb_process()` 返回前不会推进音频。首次 `char`/`cg` 走 `layer_sprite_face`（`layer_sprite.c:207`）→ `image_load`（`image.c:145`）→ **`mag_decode`（`mag.c:147`）**，缓存未命中时整段解码阻塞当前 pass（`image.c:175` 起），故只有**首次**加载明显。场景开场连续加载 bg + 多张立绘可累计数百 ms 的音频空洞 ⇒ 「立绘加载时打断」。

### 2.3 平滑虚拟时钟与「调用者数量」耦合 ⇒ 节拍漂移

`hal_wallclock_smooth_ms()`（`hal_pc98.c:154`）设计上是**每次调用按 [40,100]ms 有界前进**的全局钟（`hal.h:149/156`）。它被多个消费方共同调用：
- `audio.c`（BGM 调度，`audio_tick()` 内）
- `nb_dialog.c:257`（打字机 reveal）
- `nb_anim.c:568`（动画，仅 `a->active` 时）

因此 BGM 节拍 = **（每 pass 调用次数）× pass 频率**：
- 阻塞一段 ⇒ 无调用 ⇒ 钟滞后 ⇒ 音乐整体后移；
- 打字机/动画同时轮询 ⇒ 每 pass 调用 2–3 次 ⇒ 钟加速 ⇒ 音乐变快。

这正是「严重卡顿」的来源，也意味着**不能简单地在菜单循环里塞一句 `audio_tick()`**：紧凑自旋循环会高频调用它，使钟狂飙、BGM 加速（卡顿更糟）。必须先让时钟与调用次数解耦。

## 3. 修复设计

### Phase 1 — 时钟单点化

- `hal.h`：新增 `void hal_wallclock_smooth_advance(void)`（`:149`）；`hal_wallclock_smooth_ms()`（`:156`）改为**只读**返回当前累计值（不再有副作用）。
- `hal_pc98.c`：把原 `hal_wallclock_smooth_ms()` 的前进逻辑搬进 `hal_wallclock_smooth_advance()`（`:132`，写 `smooth_clock_total` 在 `:149`）；`hal_wallclock_smooth_ms()`（`:154`）只 `return smooth_clock_total`。
- 前进点唯一化：由「统一帧泵」（Phase 2）每帧调用一次 `hal_wallclock_smooth_advance()`；`main.c` 三处循环经帧泵调用（`:125/138/156`）。
- 收益：`audio_tick()` 变为**帧内幂等**（同一帧内重复调用不会推进时钟），从而 Phase 3 的分块泵音频安全。

### Phase 2 — 统一帧泵 + 接入所有阻塞输入循环

- 新增 `core/engine/frame.{c,h}`：`void engine_frame_pump(void)` ＝
  `vblank_wait(); hal_wallclock_smooth_advance(); anim_tick(); audio_tick(); nb_dialog_reveal_tick();`
  （鼠标 `update`/画光标仍由各循环自理，避免破坏其既有语义；帧泵**不含**键盘轮询，各循环原 kbd 时序不变。）
- `main.c` 三处循环改调该 helper。
- 接入 §2.1 全部循环。
- `ui_interact` 的 `q_timeout=600`（`nb_interact.c:59`）由「迭代次数」改为「**帧**」（接 vblank 后每迭代即一帧），数值 600 不变。

### Phase 3 — `mag_decode` 分块泵音频

- `core/lib/mag.c` 属平台无关 lib，不得直连 hal/engine ⇒ 用回调钩子。
- `mag.h` 新增 `void mag_set_progress_hook(void (*fn)(void))`（NULL 清除）。
- `mag.c` 在主 RLE 循环与 4bpp 展开循环中按 `MAG_PROGRESS_STRIDE`（`mag.c:14`，初值 2048）调用钩子；**共 4 个调用点**——RLE 循环（heap `:374`、pool `:747`）按迭代累加 `_prog`，4bpp 展开循环（heap `:400`、pool `:766`）按 `i % STRIDE`；未设置时零开销。
- 引擎在 `audio_init()`（`audio.c:453`）注册钩子 ＝ 调用 `audio_tick()`（Phase 1 后帧内幂等，安全）。

## 6. 风险

- 时钟只读化后若某帧漏调 `hal_wallclock_smooth_advance()` ⇒ 时钟停滞（BGM/打字机/动画全停）。以「帧泵独占 advance」为唯一约定。
- 给自旋循环加 vblank 节流会改变响应/CPU 占用；逐循环回归。
- `mag_decode` 内执行回调 ⇒ 回调期间做 `outb`（FM 寄存器/PCM FIFO）；需保证回调为纯泵、不重入解码。
