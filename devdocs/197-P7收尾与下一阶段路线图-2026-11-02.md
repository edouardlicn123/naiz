## 二、工作清单

### A1 — DOS/32A BGM IRQ ISR 恢复验证（优先）

**现状**：`hal_irq.c` 里 DOS/32A 下 `hal_bgm_irq_init()` 直接 `return 0`，Timer-B ISR 不安装，BGM 靠 cooperative pump（`audio_tick`）走。cmpack（DOS/4GW）保持 ISR 驱动。

**当年关闭的原因**（devdoc 194）：
> "Timer-B tick landing inside mag_decode() left the decode frame 2 bytes short (code=11 at=255998), deterministically, 6/6 runs"

**现在为什么可以重开**：
- 根因已定位：DOS/32A 把 `cli` 虚拟成 VIF，ISR/硬件 IRQ 反射落到应用栈上。当年的 ISR 安装就是在 mag_decode 正被 `cli` 包住时，硬件 IRQ 打断 → DPMI 反射 → 应用栈帧被改写。
- 现在 mag_decode 的 cli 仍保护热循环，但关键改动是 **hook 调用点用 `_enable()/hook()/_disable()` 包起来**。ISR 进来时 `IF=0`，所以反射不会落在热循环上——理论上 P7 的修复应该已经顺带解除了 ISR 路径风险。
- 但 ISR 路径还有自己的特殊性：ISR 运行在硬件 handler 上下文（`__interrupt` 属性），DPMI 给它的是另一套栈/段语义（`core/engine/audio.c:774-780` 已经说明 ISR 不能直接写 OPNA，因为 DOS/4GW 把 IRQ 放到 extender 私有栈上，`SS=0x00B0`）。当前实现用 `audio_tick_isr_pending()` 在主栈 drain ISR 累积的 units，这一层 ISR-safe 逻辑没变过。

**计划**：
1. 在 `hal_irq.c` L318 去掉 `#if defined(NAIZ_DOS32A)` 这段早退（或者加 `_DOS32A_IRQ_EXPERIMENTAL_` 开关），让 DOS/32A 构建也安装 ISR；
2. `rm -rf core/build && EXTRA_DEFS=-DAUDIO_PUMP_TRACE=0 ./makegame.sh makegame demo-a2 --pack openpack`；
3. 跑 3 次完整流程（`run_flow.sh`），看：
   - `BGM IRQ: scanning FM IRQ line; co-operative pump stays active` 是否出现
   - `[ISR] ticks=... v=... w=...` 是否周期性出现（证明 ISR 真在 fire）
   - 有没有 `mag_decode failed`
   - BGM 是否正常出声（对比 cooperative 模式）
4. 若 3/3 通过，ISR 恢复固化；若仍失败，说明 ISR 反射和 hook 反射机制不同，需要记录差异（ISR 反射的栈选择 vs hook 反射的栈选择）。

**风险**：ISR 内部的 `hal_wallclock_fixed_advance` 是 ISR-safe（无 `INT 21h`），但 `hal_bgm_irq_probe_step`/`audio_tick_isr_pending` 在主栈 drain 时，ISR 和主栈之间的竞争靠 `hal_bgm_irq_take_pending_units`（应该是原子读）保护，需要确认这一点。
