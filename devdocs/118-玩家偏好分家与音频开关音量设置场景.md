## 一、背景与动机

两件事在同一次勘察里撞到一起：

1. **游戏内设置场景几乎是空的**。`core/engine/nb_setting.c` 的布局每页留 4 个行位（`setting_row_y[]`，`nb_setting.c:99`），翻页器也已实现（`SETTING_ROWS 4`），但 `g_rows[]`（`nb_setting.c:71`）**只有 1 行**——Text Speed。玩家能调的只有打字机速度。
2. **玩家的任何选择都活不过一次 `build`**。`settings_save()` 写的是部署树里的 `games/<game>/settings.txt`（`settings.c:151`，相对路径），而 `build_game.py:320-323` **无条件**用 `projects/<game>/scene/settings.txt` 覆盖它。⇒ Language 与 Text Speed 每次构建都被打回默认值。

第 2 点不是「加功能之前应该先修的清理项」——它决定了这个方案其余部分的形态。**在偏好与项目配置共处一个文件的前提下,加进去的每一行持久化设置都是一次「下次构建即丢失」的新增项。** 所以顺序是先分家,再加行。

## 二、症状

```
$ ./makegame.sh build demo-a2 && ./makegame.sh make demo-a2
$ # 在游戏内把 Text Speed 调成 Instant、Language 设为繁体
$ ./makegame.sh build demo-a2
$ # 重新开机 → 两项均回到 settings.txt 的项目默认值
```

可观测特征：**无任何报错**。语言退回会让简体字库渲染繁体文案，是 §十一 8.3 规则事故的诱因条件之一。

## 五、根因

**玩家偏好与项目配置被放进同一个文件，而该文件位于 build 的无条件覆盖路径上。**

`settings.txt` 同时承担两个互斥职责：

- **项目配置**（`dlgstyle` `btnstyle` `version` `blacktitle` `blackdialog`）——由 `projects/<game>/scene/settings.txt` 手工维护、`build` 时注入 `config.toml` 派生的三键；
- **玩家偏好**（`lang` `text_speed`）——由 `settings_save()` 在运行期回写。

两个职责的生命周期方向相反：前者随项目走、随 commit 走；后者随玩家走、与 commit 无关。共处一文件 ⇒ **玩家的选择在设计上不可能存活**。这不是某次忘了同步，是结构性问题。

## 六、设计

### 6.1 归属划分与载入顺序

| 文件 | 归属 | 键 |
|------|------|-----|
| `settings.txt`（项目） | 构建期维护 | `dlgstyle` `btnstyle` `version` `blacktitle` `blackdialog`，以及 `lang` 的**项目默认** |
| `USER.CFG`（玩家） | 运行期回写 | `lang` `text_speed` `bgm` `snd` `vc` `bgm_vol` `pcm_vol` |

载入顺序：先 `settings.txt` 建立项目默认 → 再叠加 `USER.CFG` 的已存在键（玩家优先）。首启无 `USER.CFG` 时全部取默认。

`settings_save()` 改为只写 `USER.CFG` 的 7 键。三个调用点（`main.c:94`、`nb_mainmenu.c:114`、`nb_setting.c:331`）**签名与位置不动**，只改 `settings.c` 内部的打开目标与键集。

### 6.2 页面布局（7 行，2 页）

| 页 | 行 |
|----|-----|
| 1 | Text Speed · BGM · Sound Effect · Voice |
| 2 | BGM Volume · Sound & Voice Volume · Read Progress |

第 1 页开关、第 2 页音量与进度，语义分组优先于行数均匀。`SETTING_ROWS` 保持 4 不动（牵连其他界面），故 7 行必然分 2 页；翻页器已实现。

### 6.3 三条开关

- **状态归属**：`audio.c` 内 static + `audio_set_bgm_enabled/snd_enabled/vc_enabled` 与 getter；`settings.c` 只负责持久化（读写时调 audio 的 getter/setter）。方向与既有先例一致——`settings.c:144-145` 本就调 `dlg_set_style`/`btn_set_style`；这样 `audio.c` 不反向依赖 `settings.h`，单一事实源。
- **门控位置**：`audio_bgm_start:67`、`audio_snd_play:185`、`audio_vc_play:186` 三入口开头判开关。已核实 `nb_audio.c:29,40,51` 全经此三处，**覆盖完整、无旁路**。
- **BGM 关**：额外调 `audio_bgm_stop()`（`audio.c:112`，16 通道 all-notes-off，通道独立、干净）。
- **snd/vc 关**：新增 `static int g_pcm_channel`（0=无/1=snd/2=vc），`pcm_play` 赋值、`pcm_release()` 清零；关闭某通道时**仅当匹配**才 `pcm_release()`。零串扰。

### 6.4 两条音量（量程不对称，标签刻意不同形）

| 行 | 机制 | 量程 | 档位 → 写入 |
|----|------|------|------------|
| BGM Volume | MIDI **CC7**（标准 GM 通道音量） | 0=静音 ~127=最响，**正序** | `0%`→0 / `50%`→64 / `100%`→127 |
| Sound & Voice Volume | 86 板 **A466h** bit3~0 | **4bit、倒序、15 仍非静音** | `Max`→`0xA0` / `High`→`0xA5` / `Mid`→`0xAA` / `Low`→`0xAF` |

- **BGM**：照抄 `audio_bgm_stop():117-119` 的 16 通道循环范式，`0xB0+ch, 0x07, vol` 发 16 遍，起播与变更时各一次（约 3 行）。
- **PCM**：新增 `hal_pcm_set_volume(int step)`，`step` 夹逼 0..15 后写 `0xA0 | step`；`hal_pcm_play:131` 的硬编码 `0xA0` 改为跟随当前 step（该行原值本身正确）。
- **标签不一致是有意为之**：BGM 用百分比是行业惯例且 0 档是真静音，值得显示；PCM 是 4bit 衰减器，写 `25%` 是假信息（不存在 0 音量、衰减大概率非线性），故用词档。
- **硬约束**：snd 与 vc 共用一条 PCM 通路 ⇒ **不可能有独立音量**，只有独立开关 + 共用一条音量行。

## 八、踩坑与陷阱

1. **A466h 衰减是倒序、只有 4bit、且 `1111b` 是「最小」不是「静音」**。按「音量 0~100 线性」实现必然错向；PCM 静音要走 **A66Eh bit0**（只作用 PCM 两颗 PCM61P，不碰 FM/MIDI）。
2. **snd 与 vc 共用一条 PCM 通路**，`hal_pcm_play` 直接换绑流 ⇒ **起播音效会打断正在播的语音**。既存硬件行为，**不是 bug**，与开关无关。设置菜单可在语音播放中打开（`voice` 是非阻塞命令，`nb_audio.c:43-53` 触发即返回；`audio_stop_all()` 只在 `scene_switch()` 里调，`nb.c:300`）。
3. **BGM 与 PCM 不冲突**（分属 MPU-401 `0xC0D0/0xC0D2` 与 86 板 `A4xx`）。勘察中期曾把冲突对象搞反，已更正。
4. **CC7 可能被 SMF 自身的 CC7 事件覆盖**。
5. **A468h bit5 决定 A46Ah 的语义**（bit5=1 时 A46Ah 是 FIFO 中断间隔而非 D/A 控制）。本项目 `hal_pcm_play` 的六步协议**恰好走对**，但靠的是错误注释掩护（见下条）。
6. **三处术语错误须随本轮修正**（代码对、注释错，后人照注释改必踩雷）：`hal_audio.c:83` `PCM_CTRL_A46A_FIFO`「A46A programs fifosize」实为**中断许可 + 中断间隔**；`hal_audio.c:88` `PCM_CTRL_FIFOSIZE_MAX` 数值对但写的是中断间隔寄存器；`hal_audio.c:120`「board enable」实为 **OPNA mask**。
7. **8.3 命名**：`USER.CFG` 基名 4 字符，全大写，合规。
8. **§十四.2 硬性规定**：新增 UI 字符串一律以英文为基准、经 `tr()` 渲染，**禁止硬编码英文直绘**；纯数字/格式串属例外，故 `"%d / %d"` 合法。
9. **`CG_COUNT` 可能大于 `CG_TOTAL`(=99)**：位图仅 99 位，阅读进度须 `min()` 夹逼（C6/C29）。

## 十、待实机确认（编译通过 ≠ 已验证）
