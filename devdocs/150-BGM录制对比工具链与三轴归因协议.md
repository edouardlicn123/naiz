## 一、目的

`148 §六` 给出三轴归因的判别法，但缺两样可执行的东西：**参照时间线**与**录音 onset 检测**。本文件定义二者的工具链、测量协议与判据，使「颤/电流声」可被**数据**定位到 **A 时基 / B voicing / C LFO** 三者之一（或组合），而非靠听感猜测。

**产出**：一份 `bgm_compare` 报告（引擎实录音 vs MIDI 应有时序/音高 vs oracle 音色），据此执行 `149` 的对应修正。

---

## 二、可对比的量（及边界）

MIDI 是**音符数据不是音频**，故：

| 量 | 参照源 | 工具 | 判据 |
|---|---|---|---|
| **时序** | `.mid` 的 note-on 应有毫秒 | `midi_ref`（复用引擎 `midi.c`） | IOI 抖动 / 迟到 / 吞音 / 成簇 |
| **音高** | `.mid` 音号 | `midi_ref` + 录音 f0 | 逐音音分误差 |
| **音色** | **`fmbench` oracle** 同 patch 频谱（**非** MIDI） | `spectrum_report` | 质心 / `>5kHz` / 谐波比 |
| **"原版"听感** | GM soundfont（`TimGM6mb`）渲染 | `gm_render`（libfluidsynth ctypes） | 仅作**节奏/音高对照 + 人工 A/B**；音色属 soundfont，非 PC-98 原生 |

**边界（写死防误用）**：GM 渲染**不能**用于音色判决（不同合成器）；音色判决唯 `fmbench` oracle 为准（`136`）。

## 三、工具链（新增/改动）

### 3.1 `tools/naiz_audio/midi_ref.py`（新）
- ctypes 编译 `core/lib/midi.c`（宿主机 gcc，仿 `test_fm_seq.py`）→ `parse(path) -> (events, len_ms)`；`note_ons()` 抽 `0x9x vel>0`。
- **单一事实源**：时间线由引擎自己的解析器产生，`midi_tick_to_ms` 与运行时逐字节一致。
- 已证：`midi.c` 单独可编译（`gcc -I core/lib midi.c`），Melody Town 310 ev/108151ms、Icy Garden 1527 ev/128994ms。

### 3.2 `tools/naiz_audio/gm_render.py`（新）
- ctypes 加载 `/usr/lib/x86_64-linux-gnu/libfluidsynth.so.2`（**已装**，无需 sudo/无新 pip 依赖），`fluid_synth_sfload`(`TimGM6mb.sf2`) + `fluid_player_add/play` + `fluid_synth_write_s16` 循环 → WAV。
- 用途：① 人工听"原版"；② 作 onset 检测器的**对照输入**（干净音频上验证检测器）。

### 3.3 `tools/naiz_audio/spectrum_report.py`（改）
- 新增 `detect_onsets(x, fs)`（RMS 包络 + 起音斜率阈值 + 最小间隔）与 `measure_ioi(onsets)`；保持既有 5 项度量不动。

### 3.4 `tools/diag/bgm_compare.py`（新，编排）
```
--rec  <raw/seg/wav>  引擎录音（或 --game 走 np2kai_audio 录制）
--mid  <file.mid>     源 MIDI（参照时间线 + 音高）
--gm   <out.wav>      可选：输出 GM 渲染作对照
--analyze             出 IOI 抖动表 / 延迟漂移 / 逐音音高 / 频谱
```
- 对齐策略：以**首个 onset** 对齐，随后按 IOI 序列比对；报告 `jitter_std`、`jitter_p95`、`drift_ms_per_s`、`pitch_cents`。
- **fail-loud**：录音静音、声道/采样率不匹配、解析失败一律非零退出（`AGENTS §九.6`）。

### 3.5 `tools/tests/test_bgm_compare.py`（新）
- 合成信号单测：onset 检测（精确位置）、IOI 数学、pitch 估计；GM 渲染与实录音集成测试在缺 `DISPLAY`/`libfluidsynth` 时 `skip`（非"静默通过"）。
- 删守卫即红。

## 四、引擎侧取证（时序，确定性旁证）

`FmseqSink`（`core/lib/fmseq.h:72`）**只有寄存器写回调**（`write`），note 派发在 `fmseq.c dispatch()` 内部、无对外通道。故时序取证走**引擎层**（`core/engine/audio.c`，允许 `hal_logf`），不改 `core/lib`：

- 在 `audio_tick()` 的 BGM 派发处（FM 分支 `fmseq_pump` 前后；MPU 分支 `while` 内）加**编译期可选** trace（`BGM_TICK_TRACE`，默认关）：
  - FM：每次 `fmseq_pump` 后若派发了事件（`fmseq_cursor` 前进）记 `BGM tick cur=<ms> n=<k> seg=<pass>`；
  - MPU：`while` 内记每条 `BGM ev t=<ms> n=<idx>`。
- **判据**：若 `n` 成簇（一次多枚、随后长间隔）⇒ **A-1 帧量化**；若 `cur` 平滑漂移而 `[VC] tgt` 摆动 ⇒ **A-2 vclock 速率**。
- 与 `midi_ref` 的应有时间线比对 `cur` 的推进速率 ≈ 1.0。

> 该 trace 与 `np2kai_audio` 录音**同一次 `build`+`make`+`test` 会话**采集，一次跑齐 ① ②。

## 五、测量协议（执行步骤）

1. `make -C core`（若加了 trace 则先开宏）→ `./makegame.sh build demo-a2 && ./makegame.sh make demo-a2`。

3. 同会话：`np2kai_audio --game demo-a2 --after BGM --duration 12 --out logs/aud001.raw`（001 纯 flute）。
4. 003：`--max-presses` 推进到场景 003（`icy_garden`）→ `logs/aud003.raw`。
5. `bgm_compare --rec logs/aud001.raw --mid 'assets/demo-a2/bgm/Melody Town Theme.mid' --analyze`；003 对 `Icy Garden.mid`。
6. 离线：`fm_render bell.fmp` + `spectrum_report`（谱）；`gm_render` 出对照 wav。

### 六.3 工具链副产物与陷阱（供后人省时）

- **`pkill -f wxnp21kai` 会杀死自身 shell**（其命令行含该模式）——必须 `pkill -9 -x wxnp21kai`。
- **`makegame.sh build` 会重编引擎**（`build_game.py` 调 `make -C core`），并入的 `EXTRA_DEFS` 随之丢失；须 `export EXTRA_DEFS=...` 让子 make 继承（`Makefile` 用 `EXTRA_DEFS ?=`）。
- **传字符串宏**：`-DBGM_BENCH_KEY="icy_garden"` 被 wcl386 当裸标识符；改用 stringify（`-DBGM_BENCH_NAME=icy_garden` → `NAIZ_BGM_STR(BGM_BENCH_NAME)`）。
- **无 WM 下 GUI 输入不可达**：XTEST 键/点均不到达 guest（`b=1` 恒 0）；无头路径（`AUTOEXIT`/`BGM_BENCH`）才是可靠取证入口。
- **`[VC]` 单位**：`step/16 = ms/pass`；本例 bench（无场景渲染）实测 3.25–40 ms/pass（均值 ~5），**pass 率随负载剧烈变化**（重载曾见 ~85 ms/pass）⇒ 帧量化非固定值。

## 七、未确认项与风险

- **onset 检测的可靠性**：FM 多音叠加 + 颤音会污染包络；以 GM 渲染作对照输入先验证检测器，再上实录音。
- **libfluidsynth ABI**：仅验 `so.2` 存在；ctypes 结构/常量需逐个核对（`fluid_settings_t` 等 opaque 指针）。
- **录制依赖 `DISPLAY` + NP2kai + 新鲜 HDI**；无显示则 `skip`（非静默通过）。
- **NP2kai pass 率 ~20.5Hz** 会放大轴 A；数据须标注"模拟器侧"，真机待用户复听。
- **本次不改 `core/lib`**（sink 无 note 通道），时序取证只在引擎层加可选 trace。
