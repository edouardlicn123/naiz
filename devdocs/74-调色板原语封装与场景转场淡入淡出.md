> 3. **帧数默认**：16 帧（@60fps ≈ 0.27s），与 transition.h 现有 fallback 一致。

## 一、需求

1. 抽出**调色板读写与插值的可复用原语**（`palette.c/h`），作为场景转场淡入淡出（首批）与 NAIZ_ANIM 调色板轨（后续）的共享底层。
2. 场景切换/章节结束转场支持**调色板淡出（PFADE）**：全屏统一渐变至纯黑，替代当前 SOLID FADE 的 Bayer 抖动逐像素覆盖。
3. 视觉目标：电影式全屏明暗变化，无棋盘抖动感；**不破坏背景像素**，恢复无备份/回写开销。
4. 保持现有架构约束：engine 层仅经 `hal.h` 访问硬件端口（`hal_read_palette`/`hal_set_palette`）。

## 二、现状与依据（调研结论）

### 2.1 调色板端口可读 —— 无需软件镜像

- `core/plat/gdc.c`：`gdc_set_palette(idx,r,g,b)` = `outb 0xA8(idx) / 0xAA(g) / 0xAC(r) / 0xAE(b)`；`gdc_read_palette(idx,&r,&g,&b)` = `outb 0xA8(idx)` + `inb 0xAA/0xAC/0xAE`。
- `core/plat/hal.h:83` / `hal_pc98.c:53,67` 已将两者暴露为 `hal_set_palette`/`hal_read_palette`。
- **结论**：编译器可直接读回当前 256 条调色板作为淡出基准，无需为 fade 维护软件镜像（无需侵入 `image_set_palette`/`dlg_update_palette` 等全部既有写路径）。NP2kai 模拟器端口读回可靠。

### 2.2 转场现状与调用链

```
config.toml [transition] type/frames
   → tools/naiz_build/export_config.py（TRANSITION_MAP 字符串→宏值，get_int frames）
   → core/engine/nb_config.h（#define NAIZ_TRANSITION_TYPE 2 / NAIZ_TRANSITION_FRAMES 2，build 产物）
   → transition.h（#ifndef fallback: VBLINDS / 16）
   → layer.c:119 scene_end() → transition_run(全屏, NAIZ_TRANSITION_TYPE, NAIZ_TRANSITION_FRAMES, SOLID, 0, NULL)
```

- `scene_end()`（layer.c:119）是唯一统一转场点；转场前已 `layer_sprite_hide_all()` + 停音频 + `hal_set_palette(0,0,0,0)`（索引 0 置黑）。
- `transition_run`（transition.c:197）：阻塞式，循环 `frames` 步，每步 `hal_vblank_wait()` + `hal_mouse_update()` + `hal_mouse_draw_cursor()`；SOLID 模式直接写 VRAM。
- 现有 `TRANSITION_FADE`（transition.c:32 `transition_fade_solid`）= Bayer 8×8 抖动 `fill_rect_pattern` 逐像素覆盖目标色；BLEND 模式（transition.c:213）需 `vram_read` 备份 + `memcpy` 回写。
- **问题**：SOLID FADE 逐像素写 VRAM（跨多 vblank），且把背景像素覆盖成目标色；BLEND 复原需整套备份/回写。当前 naiz 每个场景切换都经此路径（AGENTS §十：场景切换自动清屏黑屏），是全引擎最贵显示操作之一。

### 2.3 类型宏占用

transition.h `0..5` 已占满（CUT/FADE/VBLINDS/HBLINDS/DBLINDS/RDBLINDS）。新类型用 **`TRANSITION_PFADE 6`**。

## 三、封装设计：palette.c / palette.h

新增 `core/engine/palette.c` + `core/engine/palette.h`（engine 层，经 hal.h 访问硬件；Makefile `wildcard engine/*.c` 自动收录）。只承载**纯原语**，不承载帧循环/阻塞逻辑（阻塞式淡出驱动放 transition.c，见 §四）。

```c
/* palette.h */
#define PALETTE_SIZE 256

/* Read all 256 palette entries via hal_read_palette(). */
void palette_get_all(uint8_t pal[PALETTE_SIZE][3]);

/* Write all 256 palette entries via hal_set_palette(). */
void palette_set_all(const uint8_t pal[PALETTE_SIZE][3]);

/* Per-entry linear interpolation factor t/out_frames.
 * out = from + (to-from) * step/div. */
void palette_interp(const uint8_t from[PALETTE_SIZE][3],
                    const uint8_t to[PALETTE_SIZE][3],
                    int step, int div, uint8_t out[PALETTE_SIZE][3]);
```

要点：
- 数据布局固定 `uint8_t [256][3]`（{r,g,b} 序，index = 调色板索引），无动态分配、无越界风险。
- `palette_interp` 整数运算，避免浮点：`(from[i] * (div-step) + to[i] * step + div/2) / div`，最后一位收敛到 to。
- **不写 `vblank_wait`、不写鼠标、不写日志**——保持纯函数，供任意调用方复用（transition 阻塞驱动、NAIZ_ANIM 每帧换色等）。
- C 规约：无 malloc、无 fopen、固定长度数组，天然满足 C1/C6/C9；函数签名注释用英语。

## 四、转场集成：TRANSITION_PFADE

### 4.1 类型与分发

- transition.h 增 `#define TRANSITION_PFADE 6`。
- `transition_run()` 的 SOLID 分支 switch 增加 case：`TRANSITION_PFADE` → 调 `transition_pfade_solid(x, y, w, h, step, frames, color)`（color 恒为黑 0，语义=淡出至纯黑；mode 保持 SOLID）。BLEND 分支不处理 PFADE（default 报 WARN，同现有模式）。

### 4.2 淡出驱动伪码（transition.c 内新增实现）

```
transition_pfade(step 驱动，同现有的步进循环):
  首步（step==0）：
    palette_get_all(basis)          # 捕获现场 256 条为基准
    palette_interp(basis, black, 0, frames, cur)   # cur = basis
  每步：
    palette_interp(basis, black, step, frames, cur)
    palette_set_all(cur)            # 全表端口写（768 字节 outb，瞬时）
  末步/结束（沿 shared loop）：
    palette_set_all(black)          # 确保 256 条全部纯黑（含 step 溢出）
```

集成进 transition_run 现有 step 循环（transition.c:224）：每步末尾沿用现成的 `hal_vblank_wait()` + `hal_mouse_update()` + `hal_mouse_draw_cursor()`。**无逐像素 VRAM 写、无 BLEND 备份需要。**

### 4.3 scene_end 消费链（无需改 transition_run 调用）

`scene_end` 现有调用 `transition_run(..., NAIZ_TRANSITION_TYPE, ...)` 原样保留；只要 `config.toml [transition] type="pfade"` 编译期生效即可：
- `export_config.py` 的 `TRANSITION_MAP` 增 `"pfade": 6`（`transition_config.py` 同表若重复定义需同步，见改动清单）。
- `projects/demo-a2/config.toml [transition] type = "pfade"`，`frames = 16`（默认决策 3）。
- `skip_transition`（logo/op.nb，layer.c:128）保持不变：直 `fill_rect` 纯黑，不参与 palette fade（这些场景启动无内容可淡）。

### 4.4 淡入（不纳入 palette fade，设计预留）

淡入 = 黑 → 现场：捕获场景渲染后的 palette 为 `to`，`palette_set_all(black)` 起步，同循环 `interp(basis=black, to, step, frames)`。**决策：不实现。** 将来背景加载可能采用定制的加载/淡入方式，淡入由该机制承接（此节保留 palette 原语供其复用）。

## 六、收益与局限

收益：
- **性能**：淡出从「Bayer 逐像素写 VRAM（几十万像素 + 跨多 vblank）」降为「每帧 768 字节端口 I/O」，差距 2–3 个数量级。
- **零像素破坏**：背景像素索引不动，只改查表颜色；淡出结束黑屏，无需 BLEND 备份/回写。
- **观感**：全屏统一明暗（电影式），无棋盘抖动、无逐行滚动。

局限：
- 全屏统一：同一调色板下的背景/立绘/对话框一起变暗，无法只淡出局部图层（scene_end 已在转场前隐藏立绘，fade 对象 = 背景，语义足够）。
- 依赖端口读回：真机若读端口实现不同步（返回旧值），基准可能滞后一写；NAIZ 目标平台为 NP2kai，读回可靠，风险低（防复发 §九 记录）。

## 十、防复发要点

- 数组统一 `uint8 [256][3]` 固定布局，无 malloc/越界（C1/C6/C9 天然满足）。
- **PFADE 期间禁止任何外来 palette 写**（bg/image_load/dlg_update 等）：基准 `basis` 在首步捕获，中途被改会导致漂移。转场为阻塞段、脚本不推进、`hal_mouse_invalidate_cursor` 已先调用，风险已隔离；实现时检查鼠标绘制路径不写 palette（若 hal_mouse 内部 set 高亮色需避开）。
- **末步强制 `palette_set_all(black)`**：杜绝 step 计算溢出/整除残差导致个别条目非纯黑（消灭静默不黑）。
- fade 结束新场景加载后，不得残留旧 palette 未复位（新场景镜像/图像 set_palette 会自洽覆盖；若担心残留，scene_end 末步已全黑）。
- palette_interp 用整数或 `(x*step+y*(div-step)+div/2)/div` 防溢出：`DIV` 上限=frames≤64，步长≤64，(255*64) 远小于 int 范围。
