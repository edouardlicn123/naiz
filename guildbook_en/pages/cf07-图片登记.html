Image Registration (images.map)

Created: 2026-09-27
Last updated: 2026-09-27

This page explains, from a creator's point of view, how a new image gets into the game: images.map declares the PNG→MAG conversion, ASSETS.DB registers the asset row, and build packs everything into IMAGE.DAT. For the MAG format and palette mechanics see mc04 MAG Image Mechanics; for build commands see makegame.sh.

1. File location and format

Each project has a mapping table at assets/<game>/images.map, and assets/common/images.map holds assets shared by all projects (common is processed first, then the project's own). One line registers one image:

<png path>  <MAG path>  [options...]
  • png path: source file relative to assets/<game>/; anything PIL can read works (PNG/JPG alike).
  • MAG path: output relative to projects/<game>/, usually under images/; the MAG base name must be ≤8 characters (the DOS 8.3 constraint — longer names get truncated and collide at the HDI short-name stage).
  • Lines starting with # are comments; the file header comment is the complete option reference.

Example (4 new images in demo-a2):

png/bg/bg-beach1.jpg       images/beach1.MAG   --256color --cover
png/bg/bg-home-day.jpg     images/homeday.MAG  --256color --cover
png/cg/cg01.png            images/cg01.MAG     --256color --cover

2. Per-line options

OptionMeaning
--256colorQuantize to the shared 256-color palette (the default marker, used for backgrounds, sprites, and CG alike)
--spriteCharacter sprite: palette index 15 is reserved as the transparency marker and excluded from quantization; pixels with alpha<128 map to index 15
--coverScale by the long edge to fill 640×400 and center-crop the overflow (keeps the aspect ratio, no letterboxing). Without it the mode is contain: scale by the short edge, center the result, and leave borders. Backgrounds/CG that must fill the screen need it
--ditherFloyd-Steinberg dithering during quantization
--no-resizeSkip the automatic scale to 640×400 and keep the source pixels (backgrounds only)
--filter-whiteMap near-white pixels to the palette white before quantization

The build is incremental: an image is re-converted only when the source is newer or its options changed (the signature is recorded in projects/<game>/.mag_conv_state.json); everything else is skipped.

3. Three steps to register

Writing images.map alone is not enough — the MAG must also be named in the asset database before the engine can find it:

  1. Add a line to images.map (choose the options: backgrounds get --cover, sprites get --sprite).
  2. Insert a row by hand into the img_map table of projects/<game>/ASSETS.DB (the same treatment as ANI; there is no automated registration entry yet): 
    INSERT INTO img_map (name, filename, type) VALUES ('beach1','images/beach1.MAG','IMG');
    name is the scenario reference key (lowercase); type is 'IMG' (background) / 'SPR' (sprite) / 'CG' (event image, added to the gallery).
  3. Run ./makegame.sh build <game>: PNG→MAG → IMAGE.DAT repacked → nb_asset_table.h regenerated (including cg_map).

4. Referencing from the scenario

  • Background: bg(){beach1}; event CG: cg(){cg01} — always put the object in the brace payload; parenthesized forms such as bg(beach1) are rejected.
  • cg(){key} hides the dialogue box automatically and permanently unlocks the image in the gallery after it is shown; the next line of dialogue reopens the box automatically.

5. Removing old images (4 layers of cleanup)

Retired images must be cleaned out everywhere, or leftovers ship in the package: remove the line from images.map → delete the source PNG and the MAG under projects/.../images → DELETE from ASSETS.DB by filename → drop the matching signature from .mag_conv_state.json. Before you start, confirm there are zero references in scene/*.nb and expressions.json. Deleting an entry from IMAGE.DAT leaves an empty slot, so existing asset ids do not shift.
