Engine Fundamentals

Created: 2026-06-09
Last updated: 2026-09-11

This is the first chapter of the Naiz engine creator's manual. It introduces the core concepts of the engine from a creator's perspective — no source paths, toolchain commands, or internal implementation details.

Concepts marked [Reserved] are not implemented yet and cannot be used; they are described here only to explain the design intent, for reference.

1. Screen Specifications

1.1 Resolution and Mode

The engine runs in the standard PC-98 640×400 pixel, 256-color graphics mode (PEGC packed-pixel). This is the classic visual novel display specification — 400 vertical lines give a 16:10 frame, close to the visual feel of modern 16:9.

1.2 Default Screen

After startup the engine loads the first .nb scenario file, whose bg command loads a background MAG image (if there is none, VRAM keeps its initial state). The dialogue box is overlaid on the background:

└────────────────────────────────────────────┘

  • Lower part: dialogue box (fixed position, shows dialogue)

1.3 256-Color Palette

The engine uses the PC-98 256-color emulated palette. These are the colors the engine reserves (other indices are set dynamically by MAG images):

IndexColorPurpose
0#000000 blackInitial value
7#FFFFFF whiteText, borders
15#000000 blackSprite transparent color (skipped by blit)
248#000000 (dynamic black/blue)Dialogue box background
249–255—Reserved UI colors (reserved)
The palette is updated on every bg command. Indices 248–255 are evacuated by pack_images.py at build time, and protected at runtime by cmd_bg (restores 248) and the menu modules (save/restore 250/251). Indices 7 and 15 are skipped in SPR types. See B11 §5.2 for details.

1.4 PC-98 Display Architecture

PC-98 PEGC display hardware has three parts:

Hardware layerDescriptionEngine usage
Graphic Plane AGraphics plane A (4-bit/pixel)✅ Merged into 8-bit 256-color packed-pixel 640×400 VRAM, the only render target
Graphic Plane BGraphics plane B (4-bit/pixel)
Text PlaneIndependent hardware text layer (character generator + attribute memory)❌ Unused. Invisible under DOS/4GW protected mode; text is drawn into graphics VRAM as bitmaps via draw_text()

All "software layers" of the engine (background, sprites, dialogue box, text) are composited on a single graphics VRAM layer through a multi-pass drawing order; there is no hardware compositing. The menu overlay (menu_layer) is the exception: it is composited in its own RAM buffer first, then blitted to VRAM as a full screen. This is why the engine uses pixel operations such as fill_rect/vram_blit instead of printf.

See mc03 — layer rendering and sprite swapping §1 for details.

2. Dialogue

Dialogue is the most central UI element of a visual novel engine. In Naiz, dialogue is a text box at a fixed position — its position, size, and style stay the same for the whole game.

2.1 What Dialogue Is

In most ADV/VN games, character speech ("lines") and narration are presented line by line in a dialogue box at the bottom of the screen. The player reads one line and presses a key to turn to the next — that is the basic model of a dialogue system.

Naiz's dialogue model is in-place replacement: each time a line is shown, the old text is wiped completely and the new text appears in the same position.

2.2 Dialogue Box Layout

The dialogue box is a rectangle at the bottom of the screen, overlaid on the background:

2.3 Text

Dialogue text is drawn inside the dialogue box:

PropertyValueDescription
Horizontal origin (X)104 pxLeft edge of the dialogue box + 24px indent
Vertical origin (Y)308 pxTop of the dialogue box + 28px offset
ASCII font8×16 bitmap, monospacedEach ASCII character takes 8×16 pixels (32 bytes/glyph)
CJK font16×16 bitmap, monospacedEach CJK character takes 16×16 pixels (32 bytes/glyph)
Colorwhite (index 7)Same color as the dialogue box border
Max ASCII characters per lineabout 57Dialogue text area width 456px / 8
Max CJK characters per lineabout 28Dialogue text area width 456px / 16

Current limits:

  • Supports ASCII (7-bit) + CJK (UTF-8 3-byte encoding)
  • No automatic line wrapping — overlong sentences overflow the dialogue box and get clipped, so the creator must control the character count per line
  • The text area background is cleared with palette 248 and does not rely on a fixed color index

2.4 Player Operations

Naiz's dialogue system is key-driven:

OperationKeyBehavior
Turn to the next lineSpaceShows the next line of dialogue given by host{}
Turn to the next line (alternative)EnterSame as Space
Fast-forwardCtrl (hold down)Skips all dialogue and scene events in sequence at maximum speed

Design details:

  • Space / Enter are consuming triggers — each press turns exactly one line. Holding the key does not turn pages continuously, which avoids accidentally skipping text.
  • Ctrl is fast-forward mode — while held, the engine advances frame by frame, useful for testing jumps or for players who want to skim story they have already seen.

2.5 What to Know When Designing Dialogue

Assumptions and limits of the dialogue system that creators should know:

PointDescription
Fixed positionAll dialogue appears at the same position — you cannot put "line one at the top, line two at the bottom"
In-place replacementShowing new dialogue clears the previous text (palette 248) and draws the new text; there is no "text scrolling" or "history rewind"
One line per unitOne complete block of text is shown at a time; the dialogue box height does not support multiple lines of text at once
Character name slotThe top of the dialogue box can show the speaker's name: dialogue commands such as fei/ira/neon carry the name automatically, while host narration does not
No text effectsText does not fade out, fade in, or change color — all dialogue appears in the same color at the same position
256-color limitDialogue box colors are bound by the 256-color palette; the protected UI colors are index 7 (white), 15 (transparent), and 248 (dialogue box background)

3. Scene

3.1 What a Scene Is

A scene is a unit of game flow executed in order. A visual novel consists of several scenes, and the player goes through them in sequence — like the "scenes" of a film.

Inside a scene the engine executes a series of NB commands. A command can "show dialogue", "wait for player input", "jump to another scene", and so on.

3.2 Scene Flow Example

  Scene starts
    │
    ├─ host{"这里是 Naiz 演示"}        → show dialogue, wait for the player to turn the page
    ├─ host{"Naiz 是一个文字冒险引擎"} → show dialogue, wait for the player to turn the page
    ├─ scene end                      → scene ends
    ▼
  Next scene / game over
