makegame.sh Usage Guide

Created: 2026-08-29
Last updated: 2026-11-05

makegame.sh is the game-data build script: it packs a project's scenario, assets, and configuration into an HDI image that runs in the emulator, and provides the test entry point. For building the engine, see the Watcom installation in start.sh. For daily use, running it directly and picking the project and action from the number menu is the recommended way; command-line subcommands suit scripts or experienced users.

1. Interactive menu (primary usage)

Run it with no arguments:

./makegame.sh

You get a two-level menu; at every step, type a number and press Enter:

  • Step 1: all projects are listed (e.g. 1) demo-a2 …); pick a number to enter that project.
  • Step 2: within the project, choose an action by number:
No.Action
1makegame — build project data + produce the HDI (build + make, recommended)
2build — build project data only
3make — produce the HDI image only
4test — launch the NP2kai test
5test --porttest — serial hardware test
6audio — emulator audio latency settings (global)
7pack — switch pack mode (cmpack / openpack)
0Return to the previous level

A failed menu action does not exit; it returns to the menu so you can retry. This way you never need to remember commands or project names, which makes it the best fit for daily use.

Beginner tip: to see it running, enter a project and pick the "test" item — that launches the emulator.

2. Command-line usage (advanced / scripting)

Once familiar, or when writing automation scripts, pass a subcommand directly and skip the menu:

./makegame.sh <subcommand> <game> [options] [--pack cmpack|openpack]
SubcommandWhat it does
makegame <game>Recommended: build project data + produce the HDI (build + make in one step)
build <game>Build project data only: PNG→MAG, engine, scenes, IMAGE.DAT, runtime, and regenerate nb_config.h
make <game>Produce the HDI image only: inject games/<game>/ into disks/<game>.hdi
test <game> [--serial] [--porttest] [--auto]Launch the NP2kai test
i18n-gen <game> [--force]Generate/refresh the internationalized text template
audioEmulator audio latency settings (global; BGM warble / electrical noise)
pack [cmpack|openpack]View/switch the pack mode; with an argument, writes .naiz_pack as the new default

Two safety checks:

  • make errors out if games/<game>/engine.exe is older than the engine under core/, preventing a stale engine from being packed into the HDI.
  • test errors out if disks/<game>.hdi is older than games/<game>/engine.exe, preventing the emulator from silently running an old engine.

3. Option reference

3.1 Global pack options

  • --pack cmpack: commercial chain, tools_commercial + DOS/4GW (default).
  • --pack openpack: open-source chain, tools_open + DOS/32A, with the extender bound into the EXE.
  • Precedence: --pack > NAIZ_PACK environment variable > project-root .naiz_pack > auto-detection (tools_commercial → cmpack, otherwise tools_open → openpack).
  • The pack subcommand persists the choice: without an argument it opens an interactive menu; with an argument it writes .naiz_pack directly.

3.2 Other options

  • <game>: the project directory name, located at projects/<game>/ (e.g. demo-a2).
  • --serial: emit debug output over the serial port during tests (the most reliable debugging channel).
  • --porttest: only check whether the emulator's serial port is usable; does not launch the game.
  • --auto: if games/<game>/engine_a.exe exists, copy it over engine.exe, re-inject the HDI, then test.
  • --force (i18n-gen): ignore the incremental check and force regeneration of the text.

4. Common usage examples

# In the interactive menu, pick a project → pick 1) makegame (recommended)
./makegame.sh
# Equivalent command-line form (build data + inject HDI):
./makegame.sh makegame demo-a2

# Step by step: build data, then pack the HDI
./makegame.sh build demo-a2
./makegame.sh make demo-a2

# Repack the HDI only (data unchanged)
./makegame.sh make demo-a2

# Run in the emulator over serial and watch the log
./makegame.sh test demo-a2 --serial

# Switch to the open-source chain and view the current setting
./makegame.sh pack openpack
./makegame.sh pack
