Animation Production Workflow

Created: 2026-08-29
Last updated: 2026-08-29

This is an animation production guide for galgame makers who don't write code. Making a game animation really takes three steps: ① prepare the image assets; ② write the "storyboard script" (the .na file — see the Syntax Overview for how); ③ use the animation tool to generate the final .ANI file. This page covers steps ① and ③.

1. Where animations live

Every animation belongs to an animation project (for example "protagonist blink" or "title-screen shimmer"). A project is just a folder, with two places inside:

  • The assets folder: holds your drawn images (and the palette-table files used by palette animations).
  • The scripts folder: holds the storyboard script, the .na file.

The tools create these folders for you, so you never have to fiddle with paths by hand.

2. Generating animations with the animation tool (anima.sh)

Type the following commands in a terminal (replace the project name and script name with your own):

What you want to doWhat to type
Create a new animation project (the folders are created automatically)anima.sh init 项目名
Register the assets into the nickname tableanima.sh register 项目名
Check for assets that weren't registeredanima.sh check 项目名
Build the animation file from a scriptanima.sh build 项目名/脚本名
Build every animation in the project in one goanima.sh buildall
See which animations a project hasanima.sh list

Running anima.sh with no arguments pops up a menu that walks you through step by step — handy while you're not yet familiar with the commands.

Tip: run register once before generating (or simply append --sync to build — it registers automatically before building).

3. Giving assets nicknames (the asset nickname table)

When writing a script you don't use the image's real path and filename — you write a simple "nickname". For example, write {微笑} in the script and the tool looks for the image with that nickname.

These nicknames are registered automatically by the register step — it scans your assets folder and records every image in the nickname table. So:

  • run register first, then build;
  • if a script uses a nickname that isn't registered (or the image was deleted), the tool raises an error instead of quietly producing a broken animation.

4. The output: .ANI files

Following your script, the tool packs the images into the final .ANI file — the animation that plays in the game.

  • Fullscreen animations: fill the entire screen, fixed at 640×400.
  • Cine-strip animations above the dialogue box: occupy only the strip above the dialogue box, fixed at 640×280.
