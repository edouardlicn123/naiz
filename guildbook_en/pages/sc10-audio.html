bgm / sound / voice — Audio Commands

Created: 2026-08-13 Revised: 0.3.019 (the original text called this a "platform placeholder stub with no actual sound", contradicting the real implementation shipped since 0.2.115 — corrected)

bgm(), sound(), and voice() control background music, sound effects, and voice respectively. All three are fully implemented: BGM plays MIDI parsed in real time through the OPN/OPM sound source, while sound effects and voice stream through the YM3433B PCM FIFO. Nothing is a placeholder.

1. Syntax

bgm(){key}
bgm(stop)
sound(){key}
voice(){key}

The object (the audio key) goes in the curly-brace payload; bgm(stop) is a keyword directive. This follows the same convention as bg(effect){key}: "object in braces, parentheses = parameters ± keyword".

CommandParameterDescription
bgm{key} or stopPlay / stop BGM (can loop)
sound{key}Play a sound effect (SE, one-shot)
voice{key}Play voice (one-shot)

2. Parameters

  • key is the audio asset key, written in the curly-brace payload, taken from the name column of ASSETS.DB
  • bgm(stop) stops the current BGM (sends All-Notes-Off to all 16 channels)
  • sound / voice currently only support playback, with no stop form; neither ever loops
  • The bgm(key) / sound(key) / voice(key) forms (key written inside the parentheses) are deprecated and are rejected by the engine and the scenario validator

3. Example

bgm(){morning}      # Play the morning BGM (looping)
bgm(stop)           # Stop the BGM
sound(){door_knock} # Door knock sound effect
voice(){fei_hello}  # Character voice

4. Registering Assets (Where the Keys Come From)

Audio source files live under assets/<project>/ and are registered in the img_map table of ASSETS.DB; the build packs them into a single AUDIO.DAT at the root of the deployment tree. Source files are not injected into the HDI; at runtime only AUDIO.DAT is read.

TypeSource locationFormatRegistration
BGMassets/<project>/bgm/.mid (SMF, parsed at runtime, original bytes passed through)type='BGM'
Sound effectassets/<project>/se/.pcm (8-bit mono container)type='SND'
Voiceassets/<project>/voice/.pcm (same as above)type='VC'
  • The filename column is written relative to assets/<project>/ (e.g. bgm/morning.mid); the name column is the key used in the scenario
  • wav_convert.py converts WAV to .pcm and registers it automatically (--type SND|VC --name <key>); there is no BGM converter, so produce a test track with gen_test_midi.py and then register it by hand
  • The name is also the TOC entry name inside AUDIO.DAT, so it must satisfy DOS 8.3 and stay unique after truncation — a name collision is rejected as a hard packing failure

5. Volume and Switches

  • BGM volume = MIDI CC7 (channel volume) 0–127, sent to all 16 channels; volume changes take effect immediately, with no need to replay
  • Sound effect / voice volume = the A466 electronic volume attenuation, 0–15 with the direction reversed (0 is loudest); the two share one PCM path, so there is only one volume level and they cannot be adjusted separately
  • The player settings have separate switches for BGM / sound effects / voice. Turning a channel off only truly releases the shared PCM path when that channel currently holds it — muting sound effects will not cut off a voice that is playing

Do not translate the keys: the keys of bgm() / sound() / voice() are asset names; they are not looked up through tr(), so a translation makes the engine look for audio files that do not exist. Leave the translation empty (= play under the original name).

Known minor flaw: i18n_gen extracts these keys as translatable text (unlike the exclusion lists for char / bg / cg), so they sit permanently in game_<lang>.txt as empty values. Leaving them empty is correct — do not fill in translations.

Robustness: if a key is unregistered, AUDIO.DAT is missing, or a .pcm header is invalid, the engine prints the matching BGM WARN: / PCM WARN: serial diagnostic and skips playback instead of crashing.
