Animation Script Syntax Overview

Created: 2026-08-29
Last updated: 2026-08-29

This page explains in plain language how to write the storyboard script (the .na file). Think of it as the animation's "shooting list": first the header declaration, then one line per image (or per recolor). For the detailed syntax of each command see: animaconf / frame / base / pal. To generate the animation, see the Production Workflow.

1. The script file must end in .na

Animation script filenames must end with .na (for example 眨眼.na). This is what sets them apart from ordinary scenario files (.nb); with the wrong extension the tools refuse to process the file.

2. The four constructs (commands)

ConstructUsed byWhat it does
animaconf(...)Both typesHeader declaration: is this animation fullscreen or a cine strip? A pixel animation or a palette animation? Which project does it belong to?
frame(...){...}Pixel animationsPlaces one (or several) images and states how many seconds each stays on screen
base(){...}Palette animationsDeclares the first base image, before any recoloring
pal(...){...}Palette animationsDeclares each recolor step and how long it lasts

Numbers or options go in the parentheses; inside the braces { } you write the assets' "nicknames" (the names you gave them at registration).

3. A few general rules

  • The header declaration comes first: animaconf must be the script's very first line (blank lines or # comments may precede it).
  • Pixel animations use frame; palette animations use base + pal. Never mix the two.
  • In a palette animation, base must come before pal (base image first, then the changes).
  • The braces may hold several nicknames separated by commas, e.g. {云1,云2,云3} — they play one after another in turn and share the same duration.
  • A # at the end of a line starts a comment (e.g. frame(0.3){云1} # drift by); the tools ignore comments, so they don't affect the animation.

4. Common pitfalls when writing animations (troubleshooting cheat sheet)

When a tool reports an error it tells you the line number and what went wrong. Here are the common cases in plain words:

SymptomUsually this means…
It says the script must have a .na extensionThe filename doesn't end in .na; just rename the file
It reports a problem with animaconfThe header declaration was omitted, written twice, or is not on the first line
It reports a bad region/type/project nameAn option in animaconf is misspelled, or the project folder doesn't exist
It reports cross-track or a command used in the wrong placebase/pal leaked into a pixel animation, or frame appears in a palette animation (don't mix the two)
It reports a missing frame / missing base imageA pixel animation needs at least 1 frame; a palette animation needs 1 base and at least 1 pal
It reports an unregistered nameA nickname in the braces can't be found in the asset nickname table — go run register again
It reports a wrong sizeFullscreen animation images must be 640×400; cine-strip images are at most 640 wide and 400 tall
It reports a malformed .pal fileIn the palette table, each line must be the four numbers index red green blue, with no repeated index
It says pal must come after baseIn a palette animation pal was written before base; just swap the order
