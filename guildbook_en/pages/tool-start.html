start.sh Usage Guide

Created: 2026-08-29
Last updated: 2026-08-29

start.sh is the repository's unified entry point script: it handles the environment setup check, installing the various dependencies/emulators, and code audits. For daily use, running it directly and working through the number menu is the recommended way; command-line subcommands suit scripts or experienced users.

1. Interactive menu (primary usage)

Run it with no arguments:

./start.sh

A menu appears; type a number and press Enter to run the corresponding function:

Menu numberFunction
1Run the environment check (check)
2Enter the "environment setup" submenu (install dependencies, emulators, compilers, etc. item by item — see below)
3Run the code audit (audit)
4Run the full audit (fullaudit, including a build)
0Exit

After choosing 2 to enter the install submenu, the installable items are listed; select by number again — for example the Open Watcom compiler, the NP2kai emulator, system-level tools, and so on. A failed menu action does not exit; it returns to the menu so you can retry.

Beginner tip: when setting up the environment for the first time, run 1 first to see what is missing, then use 2 to fill the gaps item by item.

Which items are "spare" and do not have to be installed?

A few items in the install submenu are optional / spare — normal development never needs them, so you can skip installing them:

  • djgpp: another compiler toolchain, only a fallback for when Open Watcom (the main one) is unavailable — normally not needed.
  • retroarch: backs up emulator configuration (backup-emu); only needed if you want to switch to RetroArch or another frontend — NP2kai is the default test emulator.
  • mirror: Git repository source (mirror) settings; only used when downloads are slow and you need to switch mirrors.
  • commercial: the commercial menu; only needed when commercial distribution is involved.

The only must-install items are: pip (Python dependencies), deps (system tools), watcom (the engine's compiler), and np2kai (the test emulator) — install the rest only as needed.

2. Command-line usage (advanced / scripting)

Once familiar, or when writing automation scripts, pass a subcommand directly and skip the menu:

./start.sh <子命令> [参数]
SubcommandWhat it does
checkCheck whether the current environment (Python venv, dependencies, toolchain) is ready
pipInstall Python dependencies (pip-install)
depsInstall system-level tools (system-tools)
np2kaiInstall/prepare the NP2kai emulator
retroarchBack up emulator configuration (backup-emu)
watcomInstall the Open Watcom compiler (for building the engine)
djgppInstall the DJGPP toolchain
mirrorEnter the Git repository source (mirror) settings
commercialThe commercial menu (commercial_menu)
auditRun the code audit (symbol-audit logs go to the terminal and logs/)
fullaudit [--no-make]The six-step pipeline audit; --no-make skips the make step

3. Common usage examples

# In the interactive menu, press 1 to see what the environment is missing (recommended)
./start.sh
# Equivalent command-line form:
./start.sh check

# Install the Watcom compiler needed to build the engine
./start.sh watcom

# Run the full audit (including a build) before committing
./start.sh fullaudit
# Audit only, without rebuilding
./start.sh fullaudit --no-make
