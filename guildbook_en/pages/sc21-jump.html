jump — In-Scene Jump

Created: 2026-11-05 Last updated: 2026-11-05

jump() shows a list of choices; after the player selects one, the script stays in the current scene and jumps to just after a tag anchor in this scene.

1. Syntax

jump(prompt;label1,tag1;label2,tag2;...)

Semicolon ; is the top-level delimiter: the first segment is the prompt, and every following segment is a two-field label,tag option.

FieldDescription
promptPrompt text (first segment, not split on commas)
labelDisplay text of the option
tagAnchor in this scene to jump to (must be declared by tag(name))

1.1 Option Segment Rules

  • A segment must have exactly two fields. A missing tag, or an extra comma (e.g. A,m1,extra), causes the segment to be dropped with a WARN.
  • If the label itself needs a comma, escape it as \, (same rule as question §1.1, handled by nb_next_field()).
  • tag allows letters/digits/underscores only and is case-sensitive.
  • Leading/trailing whitespace around fields is trimmed: A , m1 equals A,m1.
  • At most 10 option segments (parser limit); the UI shows at most 4 at once.

2. Runtime Behavior

  • After selecting option N, execution moves to the line after tagN; jumps may go forward or backward.
  • No scene switch: background, BGM, sprites and current scene state stay as they are until commands at the target change them.
  • The choice index (zero-based) is also written to last_choice; var can read it to record the route.
  • Missing tag: the engine logs a WARN, does not jump, and continues with the line after the jump line.
  • Timeout: the choice interaction has a 30-second timeout; on timeout the choice counts as “not selected”, so the script continues with the next line without jumping.
  • Like question, jump blocks the script until the player makes a choice.

3. Difference from question / jumpscene

CommandAfter selectionCrosses scenesChanges variables
questionApplies op/delta, continues to the next lineNoYes
jumpJumps to the line after a tag in this sceneNoNo (can read last_choice)
jumpsceneSwitches scene, optionally landing on a target tagYesNo (can read last_choice)

If a choice must also change variables, assign them with var at the jump target, or use question followed by scene.

4. Build-Time Validation

  • Every tag must exist in the current scene, otherwise the validator reports an error.
  • The option count must be 1–10; undeclared or invalid tag names are reported at build time.
  • The runtime missing-tag fallback exists only for unusual cases such as hot-edited scripts.

5. Example

An entrance choice:

jump(Where to?;Forest,m_forest;Town,m_town)

Forward jump and backward loop over the same block:

tag(m_loop)
host(){Listen again?}
jump(Listen again?;Again,m_loop;Leave,m_end)

tag(m_end)
host(){You leave}
  • “Again” → returns to the line after tag(m_loop), forming a loop.
  • “Leave” → jumps to the line after tag(m_end).
