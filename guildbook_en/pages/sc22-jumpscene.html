jumpscene — Cross-Scene Jump

Created: 2026-11-05 Last updated: 2026-11-05

jumpscene() shows a list of choices; after the player selects one, the remainder of the current scene is discarded and the scene switches, optionally landing directly on a tag anchor in the target scene.

1. Syntax

jumpscene(prompt;label1,scene1[,tag1];label2,scene2[,tag2];...)

Semicolon ; is the top-level delimiter: the first segment is the prompt, and every following segment has a required label,scene plus an optional tag.

FieldRequiredDescription
promptYesPrompt text (first segment, not split on commas)
labelYesOption display text; escape commas as \,
sceneYesTarget scene, see §2 normalization
tagNoAnchor to land on after the new scene loads; omit to play from the first line
  • At most 10 option segments; the UI shows at most 4 at once.
  • label escaping is identical to question §1.1, handled by nb_next_field().
  • A segment missing scene is dropped with a WARN; an empty tag equals “no tag”.

2. Scene Normalization

This shares the same resolution as the scene command; the following forms are equivalent:

FormActual scene file
003nbook003.nb
nb003nbook003.nb
nbook003nbook003.nb
nbook003.nbnbook003.nb
logo / op / mainmenulogo.nb / op.nb / mainmenu.nb
endmainmenu.nb (back to the main menu)

3. Runtime Behavior

  • After selection, all remaining lines of the current scene are discarded (including everything after this line), then the target scene is loaded.
  • Without tag: the new scene plays from its first line.
  • With tag: once the new scene is loaded, execution is placed at the line after that tag. No line before the tag runs, including sceneconf, opening bg/bgm/char. The landing block must therefore set up its own environment (put bg/bgm/char after the tag).
  • Chapter title caveat: landing on a tag skips the target scene's sceneconf, so its chapter title is not set and the save UI falls back to the scene filename. If that scene relies on the chapter title, omit tag (play from the top) or accept the fallback.
  • Missing target tag (runtime fallback): logs a WARN and plays the new scene from the top.
  • Timeout: the choice interaction has a 30-second timeout; on timeout the choice counts as “not selected” — the current scene continues with the line after jumpscene.
  • The choice index (zero-based) is written to last_choice.
  • The switch goes through the usual transition, scene reset and asset-preload flow, exactly like the scene command.

4. Build-Time Validation

  • The target scene must normalize to an existing scene/*.nb file in the project.
  • If tag is given, it must exist in the target scene.
  • The option count must be 1–10 and prompt must not be empty.

5. Example

jumpscene(Set off?;To the forest,nb002,forest_start;To town,003;Stay here,mainmenu)
  • “To the forest” → switch to nbook002.nb and land after tag(forest_start).
  • “To town” → switch to nbook003.nb and play from the first line.
  • “Stay here” → return to the main menu.

Because landing on a tag skips everything before it, the landing block must put its environment setup after the tag:

# nbook002.nb
sceneconf(){Forest, normal}
tag(forest_start)
bg(normal){forest}
bgm(){forest_theme}
host(){You walk into the forest}

This way, jumping to forest_start from another scene still sets the background and BGM; sceneconf is skipped because it precedes the tag (see the chapter-title caveat in §3).

6. Difference from scene / jump

CommandTriggerCrosses scenesLands mid-scene
sceneUnconditional or variable condition chainYesNo (from the top only)
jumpPlayer choiceNoYes (a tag in this scene)
jumpscenePlayer choiceYesYes (optional tag in the target scene)
