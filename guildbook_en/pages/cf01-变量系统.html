Variable System

Created: 2026-06-27
Last updated: 2026-07-28

A Naiz project manages its configuration through 4 JSON files. They live in the projects/<game>/ directory and are compiled into the engine at build time.

Keep this document in sync after any change so the docs match the actual definitions.

1. variables.json — variable definitions

Defines the variables the game uses at runtime (favorability, story flags, counters, and so on).

{
  "variables": [
    {
      "id":       "bond_fei",
      "name":     "Fei好感度",
      "desc":     "Fei对玩家的好感度",
      "initial":  0,
      "min":      0,
      "max":      100
    }
  ]
}
FieldTypeDescription
idstringVariable identifier (lowercase plus underscores), used by scenario commands and internal lookups
namestringDisplay name (save screen, debug output)
descstringDescription text
initialintInitial value; the engine resets the variable to this value on a cold start or a new game
minintMinimum value (default 0); out-of-range values are clamped
maxintMaximum value (default 9999); out-of-range values are clamped

Build pipeline: variables.json → export_vars.py → nb_var_table.h (NbVarDef struct array + NB_VAR_COUNT).

2. characters.json — character definitions

Defines the characters available in the game, used by the char command and linked with expressions.json.

{
  "characters": [
    {"id": 9,  "key": "fei",  "name": "Fei"},
    {"id": 10, "key": "ira",  "name": "Ira"},
    {"id": 11, "key": "neon", "name": "Neon"}
  ]
}
FieldTypeDescription
idintCharacter numeric ID. Matches char_id in expressions.json; the id field in char_map[] uses this value too
keystringCharacter key. Used by scenario commands such as char(pos, ...){ira} and fei{...} (the character key goes in the brace payload). Globally unique
namestringDisplay name. The dialogue box name label uses this value

Build pipeline: characters.json → export_asset_table.py → nb_asset_table.h (char_map[]: key→id→name lookup table).

3. expressions.json — expression mapping

Maps each character's expressions to sprite assets for the char(pos, expr){name} command to look up.

{"expressions": [
    {"char_id": 9,  "expr": "normal",    "asset_id": 1},
    {"char_id": 9,  "expr": "sad",       "asset_id": 8},
    {"char_id": 9,  "expr": "smile",     "asset_id": 9},
    {"char_id": 9,  "expr": "surprised", "asset_id": 10},
    {"char_id": 10, "expr": "normal",    "asset_id": 2},
    ...
]}
FieldTypeDescription
char_idintCharacter ID (matches id in characters.json)
exprstringExpression name (such as normal, sad, smile). Used by the char(pos, expr){name} command
asset_idintSprite asset ID (matches the id of a type='SPR' row in ASSETS.DB)

Build pipeline: expressions.json → export_asset_table.py → nb_asset_table.h (expr_map[]: (char_id, expr)→asset_id lookup table).

4. config.toml — project configuration

Project-level global configuration covering language, title, version, and transitions. It is compiled into the engine at build time, with zero runtime parsing. The format is TOML, supports # comments, and the version line is maintained by a tool. See cf02 Project Configuration File for the full reference.

Build pipeline: config.toml → export_config.py → nb_config.h (NAIZ_* macros, covering transition, styles, blackletter, default language, and version).
