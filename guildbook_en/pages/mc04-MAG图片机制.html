MAG Image Mechanics

Created: 2026-08-29
Last updated: 2026-09-11

This page explains, from a creator's point of view, the Naiz engine's MAG image format, archive storage, shared palette, and transparency conventions — i.e. how all backgrounds and character sprites are loaded and displayed on the engine side. For the lower-level byte specification, see docs/B11-MAG图片加载与显示规范.md in the repository.

1. The MAG format and 256-color mode

MAG (MAKI02) is the dominant image format on the PC-98 platform, supporting 16 colors (4bpp) and 256 colors (8bpp). The Naiz engine always uses 256-color mode (PEGC, bpp=8, num_colors≤256): decoded pixel values 0–255 map directly to hardware palette indices, with no bit-plane splitting or extra color mapping.

Component16-color256-color (used by the engine)
Pixel data4bpp (Flag A/B + color stream)8bpp
Embedded palette16 GRB entriesUp to 256 GRB entries
Screen modescreen_mode=0x00screen_mode=0x80

2. The two image types and user-string conventions

The 16-byte user field in the MAG header identifies the image type, and the engine picks its loading behavior accordingly:

User StringTypeEngine behavior
"naiz\x1a"Background / full screenCalls image_set_palette() to set the whole-scene palette + vram_blit() to write the full screen
"sprt\x1a"Character sprite / spriteDoes not call image_set_palette(); uses vram_blit_sprite(idx=15) to skip transparent pixels

Sprites (the character sprites used by the char command) and backgrounds share the same 256-color palette: the background loads first and sets the palette; sprites load afterwards and write only pixels, rendered with the background's palette. See mc03 — layer rendering and sprite swapping for details.

3. The IMAGE.DAT archive and logical IDs

Multiple MAG files are packed at build time into a single archive, IMAGE.DAT, reducing HDI root-directory entries; the engine indexes them directly by logical ID in O(1).

  • The img_map table of the asset mapping file ASSETS.DB: id (logical_id, i.e. the value passed as the scenario command parameter), filename, and type ('IMG'/'SPR').
  • pack_images.py reads img_map and packs the listed files into IMAGE.DAT; the TOC entry array index = logical_id, so the engine's image_load(id) addresses the array directly, with no filename matching.
  • Characters and expressions are defined separately in characters.yaml, where char_expressions maps expr to img_map.id.

4. The shared palette and reserved indices

In 256-color mode, all image pixels and UI elements share one palette. To keep UI colors (text, transparency, dialogue-box base color) from colliding with image pixels, the engine uses 10 reserved indices:

IndexDefault colorPurpose
7WhiteText / borders / prompts
15BlackSprite transparency (skipped during blit)
248BlackDialogue box base color (recolored dynamically by [dialog] style)
249–255—Spare UI colors (250 = menu text, 251 = menu selection)

Three stages of protection (each stage blocks conflicts on its own):

  • Stage 1, asset generation: mag_convert.py --reserved 7,15,248,... — quantization avoids the reserved indices from the start.
  • Stage 2, archive packing: pack_images.py skips PROTECTED_IDX when remapping all images to the shared palette.
  • Stage 3, engine runtime: image_set_palette() skips 7/15/248–255 and never overwrites UI colors.

5. Transparency conventions

  • Sprite PNGs are converted with mag_convert.py --sprite: areas with alpha<128 map to index 15 (the transparency marker), no resizing — the original dimensions are kept — and "sprt\x1a" is written.
  • For sprites, --reserved excludes 15, because index 15 must hold the transparency marker.
  • The y≥280 region at the bottom of a character sprite must match the dialogue-box layout (pack_images.py verifies y≥280 consistency across expression sets) so nothing shows through under the semi-transparent dialogue box.

6. Build pipeline

mag_convert.py  PNG → MAG (--sprite / --256 / --reserved)
        │
pack_images.py  ASSETS.DB(img_map) → IMAGE.DAT
        │         (shared-palette quantization + remap + post-check)
        ▼
makegame.sh build <game>  injects into the HDI

Sprite mirroring is decided implicitly by the char command's position argument (l left position mirrors automatically; c/r do not mirror). See mc02 — sprites and characters.

7. Relation to scenario commands

  • The bg command: load the background MAG → set the palette → full-screen blit → redraw sprites → restore the dialogue-box base color (248) → rebuild the dialogue-box active base (dialog_occluder, used for pseudo-transparency and hide-restore). The palette must be written before the pixels, otherwise the screen flickers.
  • The char command: load the sprite MAG → write only pixels (shared background palette) → skip transparency index 15.

For command syntax details, see sc02 bg — Background Switch and sc03 char — Sprites and Dialogue.
