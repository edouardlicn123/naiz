anima.sh Usage Guide

Created: 2026-08-29
Last updated: 2026-08-29

anima.sh is the animation production tool: it compiles .na animation scripts into .ANI files the game can use. For the script syntax, see the "Production Workflow" page under the Animation Design category (this page is a standalone document under the production-tools category and does not duplicate that content). For daily use, running it directly and working through the number menu level by level is the recommended way; command-line subcommands suit scripts or experienced users.

1. Interactive menu (primary usage)

Run it with no arguments:

./anima.sh

You get a three-level number menu; at every step, type a number and press Enter:

① Project list (first level)

Lists all animation projects (e.g. 1) myanim …), plus:

  • i creates a new animation project (init skeleton)
  • 0 exits

Pick a number to enter a project.

② Action menu (second level, project selected)

Menu numberFunction
1Check asset registration (check): whether every asset nickname used in the scripts is registered, and whether any has gone stale
2register sync: scan the assets and register them into the index db
3Build animations: enter the script submenu to build a specific animation
0Back one level (project list)

③ Script submenu (third level, after choosing "3 Build animations")

Lists all .na scripts in the project; pick a number to enter a script, then choose:

Menu numberFunction
1build: build this animation (produces the .ANI)
2build --sync: sync the index db automatically first, then build
0Back one level (action menu)

Beginner tip: for a first animation, the usual order is to press 2 in ② to register the assets, then use 3 → 1/2 to build.

2. Command-line usage (advanced / scripting)

Once familiar, or when writing automation scripts, pass a subcommand directly and skip the menu:

./anima.sh <子命令> <参数>
SubcommandWhat it does
init <项目>Create the animation project skeleton: animation/projects/<项目>/{config.toml,scripts/,db/}
register <项目>Scan the assets under assets/<项目>/anim/ and register them into the name index db
check <项目>Read-only two-way reconciliation: unregistered / stale rows / pending updates; non-zero exit code on any difference
build <项目>/<脚本>Produces animation/output/<STEM大写>.ANI; add --sync to sync the index db first
buildall [--flags]Build every script of every project
listList <项目>/<脚本>

3. Common usage examples

# In the interactive menu: i to create a project → pick the project → press 2 to register → press 3→1 to build (recommended)
./anima.sh
# Equivalent command-line form:
./anima.sh init myanim
./anima.sh register myanim
./anima.sh build myanim/blink

# Register automatically before building
./anima.sh build myanim/blink --sync

# Check that the asset registration is complete
./anima.sh check myanim

# Build all animations in one go
./anima.sh buildall

4. Notes

  • Script files must end in .na and live under animation/projects/<项目>/scripts/.
  • You must register before building (or pass --sync to build); otherwise the asset nicknames written in scripts cannot be mapped to real files.
  • check is for CI / pre-commit self-checks: it returns a non-zero exit code when there are unregistered or stale assets.
  • Finished .ANI files are output to animation/output/ and packed into the HDI by the game-data build (makegame.sh build).
