Animation Mechanics

Created: 2026-08-29
Last updated: 2026-08-29

This page explains, from a creator's point of view, the Naiz engine's frame-sequence animation system (NAIZ_ANIM): how animations are made, packed into a .ANI container, and played in a scenario, displaying concurrently with the dialogue box without leaving ghosting artifacts.

1. Animation system overview

NAIZ_ANIM is the engine's unified entry point for frame-sequence animation, built on the in-house .ANI container (v1), which carries two tracks:

  • Pixel track: per-frame replacement of the full screen (or a fixed sub-region), drawn in sync with vblank, reusing the MAG frame codec.
  • Palette track: per-frame recoloring via palette_set_all (the container embeds the original palette table, bypassing the shared-palette invariant).

The two tracks are independent; either can be used alone. Animation, the transition system, and the palette primitives share the pure data functions in palette.c/h.

2. The .ANI container and the per-frame tick table

The v1 container replaces a fixed fps with a per-frame tick table: each frame carries its own duration (in ticks), and playback timing is governed solely by the tick table as the single source of truth.

Size policy (fixed by route S)Region
fullscreen640×400 @(0,0)
cine640×280 @(0,0) (fixed to the whole strip above the dialogue box)

There is no coordinate mechanism at all — the animation size is declared in the container header, and the playback command does not specify type/coordinates (type introspection). The sec modifier can override the total-duration window: the engine converts it into a tick budget with ceil(sec×60); once stops on expiry, loop resets and continues.

3. Production workflow

Animations are described in dedicated .na scripts (strictly separated from the scenario's .nb files); the anima.sh toolchain produces standalone .ANI files:

anima.sh init <项目>          # creates animation/projects/<项目>/{config.toml,scripts/,db/}
anima.sh register <项目>      # bare names → the name index db db/<项目>.db (indexes only)
anima.sh check <项目>         # read-only reconciliation of unregistered/stale/pending entries (exit 1 on any diff)
anima.sh build <项目>/<脚本>  # parses .na → produces .ANI (--sync syncs the index db first)
  • Scripts go in scripts/<名>.na; bare names (no path, no extension) are written inside the braces and mapped to concrete frame files by the name index db.
  • Frame assets go in assets/<项目名>/anim/, and finished .ANI files are output globally to animation/output/.
  • The script syntax supports the animaconf / frame / base / pal bare-bracket sections and V1–V8 validation; a multi-image {f1,f2} explicit interleave sequence shares one duration in seconds.

4. Playback commands

The playback-side handlers live in core/engine/nb_anim.c, registered in the NB command table:

playanima(){name}                 # defaults to once: stops automatically when finished
playanima(once){name}            # explicit once (equivalent to the default)
playanima(loop){name}            # loops (fire-and-forget ambient effects)
playanima(once,sec){name}        # caps total duration at sec seconds (once stops on expiry)
playanima(loop,sec){name}        # loop + a sec-second budget per pass (resets and continues on expiry)
waitanima()                      # blocks until the current animation finishes; passes through if none is active
stopanima()                      # stops and releases the current animation; passes through if none is active
  • The animation name goes in the curly-brace payload, mirroring the shape of a dialogue line's main payload; the command does not declare fullscreen/cine/track/fps (the container header is the single source of truth).
  • Rejection rules (no silent failures): unknown keywords, a missing name, extra arguments, or sec≤0 are all rejected with a log entry, and the script continues.
  • waitanima warns when applied to a loop animation (a loop never finishes — an author error); waitanima/stopanima warn and ignore any arguments they receive, then function as usual.

5. Dialogue-box concurrency and clip_h clipping

When an animation reaches into the dialogue-box region (y≥280), sprite blits must be kept from writing into the dialogue-box VRAM or leaving ghosting artifacts:

  • The clip_h parameter of vram_blit_sprite() (limits the number of rows drawn when >0) is an architecture-level constraint that forces drawing only the region above the dialogue box.
  • If the dialogue-box region must be written for a full-body replacement, use layer_sprite_replace() and call layer_dialog_refresh() explicitly.
  • layer_sprite_face() must not write to the y≥280 region.

This matches the dialogue-box snapshot/restore strategy in mc03 — layer rendering and sprite swapping.
